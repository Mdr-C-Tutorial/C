# 35805 - 严格最长递增子序列长度（LIS: 二分优化 O(n log n)）

## 题目描述

给定一个包含 `count` 个 64 位有符号整数的数组 `items`，求其**严格最长递增子序列**（Longest Increasing Subsequence, LIS）的长度。

子序列是由原数组在不改变元素相对顺序的前提下删除某些或不删除元素所派生出的新序列。严格递增要求相邻元素之间满足严格小于关系（不允许连续相等）。

函数签名如下：

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

bool lis_length_i64(
    const int64_t *items,
    size_t count,
    size_t *out_length
);
```

要求：
1. 参数无效（`out_length == NULL`，或 `count > 0 && items == NULL`）时返回 `false`。
2. 当 `count == 0` 时，长度为 0，输出 0 并返回 `true`。
3. 算法必须在 $O(n \log n)$ 时间复杂度内完成，结合贪心策略与二分查找。
4. 辅助空间复杂度不超过 $O(n)$。

## 解题思路

1. **基础动态规划回顾（$O(n^2)$）**：
   定义 $dp[i]$ 为以元素 $items[i]$ 结尾的严格最长递增子序列的长度。
   状态转移方程为：
   $$dp[i] = 1 + \max \{ dp[j] \mid 0 \le j < i \land items[j] < items[i] \}$$
   计算每个位置需要向前扫描所有前驱元素，总体时间复杂度为 $O(n^2)$。

2. **贪心策略与单调数组构造**：
   为了使递增子序列尽可能长，在相同长度的前提下，序列末尾的元素数值**越小越好**（越小的值越容易接驳后续更大的元素）。
   因此，我们维护一个辅助数组 `tails`，其中：
   `tails[k]` 表示当前所有长度为 $k + 1$ 的严格递增子序列中，**末尾元素的最小值**。
   可以严格证明：`tails` 数组必定是**单调严格递增**的。
   （反证法：若存在 $j < k$ 使得 $tails[j] \ge tails[k]$，则长度为 $k + 1$ 的递增子序列的前 $j + 1$ 个元素必然构成一个更小的长度为 $j + 1$ 的递增子序列，产生矛盾）。

3. **二分查找加速（$O(n \log n)$）**：
   顺序遍历原数组中的每一个元素 $x = items[i]$：
   - 利用 `tails` 数组的单调性，二分查找第一个**大于等于** $x$ 的元素位置（即 `lower_bound` 下标 $pos$）；
   - 若 $pos$ 存在（即找到某个 $tails[pos] \ge x$），则用更小的 $x$ 替换 $tails[pos]$，从而优化该长度子序列的末尾值；
   - 若不存在（即 $x$ 严格大于 `tails` 中的所有元素），说明找到了一个可以延长当前最长递增子序列的新元素，直接将 $x$ 追加至 `tails` 末尾，长度递增 1。
   最终，`tails` 数组的有效长度即为原序列的严格最长递增子序列长度。

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdlib.h>

static size_t lower_bound_tails(
    const int64_t *tails,
    size_t length,
    int64_t target
) {
    size_t left = 0;
    size_t right = length;
    while (left < right) {
        size_t mid = left + (right - left) / 2;
        if (tails[mid] >= target) {
            right = mid;
        } else {
            left = mid + 1;
        }
    }
    return left;
}

bool lis_length_i64(
    const int64_t *items,
    size_t count,
    size_t *out_length
) {
    if (out_length == NULL || (count > 0 && items == NULL)) {
        return false;
    }
    if (count == 0) {
        *out_length = 0;
        return true;
    }
    if (count > SIZE_MAX / sizeof(int64_t)) {
        return false;
    }

    int64_t *tails = malloc(count * sizeof *tails);
    if (tails == NULL) {
        return false;
    }

    size_t lis_len = 0;
    for (size_t i = 0; i < count; ++i) {
        int64_t x = items[i];
        size_t pos = lower_bound_tails(tails, lis_len, x);
        tails[pos] = x;
        if (pos == lis_len) {
            ++lis_len;
        }
    }

    free(tails);
    *out_length = lis_len;
    return true;
}

int main(void) {
    size_t len = 0;

    // 参数校验
    assert(!lis_length_i64(NULL, 1, &len));
    assert(!lis_length_i64((const int64_t[]){1}, 1, NULL));

    // 空序列
    assert(lis_length_i64(NULL, 0, &len) && len == 0);

    // 单元素序列
    const int64_t a1[1] = {100};
    assert(lis_length_i64(a1, 1, &len) && len == 1);

    // 严格递增序列
    const int64_t a_inc[5] = {1, 2, 3, 4, 5};
    assert(lis_length_i64(a_inc, 5, &len) && len == 5);

    // 严格递减序列
    const int64_t a_dec[5] = {5, 4, 3, 2, 1};
    assert(lis_length_i64(a_dec, 5, &len) && len == 1);

    // 含有重复值测试（严格递增不能包含相等元素）
    // [2, 2, 2, 2] -> 长度 1
    const int64_t a_dup[4] = {2, 2, 2, 2};
    assert(lis_length_i64(a_dup, 4, &len) && len == 1);

    // 经典乱序用例: [10, 9, 2, 5, 3, 7, 101, 18]
    // 最长递增子序列如 [2, 3, 7, 101] 或 [2, 5, 7, 18]，长度为 4
    const int64_t a_std[8] = {10, 9, 2, 5, 3, 7, 101, 18};
    assert(lis_length_i64(a_std, 8, &len) && len == 4);

    // 包含负数与极值
    const int64_t a_ext[6] = {INT64_MIN, 0, -10, 20, -5, INT64_MAX};
    // 最长递增子序列: [INT64_MIN, -10, -5, INT64_MAX] 长度为 4
    assert(lis_length_i64(a_ext, 6, &len) && len == 4);

    return 0;
}
```

## 复杂度分析

- **时间复杂度**：$O(n \log n)$。遍历数组包含 $n$ 步，每一步在单调数组 `tails` 上执行一次对分查找，耗时 $O(\log n)$。
- **空间复杂度**：$O(n)$。`tails` 数组的最长可能长度等于原数组大小 $n$。

## 延伸思考 / 模式总结

注意：`tails` 数组中保存的最终元素**并不一定等于**某一个合法的真实 LIS 序列（因为更小的值会替换前面的位置，导致相对原顺序发生打乱），但其**有效长度**在数学上严格证明等于最长递增子序列的长度。若需要精确重建真实的 LIS 方案，需在二分更新时额外记录每个元素的前驱索引数组。
