# 31906 - 基数树（Radix Tree）单分支路径压缩基础

## 题目描述

普通字典树（Trie）的每条边只能承载单一字符，导致无分支的单词后缀会退化为深而狭窄的长单链（例如 `"international"` 产生深度为 13 的冗余节点链）。实现将单分支链条压缩为字符串标签的紧凑字典树——**基数树（Radix Tree / 压缩前缀树 / Compact Trie）**：

```c
#include <stdbool.h>
#include <stddef.h>

typedef struct RadixTree RadixTree;

RadixTree *radix_tree_create(void);
void radix_tree_destroy(RadixTree *tree);
bool radix_tree_insert(RadixTree *tree, const char *word);
bool radix_tree_contains(const RadixTree *tree, const char *word);
```

要求：

1. 树中的每条边不再只保存单一字符，而是保存一个以 `'\0'` 结尾的动态字符串标签 `label`。
2. 插入新单词时，若与某条既有边的标签发生**部分匹配（Partial Match）**，必须执行**边分裂（Edge Splitting）**：
   - 将公共前缀部分留在原边，目标指向新分裂节点；
   - 将旧边的剩余后缀剥离为一条新边挂在分裂节点之下；
   - 将待插入单词的剩余后缀作为另一条分支挂在分裂节点之下。
3. `radix_tree_contains` 沿边标签前缀逐段匹配，检索单词是否存在。
4. 析构时必须递归释放所有节点及其持有的动态字符串标签，杜绝内存泄漏。
5. 详细阐述 Linux 内核页缓存（Page Cache）、IP 路由表查找（LPM）等工业系统为什么普遍采用基数树而非普通 Trie。

## 解题思路

### 1. 路径压缩（Path Compression）的几何直觉

考虑依次插入单词 `"romane"`、`"romanus"` 与 `"romulus"`：
- 在普通 Trie 中，`"roman"` 前缀需要经过 5 个独立的单分支节点 `r -> o -> m -> a -> n`；
- 基数树通过**折叠（Collapsing）**中间没有分叉且不是有效单词的中间节点，将整个前缀压缩为一条边标签直接标为 `"roman"` 的复合边：
  ```text
                      ( 根节点 )
                          |
                      "rom" (公共前缀)
                          |
                     [ 分裂节点 ]
                     /          \
                "an"            "ulus"
                /  \
             "e"   "us"
  ```
树的高度被极大压缩，节点总数从 $O(\sum L)$ 骤降至 $O(N)$（$N$ 为单词数，树中最多只产生 $2N$ 个内部节点）。

### 2. 边分裂（Edge Splitting）四步演进

当向节点插入剩余字符串 `word` 时，若找到一条首字符相同的边 $e$（标签为 $e.label$）：
1. 计算两者的最长公共前缀长度 $M = \text{common\_prefix\_len}(e.label, word)$；
2. **全匹配推进**：若 $M == \text{strlen}(e.label)$，说明当前边的标签被完整包含，直接剥离前 $M$ 个字符，将剩余字串 `word + M` 递归送入 $e.target$ 处理；
3. **部分匹配分裂**：若 $M < \text{strlen}(e.label)$，说明当前边需要被切断：
   - 创建一个新的中间分裂节点 `split_node`；
   - 截取 $e.label$ 从下标 $M$ 开始的剩余后缀作为一条新边，连接到旧的目标节点 $e.target$；
   - 将原边 $e.label$ 截短为长度 $M$ 的公共前缀，其目标指针改写为指向 `split_node`；
   - 若此时待插入字串也已耗尽（$word[M] == '\0'$），则将 `split_node` 直接标为词尾；否则为待插入字串的剩余后缀 `word + M` 建立另一条平行的全新边挂在 `split_node` 下。

### 3. 工业级系统选型哲学

基数树是现代底层基础设施的支柱结构：
1. **Linux 内核页缓存（Page Cache）**：Linux 内核用基数树管理每个文件所缓存的物理内存页（`struct page`），键为文件偏移量（Page Index）。基数树在高度稀疏的文件寻址中能快速跳过连续的空洞区域（Sparse Files），相比红黑树具有更浅的树高和更高的查找并发度；
2. **最长前缀匹配（CIDR / IP Routing Table）**：在网络路由转发中，路由器需要为目标 IP 匹配掩码最长的网络号。基数树天然支持变长前缀压缩与高效前缀匹配；
3. **极度节省内存元数据**：每个单词不再需要承担十几级的节点内存管理开销，极大地保护了操作系统宝贵的内核常驻内存（Kernel Slab）。

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct RadixNode RadixNode;
typedef struct RadixEdge RadixEdge;

struct RadixEdge {
    char *label;
    RadixNode *target;
    RadixEdge *next;
};

struct RadixNode {
    RadixEdge *first_edge;
    bool is_word;
};

typedef struct RadixTree RadixTree;

struct RadixTree {
    RadixNode *root;
};

static RadixNode *create_radix_node(bool is_word) {
    RadixNode *n = malloc(sizeof *n);
    if (n == NULL) {
        return NULL;
    }
    n->first_edge = NULL;
    n->is_word = is_word;
    return n;
}

static void destroy_radix_node(RadixNode *n) {
    if (n == NULL) {
        return;
    }
    RadixEdge *curr = n->first_edge;
    while (curr != NULL) {
        RadixEdge *next = curr->next;
        destroy_radix_node(curr->target);
        free(curr->label);
        free(curr);
        curr = next;
    }
    free(n);
}

RadixTree *radix_tree_create(void) {
    RadixTree *t = malloc(sizeof *t);
    if (t == NULL) {
        return NULL;
    }
    t->root = create_radix_node(false);
    if (t->root == NULL) {
        free(t);
        return NULL;
    }
    return t;
}

void radix_tree_destroy(RadixTree *tree) {
    if (tree == NULL) {
        return;
    }
    destroy_radix_node(tree->root);
    free(tree);
}

static size_t common_prefix_len(const char *a, const char *b) {
    size_t i = 0;
    while (a[i] != '\0' && b[i] != '\0' && a[i] == b[i]) {
        i++;
    }
    return i;
}

static char *str_dup(const char *s) {
    size_t len = strlen(s);
    char *copy = malloc(len + 1);
    if (copy == NULL) {
        return NULL;
    }
    memcpy(copy, s, len + 1);
    return copy;
}

static bool insert_recursive(RadixNode *curr, const char *word) {
    if (*word == '\0') {
        curr->is_word = true;
        return true;
    }

    RadixEdge *e = curr->first_edge;
    while (e != NULL) {
        if (e->label[0] == word[0]) {
            break;
        }
        e = e->next;
    }

    if (e == NULL) {
        RadixEdge *new_edge = malloc(sizeof *new_edge);
        if (new_edge == NULL) {
            return false;
        }
        new_edge->label = str_dup(word);
        if (new_edge->label == NULL) {
            free(new_edge);
            return false;
        }
        new_edge->target = create_radix_node(true);
        if (new_edge->target == NULL) {
            free(new_edge->label);
            free(new_edge);
            return false;
        }
        new_edge->next = curr->first_edge;
        curr->first_edge = new_edge;
        return true;
    }

    size_t match_len = common_prefix_len(e->label, word);
    size_t label_len = strlen(e->label);

    if (match_len == label_len) {
        return insert_recursive(e->target, word + match_len);
    }

    RadixNode *split_node = create_radix_node(false);
    if (split_node == NULL) {
        return false;
    }

    char *old_label_rem = str_dup(e->label + match_len);
    if (old_label_rem == NULL) {
        free(split_node);
        return false;
    }

    RadixEdge *edge_to_old = malloc(sizeof *edge_to_old);
    if (edge_to_old == NULL) {
        free(old_label_rem);
        free(split_node);
        return false;
    }
    edge_to_old->label = old_label_rem;
    edge_to_old->target = e->target;
    edge_to_old->next = NULL;
    split_node->first_edge = edge_to_old;

    e->label[match_len] = '\0';
    e->target = split_node;

    if (word[match_len] == '\0') {
        split_node->is_word = true;
        return true;
    }

    RadixEdge *edge_to_new = malloc(sizeof *edge_to_new);
    if (edge_to_new == NULL) {
        return false;
    }
    edge_to_new->label = str_dup(word + match_len);
    if (edge_to_new->label == NULL) {
        free(edge_to_new);
        return false;
    }
    edge_to_new->target = create_radix_node(true);
    if (edge_to_new->target == NULL) {
        free(edge_to_new->label);
        free(edge_to_new);
        return false;
    }
    edge_to_new->next = split_node->first_edge;
    split_node->first_edge = edge_to_new;
    return true;
}

bool radix_tree_insert(RadixTree *tree, const char *word) {
    if (tree == NULL || word == NULL) {
        return false;
    }
    return insert_recursive(tree->root, word);
}

bool radix_tree_contains(const RadixTree *tree, const char *word) {
    if (tree == NULL || word == NULL) {
        return false;
    }
    const RadixNode *curr = tree->root;
    while (*word != '\0') {
        const RadixEdge *e = curr->first_edge;
        while (e != NULL) {
            if (e->label[0] == word[0]) {
                break;
            }
            e = e->next;
        }
        if (e == NULL) {
            return false;
        }
        size_t match_len = common_prefix_len(e->label, word);
        if (match_len != strlen(e->label)) {
            return false;
        }
        word += match_len;
        curr = e->target;
    }
    return curr->is_word;
}

int main(void) {
    radix_tree_destroy(NULL);

    RadixTree *rt = radix_tree_create();
    assert(rt != NULL);

    assert(radix_tree_insert(rt, "romane"));
    assert(radix_tree_insert(rt, "romanus"));
    assert(radix_tree_insert(rt, "romulus"));
    assert(radix_tree_insert(rt, "rubens"));
    assert(radix_tree_insert(rt, "ruber"));
    assert(radix_tree_insert(rt, "rubicon"));

    assert(radix_tree_contains(rt, "romane"));
    assert(radix_tree_contains(rt, "romanus"));
    assert(radix_tree_contains(rt, "romulus"));
    assert(radix_tree_contains(rt, "rubens"));
    assert(radix_tree_contains(rt, "ruber"));
    assert(radix_tree_contains(rt, "rubicon"));

    assert(!radix_tree_contains(rt, "roman"));
    assert(!radix_tree_contains(rt, "rub"));
    assert(!radix_tree_contains(rt, "rubic"));

    assert(radix_tree_insert(rt, "roman"));
    assert(radix_tree_contains(rt, "roman"));

    radix_tree_destroy(rt);
    return 0;
}
```

## 复杂度分析

- **时间复杂度**：
  - 检索与插入时，树的高度最多为实际分叉的次数（不超过单词数 $N$），单步推进跳过整段标签，总字符比较次数仍然受限于输入单词的长度 $O(L)$。相比普通 Trie，节点跳转次数减少了 $60\% \sim 90\%$。
- **空间复杂度**：
  - 内部只有在发生前缀分叉时才会产生节点，包含 $N$ 个键的基数树至多包含 $2N - 1$ 个节点，空间复杂度严格为 $O(N)$，彻底摆脱了普通 Trie 节点数量与字符总长度线性绑定的沉重负担。

## 延伸思考 / 模式总结

1. **Patricia Tree 与位压缩的巅峰**：基数树的位级别特化形态被称为 Patricia Tree（Practical Algorithm to Retrieve Information Coded in Alphanumeric）。在每个节点中不存储字符串，仅存储一个“在第几位二进制发生分叉”的整数下标，从而实现纯粹依靠位探测进行极端紧凑的高速索引。
2. **锁并发（Lock-Coupling）优势**：在数据库引擎与内核多线程并发读写中，树的高矮直接决定了并发锁竞争的激烈程度。基数树通过路径压缩极大压扁了树的拓扑高度，显著缩短了锁持有时间，成为现代内存数据库（如 Redis Streams、Masstree）存储时间序列与键空间的首选引擎。
