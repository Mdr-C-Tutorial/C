# 31904 - 01-Trie与两数最大异或对求解

## 题目

给定一个包含非负 32 位整数的无序数组，求数组中任意两个数按位异或（XOR）运算所能达到的最大值。实现基于二进制位分支的 **01-Trie（位前缀树）**，将暴力枚举的二次方时间复杂度 $O(n^2)$ 降低至线性时间 $O(32 \cdot n) = O(n)$：

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

typedef struct BitTrie BitTrie;

BitTrie *bit_trie_create(void);
void bit_trie_destroy(BitTrie *t);
bool bit_trie_insert(BitTrie *t, uint32_t val);
uint32_t bit_trie_query_max_xor(const BitTrie *t, uint32_t val);
bool find_maximum_xor_pair(const uint32_t *nums, size_t count, uint32_t *out_max_xor);
```

要求：

1. 01-Trie 的字母表大小固定为 2（分支仅包含二进制位 `0` 与 `1`）。
2. 树的高度严格固定为 32 层。插入数值时，必须从最高有效位（第 31 位 MSB）向下逐位扫描至最低位（第 0 位 LSB）。
3. `bit_trie_query_max_xor` 采用**贪心策略（Greedy Strategy）**：对于待查询数 `val` 的当前第 $i$ 位二进制位 $b \in \{0, 1\}$，优先尝试走向相反位 $1 - b$ 的分支；若相反分支存在，异或结果的第 $i$ 位可置为 1；否则只能顺着相同位 $b$ 分支下行。
4. `find_maximum_xor_pair` 处理输入数组：当 `count < 2` 或指针非法时返回 `false`。
5. 详细推导为什么贪心选择“从最高位向最低位优先走相反分支”能够严格保证得到全局最大的异或结果。

## 解题思路

### 1. 01-Trie 的拓扑映射

将一个无符号 32 位整数看作长度恒为 32 的二进制字符序列：
- 节点结构极度精简，仅包含两路子指针：
  ```c
  struct BitTrieNode {
      BitTrieNode *children[2];
  };
  ```
- 任意整数 $x$ 在树中映射为一条深度为 32 的定长路径；
- 由于每条路径长度完全相等，无需维护词尾标记，到达第 32 层叶节点即代表一个完整整数。

### 2. 异或性质与高位贪心最优性证明

按位异或运算的规则为：$0 \oplus 1 = 1$，$1 \oplus 0 = 1$，$0 \oplus 0 = 0$，$1 \oplus 1 = 0$。即**两位相反时异或结果为 1，两位相同时异或结果为 0**。

为什么必须自最高位（Bit 31）向下贪心？
考虑二进制进位制的权值分布定理：
$$2^k > \sum_{i=0}^{k-1} 2^i = 2^k - 1$$
**最高位的权重（$2^k$）严格大于其后所有更低位能够产生的最大权值总和**！
- 设第 $k$ 位若能够通过选取相反分支使得异或结果产生一个 $1$，其带来的收益为 $2^k$；
- 即使后续所有的 $k - 1$ 个低位全部产生 $0$，总收益依然为 $2^k$；
- 反之，若第 $k$ 位放弃选择相反分支（产生 $0$），即使后续所有低位全为 $1$，总收益也只有 $2^k - 1$；
因此，**只要当前高位存在相反分支，果断选取相反分支是全局最优选择**，具备强贪心选择性质（Greedy-Choice Property）。

### 3. 在线增量求解最大异或对

若先全量插入 $n$ 个数，再对每个数查询一次，需遍历两次。更优雅的在线做法是：
- 初始时将第一个数 $nums[0]$ 插入 01-Trie；
- 从 $i = 1$ 到 $n - 1$：
  1. 调用 `bit_trie_query_max_xor(t, nums[i])`，在当前已录入的数集中找出与 $nums[i]$ 异或最大的那个数，更新全局最大值；
  2. 将 $nums[i]$ 插入 01-Trie。
这种增量插入确保了每个无序对 $(nums[i], nums[j])$ 恰好被比对一次，免除了不必要的重复镜像比对。

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct BitTrieNode BitTrieNode;

struct BitTrieNode {
    BitTrieNode *children[2];
};

typedef struct BitTrie BitTrie;

struct BitTrie {
    BitTrieNode *root;
};

static void destroy_bit_node(BitTrieNode *n) {
    if (n == NULL) {
        return;
    }
    destroy_bit_node(n->children[0]);
    destroy_bit_node(n->children[1]);
    free(n);
}

BitTrie *bit_trie_create(void) {
    BitTrie *t = malloc(sizeof *t);
    if (t == NULL) {
        return NULL;
    }
    t->root = calloc(1, sizeof *t->root);
    if (t->root == NULL) {
        free(t);
        return NULL;
    }
    return t;
}

void bit_trie_destroy(BitTrie *t) {
    if (t == NULL) {
        return;
    }
    destroy_bit_node(t->root);
    free(t);
}

bool bit_trie_insert(BitTrie *t, uint32_t val) {
    if (t == NULL) {
        return false;
    }
    BitTrieNode *curr = t->root;
    for (int i = 31; i >= 0; --i) {
        uint32_t b = (val >> i) & 1U;
        if (curr->children[b] == NULL) {
            BitTrieNode *new_node = calloc(1, sizeof(BitTrieNode));
            if (new_node == NULL) {
                return false;
            }
            curr->children[b] = new_node;
        }
        curr = curr->children[b];
    }
    return true;
}

uint32_t bit_trie_query_max_xor(const BitTrie *t, uint32_t val) {
    if (t == NULL || t->root == NULL) {
        return 0;
    }
    const BitTrieNode *curr = t->root;
    uint32_t max_xor = 0;
    for (int i = 31; i >= 0; --i) {
        uint32_t b = (val >> i) & 1U;
        uint32_t opp = 1U - b;
        if (curr->children[opp] != NULL) {
            max_xor |= (1U << i);
            curr = curr->children[opp];
        } else if (curr->children[b] != NULL) {
            curr = curr->children[b];
        } else {
            break;
        }
    }
    return max_xor;
}

bool find_maximum_xor_pair(const uint32_t *nums, size_t count, uint32_t *out_max_xor) {
    if (nums == NULL || out_max_xor == NULL || count < 2) {
        return false;
    }
    BitTrie *t = bit_trie_create();
    if (t == NULL) {
        return false;
    }

    uint32_t best = 0;
    if (!bit_trie_insert(t, nums[0])) {
        bit_trie_destroy(t);
        return false;
    }

    for (size_t i = 1; i < count; ++i) {
        uint32_t cur_xor = bit_trie_query_max_xor(t, nums[i]);
        if (cur_xor > best) {
            best = cur_xor;
        }
        if (!bit_trie_insert(t, nums[i])) {
            bit_trie_destroy(t);
            return false;
        }
    }

    bit_trie_destroy(t);
    *out_max_xor = best;
    return true;
}

int main(void) {
    bit_trie_destroy(NULL);

    uint32_t nums[] = {3, 10, 5, 25, 2, 8};
    uint32_t max_xor = 0;
    assert(find_maximum_xor_pair(nums, sizeof(nums)/sizeof(nums[0]), &max_xor));
    assert(max_xor == 28);

    uint32_t nums2[] = {14, 70, 53, 83, 49, 91, 36, 80, 92, 51, 66, 70};
    assert(find_maximum_xor_pair(nums2, sizeof(nums2)/sizeof(nums2[0]), &max_xor));
    assert(max_xor == 127);

    assert(!find_maximum_xor_pair(nums, 1, &max_xor));
    assert(!find_maximum_xor_pair(NULL, 5, &max_xor));

    return 0;
}
```

## 复杂度分析

- **时间复杂度**：
  - 单个 32 位整数的插入与贪心查询均严格循环 32 次，单次操作耗时严格为 $O(32) = O(1)$。
  - 处理规模为 $n$ 的数组，总共进行 $n$ 次插入与 $n - 1$ 次查询，总运行时间严格为 $O(32 \cdot n) = O(n)$。在万级至千万级数据规模下，相比 $O(n^2)$ 的枚举具有数量级维度的性能飞跃。
- **空间复杂度**：树中最多包含 $32 \cdot n$ 个二叉节点，每个节点仅包含 2 个子指针，空间复杂度严格为 $O(32 \cdot n) = O(n)$。

## 延伸思考 / 模式总结

1. **从字符前缀到二进制位前缀的泛化**：01-Trie 的精妙之处在于将数值大小比较与按位逻辑运算抽象为字符串前缀树。只要数据具备二进制表示，便可利用数位的高低权值差异构建快速贪心解法。
2. **基数排序（Radix Sort）的同构性**：01-Trie 的递归分支划分与 MSD（Most Significant Digit）最高位优先基数排序在分治机制上完全等价。二者均依赖高位在进位制中的支配地位来剪除对低位的无效试探。
