# 31902 - 动态子节点链表 Trie 树

## 题目描述

当字符集扩大为全量 256 字节（甚至 Unicode 字符集）时，若每个节点仍分配大小为 256 的静态指针数组，将引发巨大的内存浪费（每个节点占用 $256 \times 8 = 2048$ 字节，其中绝大多数槽位为空指针）。实现基于**动态子节点单向链表**的稀疏字典树 `SparseTrie`：

```c
#include <stdbool.h>
#include <stddef.h>

typedef struct SparseTrie SparseTrie;

SparseTrie *sparse_trie_create(void);
void sparse_trie_destroy(SparseTrie *trie);
bool sparse_trie_insert(SparseTrie *trie, const unsigned char *bytes, size_t len, bool *out_inserted);
bool sparse_trie_contains(const SparseTrie *trie, const unsigned char *bytes, size_t len, bool *out_found);
```

要求：

1. 能够存储包含任意 256 种字节（$[0, 255]$）的任意二进制数据序列，允许字节值为 `0x00`。
2. 每个树节点**严禁分配固定大小的 256 槽位数组**，而是维护一条动态单向链表 `ChildLink`，仅为真实存在的分支分配子节点与关联指针。
3. `sparse_trie_insert` 将长度为 `len` 的字节串插入树中，若已存在设置 `*out_inserted = false`；若出现新分支则动态追加链接节点。
4. `sparse_trie_contains` 进行精确字节串匹配查询。
5. 在题解中从空间占用与查找效率两个维度，深入量化对比“固定静态数组 Trie”与“动态链表 Trie”的工程权衡。

## 解题思路

### 1. 稀疏分支下的指针膨胀痛点

在固定 256 槽位数组实现中：
- 节点结构体大小：$256 \times 8 \text{ 字节} + 8 \text{ 字节} = 2056$ 字节；
- 若一棵树包含 10000 个节点，总内存消耗直接突破 20MB；但如果平均每个节点只有 1.2 个实际子节点，则其中超过 $99.5\%$ 的内存都在无意义地存储 `NULL` 空指针。

### 2. 左孩子-右兄弟思想与动态链表化

动态子节点链表借鉴了树形结构的**孩子链表表示法**：
```c
struct ChildLink {
    unsigned char byte;
    SparseTrieNode *child;
    ChildLink *next;
};

struct SparseTrieNode {
    ChildLink *first_child;
    bool is_word;
};
```
- 每个节点自身只包含一个头指针 `first_child`（8 字节）与一个布尔词尾标记（1 字节 + 填充）；
- 只有当实际发生分支衍生时，才动态分配一个包含字符标号、目标节点指针以及同层兄弟后继指针的 `ChildLink`（约 24 字节）；
- 查找子节点时，沿 `first_child` 链表向后线性匹配对应字节：
  ```c
  for (ChildLink *c = node->first_child; c != NULL; c = c->next) {
      if (c->byte == target_byte) return c->child;
  }
  ```

### 3. 时空权衡的量化对比

| 评估维度 | 固定 256 路静态数组 Trie | 动态子节点链表 Trie |
| :--- | :--- | :--- |
| **单节点基础内存** | 严格 2056 字节 | 仅 16 字节（基础结构体） |
| **单条真实分支增量开销** | 0 字节（已预分配） | 约 24 字节（`ChildLink`） |
| **单步字符分支下潜耗时** | 严格 $O(1)$ 常数时间（直接下标偏移） | $O(k)$，其中 $k$ 为该节点的实际出度（$k \le 256$） |
| **最坏查询时间** | $O(L)$ | $O(L \cdot |\Sigma|)$ |
| **适用场景** | 字符集极小（$\le 26$）或分支高度饱和稠密 | 字符集宽广（如 256 字节全集、Unicode）且分支极其稀疏 |

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct ChildLink ChildLink;
typedef struct SparseTrieNode SparseTrieNode;

struct ChildLink {
    unsigned char byte;
    SparseTrieNode *child;
    ChildLink *next;
};

struct SparseTrieNode {
    ChildLink *first_child;
    bool is_word;
};

typedef struct SparseTrie SparseTrie;

struct SparseTrie {
    SparseTrieNode *root;
};

static SparseTrieNode *create_sparse_node(void) {
    SparseTrieNode *n = malloc(sizeof *n);
    if (n == NULL) {
        return NULL;
    }
    n->first_child = NULL;
    n->is_word = false;
    return n;
}

static void destroy_sparse_node(SparseTrieNode *n) {
    if (n == NULL) {
        return;
    }
    ChildLink *curr = n->first_child;
    while (curr != NULL) {
        ChildLink *next = curr->next;
        destroy_sparse_node(curr->child);
        free(curr);
        curr = next;
    }
    free(n);
}

SparseTrie *sparse_trie_create(void) {
    SparseTrie *t = malloc(sizeof *t);
    if (t == NULL) {
        return NULL;
    }
    t->root = create_sparse_node();
    if (t->root == NULL) {
        free(t);
        return NULL;
    }
    return t;
}

void sparse_trie_destroy(SparseTrie *trie) {
    if (trie == NULL) {
        return;
    }
    destroy_sparse_node(trie->root);
    free(trie);
}

static SparseTrieNode *find_child(const SparseTrieNode *n, unsigned char byte) {
    for (ChildLink *c = n->first_child; c != NULL; c = c->next) {
        if (c->byte == byte) {
            return c->child;
        }
    }
    return NULL;
}

static SparseTrieNode *get_or_add_child(SparseTrieNode *n, unsigned char byte) {
    SparseTrieNode *c = find_child(n, byte);
    if (c != NULL) {
        return c;
    }
    ChildLink *link = malloc(sizeof *link);
    if (link == NULL) {
        return NULL;
    }
    SparseTrieNode *child_node = create_sparse_node();
    if (child_node == NULL) {
        free(link);
        return NULL;
    }
    link->byte = byte;
    link->child = child_node;
    link->next = n->first_child;
    n->first_child = link;
    return child_node;
}

bool sparse_trie_insert(SparseTrie *trie, const unsigned char *bytes, size_t len, bool *out_inserted) {
    if (trie == NULL || out_inserted == NULL || (len > 0 && bytes == NULL)) {
        return false;
    }
    SparseTrieNode *curr = trie->root;
    for (size_t i = 0; i < len; ++i) {
        SparseTrieNode *next = get_or_add_child(curr, bytes[i]);
        if (next == NULL) {
            return false;
        }
        curr = next;
    }
    if (curr->is_word) {
        *out_inserted = false;
    } else {
        curr->is_word = true;
        *out_inserted = true;
    }
    return true;
}

bool sparse_trie_contains(const SparseTrie *trie, const unsigned char *bytes, size_t len, bool *out_found) {
    if (trie == NULL || out_found == NULL || (len > 0 && bytes == NULL)) {
        return false;
    }
    const SparseTrieNode *curr = trie->root;
    for (size_t i = 0; i < len; ++i) {
        SparseTrieNode *next = find_child(curr, bytes[i]);
        if (next == NULL) {
            *out_found = false;
            return true;
        }
        curr = next;
    }
    *out_found = curr->is_word;
    return true;
}

int main(void) {
    sparse_trie_destroy(NULL);

    SparseTrie *t = sparse_trie_create();
    assert(t != NULL);

    bool ins = false;
    bool fnd = false;

    const unsigned char w1[] = {0xFF, 0xFE, 0xFD};
    const unsigned char w2[] = {0xFF, 0xAA};
    const unsigned char w3[] = {0x00, 0x01, 0x02};

    assert(sparse_trie_insert(t, w1, sizeof(w1), &ins) && ins);
    assert(sparse_trie_insert(t, w2, sizeof(w2), &ins) && ins);
    assert(sparse_trie_insert(t, w3, sizeof(w3), &ins) && ins);
    assert(sparse_trie_insert(t, w1, sizeof(w1), &ins) && !ins);

    assert(sparse_trie_contains(t, w1, sizeof(w1), &fnd) && fnd);
    assert(sparse_trie_contains(t, w2, sizeof(w2), &fnd) && fnd);
    assert(sparse_trie_contains(t, w3, sizeof(w3), &fnd) && fnd);

    const unsigned char w4[] = {0xFF};
    assert(sparse_trie_contains(t, w4, sizeof(w4), &fnd) && !fnd);

    sparse_trie_destroy(t);
    return 0;
}
```

## 复杂度分析

- **时间复杂度**：
  - `sparse_trie_insert` 与 `sparse_trie_contains`：单步字符推进需要遍历链表匹配字节，耗时正比于该节点的实际出度 $k$（$k \le |\Sigma|$）。平均情况下绝大多数稀疏节点出度极小（通常 $k \le 3$），实际查找平均耗时仍为 $O(L)$；最坏情况下为 $O(L \cdot |\Sigma|)$。
- **空间复杂度**：消除了绝大部分空指针浪费，仅分配实际存在的边链接节点，空间复杂度严格为 $O(\text{节点总数} + \text{边总数}) = O(\sum L)$，内存利用率相比固定 256 槽位数组暴增数十倍。

## 延伸思考 / 模式总结

1. **链表排序与二分升级**：若节点的实际子节点数较多，可将单向链表改写为**紧凑有序动态数组（Sorted Vector）**。结合二分查找进行字符定位，可将链表单层扫描时间压缩至 $O(\log k)$，兼备极低的内存占用与缓存亲和力。
2. **多态节点优化策略**：现代高性能库（例如 ART / 自适应基数树 Adaptive Radix Tree）采用了革命性的自适应多态节点设计：根据子节点实际数量，动态在 `Node4`（固定4个子节点）、`Node16`、`Node48` 与 `Node256` 之间动态变形升级，兼得了稀疏时的极低空间与稠密时的 $O(1)$ 极速寻址。
