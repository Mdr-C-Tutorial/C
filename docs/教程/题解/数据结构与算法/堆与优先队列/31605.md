# 31605 - 基于小顶堆的海量数据流 Top-K 筛选

## 题目描述

在面对海量无法一次性载入内存的数据流时，需要实时筛选出全局最大的前 $k$ 个元素。实现流式数据筛选器 `TopKSelector`，同时保留离线数组中选出最小前 $k$ 个元素的接口 `smallest_k_i64`：

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

typedef struct TopKSelector TopKSelector;

TopKSelector *topk_selector_create(size_t k);
void topk_selector_destroy(TopKSelector *sel);
void topk_selector_feed(TopKSelector *sel, int64_t item);
bool topk_selector_dump_sorted(
    const TopKSelector *sel,
    int64_t *out_items,
    size_t *out_count
);
bool smallest_k_i64(
    const int64_t *items,
    size_t count,
    size_t k,
    int64_t *out_items
);
```

要求：

1. `TopKSelector` 内部仅允许维护大小为 $k$ 的小顶堆。每流入一个新元素，时间复杂度应控制在 $O(\log k)$，空间复杂度严格为 $O(k)$。
2. 数据流输入完毕后，调用 `topk_selector_dump_sorted` 将前 $k$ 大元素按升序写入 `out_items`，并设置 `*out_count`。若实际流入元素总数 $m < k$，则仅导出实际存在的 $m$ 个元素。
3. `smallest_k_i64` 从不可修改的数组中选出最小的前 $k$ 个元素，按非递减顺序输出。内部使用大小为 $k$ 的大顶堆，时间复杂度 $O(n \log k)$，额外空间 $O(k)$。
4. 所有接口均须保证强异常安全：当 $k=0$ 时操作成功；分配失败或参数无效时，输出数组和输出对象保持不变。

## 解题思路

### 1. 为什么“最大前 K 项”要用小顶堆？

求解流式数据的 Top-K 最大值时，直觉上容易误用大顶堆，但大顶堆的堆顶是当前的最大值，无法快速感知堆中“最弱（最小）”的竞争者。

正确的策略是维护一个**容量为 $k$ 的小顶堆**：
- 堆顶 `heap[0]` 始终是当前候选集合中的**门槛值**（即前 $k$ 大元素中的最小值）；
- 当新元素 $x$ 到达时：
  - 若堆尚未填满（元素数 $< k$），直接入堆并执行上滤；
  - 若堆已满且 $x \le \text{heap}[0]$，说明 $x$ 甚至不如当前前 $k$ 名中垫底的元素，直接舍弃，耗时 $O(1)$；
  - 若堆已满且 $x > \text{heap}[0]$，说明 $x$ 有资格进入前 $k$ 名，将堆顶替换为 $x$（淘汰原门槛值），随后从根节点执行下滤恢复小顶堆不变式，耗时 $O(\log k)$。

### 2. 为什么“最小前 K 项”要用大顶堆？

对偶地，在 `smallest_k_i64` 中求最小的前 $k$ 个元素时，应维护**容量为 $k$ 的大顶堆**：
- 堆顶是当前保留的 $k$ 个最小元素中的最大者；
- 若新元素小于堆顶，则淘汰堆顶并将其下滤替换；
- 扫描结束后，直接对该大小为 $k$ 的大顶堆执行原地堆排序，即可在不借助任何额外存储的前提下得到非递减升序序列。

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct TopKSelector TopKSelector;

struct TopKSelector {
    int64_t *heap;
    size_t k;
    size_t count;
};

static void swap_i64(int64_t *a, int64_t *b) {
    int64_t tmp = *a;
    *a = *b;
    *b = tmp;
}

static void min_sift_up(int64_t *arr, size_t i) {
    while (i > 0) {
        size_t p = (i - 1) / 2;
        if (arr[p] <= arr[i]) {
            break;
        }
        swap_i64(&arr[p], &arr[i]);
        i = p;
    }
}

static void min_sift_down(int64_t *arr, size_t size, size_t i) {
    while (i < size / 2) {
        size_t left = i * 2 + 1;
        size_t right = left + 1;
        size_t smallest = i;

        if (arr[left] < arr[smallest]) {
            smallest = left;
        }
        if (right < size && arr[right] < arr[smallest]) {
            smallest = right;
        }
        if (smallest == i) {
            break;
        }
        swap_i64(&arr[i], &arr[smallest]);
        i = smallest;
    }
}

TopKSelector *topk_selector_create(size_t k) {
    TopKSelector *sel = malloc(sizeof *sel);
    if (sel == NULL) {
        return NULL;
    }
    sel->k = k;
    sel->count = 0;
    sel->heap = NULL;
    if (k > 0) {
        if (k > SIZE_MAX / sizeof(int64_t)) {
            free(sel);
            return NULL;
        }
        sel->heap = malloc(k * sizeof(int64_t));
        if (sel->heap == NULL) {
            free(sel);
            return NULL;
        }
    }
    return sel;
}

void topk_selector_destroy(TopKSelector *sel) {
    if (sel == NULL) {
        return;
    }
    free(sel->heap);
    free(sel);
}

void topk_selector_feed(TopKSelector *sel, int64_t item) {
    if (sel == NULL || sel->k == 0) {
        return;
    }
    if (sel->count < sel->k) {
        sel->heap[sel->count] = item;
        min_sift_up(sel->heap, sel->count);
        sel->count++;
    } else if (item > sel->heap[0]) {
        sel->heap[0] = item;
        min_sift_down(sel->heap, sel->k, 0);
    }
}

bool topk_selector_dump_sorted(
    const TopKSelector *sel,
    int64_t *out_items,
    size_t *out_count
) {
    if (sel == NULL || out_count == NULL) {
        return false;
    }
    if (sel->count > 0 && out_items == NULL) {
        return false;
    }
    *out_count = sel->count;
    if (sel->count == 0) {
        return true;
    }

    int64_t *copy = malloc(sel->count * sizeof(int64_t));
    if (copy == NULL) {
        return false;
    }
    memcpy(copy, sel->heap, sel->count * sizeof(int64_t));

    size_t active = sel->count;
    for (size_t i = 0; i < sel->count; ++i) {
        out_items[i] = copy[0];
        copy[0] = copy[active - 1];
        active--;
        if (active > 1) {
            min_sift_down(copy, active, 0);
        }
    }
    free(copy);
    return true;
}

static void max_sift_up(int64_t *arr, size_t i) {
    while (i > 0) {
        size_t p = (i - 1) / 2;
        if (arr[p] >= arr[i]) {
            break;
        }
        swap_i64(&arr[p], &arr[i]);
        i = p;
    }
}

static void max_sift_down(int64_t *arr, size_t size, size_t i) {
    while (i < size / 2) {
        size_t left = i * 2 + 1;
        size_t right = left + 1;
        size_t largest = i;

        if (arr[left] > arr[largest]) {
            largest = left;
        }
        if (right < size && arr[right] > arr[largest]) {
            largest = right;
        }
        if (largest == i) {
            break;
        }
        swap_i64(&arr[i], &arr[largest]);
        i = largest;
    }
}

bool smallest_k_i64(
    const int64_t *items,
    size_t count,
    size_t k,
    int64_t *out_items
) {
    if (k > count || (count > 0 && items == NULL) ||
        (k > 0 && out_items == NULL)) {
        return false;
    }
    if (k == 0) {
        return true;
    }
    if (k > SIZE_MAX / sizeof(int64_t)) {
        return false;
    }

    int64_t *heap = malloc(k * sizeof(int64_t));
    if (heap == NULL) {
        return false;
    }

    size_t heap_size = 0;
    for (size_t i = 0; i < count; ++i) {
        if (heap_size < k) {
            heap[heap_size] = items[i];
            heap_size++;
            max_sift_up(heap, heap_size - 1);
        } else if (items[i] < heap[0]) {
            heap[0] = items[i];
            max_sift_down(heap, k, 0);
        }
    }

    size_t active = k;
    while (active > 1) {
        swap_i64(&heap[0], &heap[active - 1]);
        active--;
        max_sift_down(heap, active, 0);
    }
    memcpy(out_items, heap, k * sizeof(int64_t));
    free(heap);
    return true;
}

int main(void) {
    TopKSelector *sel = topk_selector_create(3);
    assert(sel != NULL);
    int64_t stream[] = {5, 2, 9, 1, 7, 6, 8, 3, 4};
    for (size_t i = 0; i < sizeof(stream) / sizeof(stream[0]); ++i) {
        topk_selector_feed(sel, stream[i]);
    }
    int64_t top3[3] = {0};
    size_t out_count = 0;
    assert(topk_selector_dump_sorted(sel, top3, &out_count));
    assert(out_count == 3);
    assert(top3[0] == 7 && top3[1] == 8 && top3[2] == 9);
    topk_selector_destroy(sel);

    int64_t arr[] = {9, 1, 5, 3, 7, 2, 8, 4, 6};
    int64_t smallest3[3] = {0};
    assert(smallest_k_i64(arr, 9, 3, smallest3));
    assert(smallest3[0] == 1 && smallest3[1] == 2 && smallest3[2] == 3);

    return 0;
}
```

## 复杂度分析

- **时间复杂度**：
  - 处理大小为 $n$ 的数据流时，每个元素最多触发一次 $O(\log k)$ 的下滤或上滤，总时间复杂度为 $O(n \log k)$。当 $k \ll n$ 时，渐近性能接近线性扫描。
  - 导出结果时对大小为 $k$ 的堆进行排序，耗时 $O(k \log k)$。
- **空间复杂度**：堆结构固定占用 $k$ 个元素的存储空间，额外空间复杂度严格为 $O(k)$，与数据流总量 $n$ 完全无关。

## 延伸思考 / 模式总结

1. **有限内存与无限数据流的桥梁**：小顶堆在流式数据 Top-K 场景下的核心价值在于“剪枝”——它用极小代价排除了绝大多数明显不达标的数据项，确保系统工作集尺寸始终维持在紧凑的 $O(k)$，极大地保护了 CPU 缓存并允许处理体量远超物理内存极限的海量数据。
2. **极值对偶律**：
   - 求全局最大 $K$ 个值 $\iff$ 维护大小为 $k$ 的**小顶堆**（动态淘汰堆内最小项）；
   - 求全局最小 $K$ 个值 $\iff$ 维护大小为 $k$ 的**大顶堆**（动态淘汰堆内最大项）。
