# 31604 - 堆排序与稳定性辨析

## 题目描述

实现基于二叉堆的原地排序算法（升序与降序），并从算法机理上深入辨析堆排序的不稳定性（Unstable），给出最小反例和执行轨迹推导：

```c
#include <stddef.h>
#include <stdint.h>

void heap_sort_ascending(int64_t *array, size_t size);
void heap_sort_descending(int64_t *array, size_t size);
```

要求：

1. `heap_sort_ascending` 实现原地升序排序：首先在输入数组上原地构建大顶堆，随后反复将堆顶最大元素与当前有效堆区间的末尾元素交换，并对新的根节点执行下滤，直至全数组有序。
2. `heap_sort_descending` 实现原地降序排序：在输入数组上原地构建小顶堆，随后反复将堆顶最小元素与当前有效堆区间的末尾元素交换并下滤。
3. 辅助空间复杂度严格为 $O(1)$，指针为 `NULL` 或 `size <= 1` 时安全退出。
4. 在题解中证明为什么堆排序不是稳定排序算法，给出包含相同键值的最小反例，并追踪建堆或弹出阶段相对次序被打破的全过程。

## 解题思路

### 1. 原地堆排序的工作原理

堆排序分为两个阶段：
1. **原地建堆阶段**：使用 Floyd 算法，在 $O(n)$ 时间内将无序数组组织为堆结构。
   - 要获得升序输出，必须构建**大顶堆**；
   - 要获得降序输出，必须构建**小顶堆**。
2. **循环收割与下滤阶段**：
   - 维护堆的有效规模 `active`，初始为 `size`；
   - 每次循环中，堆顶元素 `array[0]` 即为当前活跃区间的极值；
   - 将 `array[0]` 与 `array[active - 1]` 交换，此时该极值已归位至其最终的排序下标处；
   - 将活跃区间缩小 `active--`，然后从根节点 `0` 开始对长度为 `active` 的前缀区间执行单次下滤；
   - 重复执行 $n - 1$ 次后，整段数组即转变为全局有序序列。

### 2. 堆排序的不稳定性机理与最小反例

排序算法的**稳定性**要求：若输入中存在键值相等的两项 $A_i$ 与 $A_j$（且初始下标 $i < j$），则排序完成后 $A_i$ 必须依然排在 $A_j$ 的前面。

堆排序在以下两个阶段均可能彻底破坏同键值项的初始相对顺序：
- **远距离跨步交换**：下滤过程中的父子交换跨越了中间节点；
- **末尾回填颠倒**：收割极值时将末尾元素交换至根节点，直接颠倒了前后相对位置。

#### 最小反例构造与轨迹追踪

考虑升序排序下的输入序列（带唯一标识标签以区分相等键）：
$$\text{Array} = [3_a, 3_b, 2]$$
此时两相等键的初始先后顺序为 $3_a$ 在前、$3_b$ 在后。

1. **Floyd 建堆阶段**：
   - 数组长度为 3，最后一个非叶节点下标为 $\lfloor 3 / 2 \rfloor - 1 = 0$；
   - 对根节点下标 0 执行下滤：
     - 左孩子为下标 1（值 $3_b$），右孩子为下标 2（值 $2$）；
     - 当前节点值 $3_a$ 与最大孩子 $3_b$ 相等，无需交换；
     - 建堆完成，数组依然保持 $[3_a, 3_b, 2]$。
2. **第一轮收割（`active = 3`）**：
   - 将堆顶 `array[0]`（即 $3_a$）与末尾 `array[2]`（即 $2$）交换；
   - 数组变为 $[2, 3_b, \mathbf{3_a}]$；
   - 活跃区间缩小为 `active = 2`；
   - 对根节点 $2$ 执行下滤：其左孩子为下标 1（值 $3_b$），因为 $3_b > 2$，交换根与左孩子；
   - 活跃区间变为 $[3_b, 2]$，全数组状态为 $[3_b, 2, \mathbf{3_a}]$。
3. **第二轮收割（`active = 2`）**：
   - 将堆顶 `array[0]`（即 $3_b$）与末尾 `array[1]`（即 $2$）交换；
   - 数组变为 $[2, \mathbf{3_b}, \mathbf{3_a}]$；
   - 排序终止。

观察最终排序结果：$[2, 3_b, 3_a]$。
相等键 $3_b$ 被排到了 $3_a$ 的前面，其初始相对顺序被完全颠倒。因此，**堆排序是本质不稳定的排序算法**。

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>

static void swap_i64(int64_t *a, int64_t *b) {
    int64_t tmp = *a;
    *a = *b;
    *b = tmp;
}

static void max_sift_down(int64_t *arr, size_t size, size_t i) {
    while (i < size / 2) {
        size_t left = i * 2 + 1;
        size_t right = left + 1;
        size_t largest = i;

        if (arr[left] > arr[largest]) {
            largest = left;
        }
        if (right < size && arr[right] > arr[largest]) {
            largest = right;
        }
        if (largest == i) {
            break;
        }
        swap_i64(&arr[i], &arr[largest]);
        i = largest;
    }
}

static void min_sift_down(int64_t *arr, size_t size, size_t i) {
    while (i < size / 2) {
        size_t left = i * 2 + 1;
        size_t right = left + 1;
        size_t smallest = i;

        if (arr[left] < arr[smallest]) {
            smallest = left;
        }
        if (right < size && arr[right] < arr[smallest]) {
            smallest = right;
        }
        if (smallest == i) {
            break;
        }
        swap_i64(&arr[i], &arr[smallest]);
        i = smallest;
    }
}

void heap_sort_ascending(int64_t *array, size_t size) {
    if (array == NULL || size <= 1) {
        return;
    }
    size_t i = size / 2;
    while (i > 0) {
        --i;
        max_sift_down(array, size, i);
    }
    size_t active = size;
    while (active > 1) {
        --active;
        swap_i64(&array[0], &array[active]);
        max_sift_down(array, active, 0);
    }
}

void heap_sort_descending(int64_t *array, size_t size) {
    if (array == NULL || size <= 1) {
        return;
    }
    size_t i = size / 2;
    while (i > 0) {
        --i;
        min_sift_down(array, size, i);
    }
    size_t active = size;
    while (active > 1) {
        --active;
        swap_i64(&array[0], &array[active]);
        min_sift_down(array, active, 0);
    }
}

int main(void) {
    int64_t arr1[] = {12, 11, 13, 5, 6, 7, 13, -2, 0};
    size_t n1 = sizeof(arr1) / sizeof(arr1[0]);
    heap_sort_ascending(arr1, n1);
    for (size_t i = 1; i < n1; ++i) {
        assert(arr1[i - 1] <= arr1[i]);
    }

    int64_t arr2[] = {12, 11, 13, 5, 6, 7, 13, -2, 0};
    size_t n2 = sizeof(arr2) / sizeof(arr2[0]);
    heap_sort_descending(arr2, n2);
    for (size_t i = 1; i < n2; ++i) {
        assert(arr2[i - 1] >= arr2[i]);
    }

    return 0;
}
```

## 复杂度分析

- **时间复杂度**：
  - 建堆阶段消耗 $O(n)$ 时间；
  - 随后执行 $n - 1$ 次循环，每次循环包含一次 $O(1)$ 的首尾交换与一次耗时 $O(\log k)$ 的下滤，求和为 $\sum_{k=2}^n \log_2 k = \Theta(n \log n)$；
  - 无论最好、最坏或平均情况，堆排序的时间复杂度恒稳定为 $\Theta(n \log n)$。
- **空间复杂度**：全过程均在原数组内通过下标迭代完成，辅助空间复杂度严格为 $O(1)$。

## 延伸思考 / 模式总结

1. **最坏情况时间的绝对确定性**：与快速排序在最坏分区退化下可能退化到 $O(n^2)$ 不同，堆排序具有严格的 $O(n \log n)$ 最坏时间上界，这使得它常作为内省排序（Introsort，如 C++ `std::sort`）在递归深度过深时的兜底保底策略。
2. **缓存局部性的劣势**：虽然理论渐近复杂度同为 $O(n \log n)$，但堆排序在实际系统中的常数因子通常劣于快速排序。原因是堆节点的父子访问在下标上成倍跳跃（$i \to 2i+1$），当数组规模超出 L1/L2 缓存后，下滤过程会引发高频的 Cache Miss。
