# 31608 - d-叉堆下滤比较次数权衡与性能分析

## 题目

普通二叉堆的每个内部节点拥有 2 个子节点。将其推广为每个内部节点最多拥有 $d$ 个子节点的 **$d$-叉堆（d-ary Heap，$d \ge 2$）**。实现泛型参数化分支因子 $d$ 的小顶堆 `DAryMinHeap`，并对其在算法理论比较次数与现代硬件体系结构下的性能权衡进行深入分析：

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

typedef struct DAryMinHeap DAryMinHeap;

DAryMinHeap *d_ary_heap_create(size_t d);
void d_ary_heap_destroy(DAryMinHeap *heap);
bool d_ary_heap_push(DAryMinHeap *heap, int64_t value);
bool d_ary_heap_pop(DAryMinHeap *heap, int64_t *out_value);
bool d_ary_heap_peek(const DAryMinHeap *heap, int64_t *out_value);
size_t d_ary_heap_size(const DAryMinHeap *heap);
```

要求：

1. `d_ary_heap_create(d)` 中要求 $d \ge 2$；若 $d < 2$ 则创建失败返回 `NULL`。
2. 精确实现 $d$-叉堆的一维数组基于 0 的下标拓扑转换：
   - 节点 $i$ 的第 $k$ 个子节点（$1 \le k \le d$）下标为 $d \cdot i + k$；
   - 节点 $i$ 的父节点下标为 $\lfloor (i - 1) / d \rfloor$。
3. 严格防范计算子节点乘法时的算术溢出；上滤与下滤过程必须正确维护小顶堆不变式。
4. 在题解中运用微积分极值分析求出使“下滤比较次数”最小的理论分支因子 $d$，并解释为什么在现代计算机体系结构中，工程实践通常偏好选择 $d = 4$ 或 $d = 8$。

## 解题思路

### 1. $d$-叉堆的下标体系映射

在基于 $0$ 的紧凑数组中，$d$-叉树的节点排布规律如下：
- 根节点置于下标 $0$；
- 节点 $i$ 的所有子节点位于闭区间 $[d \cdot i + 1, \; \min(d \cdot i + d, \; \text{size} - 1)]$；
- 节点 $i$（$i > 0$）的父节点下标严格由整除运算给出：
  $$\text{parent}(i) = \left\lfloor \frac{i - 1}{d} \right\rfloor$$
- 该几何映射使得数组无任何内部碎片，所有树层自左向右连续紧贴。

### 2. 上滤与下滤的复杂度权衡

设堆内包含 $n$ 个元素，树的高度为：
$$H \approx \log_d n = \frac{\ln n}{\ln d}$$

- **上滤操作（Push / Decrease-Key）**：
  新元素自底向上与父节点比较。每上一层只需与自己的唯一个父节点比较一次，并执行一次交换。
  最大比较次数为：
  $$C_{\text{up}} \approx \log_d n = \frac{\ln n}{\ln d}$$
  显然，**分支因子 $d$ 越大，树高越矮，上滤越快**。

- **下滤操作（Pop-Min）**：
  从根节点向下下滤时，在树的每一层，为了选出所有兄弟子节点中的极小者，需要在至多 $d$ 个子节点中进行 $d - 1$ 次两两比较，随后与当前节点比较一次以决定是否继续下潜。
  因此，每层开销约为 $d$ 次比较。总下滤比较次数为：
  $$C_{\text{down}}(d) \approx d \log_d n = \left( \frac{d}{\ln d} \right) \ln n$$

### 3. 微积分极值分析：理论最优的 $d$

为了求出使得下滤比较次数最小的分支因子 $d$，考察连续函数：
$$f(x) = \frac{x}{\ln x} \quad (x > 1)$$
求其一阶导数：
$$f'(x) = \frac{1 \cdot \ln x - x \cdot (1/x)}{(\ln x)^2} = \frac{\ln x - 1}{(\ln x)^2}$$
令导数等于零 $f'(x) = 0$，解得：
$$\ln x = 1 \implies x = e \approx 2.71828$$
- 当 $x \in (1, e)$ 时，$f'(x) < 0$，$f(x)$ 单调递减；
- 当 $x \in (e, +\infty)$ 时，$f'(x) > 0$，$f(x)$ 单调递增。

因此，极小值在欧拉常数 $e$ 处取得。由于堆的分支因子 $d$ 必须是正整数：
- 考察 $d = 2$：$\frac{2}{\ln 2} \approx \frac{2}{0.693} \approx 2.885$；
- 考察 $d = 3$：$\frac{3}{\ln 3} \approx \frac{3}{1.099} \approx 2.731$；
- 考察 $d = 4$：$\frac{4}{\ln 4} = \frac{4}{2 \ln 2} \approx 2.885$。

**纯比较次数视角下的结论**：$d = 3$ 在纯理论比较次数上最优，而 $d = 4$ 与 $d = 2$ 的理论比较次数完全持平。

### 4. 体系结构与缓存局部性（Cache Locality）现实

尽管理论上 $d = 3$ 比较次数最少，但在现代计算机体系结构中，工程实践压倒性地选择 **$d = 4$**：
1. **CPU 缓存行对齐（Cache Line Alignment）**：现代 CPU 缓存行通常为 64 字节。若存储 64 位整数（每个 8 字节），4 个连续的子节点恰好占用 $4 \times 8 = 32$ 字节，或者 8 个子节点恰好填满 64 字节。CPU 触发一次内存总线读取即可将所有兄弟节点一次性全部载入 L1 Cache，后续在它们之间寻找极小值完全在极高速的寄存器和 L1 缓存中完成，避免了多次离散 Cache Miss。
2. **位运算位移替代除法**：当 $d = 4$ 时，子节点与父节点下标计算可退化为极速的位运算：$4 \cdot i = i \ll 2$，$(i - 1) / 4 = (i - 1) \gg 2$。无需调用硬件除法指令周期。
3. **Dijkstra 等算法的偏向性**：在密集图上，`decrease-key`（上滤）的调用频次远高于 `pop-min`（下滤）。$d = 4$ 将树高直接压缩了一半，大幅加速了占主导地位的上滤操作。

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct DAryMinHeap DAryMinHeap;

struct DAryMinHeap {
    int64_t *items;
    size_t size;
    size_t capacity;
    size_t d;
};

static void swap_i64(int64_t *a, int64_t *b) {
    int64_t tmp = *a;
    *a = *b;
    *b = tmp;
}

DAryMinHeap *d_ary_heap_create(size_t d) {
    if (d < 2) {
        return NULL;
    }
    DAryMinHeap *h = malloc(sizeof *h);
    if (h == NULL) {
        return NULL;
    }
    h->items = NULL;
    h->size = 0;
    h->capacity = 0;
    h->d = d;
    return h;
}

void d_ary_heap_destroy(DAryMinHeap *heap) {
    if (heap == NULL) {
        return;
    }
    free(heap->items);
    free(heap);
}

static bool heap_reserve(DAryMinHeap *h) {
    if (h->size < h->capacity) {
        return true;
    }
    size_t max_cap = SIZE_MAX / sizeof(int64_t);
    if (h->capacity >= max_cap) {
        return false;
    }
    size_t next = h->capacity == 0 ? 8 : (h->capacity > max_cap / 2 ? max_cap : h->capacity * 2);
    if (next <= h->size) {
        return false;
    }
    int64_t *new_items = realloc(h->items, next * sizeof(int64_t));
    if (new_items == NULL) {
        return false;
    }
    h->items = new_items;
    h->capacity = next;
    return true;
}

static void sift_up(DAryMinHeap *h, size_t i) {
    while (i > 0) {
        size_t p = (i - 1) / h->d;
        if (h->items[p] <= h->items[i]) {
            break;
        }
        swap_i64(&h->items[p], &h->items[i]);
        i = p;
    }
}

static void sift_down(DAryMinHeap *h, size_t i) {
    size_t d = h->d;
    while (1) {
        if (i > (SIZE_MAX - 1) / d) {
            break;
        }
        size_t first_child = i * d + 1;
        if (first_child >= h->size) {
            break;
        }

        size_t best = first_child;
        size_t last_child = first_child + d;
        if (last_child > h->size) {
            last_child = h->size;
        }
        for (size_t c = first_child + 1; c < last_child; ++c) {
            if (h->items[c] < h->items[best]) {
                best = c;
            }
        }

        if (h->items[i] <= h->items[best]) {
            break;
        }
        swap_i64(&h->items[i], &h->items[best]);
        i = best;
    }
}

bool d_ary_heap_push(DAryMinHeap *heap, int64_t value) {
    if (heap == NULL) {
        return false;
    }
    if (!heap_reserve(heap)) {
        return false;
    }
    heap->items[heap->size] = value;
    sift_up(heap, heap->size);
    heap->size++;
    return true;
}

bool d_ary_heap_peek(const DAryMinHeap *heap, int64_t *out_value) {
    if (heap == NULL || out_value == NULL || heap->size == 0) {
        return false;
    }
    *out_value = heap->items[0];
    return true;
}

bool d_ary_heap_pop(DAryMinHeap *heap, int64_t *out_value) {
    if (heap == NULL || out_value == NULL || heap->size == 0) {
        return false;
    }
    *out_value = heap->items[0];
    heap->size--;
    if (heap->size > 0) {
        heap->items[0] = heap->items[heap->size];
        sift_down(heap, 0);
    }
    return true;
}

size_t d_ary_heap_size(const DAryMinHeap *heap) {
    if (heap == NULL) {
        return 0;
    }
    return heap->size;
}

int main(void) {
    assert(d_ary_heap_create(1) == NULL);

    DAryMinHeap *h4 = d_ary_heap_create(4);
    assert(h4 != NULL);

    int64_t vals[] = {35, 12, 89, 4, 23, 7, 19, 56, 3, 42, 1, 99};
    size_t count = sizeof(vals) / sizeof(vals[0]);
    for (size_t i = 0; i < count; ++i) {
        assert(d_ary_heap_push(h4, vals[i]));
    }
    assert(d_ary_heap_size(h4) == count);

    int64_t prev = -1;
    int64_t cur = 0;
    for (size_t i = 0; i < count; ++i) {
        assert(d_ary_heap_pop(h4, &cur));
        if (i > 0) {
            assert(prev <= cur);
        }
        prev = cur;
    }
    assert(d_ary_heap_size(h4) == 0);

    d_ary_heap_destroy(h4);
    return 0;
}
```

## 复杂度分析

- **时间复杂度**：
  - `d_ary_heap_push`：上滤最大移动高度为 $\log_d n$，单次比较并交换，时间复杂度为 $O(\log_d n)$。当 $d=4$ 时，树高仅为二叉堆的一半。
  - `d_ary_heap_pop`：每层寻找 $d$ 个子节点的极小值需 $d-1$ 次比较，下滤沿树高下潜，总比较次数为 $O(d \log_d n)$。
  - `d_ary_heap_peek`：直接读取下标 0，严格为 $O(1)$。
- **空间复杂度**：动态数组连续存储 $n$ 个元素，空间复杂度为 $O(n)$。

## 延伸思考 / 模式总结

1. **理论抽象与硬件特性的交汇**：渐近分析中的 $\log_2 n$ 与 $\log_4 n$ 在大 $O$ 意义下仅相差常数倍数（$\log_4 n = \frac{1}{2} \log_2 n$），但当结合 CPU 缓存行（Cache Line）、SIMD 向量化指令（如 AVX2 一条指令同时比对 4 个整数）和硬件分支预测器时，分支因子的精细调优往往能带来数倍的真实吞吐量提升。
2. **多叉树索引的统一哲学**：从 $d$-叉堆到外存 B 树 / B+ 树，其背后的系统哲学是一脉相承的——当单次跨节点寻址成本极高（磁盘 I/O 或内存 Cache Miss）时，通过增加节点分支度 $d$ 来大幅压缩树的高度，是降低全局访问延迟的最通用武器。
