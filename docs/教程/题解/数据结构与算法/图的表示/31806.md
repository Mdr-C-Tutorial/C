# 31806 - 无向图邻接多重表与边对象共享

## 题目描述

在普通邻接表中表示无向图时，每一条无向边 $(u, v)$ 都必须拆分复制为两个独立的边节点（分别挂在 $u$ 与 $v$ 的链表中）。这导致对某条边进行状态标记（如是否访问过、权重修改、删除）时，必须在两个链表中分别搜寻同步，极易产生状态不一致。实现无向图边对象共享表示法——**邻接多重表（Adjacency Multilist）**：

```c
#include <stdbool.h>
#include <stddef.h>

typedef struct MultiListGraph MultiListGraph;

MultiListGraph *ml_graph_create(size_t vertex_count);
void ml_graph_destroy(MultiListGraph *graph);
bool ml_graph_add_edge(MultiListGraph *graph, size_t u, size_t v);
bool ml_graph_mark_edge(MultiListGraph *graph, size_t u, size_t v, bool *out_previously_marked);
void ml_graph_reset_marks(MultiListGraph *graph);
size_t ml_graph_degree(const MultiListGraph *graph, size_t vertex);
```

要求：

1. 顶点编号为 $[0, \text{vertex\_count} - 1]$。全图的每一条物理无向边**仅且必须仅分配一个单一的边对象结构体**。
2. 边节点结构体包含：
   - 两个端点 `ivex` 与 `jvex`；
   - 依附于 `ivex` 的下一条边指针 `ilink`；
   - 依附于 `jvex` 的下一条边指针 `jlink`；
   - 边状态标记 `marked`。
3. `ml_graph_add_edge` 在 $O(1)$ 时间内将同一个边对象同时挂接至两个端点的链表头部。
4. `ml_graph_mark_edge` 找到连接 $u$ 与 $v$ 的边对象，将其 `marked` 设为 `true`，并将此前旧标记值写入 `*out_previously_marked`。验证从 $u$ 侧标记该边后，从 $v$ 侧立刻可感知该标记已更新。
5. 析构时必须安全释放全图所有共享边节点，保证每条边恰被释放一次，零内存泄漏与零重复释放。

## 解题思路

### 1. 边的实体化共享哲学

无向图的边是一条无方向的物理连接。普通邻接表将其强制“有向化”为两条对称边，带来严重的弊端：
- 若要在欧拉回路遍历或最小生成树算法中“标记一条边已被走过”，必须同时找到 $(u, v)$ 与 $(v, u)$ 两个对象分别设置，开销为两次链表遍历；
- 若要删除一条边，必须在两个端点的链表中各自执行链表节点的脱钩与释放。

邻接多重表（Adjacency Multilist）确立了**边作为单一实体对象（Single Entity Object）**的核心思想：
- 每一条无向边只分配一个 `MultiEdge`；
- 该对象同时拥有两根链表指针：
  - `ilink`：将所有依附于端点 `ivex` 的边串接起来；
  - `jlink`：将所有依附于端点 `jvex` 的边串接起来。

```text
 顶点 u -------------------------------> MultiEdge
                                        +-------------------+
                                        | ivex (u) | jvex(v)|
                                        |-------------------|
                                 +----->| ilink    | jlink  |------+
                                 |      +-------------------+      |
                                 |                                 |
 下一条属于 u 的边 <---------------+                                 +---> 下一条属于 v 的边
```

### 2. 双视角对称遍历机制

当从某个顶点 $curr$ 出发沿链表向外枚举邻接边时：
- 读取当前边指针 `e`；
- 判断 $curr$ 对应于该边的哪一个端点：
  - 若 `curr == e->ivex`：则对端邻接点为 `e->jvex`，该顶点在边上的后继链表指针为 `e->ilink`；
  - 若 `curr == e->jvex`：则对端邻接点为 `e->ivex`，该顶点在边上的后继链表指针为 `e->jlink`。
无论通过 $u$ 还是通过 $v$ 定位到该边，修改该边上的任何成员（例如 `marked = true`），对端在遍历到此边时均自然直接生效，达成了真正意义上的强原子共享。

### 3. 基于标记的两趟安全析构机制

由于每条边同时悬挂在两个顶点的链表中，若简单随顶点遍历调用 `free` 会导致重复释放崩溃：
1. **第一趟（标记待删）**：遍历每个顶点的链表，将沿途遇到的全部边对象打上 `marked = true`；
2. **第二趟（单次释放）**：再次遍历每个顶点的链表，当检查到某条边的 `marked == true` 时，说明该边尚未被释放。先将 `marked` 清零，然后调用 `free(curr)` 释放该边对象；后序若从另一个端点再次扫描到同一内存块时，由于 `marked == false` 会自动跳过释放。
全图 $E$ 条共享边被严格且优雅地各释放一次。

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct MultiEdge MultiEdge;

struct MultiEdge {
    size_t ivex;
    size_t jvex;
    MultiEdge *ilink;
    MultiEdge *jlink;
    bool marked;
};

typedef struct {
    MultiEdge *first_edge;
} MultiVex;

typedef struct MultiListGraph MultiListGraph;

struct MultiListGraph {
    MultiVex *vertices;
    size_t vertex_count;
};

MultiListGraph *ml_graph_create(size_t vertex_count) {
    MultiListGraph *g = malloc(sizeof *g);
    if (g == NULL) {
        return NULL;
    }
    g->vertex_count = vertex_count;
    g->vertices = NULL;
    if (vertex_count > 0) {
        if (vertex_count > SIZE_MAX / sizeof(MultiVex)) {
            free(g);
            return NULL;
        }
        g->vertices = calloc(vertex_count, sizeof(MultiVex));
        if (g->vertices == NULL) {
            free(g);
            return NULL;
        }
    }
    return g;
}

void ml_graph_destroy(MultiListGraph *graph) {
    if (graph == NULL) {
        return;
    }
    for (size_t i = 0; i < graph->vertex_count; ++i) {
        MultiEdge *curr = graph->vertices[i].first_edge;
        while (curr != NULL) {
            MultiEdge *next = (curr->ivex == i) ? curr->ilink : curr->jlink;
            curr->marked = true;
            curr = next;
        }
    }
    for (size_t i = 0; i < graph->vertex_count; ++i) {
        MultiEdge *curr = graph->vertices[i].first_edge;
        while (curr != NULL) {
            MultiEdge *next = (curr->ivex == i) ? curr->ilink : curr->jlink;
            if (curr->marked) {
                curr->marked = false;
                free(curr);
            }
            curr = next;
        }
    }
    free(graph->vertices);
    free(graph);
}

bool ml_graph_add_edge(MultiListGraph *graph, size_t u, size_t v) {
    if (graph == NULL || u >= graph->vertex_count || v >= graph->vertex_count) {
        return false;
    }
    MultiEdge *e = malloc(sizeof *e);
    if (e == NULL) {
        return false;
    }
    e->ivex = u;
    e->jvex = v;
    e->marked = false;

    e->ilink = graph->vertices[u].first_edge;
    graph->vertices[u].first_edge = e;

    e->jlink = graph->vertices[v].first_edge;
    graph->vertices[v].first_edge = e;

    return true;
}

bool ml_graph_mark_edge(MultiListGraph *graph, size_t u, size_t v, bool *out_previously_marked) {
    if (graph == NULL || out_previously_marked == NULL ||
        u >= graph->vertex_count || v >= graph->vertex_count) {
        return false;
    }
    for (MultiEdge *e = graph->vertices[u].first_edge; e != NULL; e = (e->ivex == u ? e->ilink : e->jlink)) {
        size_t other = (e->ivex == u) ? e->jvex : e->ivex;
        if (other == v) {
            *out_previously_marked = e->marked;
            e->marked = true;
            return true;
        }
    }
    return false;
}

void ml_graph_reset_marks(MultiListGraph *graph) {
    if (graph == NULL) {
        return;
    }
    for (size_t i = 0; i < graph->vertex_count; ++i) {
        for (MultiEdge *e = graph->vertices[i].first_edge; e != NULL; e = (e->ivex == i ? e->ilink : e->jlink)) {
            e->marked = false;
        }
    }
}

size_t ml_graph_degree(const MultiListGraph *graph, size_t vertex) {
    if (graph == NULL || vertex >= graph->vertex_count) {
        return 0;
    }
    size_t deg = 0;
    for (const MultiEdge *e = graph->vertices[vertex].first_edge; e != NULL; e = (e->ivex == vertex ? e->ilink : e->jlink)) {
        deg++;
    }
    return deg;
}

int main(void) {
    ml_graph_destroy(NULL);

    MultiListGraph *g = ml_graph_create(4);
    assert(g != NULL);
    assert(ml_graph_add_edge(g, 0, 1));
    assert(ml_graph_add_edge(g, 0, 2));
    assert(ml_graph_add_edge(g, 1, 2));
    assert(ml_graph_add_edge(g, 2, 3));

    assert(ml_graph_degree(g, 0) == 2);
    assert(ml_graph_degree(g, 2) == 3);

    bool prev = true;
    assert(ml_graph_mark_edge(g, 0, 1, &prev) && !prev);
    assert(ml_graph_mark_edge(g, 1, 0, &prev) && prev);

    ml_graph_reset_marks(g);
    assert(ml_graph_mark_edge(g, 0, 1, &prev) && !prev);

    ml_graph_destroy(g);
    return 0;
}
```

## 复杂度分析

- **时间复杂度**：
  - `ml_graph_add_edge`：仅需同时将单条边挂接在两个顶点的链表头部，时间复杂度严格为 $O(1)$。
  - `ml_graph_mark_edge`：沿其中一个端点的边链表搜索目标边并原子标记，时间复杂度为 $O(\min(\text{deg}(u), \text{deg}(v)))$。
  - `ml_graph_degree`：遍历指定顶点的多重链，时间复杂度为 $O(\text{deg}(v))$。
  - `ml_graph_destroy`：两趟遍历处理，时间复杂度为 $O(V + E)$。
- **空间复杂度**：全图 $E$ 条无向边严格只分配 $E$ 个结构体，内存开销较普通无向邻接表直接减半，空间复杂度严格为 $O(V + E)$。

## 延伸思考 / 模式总结

1. **边权编辑与删边的天然敏捷性**：在需要动态更新边权或频繁删边的算法中，邻接多重表的优势展现得淋漓尽致。只要持有某条边的句柄指针，即可在 $O(1)$ 时间内就地修改其权值，完全免除了在另一端点再次查找对应反向边的同步复杂性。
2. **多重链拓扑的推广**：这种多个顶点交替共享同一连接对象的模式，在计算几何的**双向连通边表（DCEL / 半边结构）**以及三维网格建模的**翼边结构（Winged-Edge）**中构成了核心骨架。
