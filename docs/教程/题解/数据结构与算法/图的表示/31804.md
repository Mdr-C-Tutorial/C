# 31804 - 链式前向星连续存储与索引设计

## 题目描述

普通邻接表依赖离散的堆指针链表存储边，容易引发严重的内存碎片与 CPU 缓存未命中（Cache Miss）。实现基于紧凑连续内存数组的静态链表化图表示法——**链式前向星（Forward Star）**：

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

typedef struct ForwardStarGraph ForwardStarGraph;

ForwardStarGraph *fs_graph_create(size_t vertex_count, size_t edge_capacity, bool directed);
void fs_graph_destroy(ForwardStarGraph *graph);
bool fs_graph_add_edge(ForwardStarGraph *graph, size_t from, size_t to, int64_t weight);
bool fs_graph_out_degree(const ForwardStarGraph *graph, size_t vertex, size_t *out_deg);
```

要求：

1. 内部仅分配两块平整的连续内存数组：
   - 表头索引数组 `head`：长度为 `vertex_count`，记录每个顶点出发的第一条边在边数组中的下标；初始全置为无效哨兵值（`SIZE_MAX`）；
   - 边对象连续数组 `edges`：容量为 `edge_capacity`，元素结构包含终点 `to`、权重 `weight` 以及同一起点的下一条边下标 `next`。
2. `fs_graph_add_edge` 在 $O(1)$ 时间内以类似单链表头插法的机制追加边，并更新 `head[from]`；若边数组容量已满或参数非法，安全返回 `false` 且不修改原图。
3. `fs_graph_out_degree` 遍历该顶点的链式索引，统计出度。
4. 深入剖析链式前向星在现代 CPU 体系结构下的缓存局部性优势，对比分析其与传统邻接表的优缺点。

## 解题思路

### 1. 数组模拟静态链表：头插法与连续排布

链式前向星巧妙地用**数组下标**替代了 C 语言的**动态堆指针**：
- 边数组 `edges` 是一块完全平铺的连续内存；
- 每插入一条边，直接在边数组的末尾 `edge_count++` 分配一个槽位；
- 维护链接关系时采用类似单链表的**头插法（Head-Insertion）**：
  ```c
  edges[edge_idx].next = head[from];
  head[from] = edge_idx;
  ```
- 遍历从顶点 $u$ 出发的所有边时，形成极其紧凑的固定习惯用法：
  ```c
  for (size_t e = graph->head[u]; e != SIZE_MAX; e = graph->edges[e].next) {
      size_t v = graph->edges[e].to;
      int64_t w = graph->edges[e].weight;
      // 访问边 (u -> v, 权重 w)
  }
  ```

### 2. 硬件体系结构层面的性能优势

链式前向星在高性能图计算、算法竞赛以及工业图引擎中被广泛偏爱，其核心原因并非渐近时间复杂度的差异，而是对底层硬件的极致友好：
1. **零指针反引用与内存紧凑性**：64 位操作系统下，每个普通堆链表节点不仅需要包含 8 字节的 `next` 指针，更需承受 `malloc` 堆分配器的头部管理元数据（通常为 8 到 16 字节）以及内存对齐填充。链式前向星一次性申请平整大数组，杜绝了元数据开销与碎内存；
2. **CPU 缓存预取亲和力（Cache Prefetching）**：在加边或批量处理时，边对象在物理地址上连续存放，硬件预取器（L1/L2 Streamer Prefetcher）能以极高命中率提前将后续边载入高速缓存，大幅削减了内存总线停顿周期；
3. **极简极速的全局重置**：清空图的所有边只需简单调用 `memset(head, 0xFF, sizeof(head))` 将表头重置为 `SIZE_MAX` 并置 `edge_count = 0`，耗时仅数个微秒，完全免除了深度遍历逐个调用 `free` 的沉重系统调用开销。

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct {
    size_t to;
    size_t next;
    int64_t weight;
} FSEdge;

typedef struct ForwardStarGraph ForwardStarGraph;

struct ForwardStarGraph {
    size_t *head;
    FSEdge *edges;
    size_t vertex_count;
    size_t edge_count;
    size_t edge_capacity;
    bool directed;
};

ForwardStarGraph *fs_graph_create(size_t vertex_count, size_t edge_capacity, bool directed) {
    ForwardStarGraph *g = malloc(sizeof *g);
    if (g == NULL) {
        return NULL;
    }
    g->vertex_count = vertex_count;
    g->edge_count = 0;
    g->edge_capacity = edge_capacity;
    g->directed = directed;
    g->head = NULL;
    g->edges = NULL;

    if (vertex_count > 0) {
        g->head = malloc(vertex_count * sizeof(size_t));
        if (g->head == NULL) {
            free(g);
            return NULL;
        }
        for (size_t i = 0; i < vertex_count; ++i) {
            g->head[i] = SIZE_MAX;
        }
    }
    if (edge_capacity > 0) {
        g->edges = malloc(edge_capacity * sizeof(FSEdge));
        if (g->edges == NULL) {
            free(g->head);
            free(g);
            return NULL;
        }
    }
    return g;
}

void fs_graph_destroy(ForwardStarGraph *graph) {
    if (graph == NULL) {
        return;
    }
    free(graph->head);
    free(graph->edges);
    free(graph);
}

static bool add_single_directed_edge(ForwardStarGraph *g, size_t from, size_t to, int64_t weight) {
    if (g->edge_count >= g->edge_capacity) {
        return false;
    }
    size_t edge_idx = g->edge_count++;
    g->edges[edge_idx].to = to;
    g->edges[edge_idx].weight = weight;
    g->edges[edge_idx].next = g->head[from];
    g->head[from] = edge_idx;
    return true;
}

bool fs_graph_add_edge(ForwardStarGraph *graph, size_t from, size_t to, int64_t weight) {
    if (graph == NULL || from >= graph->vertex_count || to >= graph->vertex_count) {
        return false;
    }
    size_t needed = graph->directed ? 1 : 2;
    if (graph->edge_count + needed > graph->edge_capacity) {
        return false;
    }
    if (!add_single_directed_edge(graph, from, to, weight)) {
        return false;
    }
    if (!graph->directed) {
        add_single_directed_edge(graph, to, from, weight);
    }
    return true;
}

bool fs_graph_out_degree(const ForwardStarGraph *graph, size_t vertex, size_t *out_deg) {
    if (graph == NULL || out_deg == NULL || vertex >= graph->vertex_count) {
        return false;
    }
    size_t deg = 0;
    for (size_t e = graph->head[vertex]; e != SIZE_MAX; e = graph->edges[e].next) {
        deg++;
    }
    *out_deg = deg;
    return true;
}

int main(void) {
    fs_graph_destroy(NULL);

    ForwardStarGraph *g = fs_graph_create(4, 10, true);
    assert(g != NULL);
    assert(fs_graph_add_edge(g, 0, 1, 10));
    assert(fs_graph_add_edge(g, 0, 2, 20));
    assert(fs_graph_add_edge(g, 1, 2, 30));

    size_t deg = 0;
    assert(fs_graph_out_degree(g, 0, &deg) && deg == 2);
    assert(fs_graph_out_degree(g, 1, &deg) && deg == 1);
    assert(fs_graph_out_degree(g, 2, &deg) && deg == 0);

    fs_graph_destroy(g);
    return 0;
}
```

## 复杂度分析

- **时间复杂度**：
  - `fs_graph_add_edge`：仅需数组下标追加与单次表头更新，时间复杂度严格为 $O(1)$。
  - `fs_graph_out_degree`：沿静态链表遍历该顶点的出边，时间复杂度为 $O(\text{out\_deg}(v))$。
  - `fs_graph_create`：连续内存分配与表头初始化，时间复杂度为 $O(V)$。
- **空间复杂度**：为 $V$ 个表头与 $E_{\text{cap}}$ 条边分配整块连续内存，空间复杂度严格为 $O(V + E_{\text{cap}})$。

## 延伸思考 / 模式总结

1. **CSR（压缩稀疏行）的前身**：链式前向星与科学计算中的稀疏矩阵标准存储格式 CSR（Compressed Sparse Row）仅一步之遥。若将所有边在插入完毕后按起点集中排序，消除 `next` 指针，即可蜕变为纯粹由两个下标偏置数组构成的 CSR 格式，具备最为极致的空间压缩率。
2. **容量预估的工程权衡**：链式前向星的唯一局限在于需要预先指定或动态成倍扩展 `edge_capacity`。在未知边规模的极端动态流场景下，成倍扩容 `realloc` 边数组时需要保证既有下标索引不受地址搬移影响，因此通常建议在已知图规模上限时优先采用。
