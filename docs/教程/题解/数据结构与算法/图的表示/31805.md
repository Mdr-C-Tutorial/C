# 31805 - 有向图十字链表出入弧双向追踪

## 题目

普通邻接表仅能快速遍历出边，查询入边与前驱顶点需要耗时 $O(V + E)$ 全图扫描；而逆邻接表又失去了快速遍历出边的能力。实现将邻接表与逆邻接表无缝缝合的经典数据结构——**有向图十字链表（Orthogonal List）**：

```c
#include <stdbool.h>
#include <stddef.h>

typedef struct OrthogonalGraph OrthogonalGraph;

OrthogonalGraph *ortho_graph_create(size_t vertex_count);
void ortho_graph_destroy(OrthogonalGraph *graph);
bool ortho_graph_add_arc(OrthogonalGraph *graph, size_t tail, size_t head);
bool ortho_graph_in_degree(const OrthogonalGraph *graph, size_t vertex, size_t *out_in_deg);
bool ortho_graph_out_degree(const OrthogonalGraph *graph, size_t vertex, size_t *out_out_deg);
```

要求：

1. 顶点编号为 $[0, \text{vertex\_count} - 1]$。每个顶点记录出弧链表头指针 `first_out` 与入弧链表头指针 `first_in`。
2. 弧（有向边）节点包含四项核心成员：
   - 弧尾顶点 `tail_vex`（起点）与弧头顶点 `head_vex`（终点）；
   - 入弧链指针 `hlink`：指向同一弧头（入点相同）的下一条弧；
   - 出弧链指针 `tlink`：指向同一弧尾（出点相同）的下一条弧。
3. `ortho_graph_add_arc` 在 $O(1)$ 时间内同时将新弧挂载到起点的出弧链表与终点的入弧链表头部。
4. `ortho_graph_in_degree` 与 `ortho_graph_out_degree` 分别在正比于该顶点自身入度与出度（严格为 $O(\text{deg}(v))$）的时间内完成统计，严禁扫描任何无关顶点的链表。
5. 析构函数必须确保每条在两组链表中被共同引用的弧节点被且仅被释放一次，严防重复释放（Double Free）与悬挂指针。

## 解题思路

### 1. 邻接表与逆邻接表的正交缝合

在有向图中，一条弧 $tail \to head$ 同时具有两重身份：
- 它是起点 $tail$ 的一条**出弧（Outgoing Arc）**；
- 它也是终点 $head$ 的一条**入弧（Incoming Arc）**。

十字链表之所以称为“十字”，是因为每个弧节点位于两个正交维度的交汇点上：
- 水平链（出弧链 `tlink`）：将所有从同一个 $tail$ 出发的弧串联起来；
- 垂直链（入弧链 `hlink`）：将所有到达同一个 $head$ 的弧串联起来。

```text
               顶点 head 的 first_in
                       |
                       v
                +-------------+
                | tail | head |
   ... -------->|-------------|--------> 下一条出弧 (tlink)
    (tlink)     | hlink| tlink|
                +-------------+
                       |
                       v (hlink)
               下一条入弧
```

这种正交编织机制使得单个物理弧节点被两个正交链表同时共享，兼具了邻接表与逆邻接表的全部能力，却完全没有重复存储两份边数据的空间浪费。

### 2. 双向定位与度数统计效率飞跃

在普通邻接表中：
- 出度查询：$O(\text{out\_deg}(v))$；
- 入度查询：必须完整遍历所有 $V$ 个顶点的全部出边，时间高达 $O(V + E)$。

在十字链表中：
- 出度查询：顺着 `first_out` 沿 `tlink` 遍历，耗时严格为 $O(\text{out\_deg}(v))$；
- 入度查询：顺着 `first_in` 沿 `hlink` 遍历，耗时严格为 $O(\text{in\_deg}(v))$。
无需任何全图遍历即可在真正的局部时间内完成前驱与后继双向导航。

### 3. 对象所有权与防重复释放设计

十字链表的每个弧节点同时被两个指针链追踪，析构时若两组链表都调用 `free` 会引发致命的 Double Free：
- **析构不变式契约**：规定每条弧的主拥有者为其起点（$tail$）的出弧链表；
- 销毁图时，仅沿所有顶点的 `first_out` 链遍历并释放弧节点；
- 遍历完成后，全图所有的弧节点恰好被且仅被访问并销毁一次。

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct OrthoArc OrthoArc;

struct OrthoArc {
    size_t tail_vex;
    size_t head_vex;
    OrthoArc *hlink;
    OrthoArc *tlink;
};

typedef struct {
    OrthoArc *first_in;
    OrthoArc *first_out;
} OrthoVex;

typedef struct OrthogonalGraph OrthogonalGraph;

struct OrthogonalGraph {
    OrthoVex *vertices;
    size_t vertex_count;
};

OrthogonalGraph *ortho_graph_create(size_t vertex_count) {
    OrthogonalGraph *g = malloc(sizeof *g);
    if (g == NULL) {
        return NULL;
    }
    g->vertex_count = vertex_count;
    g->vertices = NULL;
    if (vertex_count > 0) {
        if (vertex_count > SIZE_MAX / sizeof(OrthoVex)) {
            free(g);
            return NULL;
        }
        g->vertices = calloc(vertex_count, sizeof(OrthoVex));
        if (g->vertices == NULL) {
            free(g);
            return NULL;
        }
    }
    return g;
}

void ortho_graph_destroy(OrthogonalGraph *graph) {
    if (graph == NULL) {
        return;
    }
    for (size_t i = 0; i < graph->vertex_count; ++i) {
        OrthoArc *curr = graph->vertices[i].first_out;
        while (curr != NULL) {
            OrthoArc *next = curr->tlink;
            free(curr);
            curr = next;
        }
    }
    free(graph->vertices);
    free(graph);
}

bool ortho_graph_add_arc(OrthogonalGraph *graph, size_t tail, size_t head) {
    if (graph == NULL || tail >= graph->vertex_count || head >= graph->vertex_count) {
        return false;
    }
    OrthoArc *arc = malloc(sizeof *arc);
    if (arc == NULL) {
        return false;
    }
    arc->tail_vex = tail;
    arc->head_vex = head;

    arc->tlink = graph->vertices[tail].first_out;
    graph->vertices[tail].first_out = arc;

    arc->hlink = graph->vertices[head].first_in;
    graph->vertices[head].first_in = arc;

    return true;
}

bool ortho_graph_in_degree(const OrthogonalGraph *graph, size_t vertex, size_t *out_in_deg) {
    if (graph == NULL || out_in_deg == NULL || vertex >= graph->vertex_count) {
        return false;
    }
    size_t deg = 0;
    for (const OrthoArc *a = graph->vertices[vertex].first_in; a != NULL; a = a->hlink) {
        deg++;
    }
    *out_in_deg = deg;
    return true;
}

bool ortho_graph_out_degree(const OrthogonalGraph *graph, size_t vertex, size_t *out_out_deg) {
    if (graph == NULL || out_out_deg == NULL || vertex >= graph->vertex_count) {
        return false;
    }
    size_t deg = 0;
    for (const OrthoArc *a = graph->vertices[vertex].first_out; a != NULL; a = a->tlink) {
        deg++;
    }
    *out_out_deg = deg;
    return true;
}

int main(void) {
    ortho_graph_destroy(NULL);

    OrthogonalGraph *g = ortho_graph_create(4);
    assert(g != NULL);
    assert(ortho_graph_add_arc(g, 0, 1));
    assert(ortho_graph_add_arc(g, 0, 2));
    assert(ortho_graph_add_arc(g, 1, 2));
    assert(ortho_graph_add_arc(g, 2, 0));

    size_t in_deg = 0;
    size_t out_deg = 0;
    assert(ortho_graph_out_degree(g, 0, &out_deg) && out_deg == 2);
    assert(ortho_graph_in_degree(g, 0, &in_deg) && in_deg == 1);

    assert(ortho_graph_out_degree(g, 2, &out_deg) && out_deg == 1);
    assert(ortho_graph_in_degree(g, 2, &in_deg) && in_deg == 2);

    ortho_graph_destroy(g);
    return 0;
}
```

## 复杂度分析

- **时间复杂度**：
  - `ortho_graph_add_arc`：涉及两次常量时间的头指针更新，时间复杂度严格为 $O(1)$。
  - `ortho_graph_in_degree`：仅遍历目标顶点的入弧链，时间复杂度为 $O(\text{in\_deg}(v))$。
  - `ortho_graph_out_degree`：仅遍历源顶点的出弧链，时间复杂度为 $O(\text{out\_deg}(v))$。
  - `ortho_graph_create` 与 `ortho_graph_destroy`：时间复杂度分别为 $O(V)$ 与 $O(V + E)$。
- **空间复杂度**：为 $V$ 个顶点分配正反表头指针，为每条弧分配一个包含两根指针的节点，空间复杂度严格为 $O(V + E)$。

## 延伸思考 / 模式总结

1. **双向导航的经典适用场景**：十字链表是拓扑排序中查找入度为 0 顶点、强连通分量 Tarjan 算法、关键路径（CPM）前驱时间推导以及网络流增广路径寻找的理想底层表示。
2. **指针织网与多重引用的统一生命周期治理**：十字链表展示了在不引入复杂引用计数的情况下，如何通过“确立单一所有权归属主轴”（以 `first_out` 为主销毁轴）安全治理多图元交叉引用的系统架构技巧。
