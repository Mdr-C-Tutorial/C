# 题解：31304

## 题目

实现字节序列的 FNV-1a 散列函数，以及满足等价一致性契约的不区分 ASCII 大小写字符串散列与比较函数：

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

uint64_t fnv1a_hash_bytes(const void *data, size_t len);
uint64_t fnv1a_hash_ascii_icase(const char *s);
bool ascii_str_iequal(const char *a, const char *b);
```

要求：

1. `fnv1a_hash_bytes` 支持包含任意 `0x00` 字节的二进制内存块；当 `len == 0` 时返回 FNV-1a 64 位初始偏移基数 `UINT64_C(14695981039346656037)`。
2. `ascii_str_iequal` 与 `fnv1a_hash_ascii_icase` 仅将 `'A'..'Z'` 折叠为 `'a'..'z'`，其余字节保持原值；对任意非空字符串 `a, b`，若 `ascii_str_iequal(a, b)` 为 `true`，则必须保证 `fnv1a_hash_ascii_icase(a) == fnv1a_hash_ascii_icase(b)`。
3. 结合具体例子回答：若散列表使用 `ascii_str_iequal` 判定键相等，但散列函数误用了区分大小写的 `fnv1a_hash_str`，先插入 `"Content-Length"` 再查询或重复插入 `"content-length"` 时分别会发生什么错误？

## 解析

### 1. FNV-1a 算法规范

FNV-1a（Fowler–Noll–Vo）在处理每个字节时遵循“先异或输入字节，再乘以 FNV 质数”的次序：
- 64 位初始偏移基数 (Offset Basis)：`14695981039346656037`（十六进制 `0xcbf29ce484222325`）；
- 64 位 FNV 质数 (Prime)：`1099511628211`（十六进制 `0x100000001b3`）。

### 2. 等价一致性契约 (Equivalence Consistency Contract)

散列表正确工作的核心代数公理是：

$$\text{equal}(k_1, k_2) \implies \text{hash}(k_1) == \text{hash}(k_2)$$

如果两个对象在语义上被判定为“相同”，它们在散列表中就必须被路由到同一个初始桶中。因此，在不区分大小写的比较语义下，散列函数在累计每个字符前，必须先将大写字母 `'A' \dots 'Z'` 折叠为小写 `'a' \dots 'z'`。

### 3. 契约破坏导致的错误后果

假设散列表使用区分大小写的散列函数，但使用不区分大小写的键比较函数：
1. **查询失败（假阴性，False Negative）**：
   - 插入 `"Content-Length"` 时，根据其大写计算出的散列值 $H_1$，键被放入桶 $B_1 = H_1 \bmod m$ 中；
   - 随后查找 `"content-length"` 时，散列函数根据全小写计算出完全不同的散列值 $H_2$，从而到桶 $B_2 = H_2 \bmod m$ 中寻找；
   - 只要 $B_1 \neq B_2$（极大概率成立），查找过程根本不会触碰桶 $B_1$ 内的节点，直接报告该键不存在，导致查询失败。
2. **重复插入破坏唯一性（数据不一致）**：
   - 当调用方试图向集合中插入 `"content-length"` 时，由于在桶 $B_2$ 未找到同义词，集合会允许插入新键；
   - 导致本应等价去重的集合中同时存在 `"Content-Length"` 与 `"content-length"` 两个条目。

## 答案

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

static inline unsigned char to_ascii_lower(unsigned char c) {
    if (c >= 'A' && c <= 'Z') {
        return (unsigned char)(c + ('a' - 'A'));
    }
    return c;
}

uint64_t fnv1a_hash_bytes(const void *data, size_t len) {
    uint64_t hash = UINT64_C(14695981039346656037);
    if (data == NULL || len == 0) {
        return hash;
    }
    const unsigned char *p = (const unsigned char *)data;
    for (size_t i = 0; i < len; ++i) {
        hash ^= (uint64_t)p[i];
        hash *= UINT64_C(1099511628211);
    }
    return hash;
}

uint64_t fnv1a_hash_ascii_icase(const char *s) {
    uint64_t hash = UINT64_C(14695981039346656037);
    if (s == NULL) {
        return hash;
    }
    for (const unsigned char *p = (const unsigned char *)s; *p != '\0'; ++p) {
        hash ^= (uint64_t)to_ascii_lower(*p);
        hash *= UINT64_C(1099511628211);
    }
    return hash;
}

bool ascii_str_iequal(const char *a, const char *b) {
    if (a == NULL || b == NULL) {
        return false;
    }
    const unsigned char *p1 = (const unsigned char *)a;
    const unsigned char *p2 = (const unsigned char *)b;

    while (*p1 != '\0' && *p2 != '\0') {
        if (to_ascii_lower(*p1) != to_ascii_lower(*p2)) {
            return false;
        }
        p1++;
        p2++;
    }
    return *p1 == '\0' && *p2 == '\0';
}

int main(void) {
    // 1. 验证空缓冲区基数
    assert(fnv1a_hash_bytes(NULL, 0) == UINT64_C(14695981039346656037));
    assert(fnv1a_hash_ascii_icase(NULL) == UINT64_C(14695981039346656037));

    // 2. 验证二进制含 0x00 字节的散列稳定性
    const unsigned char bin1[4] = {1, 0, 2, 0};
    const unsigned char bin2[4] = {1, 0, 2, 1};
    assert(fnv1a_hash_bytes(bin1, 4) != fnv1a_hash_bytes(bin2, 4));

    // 3. 验证不区分大小写的等价一致性契约
    const char *s1 = "Content-Length";
    const char *s2 = "content-length";
    const char *s3 = "CONTENT-LENGTH";
    assert(ascii_str_iequal(s1, s2));
    assert(ascii_str_iequal(s2, s3));
    assert(!ascii_str_iequal(s1, "Content-Type"));

    uint64_t h1 = fnv1a_hash_ascii_icase(s1);
    uint64_t h2 = fnv1a_hash_ascii_icase(s2);
    uint64_t h3 = fnv1a_hash_ascii_icase(s3);
    assert(h1 == h2 && h2 == h3);

    return 0;
}
```
