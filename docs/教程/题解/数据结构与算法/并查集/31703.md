# 31703 - 动态图连通分量计数与环路判定

## 题目描述

在无向图中，边的加入是一个动态流式过程。利用并查集实现无向图动态连通性跟踪器 `GraphConnectivityTracker`，实时维护连通分量总数并在加边时瞬间判定该边是否在图中引入了环路：

```c
#include <stdbool.h>
#include <stddef.h>

typedef struct GraphConnectivityTracker GraphConnectivityTracker;

GraphConnectivityTracker *gct_create(size_t vertex_count);
void gct_destroy(GraphConnectivityTracker *tracker);
bool gct_add_edge(
    GraphConnectivityTracker *tracker,
    size_t u,
    size_t v,
    bool *out_created_cycle
);
size_t gct_component_count(const GraphConnectivityTracker *tracker);
bool gct_is_connected(
    const GraphConnectivityTracker *tracker,
    size_t u,
    size_t v,
    bool *out_connected
);
```

要求：

1. 初始时图包含 $V$ 个孤立顶点，连通分量总数为 $V$。
2. 每当加入无向边 $(u, v)$ 时：
   - 若 $u$ 与 $v$ 已处于同一连通分量，说明该边属于多余边，在图中构成了一个简单环路，置 `*out_created_cycle = true`，连通分量数保持不变；
   - 若 $u$ 与 $v$ 分属不同分量，将两分量合并，置 `*out_created_cycle = false`，连通分量总数精确减少 1。
3. `gct_is_connected` 判定顶点 $u$ 与 $v$ 当前是否相互可达。
4. 顶点编号越界或指针非法时返回 `false`，且不得修改内部连通分量状态和输出对象。
5. 说明并查集环路检测机制与 Kruskal 最小生成树算法之间的内在联系。

## 解题思路

### 1. 动态图的并查集对偶模型

无向图的连通性本质上是顶点集合上的等价关系（具备自反性、对称性与传递性）。
并查集天生是维护等价类的最优数据结构：
- 图的每一个**连通分量（Connected Component）**严格对应并查集中的一棵不相交子树；
- 初始时全图无边，包含 $V$ 个独立的孤立连通分量，故 `component_count = vertex_count`；
- 每成功执行一次跨集合合并，两个不相交分量合二为一，全图分量数必恰好递减 1：
  $$\text{component\_count}_{\text{new}} = \text{component\_count}_{\text{old}} - 1$$

### 2. 环路判定的拓扑充分必要条件

对于新到达的一条边 $e = (u, v)$：
- 若在加边前，两顶点已经满足 $\text{find}(u) == \text{find}(v)$，根据图论定理，说明原图中已经存在一条连接 $u$ 与 $v$ 的简单路径 $P$；
- 此时在 $u$ 与 $v$ 之间新增边 $e$，边 $e$ 与既有路径 $P$ 必然闭合构成一个环（Cycle）。因此，**当且仅当新边的两端点在加入前已属于同一等价类时，该边在图中引入了环路**。
- 若两端点不属于同一等价类，这条边则充当连接两个分量的桥梁，绝不可能成环。

### 3. 与 Kruskal 最小生成树算法的联系

在贪心算法求解最小生成树（MST）时，Kruskal 算法的核心逻辑正是这一判定准则：
1. 将全图的所有边按权重升序排列；
2. 依次遍历每条边 $(u, v)$，调用并查集测试 $u$ 与 $v$ 是否连通；
3. 若未连通，说明此边安全，将其纳入生成树并合并两端点；
4. 若已连通，说明若选取此边将产生多余环路，果断舍弃此边。
并查集在近乎常数的时间内完成了环路剪枝，保证了 Kruskal 算法的高效性。

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct GraphConnectivityTracker GraphConnectivityTracker;

struct GraphConnectivityTracker {
    size_t *parent;
    size_t *rank;
    size_t vertex_count;
    size_t component_count;
};

GraphConnectivityTracker *gct_create(size_t vertex_count) {
    GraphConnectivityTracker *gct = malloc(sizeof *gct);
    if (gct == NULL) {
        return NULL;
    }
    gct->vertex_count = vertex_count;
    gct->component_count = vertex_count;
    gct->parent = NULL;
    gct->rank = NULL;
    if (vertex_count > 0) {
        if (vertex_count > SIZE_MAX / sizeof(size_t)) {
            free(gct);
            return NULL;
        }
        gct->parent = malloc(vertex_count * sizeof(size_t));
        gct->rank = calloc(vertex_count, sizeof(size_t));
        if (gct->parent == NULL || gct->rank == NULL) {
            free(gct->parent);
            free(gct->rank);
            free(gct);
            return NULL;
        }
        for (size_t i = 0; i < vertex_count; ++i) {
            gct->parent[i] = i;
        }
    }
    return gct;
}

void gct_destroy(GraphConnectivityTracker *tracker) {
    if (tracker == NULL) {
        return;
    }
    free(tracker->parent);
    free(tracker->rank);
    free(tracker);
}

static size_t find_root(GraphConnectivityTracker *gct, size_t x) {
    size_t root = x;
    while (root != gct->parent[root]) {
        root = gct->parent[root];
    }
    size_t curr = x;
    while (curr != root) {
        size_t next = gct->parent[curr];
        gct->parent[curr] = root;
        curr = next;
    }
    return root;
}

static size_t find_root_const(const GraphConnectivityTracker *gct, size_t x) {
    while (x != gct->parent[x]) {
        x = gct->parent[x];
    }
    return x;
}

bool gct_add_edge(
    GraphConnectivityTracker *tracker,
    size_t u,
    size_t v,
    bool *out_created_cycle
) {
    if (tracker == NULL || out_created_cycle == NULL ||
        u >= tracker->vertex_count || v >= tracker->vertex_count) {
        return false;
    }
    size_t root_u = find_root(tracker, u);
    size_t root_v = find_root(tracker, v);
    if (root_u == root_v) {
        *out_created_cycle = true;
        return true;
    }
    *out_created_cycle = false;
    if (tracker->rank[root_u] < tracker->rank[root_v]) {
        tracker->parent[root_u] = root_v;
    } else if (tracker->rank[root_u] > tracker->rank[root_v]) {
        tracker->parent[root_v] = root_u;
    } else {
        tracker->parent[root_v] = root_u;
        tracker->rank[root_u]++;
    }
    tracker->component_count--;
    return true;
}

size_t gct_component_count(const GraphConnectivityTracker *tracker) {
    if (tracker == NULL) {
        return 0;
    }
    return tracker->component_count;
}

bool gct_is_connected(
    const GraphConnectivityTracker *tracker,
    size_t u,
    size_t v,
    bool *out_connected
) {
    if (tracker == NULL || out_connected == NULL ||
        u >= tracker->vertex_count || v >= tracker->vertex_count) {
        return false;
    }
    *out_connected = (find_root_const(tracker, u) == find_root_const(tracker, v));
    return true;
}

int main(void) {
    GraphConnectivityTracker *gct = gct_create(5);
    assert(gct != NULL);
    assert(gct_component_count(gct) == 5);

    bool cycle = false;
    bool conn = false;

    assert(gct_add_edge(gct, 0, 1, &cycle) && !cycle);
    assert(gct_component_count(gct) == 4);

    assert(gct_add_edge(gct, 1, 2, &cycle) && !cycle);
    assert(gct_component_count(gct) == 3);

    assert(gct_add_edge(gct, 0, 2, &cycle) && cycle);
    assert(gct_component_count(gct) == 3);

    assert(gct_is_connected(gct, 0, 2, &conn) && conn);
    assert(gct_is_connected(gct, 0, 3, &conn) && !conn);

    gct_destroy(gct);
    return 0;
}
```

## 复杂度分析

- **时间复杂度**：
  - `gct_create`：初始化分配并设置数组，时间复杂度为 $O(V)$。
  - `gct_add_edge`：包含两次带路径压缩的寻根和一次按秩合并，单次加边的摊还时间复杂度为 $O(\alpha(V))$。处理 $E$ 条边的总时间严格为 $O(E \cdot \alpha(V))$。
  - `gct_component_count`：直接读取计数器，时间复杂度严格为 $O(1)$。
  - `gct_is_connected`：非破坏性只读寻根，单次时间复杂度为 $O(\alpha(V))$。
- **空间复杂度**：仅维护 `parent` 与 `rank` 两个连续数组，额外空间复杂度严格为 $O(V)$，与边数 $E$ 完全解耦。

## 延伸思考 / 模式总结

1. **图的稀疏性与空间解耦**：当图中的边数 $E$ 极其庞大（例如海量网络拓扑）时，传统的邻接矩阵需要 $O(V^2)$ 空间，甚至邻接链表也需要占用 $O(V + E)$ 内存；而并查集仅消耗固定 $O(V)$ 内存即可在线完成全图连通性与环路判定，是处理流式超大图数据的绝佳工具。
2. **基环树与森林判定**：如果一个无向图包含 $V$ 个顶点和 $V$ 条边，当且仅当并查集在处理最后一条边时产生且仅产生一次 `out_created_cycle == true`，该图恰好构成一个包含唯一环的**基环树（Pseudotree）**。并查集的环判定能力为特殊图结构的识别提供了极为强劲的底层支撑。
