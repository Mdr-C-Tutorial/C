# 35605 - 计数排序（非负整数前缀和位置确定，保证稳定性）

## 题目

计数排序（非负整数前缀和位置确定，保证稳定性）：

实现基于前缀和定位的稳定计数排序（Counting Sort）：

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

typedef struct {
    int64_t key;
    uint64_t payload;
} SortRecord;

bool counting_sort_stable(
    SortRecord *items,
    size_t count,
    uint32_t max_key
);
```

要求：

1. 统计每个键值频次后，将其原地累加转换为前缀和数组；
2. 解释并证明：为什么在向临时输出数组回填元素时，必须**从后向前逆序遍历**原数组才能保证相同键记录的稳定性；
3. 参数校验与内存分配失败时返回 `false`，时间复杂度满足严格的 $\Theta(n + k)$（$k$ 为键值范围），额外空间为 $O(n + k)$。

## 解题思路

### 1. 计数排序与前缀和定位原理

计数排序是一种非比较型排序算法。当输入元素的键均为介于 $[0, max\_key]$ 内的整数时，算法通过统计每个键出现的绝对频次直接计算出各元素的最终输出槽位：
1. **频次统计**：创建大小为 $k = max\_key + 1$ 的计数器数组 `counts`，统计每个键出现的次数；
2. **前缀和转换**：对计数器数组计算前缀和：
   $$counts[i] \leftarrow \sum_{j=0}^{i} counts[j]$$
   此时，$counts[k]$ 的数学含义为：**在排序后的最终数组中，所有键值小于等于 $k$ 的元素总数**。换言之，键值为 $k$ 的最后一个元素应该被安置在下标 $counts[k] - 1$ 处。

### 2. 逆序回填保证稳定性的形式化证明

设原输入数组中有两个相同键的记录：$A$ 位于下标 $p$，$B$ 位于下标 $q$（其中 $p < q$，且 $A.key = B.key = k$）。
- 若我们**从后向前（$i$ 从 $count - 1$ 逆序递减至 $0$）**扫描输入数组：
  - 算法首先遇到下标靠后的记录 $B$；
  - 此时计数器指示位置为 $counts[k] - 1$，$B$ 被存入输出数组的该位置，随后计数器自减为 $counts[k] - 2$；
  - 随后算法在更早的下标处遇到记录 $A$；
  - 此时 $A$ 被存入输出数组的更小下标位置（$\le counts[k] - 2$）。
  - 因此在输出数组中，$A$ 的下标严格小于 $B$ 的下标，**两者相对先后顺序与输入完全一致，稳定性得证**！
- 反之，若从前向后正序扫描，先遇到的 $A$ 会被放入较小下标，后遇到的 $B$ 也会递增放入更大下标（或者若用自减则次序彻底颠倒）。因此，前缀和方案必须配合**从后向前逆序填充**才能保证严格稳定。

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct {
    int64_t key;
    uint64_t payload;
} SortRecord;

bool counting_sort_stable(SortRecord *items, size_t count, uint32_t max_key) {
    if (count <= 1) {
        return true;
    }
    if (items == NULL) {
        return false;
    }

    size_t num_buckets = (size_t)max_key + 1;
    size_t *counts = calloc(num_buckets, sizeof(size_t));
    SortRecord *output = malloc(count * sizeof(SortRecord));
    if (counts == NULL || output == NULL) {
        free(counts);
        free(output);
        return false;
    }

    /* 1. 频次统计 */
    for (size_t i = 0; i < count; ++i) {
        if (items[i].key < 0 || (uint64_t)items[i].key > max_key) {
            free(counts);
            free(output);
            return false;
        }
        counts[(size_t)items[i].key]++;
    }

    /* 2. 前缀和计算：counts[i] 表示小于等于 i 的元素总数 */
    for (size_t i = 1; i < num_buckets; ++i) {
        counts[i] += counts[i - 1];
    }

    /* 3. 逆序回填：从后向前遍历保证严格稳定性 */
    for (size_t i = count; i > 0; --i) {
        size_t k = (size_t)items[i - 1].key;
        output[counts[k] - 1] = items[i - 1];
        counts[k]--;
    }

    /* 4. 将排序结果写回原数组 */
    memcpy(items, output, count * sizeof(SortRecord));

    free(counts);
    free(output);
    return true;
}

int main(void) {
    /* 1. 稳定性验证：相同 key 的记录必须保持输入先后顺序 */
    SortRecord data[] = {
        {2, 101}, {0, 201}, {2, 102}, {1, 301}, {2, 103}, {0, 202}
    };
    assert(counting_sort_stable(data, 6, 2));

    /* 检查 key == 0 的两项相对顺序 */
    assert(data[0].key == 0 && data[0].payload == 201);
    assert(data[1].key == 0 && data[1].payload == 202);

    /* 检查 key == 1 的项 */
    assert(data[2].key == 1 && data[2].payload == 301);

    /* 检查 key == 2 的三项相对顺序 */
    assert(data[3].key == 2 && data[3].payload == 101);
    assert(data[4].key == 2 && data[4].payload == 102);
    assert(data[5].key == 2 && data[5].payload == 103);

    /* 2. 越界输入契约校验 */
    SortRecord bad[] = {{5, 1}};
    assert(!counting_sort_stable(bad, 1, 3)); // 5 > max_key(3) 校验失败

    /* 3. 空输入测试 */
    assert(counting_sort_stable(NULL, 0, 10));

    printf("All counting_sort_stable tests passed successfully.\n");
    return 0;
}
```

## 复杂度分析

- **时间复杂度**：$\Theta(n + k)$。包含一次 $n$ 步频次统计、一次 $k$ 步前缀和累加、一次 $n$ 步逆序回填和一次内存复制。当 $k = O(n)$ 时，整体达到线性时间 $\Theta(n)$。
- **空间复杂度**：$\Theta(n + k)$。需要大小为 $k$ 的计数器数组和大小为 $n$ 的临时输出缓冲区。

## 延伸思考 / 模式总结

计数排序是突破比较排序 $\Omega(n \log n)$ 理论下界的一柄利剑。其“**频次统计 $\to$ 前缀和定位 $\to$ 逆序稳定回填**”的三部曲范式，构成了基数排序（Radix Sort）不可或缺的底层稳定子过程。
