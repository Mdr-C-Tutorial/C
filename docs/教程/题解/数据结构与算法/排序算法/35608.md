# 35608 - 外部排序（多路平衡归并与败者树框架）

## 题目

外部排序（多路平衡归并与败者树框架）：

在海量数据外存排序中，内存无法一次性容纳全部记录。实现 $k$ 路归并败者树（Loser Tree）：

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

typedef struct {
    const int64_t *data;
    size_t size;
    size_t cursor;
} MergeRun;

bool lt_merge(
    MergeRun *runs,
    size_t k,
    int64_t *out_merged,
    size_t total_count
);
```

要求：

1. 形式化说明为什么使用传统选择树/顺序查找需要 $O(k)$ 选出最小元素，而败者树通过自底向上沿路径调整仅需 $\lceil \log_2 k \rceil$ 次比较；
2. 构造支持任意 $k$ 路（补齐为 2 的幂次 $K$）的败者树结构，`tree[0]` 始终维护全局胜者；
3. 模拟 $k$ 个已排好序的初始归并段（Runs）合并为全局有序序列，时间复杂度达到 $O(N \log k)$（$N$ 为总记录数）。

## 解题思路

### 1. 外存排序与 $k$ 路平衡归并

当待排序数据量 $N$ 远超出内存容量 $M$ 时，必须借助外部存储（磁盘/SSD）：
- **第一阶段（置换选择/初始段生成）**：在内存中分批将数据排成局部有序的“归并段（Initial Runs）”，写回磁盘。设共有 $k$ 个归并段；
- **第二阶段（多路归并）**：若采用两路归并，需要扫描全部数据 $\lceil \log_2 k \rceil$ 遍（即磁盘 I/O 读写次数与 $\log_2 k$ 成正比）。为了减少极端昂贵的磁盘 I/O 遍数，工业界普遍采用 **$k$ 路平衡归并**，使得 I/O 趟数急剧减少为 $\lceil \log_k k \rceil = 1$ 趟！

### 2. 为什么选择败者树（Loser Tree）而非胜者树？

在 $k$ 路归并中，每输出一个元素，就必须从其所在的归并段补充一个新元素，并重新竞争出下一个全局最小值。
- **简单线性比较**：在 $k$ 个候选中线性扫描需 $k - 1$ 次比较，输出 $N$ 个元素总共需要 $O(N \cdot k)$ 次比较。当 $k$ 较大时（如 $k = 1024$），CPU 比较开销会反客为主成为新瓶颈；
- **胜者树（Winner Tree）**：每个非叶节点记录该局的胜者（较小值）。当新元素从叶节点向上调整时，需要与其**兄弟节点**比较，因此每上一层必须同时访问当前节点与兄弟节点两个对象；
- **败者树（Loser Tree）**：败者树是非叶节点记录比赛**失败者**（较大者）的完全二叉树，而比赛的**胜利者向上继续晋级**。
  在自底向上调整过程中，新晋胜者只需**与当前父节点记录的先前败者比较一次**：较小者继续向上作为新胜者晋级，较大者作为新败者留在当前节点。整个沿树上升的路径上，**每层严格仅需 1 次比较**，完全消除了读取兄弟节点的开销，流水线和寄存器利用效率显著更高。

### 3. 算法实现结构

- 将实际路数 $k$ 向上补齐为 2 的幂次 $K$；
- 败者树大小为 $K$：`tree[1..K-1]` 记录各场比赛的败者归并段编号，`tree[0]` 记录全局最终胜者；
- 若某个归并段已读取完毕，其键值虚拟标记为正无穷大 `INT64_MAX`，使其自动沦为永久败者；
- 每次从 `tree[0]` 提取胜者元素并追加到输出序列，随后将该段游标前进 1 位并调用 `lt_adjust`，耗时严格为 $\Theta(\log_2 K)$。

## C 语言实现

```c
#include <assert.h>
#include <inttypes.h>
#include <limits.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct {
    const int64_t *data;
    size_t size;
    size_t cursor;
} MergeRun;

typedef struct {
    size_t k;
    size_t K;
    size_t *tree;
    MergeRun *runs;
    bool initializing;
} LoserTree;

static int64_t lt_get_val(const LoserTree *lt, size_t run_idx) {
    if (run_idx == lt->K) {
        return lt->initializing ? INT64_MIN : INT64_MAX;
    }
    if (run_idx >= lt->k || lt->runs[run_idx].cursor >= lt->runs[run_idx].size) {
        return INT64_MAX;
    }
    return lt->runs[run_idx].data[lt->runs[run_idx].cursor];
}

static void lt_adjust(LoserTree *lt, size_t s) {
    size_t t = (s + lt->K) / 2;
    while (t > 0) {
        if (lt_get_val(lt, s) > lt_get_val(lt, lt->tree[t])) {
            size_t tmp = s;
            s = lt->tree[t];
            lt->tree[t] = tmp;
        }
        t /= 2;
    }
    lt->tree[0] = s; /* tree[0] 保存最终胜者 */
}

bool lt_merge(MergeRun *runs, size_t k, int64_t *out_merged, size_t total_count) {
    if (runs == NULL || out_merged == NULL || k == 0) {
        return false;
    }

    LoserTree lt;
    lt.k = k;
    lt.runs = runs;

    /* 向上补齐为 2 的幂次 */
    size_t K = 1;
    while (K < k) {
        K <<= 1;
    }
    lt.K = K;

    lt.tree = malloc(K * sizeof(size_t));
    if (lt.tree == NULL) {
        return false;
    }

    lt.initializing = true;
    for (size_t i = 0; i < K; ++i) {
        lt.tree[i] = K;
    }
    for (size_t i = K; i > 0; --i) {
        lt_adjust(&lt, i - 1);
    }
    lt.initializing = false;

    size_t out_idx = 0;
    while (out_idx < total_count) {
        size_t win = lt.tree[0];
        if (win >= k || runs[win].cursor >= runs[win].size) {
            break;
        }
        out_merged[out_idx++] = runs[win].data[runs[win].cursor++];
        lt_adjust(&lt, win);
    }

    free(lt.tree);
    return out_idx == total_count;
}

int main(void) {
    /* 3 个初始归并段模拟归并测试 */
    int64_t r1[] = {1, 5, 9};
    int64_t r2[] = {2, 6, 10};
    int64_t r3[] = {3, 7, 11};
    MergeRun runs[] = {
        {r1, 3, 0},
        {r2, 3, 0},
        {r3, 3, 0}
    };
    int64_t merged[9] = {0};

    assert(lt_merge(runs, 3, merged, 9));

    int64_t expected[] = {1, 2, 3, 5, 6, 7, 9, 10, 11};
    for (size_t i = 0; i < 9; ++i) {
        assert(merged[i] == expected[i]);
    }

    /* 空输入校验保护 */
    assert(!lt_merge(NULL, 0, merged, 9));

    printf("All LoserTree external multi-way merge tests passed successfully.\n");
    return 0;
}
```

## 复杂度分析

- **时间复杂度**：
  - 构建败者树：$O(k \log k)$；
  - 归并提取：每提取一个元素执行一次树高调整，耗时 $\Theta(\log k)$。对于全量 $N$ 个记录，总时间复杂度为严格的 $\Theta(N \log k)$。
- **空间复杂度**：$\Theta(K) = O(k)$。仅需常数阶 $O(k)$ 的树节点内存存储败者段编号，完全与总数据量 $N$ 无关，极其契合外存流式归并。

## 延伸思考 / 模式总结

败者树是外部排序算法的经典明珠。在分布式系统（如 MapReduce 的 Shuffle-Sort 阶段）与数据库引擎（如 PostgreSQL、SQLite 的 External Merge Sort）中，多路平衡归并配合败者树，以最小的 CPU 指令开销将分散于不同磁盘分区的海量数据高效汇聚为单一有序流。
