# 35606 - 针对 32 位无符号整数的低位优先基数排序（LSD Radix Sort）

## 题目描述

针对 32 位无符号整数的低位优先基数排序（LSD Radix Sort）：

实现无符号 32 位整型的高性能低位优先基数排序：

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

bool radix_sort_u32(uint32_t *items, size_t count);
```

要求：

1. 采用以 256 为基数（按字节切分，每轮处理 8 个二进制位）的 4 轮稳定计数排序子过程；
2. 证明低位优先基数排序基于子排序稳定性的正确性（数学归纳法）；
3. 原地利用单个大小为 `count` 的临时缓冲区在两数组间往复切换，时间复杂度为严格的 $\Theta(4 \cdot (n + 256)) = \Theta(n)$，空间复杂度为 $O(n)$。

## 解题思路

### 1. 低位优先（LSD）基数排序原理

对于 32 位无符号整数，每个数可以视为 4 个以 256 为基数的“数位（Digit）”构成的序列：$D_3 D_2 D_1 D_0$，其中每个数位 $D_k = (x \gg (8k)) \ \& \ \text{0xFF}$ 取值范围为 $[0, 255]$。
LSD 基数排序从最低位 $D_0$ 开始，逐轮向最高位 $D_3$ 推进，共执行 4 轮基于单字节的**稳定计数排序**。

### 2. 正确性归纳证明

**数学归纳法**：
- **归纳命题**：在第 $p$ 轮（$p = 0, 1, 2, 3$）排序结束后，数组关于低 $p + 1$ 个字节组成的数值严格有序。
- **基底（$p = 0$）**：第一轮对最低位字节 $D_0$ 执行稳定计数排序，显然数组关于最低字节有序。
- **归纳步**：假设在第 $p$ 轮后，数组关于低 $p + 1$ 个字节已有序。
  在第 $p + 1$ 轮中，我们按第 $p + 1$ 位字节进行稳定计数排序：
  - 若两个数在第 $p + 1$ 位上的字节值不同，计数排序直接将字节较小的数排在前面，符合高位优先决定大小的规则；
  - 若两个数在第 $p + 1$ 位上的字节值相同，根据**计数排序的稳定性**，它们在第 $p + 1$ 轮排序后将严格保持第 $p$ 轮结束时的先后次序。而由归纳假设，它们在第 $p$ 轮结束时已经关于低位有序！
  因此，数组在第 $p + 1$ 轮后必然关于前 $p + 2$ 个字节完全有序。
- **结论**：4 轮结束后，数组关于全部 32 个二进制位完全有序。

### 3. 工程优化技巧

- **基数选取 256**：8 个二进制位恰好对应一个硬件字节 `uint8_t`，位运算提取 `(x >> shift) & 0xFF` 极为高效；且桶数组大小仅需 $256 \times \text{sizeof(size\_t)} = 2048$ 字节，能完全驻留在 CPU L1 数据缓存中，几乎零 Cache Miss。
- **双缓冲乒乓操作**：只需分配一个大小为 `count` 的辅助数组，在 4 轮迭代中让数据在输入数组与临时数组间往复流动，避免反复申请内存。

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

bool radix_sort_u32(uint32_t *items, size_t count) {
    if (count <= 1) {
        return true;
    }
    if (items == NULL) {
        return false;
    }

    uint32_t *temp = malloc(count * sizeof(uint32_t));
    if (temp == NULL) {
        return false;
    }

    /* 4 轮迭代：每轮处理一个字节 (8 bits)，基数为 256 */
    for (size_t shift = 0; shift < 32; shift += 8) {
        size_t buckets[256] = {0};

        /* 1. 统计当前字节频次 */
        for (size_t i = 0; i < count; ++i) {
            uint8_t byte = (uint8_t)((items[i] >> shift) & 0xFF);
            buckets[byte]++;
        }

        /* 2. 计算前缀和确定位置 */
        for (size_t i = 1; i < 256; ++i) {
            buckets[i] += buckets[i - 1];
        }

        /* 3. 逆序回填保证子过程稳定性 */
        for (size_t i = count; i > 0; --i) {
            uint8_t byte = (uint8_t)((items[i - 1] >> shift) & 0xFF);
            temp[buckets[byte] - 1] = items[i - 1];
            buckets[byte]--;
        }

        /* 4. 拷贝回 items，为下一轮更高字节的排序做准备 */
        memcpy(items, temp, count * sizeof(uint32_t));
    }

    free(temp);
    return true;
}

int main(void) {
    /* 1. 常规数据与多字节跨度测试 */
    uint32_t arr[] = {170, 45, 75, 90, 802, 24, 2, 66};
    size_t n = sizeof(arr) / sizeof(arr[0]);
    assert(radix_sort_u32(arr, n));
    for (size_t i = 1; i < n; ++i) {
        assert(arr[i - 1] <= arr[i]);
    }

    /* 2. 包含 0 与 UINT32_MAX 极端大数测试 */
    uint32_t ext[] = {UINT32_MAX, 0, 1000000, 42, UINT32_MAX - 1, 1};
    assert(radix_sort_u32(ext, 6));
    assert(ext[0] == 0);
    assert(ext[1] == 1);
    assert(ext[2] == 42);
    assert(ext[3] == 1000000);
    assert(ext[4] == UINT32_MAX - 1);
    assert(ext[5] == UINT32_MAX);

    /* 3. 空数组与单元素测试 */
    assert(radix_sort_u32(NULL, 0));
    uint32_t single[] = {888};
    assert(radix_sort_u32(single, 1) && single[0] == 888);

    printf("All radix_sort_u32 tests passed successfully.\n");
    return 0;
}
```

## 复杂度分析

- **时间复杂度**：$\Theta(4 \cdot (n + 256)) = \Theta(n)$。在 32 位机器字长下，固定扫描 4 轮，每轮操作与 $n$ 成严格正比，实际运行速度往往远超基于比较的 $O(n \log n)$ 算法。
- **空间复杂度**：$\Theta(n)$。需要一个长度为 $n$ 的辅助数组用于缓冲，以及 $256 \times \text{sizeof(size\_t)}$ 的常数阶桶空间。

## 延伸思考 / 模式总结

基数排序是“非比较排序之王”。为什么是低位优先（LSD）而不是高位优先（MSD）？
MSD（从最高位开始）会将数据切分成大量相互独立的不等长子桶，需要递归处理每个子桶，产生深层的递归调用和极差的内存局部性；而 LSD 每轮始终对**整个数组做连续流式扫描**，内存预取友好度极高，是现代 GPU 和多核 CPU 并行排序的核心实现技术。
