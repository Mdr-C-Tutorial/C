# 35101 - 霍尔三元组前置/后置条件断言与防溢出加减契约验证

## 题目描述

使用霍尔逻辑（Hoare Logic）的断言规范为 64 位有符号整数的安全加法与减法设计前置条件（Precondition）与后置条件（Postcondition）契约，并实现防溢出运算函数：

```c
#include <stdbool.h>
#include <stdint.h>

bool safe_add_i64(int64_t a, int64_t b, int64_t *out);
bool safe_sub_i64(int64_t a, int64_t b, int64_t *out);
```

要求：

1. 用形式化霍尔三元组 $\{P\}\ S\ \{Q\}$ 表述函数契约。
2. 当且仅当运算结果未超出 `[INT64_MIN, INT64_MAX]` 且 `out != NULL` 时写入正确计算结果并返回 `true`。
3. 溢出时不触发 C 语言有符号整数溢出的未定义行为（Undefined Behavior），保持输出指针指向的对象原值不变并返回 `false`。
4. 编写完备的边界值单元测试断言。

## 解题思路

### 1. 霍尔逻辑与程序契约

霍尔三元组的一般形式为：

$$\{P\}\ S\ \{Q\}$$

其中 $P$ 为前置断言，$S$ 为待执行程序段，$Q$ 为后置断言。其语义为：若在满足 $P$ 的状态下执行 $S$ 且 $S$ 终止，则终止状态必然满足 $Q$。

对于带布尔返回值的安全防溢出函数：
- **安全加法契约**：
  - 前置条件 $P_{\text{add}} \equiv \text{true}$（对任意输入操作数 $a, b \in [\text{INT64\_MIN}, \text{INT64\_MAX}]$ 均合法调用）。
  - 后置条件 $Q_{\text{add}}$：
    - 若 $\text{out} == \text{NULL}$，返回 `false`。
    - 若 $\text{out} \ne \text{NULL}$ 且 $\text{INT64\_MIN} \le a + b \le \text{INT64\_MAX}$，返回 `true` 且 $*\text{out} = a + b$。
    - 若 $a + b > \text{INT64\_MAX}$ 或 $a + b < \text{INT64\_MIN}$，返回 `false` 且 $*\text{out}$ 保持调用前的值不变。
- **安全减法契约**同理。

### 2. 避免未定义行为的代数判定

根据 ISO C17 标准第 6.5 节规定，有符号整数运算溢出属于未定义行为（Undefined Behavior, UB），编译器有权假定溢出永不发生并优化掉溢出检查（如直接将 `a + b < a` 优化为 `false`）。因此，判定逻辑必须在执行实际加法或减法之前完成：

- **加法上溢判定**：当 $b > 0$ 时，若 $a > \text{INT64\_MAX} - b$，则发生上溢。由于 $b > 0$，$\text{INT64\_MAX} - b$ 不会发生溢出，比较完全合法。
- **加法下溢判定**：当 $b < 0$ 时，若 $a < \text{INT64\_MIN} - b$，则发生下溢。由于 $b < 0$，$-b > 0$，$\text{INT64\_MIN} - b$ 在代数上为负数加上正数，严格落在 $[\text{INT64\_MIN} + 1, -1]$ 内，计算安全。
- **减法溢出判定**：
  - 当 $b < 0$ 时，减负数相当于加正数，若 $a > \text{INT64\_MAX} + b$ 则发生上溢。
  - 当 $b > 0$ 时，若 $a < \text{INT64\_MIN} + b$ 则发生下溢。

## C 语言实现

```c
#include <assert.h>
#include <limits.h>
#include <stdbool.h>
#include <stdint.h>
#include <stdio.h>

bool safe_add_i64(int64_t a, int64_t b, int64_t *out) {
    if (out == NULL) {
        return false;
    }
    if ((b > 0 && a > INT64_MAX - b) ||
        (b < 0 && a < INT64_MIN - b)) {
        return false;
    }
    *out = a + b;
    return true;
}

bool safe_sub_i64(int64_t a, int64_t b, int64_t *out) {
    if (out == NULL) {
        return false;
    }
    if ((b < 0 && a > INT64_MAX + b) ||
        (b > 0 && a < INT64_MIN + b)) {
        return false;
    }
    *out = a - b;
    return true;
}

int main(void) {
    int64_t res = 0;

    /* 正常加法与边界验证 */
    assert(safe_add_i64(100, 200, &res) && res == 300);
    assert(safe_add_i64(INT64_MAX, 0, &res) && res == INT64_MAX);
    assert(safe_add_i64(INT64_MIN, 0, &res) && res == INT64_MIN);
    assert(safe_add_i64(INT64_MIN, 1, &res) && res == INT64_MIN + 1);

    /* 加法溢出验证（确保原值不变） */
    res = 42;
    assert(!safe_add_i64(INT64_MAX, 1, &res) && res == 42);
    assert(!safe_add_i64(INT64_MIN, -1, &res) && res == 42);
    assert(!safe_add_i64(INT64_MAX, INT64_MAX, &res) && res == 42);

    /* 正常减法与边界验证 */
    assert(safe_sub_i64(200, 50, &res) && res == 150);
    assert(safe_sub_i64(INT64_MIN, 0, &res) && res == INT64_MIN);
    assert(safe_sub_i64(INT64_MAX, 1, &res) && res == INT64_MAX - 1);

    /* 减法溢出验证 */
    res = 99;
    assert(!safe_sub_i64(INT64_MIN, 1, &res) && res == 99);
    assert(!safe_sub_i64(INT64_MAX, -1, &res) && res == 99);

    /* 空指针契约验证 */
    assert(!safe_add_i64(10, 20, NULL));
    assert(!safe_sub_i64(10, 20, NULL));

    printf("All safe_add_i64 and safe_sub_i64 tests passed.\n");
    return 0;
}
```

## 复杂度分析

- **时间复杂度**：$\Theta(1)$。判定逻辑仅包含少量的简单整型比较与算术运算。
- **空间复杂度**：$\Theta(1)$。仅使用常数个局部存储单元，无动态分配。

## 延伸思考 / 模式总结

在形式化算法规约中，必须区分两类契约处理机制：
1. **防御性编程（Defensive Programming）**：通过返回值指示运算成功与否，适合边界受外部输入驱动的场景。
2. **形式化前置条件断言（Assert-based Contracts）**：通过静态分析或断言确保输入数据先验合法，适合模块内部严密的调用链。

例如在某些算法问题中，计算可以通过纯数学技巧先化简为闭式解（如极值中点问题中 $n$ 个点横坐标严格递增时至少产生 $2n - 3$ 个互不重合的中点；或环形对称博弈中当 $n \ge 3$ 时后手通过模仿策略必胜），程序本身直接输出结果；但在底层算术实现中，无论业务逻辑如何简化，底层的基本算术操作必须始终符合霍尔契约，杜绝静默溢出引发的逻辑灾难。
