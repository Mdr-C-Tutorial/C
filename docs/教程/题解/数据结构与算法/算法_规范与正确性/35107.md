# 35107 - 基于形式化前置契约的除法与模安全防崩封装

## 题目

基于形式化前置契约实现 64 位有符号整数的安全带余除法与模运算封装：

```c
#include <stdbool.h>
#include <stdint.h>

bool safe_div_mod_i64(
    int64_t a,
    int64_t b,
    int64_t *out_quotient,
    int64_t *out_remainder
);
```

要求：

1. 形式化分析除法可能触发的未定义行为（除以零、`INT64_MIN / -1` 溢出）。
2. 严格遵循 C17 标准向零截断（Truncation toward zero）语义，确保后置条件恒满足代数恒等式 $a = q \cdot b + r$ 以及 $|r| < |b|$。
3. 深入对比防御性契约检查（返回 `bool` 状态码）与断言宏（`assert`）在软件工程抽象层中的适用场景。

## 解题思路

### 1. C 语言带余除法的陷阱与未定义行为

在 ISO C17 标准（6.5.5 Multiplicative operators）中，除法运算符 `/` 与模运算符 `%` 在以下两种情况下属于未定义行为（UB）：
1. **除数为零**（$b = 0$）：绝大多数硬件平台（如 x86 的 `idiv` 指令）会抛出除零硬件异常（Fault），直接导致操作系统向进程发送 `SIGFPE` 信号终止程序；
2. **符号溢出**（$a == \text{INT64\_MIN} \land b == -1$）：在补码表示下，$\text{INT64\_MIN} = -2^{63}$，其商为 $2^{63} = \text{INT64\_MAX} + 1$，无法存入 64 位有符号整型。在 x86 架构下，`idiv` 指令触发整型溢出异常同样会引发 `SIGFPE` 崩溃。

### 2. C17 标准向零截断语义

C99 之后的 C 标准明确规定：
- 整数商 $a / b$ 的结果为代数商向零截断（Truncate toward zero，舍去小数部分）；
- 余数满足欧几里得恒等式：
  $$(a / b) \times b + a \bmod b = a$$
- 这导致余数的符号严格与被除数 $a$ 的符号一致（当余数非零时），且 $|r| < |b|$。

### 3. 契约设计与防御策略

- **前置契约**：
  检查输出指针有效性 `out_quotient != NULL && out_remainder != NULL`；
  拦截非法输入条件：$b == 0$ 或 $(a == \text{INT64\_MIN} \land b == -1)$。若触发，直接返回 `false` 且不修改输出对象。
- **后置保证**：
  若返回 `true`，通过静态代数恒等式断言 $a == q \cdot b + r$ 及 $|r| < |b|$。

## C 语言实现

```c
#include <assert.h>
#include <inttypes.h>
#include <limits.h>
#include <stdbool.h>
#include <stdint.h>
#include <stdio.h>

bool safe_div_mod_i64(
    int64_t a,
    int64_t b,
    int64_t *out_quotient,
    int64_t *out_remainder
) {
    /* 前置契约：指针必须非空 */
    if (out_quotient == NULL || out_remainder == NULL) {
        return false;
    }
    /* 前置契约：防除零未定义行为 */
    if (b == 0) {
        return false;
    }
    /* 前置契约：防 INT64_MIN / -1 有符号溢出硬件陷阱 */
    if (a == INT64_MIN && b == -1) {
        return false;
    }

    int64_t q = a / b;
    int64_t r = a % b;

    /* 后置条件断言：C 标准代数恒等式 */
    assert(a == q * b + r);
    /* 余数绝对值严格小于除数绝对值 */
    uint64_t abs_r = (r < 0) ? (0ULL - (uint64_t)r) : (uint64_t)r;
    uint64_t abs_b = (b < 0) ? (0ULL - (uint64_t)b) : (uint64_t)b;
    assert(abs_r < abs_b);

    *out_quotient = q;
    *out_remainder = r;
    return true;
}

int main(void) {
    int64_t q = 0, r = 0;

    /* 正数除法：7 / 3 = 2 余 1 */
    assert(safe_div_mod_i64(7, 3, &q, &r) && q == 2 && r == 1);

    /* 负被除数向零截断：-7 / 3 = -2 余 -1 */
    assert(safe_div_mod_i64(-7, 3, &q, &r) && q == -2 && r == -1);

    /* 负除数：7 / -3 = -2 余 1 */
    assert(safe_div_mod_i64(7, -3, &q, &r) && q == -2 && r == 1);

    /* 双负数：-7 / -3 = 2 余 -1 */
    assert(safe_div_mod_i64(-7, -3, &q, &r) && q == 2 && r == -1);

    /* 整除边界：6 / 3 = 2 余 0 */
    assert(safe_div_mod_i64(6, 3, &q, &r) && q == 2 && r == 0);

    /* 边界极端值防御：除以 0 必须安全拦截 */
    assert(!safe_div_mod_i64(10, 0, &q, &r));

    /* 极端溢出防御：INT64_MIN / -1 必须安全拦截，防止 SIGFPE */
    assert(!safe_div_mod_i64(INT64_MIN, -1, &q, &r));

    /* 空指针契约防御 */
    assert(!safe_div_mod_i64(10, 2, NULL, &r));
    assert(!safe_div_mod_i64(10, 2, &q, NULL));

    printf("All safe_div_mod_i64 tests passed successfully.\n");
    return 0;
}
```

## 复杂度分析

- **时间复杂度**：$\Theta(1)$。仅执行单次硬件除法指令与边界判断。
- **空间复杂度**：$\Theta(1)$。无动态内存分配。

## 延伸思考 / 模式总结

在系统级 C 语言开发中，除法与求模运算具有天然的不对称脆弱性。许多高级语言（如 Python）采用底整除（Floor Division），即商向负无穷截断，余数符号与除数一致；而 C17 采用向零截断。无论是哪种数学定义，算法设计者都必须在接口边界处筑牢前置契约壁垒，防患未定义行为于未然。
