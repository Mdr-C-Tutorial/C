# 35403 - 最短生产时间（二分答案求极值）

## 题目描述

有若干台机器并行生产同一种产品。第 `i` 台机器每生产一件产品需要 `machine_times[i]` 个时间单位。实现：

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

bool minimum_production_time(
    const uint64_t *machine_times,
    size_t machine_count,
    uint64_t target,
    uint64_t *out_time
);
```

要求：

1. 返回生产至少 `target` 件产品所需的最短时间。
2. `target` 为 0 时结果为 0，此时机器数组可以为空。
3. `target` 大于 0 时至少有一台机器，并且每个生产时间都必须大于 0。
4. 不能通过“最慢或最快机器耗时乘以目标件数”直接构造可能溢出的上界。
5. 累加各机器产量时不得溢出；达到目标后应立即停止累加。
6. 参数无效或答案不能用 `uint64_t` 表示时返回 `false`，并保持输出对象不变。
7. 使用答案二分，时间复杂度为 $O(m\log T)$，其中 $m$ 为机器数量，$T$ 为答案。

## 解题思路

### 1. 判定函数的单调性与答案二分

设在时间 $t$ 内，机器 $i$ 可独立生产的数量为 $\lfloor t / \text{machine\_times}[i] \rfloor$。则所有机器在时间 $t$ 内的总产能为：

$$f(t) = \sum_{i=0}^{m-1} \left\lfloor \frac{t}{\text{machine\_times}[i]} \right\rfloor$$

由于每个单项 $\lfloor t / t_i \rfloor$ 均关于 $t$ 单调非递减，其和函数 $f(t)$ 也是关于 $t$ 的单调非递减函数。
定义单调谓词：

$$P(t) \equiv (f(t) \ge \text{target})$$

若 $P(t_1) = \text{true}$，则对任意 $t_2 \ge t_1$ 恒有 $P(t_2) = \text{true}$。因此可行解构成了半开无限区间 $[T^*, +\infty)$，求最小时间 $T^*$ 完全等价于在时间轴上求谓词 $P(t)$ 的 `lower_bound`！

### 2. 工程健壮性与防溢出设计

1. **安全倍增寻找搜索上界 `high`**：
   直接用“最大机器耗时 $\times$ 目标件数”极易超出 `UINT64_MAX`。稳健方案是从 $high = 1$ 开始倍增探查：只要 $P(high) = \text{false}$，令 $high \leftarrow \min(2 \times high, \text{UINT64\_MAX})$。由于 $T^*$ 有限，至多经过 $\lceil \log_2 T^* \rceil$ 次倍增即可锁定可行上界。
2. **饱和累加防止加法溢出**：
   在计算各机器产能和时，一旦累计产量满足 $amount \ge target - produced$，说明当前时间已足以完成目标，立即提前返回 `true`，杜绝继续相加导致无符号 64 位整数回绕。

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>

static bool can_produce(
    const uint64_t *machine_times,
    size_t machine_count,
    uint64_t time,
    uint64_t target
) {
    uint64_t produced = 0;
    for (size_t i = 0; i < machine_count; ++i) {
        uint64_t amount = time / machine_times[i];
        /* 饱和判定：防止 produced 累加发生无符号溢出 */
        if (amount >= target - produced) {
            return true;
        }
        produced += amount;
    }
    return produced >= target;
}

bool minimum_production_time(
    const uint64_t *machine_times,
    size_t machine_count,
    uint64_t target,
    uint64_t *out_time
) {
    if (out_time == NULL) {
        return false;
    }
    if (target == 0) {
        *out_time = 0;
        return true;
    }
    if (machine_count == 0 || machine_times == NULL) {
        return false;
    }
    for (size_t i = 0; i < machine_count; ++i) {
        if (machine_times[i] == 0) {
            return false;
        }
    }

    /* 指数级翻倍寻找有效上界，规避直接相乘导致的 UINT64 溢出 */
    uint64_t high = 1;
    while (!can_produce(machine_times, machine_count, high, target)) {
        if (high == UINT64_MAX) {
            return false;
        }
        high = (high > UINT64_MAX / 2) ? UINT64_MAX : (high * 2);
    }

    /* 在区间 [low, high] 上对单调谓词执行二分下界查找 */
    uint64_t low = 0;
    while (low < high) {
        uint64_t mid = low + (high - low) / 2;
        if (can_produce(machine_times, machine_count, mid, target)) {
            high = mid;
        } else {
            low = mid + 1;
        }
    }

    *out_time = low;
    return true;
}

int main(void) {
    uint64_t machines[] = {2, 3, 7};
    uint64_t ans = 0;

    /*
     * 机器耗时 2, 3, 7，目标件数 8：
     * 时间 8 时：8/2 + 8/3 + 8/7 = 4 + 2 + 1 = 7 件 < 8
     * 时间 9 时：9/2 + 9/3 + 9/7 = 4 + 3 + 1 = 8 件 >= 8
     * 最短时间应为 9
     */
    assert(minimum_production_time(machines, 3, 8, &ans) && ans == 9);

    /* 目标为 0 件：时间为 0 */
    assert(minimum_production_time(NULL, 0, 0, &ans) && ans == 0);

    /* 单机器边界 */
    uint64_t single[] = {5};
    assert(minimum_production_time(single, 1, 10, &ans) && ans == 50);

    /* 机器耗时为 0 非法输入前置保护 */
    uint64_t bad_machines[] = {2, 0, 5};
    assert(!minimum_production_time(bad_machines, 3, 10, &ans));

    printf("All minimum_production_time tests passed successfully.\n");
    return 0;
}
```

## 复杂度分析

- **时间复杂度**：$O(m \log T^*)$。其中 $m$ 为机器数量，$T^*$ 为最终答案。单次检验遍历机器需 $O(m)$，答案二分执行 $O(\log T^*)$ 次迭代。
- **空间复杂度**：$\Theta(1)$。仅维护常数个 64 位无符号整型对象。

## 延伸思考 / 模式总结

“答案二分”将一个复杂的最优化求极值问题（Minimize $T$ subject to Capacity $\ge$ Target）成功转化为一系列简单的可行性判定问题（Is Capacity(T) $\ge$ Target?）。只要问题具有单调可行性边界，二分答案均能以对数级的收敛速度逼近最优解。
