# 35407 - 中位数的中位数算法（BFPRT）最坏 O(n) 确定性选择

## 题目

中位数的中位数算法（BFPRT / Median of Medians）最坏 $O(n)$ 确定性选择：

实现最坏情况下依然保证严格 $O(n)$ 时间复杂度的确定性选择算法：

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

bool bfprt_select(
    int64_t *items,
    size_t count,
    size_t order,
    int64_t *out_value
);
```

要求：

1. 5 分组策略：将数组按 5 个元素一组分组，组内插入排序求中位数；
2. 递归寻找各组中位数的中位数作为确定性优质枢轴 $x$；
3. 围绕 $x$ 进行划分，形式化证明划分后排除的元素数量至少为 $\frac{3}{10}n - 6$；
4. 建立递归主方程 $T(n) \le T(\lceil n/5 \rceil) + T(7n/10 + 6) + O(n)$，并使用替换法严格证明 $T(n) = O(n)$；
5. 给出完整可编译的 C 语言实现与单元测试。

## 解题思路

### 1. BFPRT 算法设计（Blum, Floyd, Pratt, Rivest, Tarjan 1973）

为了解决快速选择最坏 $O(n^2)$ 的缺陷，五位图灵奖得主共同提出了确定性线性时间选择算法：
1. **5 分组（Divide into groups of 5）**：
   将当前包含 $n$ 个元素的数组切分为 $\lceil n / 5 \rceil$ 个组，每组包含 5 个元素（最后一组可能少于 5 个）；
2. **求组内中位数（Find medians of each group）**：
   对每组执行至多 7 次比较的插入排序，提取其中位数（第 3 个元素），共得到 $\lceil n / 5 \rceil$ 个中位数；
3. **递归求中位数的中位数（Recursive Median-of-Medians）**：
   将这 $\lceil n / 5 \rceil$ 个中位数收集到数组前部，递归调用自身，求出这批中位数的中位数，记为枢轴 $x$；
4. **三路划分（Partition around x）**：
   围绕 $x$ 对原数组进行三路分区；
5. **递归单侧（Recurse on Subproblem）**：
   判断目标秩与划分边界的关系，仅在包含目标的子区间继续递归。

### 2. 划分下界证明与主定理替换法

为什么选 5 个元素一组？
在这 $\lceil n / 5 \rceil$ 组中，除去枢轴所在组和不足 5 个元素的末尾组，至少有一半的组（即至少 $\frac{1}{2} \lceil n/5 \rceil - 2$ 组）的中位数 $\le x$。
而在这些组中，每组至少有 3 个元素（该组最小者、次小者、中位数）小于等于 $x$。
因此，数组中**严格小于等于 $x$ 的元素总数**至少为：

$$3 \times \left( \frac{1}{2} \left\lceil \frac{n}{5} \right\rceil - 2 \right) \ge \frac{3n}{10} - 6$$

同理，**严格大于等于 $x$ 的元素总数**也至少为 $\frac{3n}{10} - 6$。
这意味着在最坏情况下，递归处理的最大子问题规模至多为：

$$n - \left( \frac{3n}{10} - 6 \right) = \frac{7n}{10} + 6$$

**递归时间主方程**：

$$T(n) \le T\left( \left\lceil \frac{n}{5} \right\rceil \right) + T\left( \frac{7n}{10} + 6 \right) + c \cdot n$$

关键数学特征：子问题规模系数之和为：

$$\frac{1}{5} + \frac{7}{10} = \frac{9}{10} < 1$$

由于 $\frac{9}{10} < 1$，级数收敛！用数学归纳法假设 $T(n) \le d \cdot n$：

$$T(n) \le d \cdot \left(\frac{n}{5} + 1\right) + d \cdot \left(\frac{7n}{10} + 6\right) + c \cdot n = \frac{9}{10} d \cdot n + 7d + c \cdot n$$

只要取常数 $d \ge 20c$，当 $n$ 充分大时即有 $\frac{9}{10} d \cdot n + 7d + c \cdot n \le d \cdot n$。因此在最坏情况下时间复杂度依然严格为 $O(n)$！

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>

static void swap_i64(int64_t *a, int64_t *b) {
    int64_t tmp = *a;
    *a = *b;
    *b = tmp;
}

static void insertion_sort_slice(int64_t *a, size_t left, size_t right) {
    for (size_t i = left + 1; i <= right; ++i) {
        int64_t key = a[i];
        size_t j = i;
        while (j > left && a[j - 1] > key) {
            a[j] = a[j - 1];
            j--;
        }
        a[j] = key;
    }
}

static int64_t bfprt_get_pivot(int64_t *a, size_t left, size_t right);

static int64_t bfprt_internal(int64_t *a, size_t left, size_t right, size_t k) {
    if (left == right) {
        return a[left];
    }

    int64_t pivot = bfprt_get_pivot(a, left, right);

    /* 围绕确定性枢轴执行三路划分 */
    size_t lt = left;
    size_t i = left;
    size_t gt = right;

    while (i <= gt) {
        if (a[i] < pivot) {
            swap_i64(&a[lt++], &a[i++]);
        } else if (a[i] > pivot) {
            swap_i64(&a[i], &a[gt--]);
        } else {
            i++;
        }
    }

    if (k < lt) {
        return bfprt_internal(a, left, lt - 1, k);
    } else if (k > gt) {
        return bfprt_internal(a, gt + 1, right, k);
    } else {
        return pivot;
    }
}

static int64_t bfprt_get_pivot(int64_t *a, size_t left, size_t right) {
    size_t n = right - left + 1;
    if (n <= 5) {
        insertion_sort_slice(a, left, right);
        return a[left + n / 2];
    }

    size_t num_groups = (n + 4) / 5;
    for (size_t i = 0; i < num_groups; ++i) {
        size_t sub_left = left + i * 5;
        size_t sub_right = sub_left + 4;
        if (sub_right > right) {
            sub_right = right;
        }
        insertion_sort_slice(a, sub_left, sub_right);
        size_t sub_mid = sub_left + (sub_right - sub_left) / 2;
        /* 将各组中位数交换至区间前端 */
        swap_i64(&a[left + i], &a[sub_mid]);
    }

    /* 递归求解中位数的中位数 */
    return bfprt_internal(a, left, left + num_groups - 1, left + num_groups / 2);
}

bool bfprt_select(int64_t *items, size_t count, size_t order, int64_t *out_value) {
    if (items == NULL || out_value == NULL || count == 0 || order >= count) {
        return false;
    }
    *out_value = bfprt_internal(items, 0, count - 1, order);
    return true;
}

int main(void) {
    int64_t arr[] = {12, 3, 5, 7, 4, 19, 26, 1, 8, 10, 2};
    size_t n = sizeof(arr) / sizeof(arr[0]);
    int64_t val = 0;

    /* 排序后为: 1, 2, 3, 4, 5, 7, 8, 10, 12, 19, 26 */
    assert(bfprt_select(arr, n, 0, &val) && val == 1);
    assert(bfprt_select(arr, n, 4, &val) && val == 5);
    assert(bfprt_select(arr, n, 10, &val) && val == 26);

    /* 边界测试：单元素与越界 */
    int64_t single[] = {99};
    assert(bfprt_select(single, 1, 0, &val) && val == 99);
    assert(!bfprt_select(single, 1, 1, &val));
    assert(!bfprt_select(NULL, 0, 0, &val));

    printf("All BFPRT deterministic O(n) selection tests passed successfully.\n");
    return 0;
}
```

## 复杂度分析

- **时间复杂度**：最坏情况下严格为 $\Theta(n)$。由于划分比例系数之和 $1/5 + 7/10 = 0.9 < 1$，即使最坏情况也不存在退化为 $O(n^2)$ 的可能。
- **空间复杂度**：$O(\log n)$。主要是递归调用栈的深度开销。

## 延伸思考 / 模式总结

为什么不是 3 个一组？
若 3 个一组，$\frac{1}{3} + \frac{2}{3} = 1$，求和系数为 1，展开后会变成 $T(n) = O(n \log n)$，无法实现线性时间！
正是因为选取了不小于 5 的奇数，使得系数之和严格小于 1，才完成了理论上的重大突破。
