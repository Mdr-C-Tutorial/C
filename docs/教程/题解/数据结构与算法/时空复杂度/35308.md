# 35308 - 支持减半缩容的动态数组平摊复杂度（震荡效应与 1/4 缩容策略）

## 题目描述

在动态数组设计中，若在元素个数减少至容量的一半（$1/2$）时立即执行减半缩容，会导致恶劣的“震荡效应（Thrashing）”。

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

typedef struct ShrinkVector ShrinkVector;

bool svec_init(ShrinkVector *v, size_t cap);
void svec_free(ShrinkVector *v);
bool svec_push(ShrinkVector *v, int64_t val);
bool svec_pop(ShrinkVector *v, int64_t *out_val);
```

要求：

1. 构造一个在扩容边界交替执行 `push` 与 `pop` 的恶劣操作序列，证明采用 $1/2$ 缩容策略时平均每次操作耗时退化为 $\Omega(n)$；
2. 说明为何将缩容阈值设为装载率低于 $1/4$ 时才将容量减半至 $1/2$ 能够彻底消除震荡；
3. 设计分段势能函数 $\Phi(D) = \begin{cases} 2 \cdot \text{size} - \text{cap}, & \text{size} \ge \text{cap} / 2 \\ \text{cap} / 2 - \text{size}, & \text{size} < \text{cap} / 2 \end{cases}$，严格证明 `push` 与 `pop` 的摊还时间复杂度均为 $O(1)$；
4. 编写 C 语言实现并用单元测试断言检验扩容与缩容逻辑。

## 解题思路

### 1. 1/2 缩容策略的震荡效应（Thrashing）

假设一个动态数组的容量为 $2k$。如果设计策略为：当容量满时倍增至 $2k$，当元素个数降至一半 $k$ 时立即减半至 $k$。
考虑以下恶劣的操作交替序列：
1. 初始时数组恰好装满 $k$ 个元素，容量为 $k$；
2. 执行一次 `push`：元素达到 $k + 1$，容量倍增至 $2k$，需要复制 $k$ 个元素，耗时 $\Theta(k)$；
3. 紧接着执行一次 `pop`：元素降回 $k$，触发减半缩容至 $k$，需要复制 $k$ 个元素，耗时 $\Theta(k)$；
4. 再次执行 `push`：元素升至 $k + 1$，再次触发扩容至 $2k$，耗时 $\Theta(k)$；
5. 重复上述交替过程 $m$ 次。

在这一序列中，**每一次**操作都强制触发了整表内存重新分配与全量复制，导致 $m$ 次操作的总代价高达 $\Theta(m \cdot k)$，单次操作的平摊时间退化为巨额的 $\Omega(n)$！

### 2. 1/4 延迟缩容策略消除震荡的机理

消除震荡的关键在于引入**滞后缓冲（Hysteresis）**：
- 当元素满（装载率 $\alpha = 1$）时，将容量翻倍，扩容后装载率降为 $\alpha = 1/2$；
- 当元素减少到容量的四分之一（装载率 $\alpha = 1/4$）时，才将容量减半至 $1/2$。
- **缓冲效应**：缩容完成后，装载率恰好恢复为 $\frac{\text{cap} / 4}{\text{cap} / 2} = 1/2$。
  - 要想再次触发缩容，必须再连续执行至少 $\text{cap} / 8$ 次 `pop`；
  - 要想触发扩容，必须再连续执行至少 $\text{cap} / 4$ 次 `push`。
  两次昂贵的内存重新分配之间，必须经过 $\Omega(\text{cap})$ 次廉价的常规操作，从而保证了昂贵操作的成本被充分摊平。

### 3. 分段势能函数证明

定义状态 $D_i$ 的分段势能函数为：

$$\Phi(D_i) = \begin{cases}
2 \cdot \text{size}_i - \text{cap}_i, & \text{size}_i \ge \text{cap}_i / 2 \\
\frac{\text{cap}_i}{2} - \text{size}_i, & \text{size}_i < \text{cap}_i / 2
\end{cases}$$

- 当 $\text{size} = \text{cap} / 2$ 时，$\Phi = 0$ 为最低点；
- 当数组满 $\text{size} = \text{cap}$ 时，$\Phi = \text{cap}$；
- 当数组处于缩容边缘 $\text{size} = \text{cap} / 4$ 时，$\Phi = \text{cap}/2 - \text{cap}/4 = \text{cap}/4$；
- 始终满足 $\Phi(D) \ge 0$，势能函数合法。

**摊还代价计算**：
- **`push` 操作**：
  - 若 $\text{size} \ge \text{cap} / 2$ 且未扩容：$c_i = 1$，$\Delta \Phi = 2$，$\hat{c}_i = 1 + 2 = 3$；
  - 若触发倍增扩容（$\text{size} = \text{cap} = k$）：实际复制 $k$ 个元素并写入 1 个新元素，$c_i = k + 1$。扩容后新容量为 $2k$，新大小为 $k + 1$。扩容前势能 $\Phi_{old} = 2k - k = k$，扩容后势能 $\Phi_{new} = 2(k + 1) - 2k = 2$。势能变化 $\Delta \Phi = 2 - k$。故摊还代价为：
    $$\hat{c}_i = (k + 1) + (2 - k) = 3 = O(1)$$
- **`pop` 操作**：
  - 若 $\text{size} < \text{cap} / 2$ 且未缩容：$c_i = 1$，$\Delta \Phi = 1$，$\hat{c}_i = 1 + 1 = 2$；
  - 若触发减半缩容（$\text{size} = \text{cap} / 4 = k$）：实际复制 $k$ 个元素，$c_i = k$。缩容前容量为 $4k$，势能 $\Phi_{old} = 2k - k = k$。缩容后新容量为 $2k$，新大小为 $k - 1$。新势能 $\Phi_{new} = k - (k - 1) = 1$。势能变化 $\Delta \Phi = 1 - k$。故摊还代价为：
    $$\hat{c}_i = k + (1 - k) = 1 = O(1)$$

两种情况下 `push` 与 `pop` 的摊还时间复杂度均严格为 $O(1)$！

## C 语言实现

```c
#include <assert.h>
#include <inttypes.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct ShrinkVector {
    int64_t *data;
    size_t size;
    size_t capacity;
} ShrinkVector;

bool svec_init(ShrinkVector *v, size_t cap) {
    if (v == NULL) {
        return false;
    }
    size_t initial_cap = (cap > 0) ? cap : 4;
    v->data = malloc(initial_cap * sizeof(int64_t));
    if (v->data == NULL) {
        return false;
    }
    v->size = 0;
    v->capacity = initial_cap;
    return true;
}

void svec_free(ShrinkVector *v) {
    if (v != NULL) {
        free(v->data);
        v->data = NULL;
        v->size = 0;
        v->capacity = 0;
    }
}

bool svec_push(ShrinkVector *v, int64_t val) {
    if (v == NULL) {
        return false;
    }
    if (v->size == v->capacity) {
        size_t new_cap = v->capacity * 2;
        int64_t *new_data = realloc(v->data, new_cap * sizeof(int64_t));
        if (new_data == NULL) {
            return false;
        }
        v->data = new_data;
        v->capacity = new_cap;
    }
    v->data[v->size++] = val;
    return true;
}

bool svec_pop(ShrinkVector *v, int64_t *out_val) {
    if (v == NULL || v->size == 0) {
        return false;
    }
    if (out_val != NULL) {
        *out_val = v->data[--v->size];
    } else {
        v->size--;
    }

    /* 1/4 缩容策略：当装载率降至 1/4 且容量大于基础门槛 8 时，容量减半 */
    if (v->size > 0 && v->size <= v->capacity / 4 && v->capacity > 8) {
        size_t new_cap = v->capacity / 2;
        int64_t *new_data = realloc(v->data, new_cap * sizeof(int64_t));
        if (new_data != NULL) {
            v->data = new_data;
            v->capacity = new_cap;
        }
    }
    return true;
}

int main(void) {
    ShrinkVector v;
    assert(svec_init(&v, 4));

    /* 连续插入触发扩容 */
    for (int64_t i = 0; i < 32; ++i) {
        assert(svec_push(&v, i));
    }
    assert(v.capacity >= 32);
    size_t peak_cap = v.capacity;

    /* 连续弹出触发 1/4 缩容 */
    int64_t val = 0;
    for (size_t i = 0; i < 26; ++i) {
        assert(svec_pop(&v, &val));
    }
    /* 剩余 6 个元素，由于 6 <= peak_cap / 4，容量应已安全收缩 */
    assert(v.size == 6);
    assert(v.capacity < peak_cap);

    svec_free(&v);
    printf("ShrinkVector 1/4 shrinking amortized tests passed.\n");
    return 0;
}
```

## 复杂度分析

- **单步最坏时间复杂度**：扩容与缩容发生时为 $O(n)$。
- **平摊时间复杂度**：
  - `push`：$\Theta(1)$；
  - `pop`：$\Theta(1)$。
- **空间复杂度**：$\Theta(n)$。装载率始终不低于 $25\%$，内存利用率保持在优良区间。

## 延伸思考 / 模式总结

1/4 缩容策略是计算机科学中“**迟滞控制（Hysteresis Control）**”的典范应用。在物理恒温器、网络拥塞控制（TCP 慢启动与拥塞避免）以及垃圾回收堆扩缩容中，系统均刻意拉大触发上调与下调的状态阈值差，从而规避边界震荡损耗。
