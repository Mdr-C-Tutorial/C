# 35305 - 支持清空操作的动态哈希表摊还成本证明

## 题目描述

设计支持 `insert`（插入键值）与 `clear`（清空全部元素并重置哈希槽）的动态哈希表：

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

typedef struct ClearableHashTable ClearableHashTable;

bool cht_init(ClearableHashTable *h, size_t cap);
void cht_free(ClearableHashTable *h);
bool cht_insert(ClearableHashTable *h, int64_t key);
void cht_clear(ClearableHashTable *h);
```

要求：

1. 虽然单次 `clear` 操作需要遍历重置哈希槽，单步最坏代价为 $O(N)$（$N$ 为哈希表容量）；
2. 使用记账法或势能法，为每次 `insert` 分配充足的平摊信用，证明在任意由 $m$ 次合法 `insert` 与 `clear` 构成的操作序列下，总时间代价严格为 $O(m)$，即单次操作的平摊复杂度仍为 $O(1)$；
3. 给出完整 C 语言实现并测试。

## 解题思路

### 1. 记账法与平摊分析

考虑容量与元素数量成正比的哈希表结构。设单次插入一个新键的实际代价为 $1$ 个时间单位；清空操作需要重置槽位标记，若维护了非空槽链表或索引列表，实际耗时与当前表中元素个数 $k$ 成正比（实际代价为 $c_{\text{clear}} = k$）。即使在全槽扫描模型下，只要装载率维持在常数下界，重置开销也严格由表中元素数量控制。

**记账法费用分配**：
- 为每次 `insert` 收取平摊费用 $\hat{c}_{\text{insert}} = \$2$：
  - **\$1**：用于支付本次将键存入槽位的实际写入代价；
  - **\$1**：作为信用存款存储在该元素对应的账面上，专门用于未来该元素被 `clear` 操作重置时的清除开销。
- 为每次 `clear` 收取平摊费用 $\hat{c}_{\text{clear}} = \$0$：
  - 清空操作自身不需要向用户额外收费，它所消耗的全部实际清空代价（清除 $k$ 个元素需 $k$ 次操作），完全由这 $k$ 个元素在插入时预存的 $k \times \$1 = \$k$ 信用余额全额支付。

由于表中每个存在的元素均持有 $\$1$ 存款，存款总额始终等于当前元素总数 $k \ge 0$。因此账面信用永不透支，总摊还收费 $\sum \hat{c} = 2 \cdot m_{\text{insert}} + 0 \cdot m_{\text{clear}} \le 2m$ 构成了总实际耗时的严密上界，证明了平摊代价为 $O(1)$。

### 2. 势能法（Potential Method）形式化推导

定义哈希表状态 $H_i$ 的势能函数为当前有效元素个数：

$$\Phi(H_i) = \text{count}(H_i) \ge 0$$

- **`insert` 操作**（元素个数增加 1）：
  - 实际代价 $c_i = 1$；
  - 势能变化 $\Delta \Phi = (k + 1) - k = 1$；
  - 摊还代价 $\hat{c}_i = c_i + \Delta \Phi = 1 + 1 = 2 = O(1)$。
- **`clear` 操作**（将 $k$ 个元素全部清空）：
  - 实际代价 $c_i = k$；
  - 势能变化 $\Delta \Phi = 0 - k = -k$；
  - 摊还代价 $\hat{c}_i = c_i + \Delta \Phi = k + (-k) = 0 = O(1)$。

两种操作的摊还代价均为常数，从而对于任意 $m$ 次操作的序列，总耗时为 $O(m)$。

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct ClearableHashTable {
    int64_t *table;
    bool *occupied;
    size_t *occupied_indices; /* 维护已占用槽位下标，实现与元素数严格成正比的高效清空 */
    size_t capacity;
    size_t count;
    size_t total_work;        /* 记录实际操作步数以验证平摊理论 */
} ClearableHashTable;

bool cht_init(ClearableHashTable *h, size_t cap) {
    if (h == NULL || cap == 0) {
        return false;
    }
    h->table = calloc(cap, sizeof(int64_t));
    h->occupied = calloc(cap, sizeof(bool));
    h->occupied_indices = malloc(cap * sizeof(size_t));
    if (!h->table || !h->occupied || !h->occupied_indices) {
        free(h->table);
        free(h->occupied);
        free(h->occupied_indices);
        return false;
    }
    h->capacity = cap;
    h->count = 0;
    h->total_work = 0;
    return true;
}

void cht_free(ClearableHashTable *h) {
    if (h != NULL) {
        free(h->table);
        free(h->occupied);
        free(h->occupied_indices);
        h->capacity = 0;
        h->count = 0;
    }
}

bool cht_insert(ClearableHashTable *h, int64_t key) {
    if (h == NULL || h->count >= h->capacity) {
        return false;
    }
    size_t idx = (size_t)(key >= 0 ? key : -key) % h->capacity;
    while (h->occupied[idx]) {
        if (h->table[idx] == key) {
            return true; /* 键已存在 */
        }
        idx = (idx + 1) % h->capacity;
        h->total_work++;
    }
    h->occupied[idx] = true;
    h->table[idx] = key;
    h->occupied_indices[h->count] = idx;
    h->count++;
    h->total_work++;
    return true;
}

void cht_clear(ClearableHashTable *h) {
    if (h == NULL) {
        return;
    }
    /* 仅重置已占用的槽位，开销与元素个数 k 严格成正比 */
    for (size_t i = 0; i < h->count; ++i) {
        size_t idx = h->occupied_indices[i];
        h->occupied[idx] = false;
        h->total_work++;
    }
    h->count = 0;
}

int main(void) {
    ClearableHashTable h;
    assert(cht_init(&h, 32));

    const size_t rounds = 20;
    for (size_t r = 0; r < rounds; ++r) {
        for (int64_t i = 0; i < 10; ++i) {
            assert(cht_insert(&h, (int64_t)(r * 100 + i)));
        }
        assert(h.count == 10);
        cht_clear(&h);
        assert(h.count == 0);
    }

    /* 验证总工作量不超过操作数的两倍常数阶 */
    size_t total_ops = rounds * (10 + 1); // 20 轮，每轮 10 次 insert + 1 次 clear
    assert(h.total_work <= 3 * total_ops);

    cht_free(&h);
    printf("ClearableHashTable amortized tests passed: total work = %zu (ops = %zu)\n", h.total_work, total_ops);
    return 0;
}
```

## 复杂度分析

- **单步最坏时间复杂度**：
  - `insert`：$O(N)$；
  - `clear`：$O(k)$，其中 $k$ 为当前表中元素个数。
- **平摊时间复杂度**：$\Theta(1)$。在连续的 $m$ 次混合操作中，总耗时为 $O(m)$。
- **空间复杂度**：$\Theta(N)$。维护固定哈希槽数组与索引缓冲区。

## 延伸思考 / 模式总结

支持清空操作的平摊分析展示了一个关键结论：**单次操作的最坏代价并不能代表其在长期序列中的真实成本**。只要高成本操作的发生频率受到前期低成本操作的严格约束（例如必须先执行 $k$ 次插入才能积累出清空 $k$ 个元素的开销），那么高昂代价总能被有效均摊。
