# 36201 - 朴素暴力字符串匹配与滑动窗口

## 题目描述

给定一个文本字节序列 `text`（长度为 `text_count`）和一个模式字节序列 `pattern`（长度为 `pattern_count`）。

使用朴素的滑动窗口算法：
1. 找出模式串在文本串中**首次出现的起始下标**（若未找到，输出 `SIZE_MAX`）；
2. 统计模式串在文本串中**出现的总次数**（允许相互重叠出现）。

函数签名如下：

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

bool naive_string_search_u8(
    const unsigned char *text,
    size_t text_count,
    const unsigned char *pattern,
    size_t pattern_count,
    size_t *out_first_index,
    size_t *out_match_count
);
```

要求：
1. 输入数据为任意二进制字节序列（允许包含 `0x00` 字节），不得调用依赖空字符结尾的字符串函数。
2. 参数无效时返回 `false`。
3. 当 `pattern_count == 0` 时，空模式在位置 0 处首次出现，且共匹配 `text_count + 1` 次。
4. 当 `text_count < pattern_count` 时，输出 `*out_first_index = SIZE_MAX`，匹配次数为 0，返回 `true`。
5. 空间复杂度必须为 $O(1)$，分析其最好和最坏时间复杂度。

## 解题思路

1. **滑动窗口基本原理**：
   朴素字符串匹配将模式串视作一个长度为 $m = pattern\_count$ 的滑动窗口。
   窗口在文本串上从下标 $i = 0$ 开始，一直滑动到 $i = text\_count - pattern\_count$。
   对于每个起始位置 $i$：
   内部从 $j = 0$ 到 $m - 1$ 逐字符比对 $text[i + j]$ 与 $pattern[j]$：
   - 若遇到失配字符（$text[i + j] \neq pattern[j]$），窗口向右滑动 1 位（$i$ 递增 1），重新从 $j = 0$ 开始比对；
   - 若所有 $m$ 个字符完全匹配，说明在起始位置 $i$ 找到了一个合法出现。

2. **可重叠统计与首次匹配捕获**：
   维护计数器 `match_count` 与首次匹配标志。
   命中时：
   - 若此前尚未捕获首次匹配，记录 `*out_first_index = i`；
   - `match_count` 递增 1；
   - 窗口依然仅向右移动 1 位（继续检查 $i + 1$），从而不遗漏任何重叠匹配（例如在 `"aaaa"` 中匹配 `"aa"` 计为 3 次）。

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

bool naive_string_search_u8(
    const unsigned char *text,
    size_t text_count,
    const unsigned char *pattern,
    size_t pattern_count,
    size_t *out_first_index,
    size_t *out_match_count
) {
    if (out_first_index == NULL || out_match_count == NULL ||
        (text_count > 0 && text == NULL) ||
        (pattern_count > 0 && pattern == NULL)) {
        return false;
    }

    if (pattern_count == 0) {
        *out_first_index = 0;
        *out_match_count = text_count + 1;
        return true;
    }

    if (text_count < pattern_count) {
        *out_first_index = SIZE_MAX;
        *out_match_count = 0;
        return true;
    }

    size_t first_idx = SIZE_MAX;
    size_t count = 0;
    size_t max_start = text_count - pattern_count;

    for (size_t i = 0; i <= max_start; ++i) {
        bool match = true;
        for (size_t j = 0; j < pattern_count; ++j) {
            if (text[i + j] != pattern[j]) {
                match = false;
                break;
            }
        }

        if (match) {
            if (first_idx == SIZE_MAX) {
                first_idx = i;
            }
            count++;
        }
    }

    *out_first_index = first_idx;
    *out_match_count = count;
    return true;
}

int main(void) {
    size_t first = 0;
    size_t count = 0;

    // 参数校验
    assert(!naive_string_search_u8(NULL, 5, (const unsigned char*)"a", 1, &first, &count));

    // 空模式
    assert(naive_string_search_u8((const unsigned char*)"abc", 3, NULL, 0, &first, &count));
    assert(first == 0 && count == 4);

    // 标准测试用例 1: 重叠出现
    // text: "aaaaa", pattern: "aa"
    // 首次出现在 0，共出现 4 次 (下标 0, 1, 2, 3)
    const unsigned char t1[] = "aaaaa";
    const unsigned char p1[] = "aa";
    assert(naive_string_search_u8(t1, 5, p1, 2, &first, &count));
    assert(first == 0);
    assert(count == 4);

    // 标准测试用例 2:
    // text: "hello world hello", pattern: "hello"
    // 首次在 0, 共 2 次
    const unsigned char t2[] = "hello world hello";
    const unsigned char p2[] = "hello";
    assert(naive_string_search_u8(t2, 17, p2, 5, &first, &count));
    assert(first == 0);
    assert(count == 2);

    // 未找到测试
    const unsigned char p3[] = "xyz";
    assert(naive_string_search_u8(t2, 17, p3, 3, &first, &count));
    assert(first == SIZE_MAX);
    assert(count == 0);

    return 0;
}
```

## 复杂度分析

- **时间复杂度**：
  - **最坏情况**：$O((n - m + 1) \times m) = O(nm)$。当文本串形如 $A^n$，模式串形如 $A^{m-1}B$ 时，每次内层循环比对 $m - 1$ 个字符后才失配，滑动步长仅为 1。
  - **最好情况**：$O(n)$。若字符集较大，模式串首字符极少在文本中出现，内层循环绝大多数在 $j = 0$ 时即失配退出。
- **空间复杂度**：$O(1)$。仅使用常数个整型对象记录下标与计数，无需任何额外动态内存。

## 延伸思考 / 模式总结

朴素算法是所有字符串模式匹配的基准参照。其主要缺陷在于：当失配发生时，文本指针发生了大幅度回退，完全丢弃了前序比对中已经获得的有效字符信息。后续的 KMP、Boyer-Moore、Sunday 算法均致力于通过预处理模式串，消灭文本指针回退或最大化滑动步长。
