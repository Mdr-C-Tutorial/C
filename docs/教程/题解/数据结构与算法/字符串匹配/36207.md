# 36207 - Sunday 算法高效单模式串匹配

## 题目描述

实现 **Sunday 字符串匹配算法**，在文本字节序列 `text` 中快速查找模式字节序列 `pattern` 首次出现的起始下标。

Sunday 算法以其极度简练的逻辑和卓越的平均匹配速度闻名。与 BM 算法不同，Sunday 算法在失配时关注的是**文本串中参与匹配子串的下一个字符**。

函数签名如下：

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

bool sunday_search_u8(
    const unsigned char *text,
    size_t text_count,
    const unsigned char *pattern,
    size_t pattern_count,
    size_t *out_first_index
);
```

要求：
1. 预处理大小为 256 的字节偏移跳转表 `shift`，记录每个可能字节在失配时的安全跳转步长。
2. 参数无效时返回 `false`；未找到时输出 `*out_first_index = SIZE_MAX` 并返回 `true`。
3. 当 `pattern_count == 0` 时，输出首次下标 0 并返回 `true`。
4. 空间复杂度限制为 $O(1)$（仅使用固定 256 项的局部栈上跳转表）。

## 解题思路

1. **Sunday 算法的核心直觉**：
   假设当前模式串 $P$ 与文本串 $T$ 在窗口区间 $T[i \dots i + m - 1]$ 对齐比对。
   无论比对过程中在哪个具体位置发生失配，模式串下一次向右滑动后，**文本串中的字符 $c = T[i + m]$（即紧随当前匹配窗口之后的下一个字符）必然会参与到下一轮匹配中**！

2. **偏移跳转表构造（Shift Table）**：
   因此，我们只需要考察字符 $c = T[i + m]$ 是否在模式串 $P$ 中出现过：
   - 若 $c$ 根本不在模式串中出现：
     下一轮匹配窗口如果覆盖了字符 $c$，必然会再度失配。因此模式串可以直接跳过整个字符 $c$，滑动步长为：
     $$shift = m + 1$$
   - 若 $c$ 在模式串中出现过：
     为了不错过潜在匹配，我们必须将模式串中**最靠右出现的那个字符 $c$** 与文本中的 $T[i + m]$ 对齐。
     设最靠右的 $c$ 在模式串中的下标为 $k$（$0 \le k < m$），则滑动步长为：
     $$shift = m - k$$
   预处理时，初始化所有 256 个字节的跳转步长为 $m + 1$；然后从左向右遍历模式串，设置 $shift[P[k]] = m - k$。

3. **主匹配循环**：
   指针 $i$ 初始为 0。
   每次尝试正向比对 $T[i \dots i + m - 1]$ 与 $P[0 \dots m - 1]$：
   - 若完全相同，直接返回当前下标 $i$；
   - 若失配，检查 $i + m < n$ 是否成立：
     若超出文本末尾，说明后续剩余长度已不足 $m$，直接终止搜索；
     否则，执行 $i += shift[T[i + m]]$ 继续下一轮比对。

## C 语言实现

```c
#include <assert.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

bool sunday_search_u8(
    const unsigned char *text,
    size_t text_count,
    const unsigned char *pattern,
    size_t pattern_count,
    size_t *out_first_index
) {
    if (out_first_index == NULL ||
        (text_count > 0 && text == NULL) ||
        (pattern_count > 0 && pattern == NULL)) {
        return false;
    }

    if (pattern_count == 0) {
        *out_first_index = 0;
        return true;
    }

    if (text_count < pattern_count) {
        *out_first_index = SIZE_MAX;
        return true;
    }

    size_t m = pattern_count;
    size_t n = text_count;

    // 构建 Sunday 偏移跳转表 (固定 256 项)
    size_t shift[256];
    for (size_t c = 0; c < 256; ++c) {
        shift[c] = m + 1;
    }
    for (size_t k = 0; k < m; ++k) {
        shift[pattern[k]] = m - k;
    }

    size_t i = 0;
    while (i <= n - m) {
        size_t j = 0;
        while (j < m && text[i + j] == pattern[j]) {
            j++;
        }

        if (j == m) {
            *out_first_index = i; // 找到首次匹配
            return true;
        }

        // 失配后，观察文本窗口后的下一个字符
        if (i + m < n) {
            i += shift[text[i + m]];
        } else {
            break; // 剩余字符不足以容纳整个模式串
        }
    }

    *out_first_index = SIZE_MAX;
    return true;
}

int main(void) {
    size_t idx = 0;

    // 参数校验
    assert(!sunday_search_u8(NULL, 1, (const unsigned char*)"a", 1, &idx));

    // 空模式
    assert(sunday_search_u8((const unsigned char*)"abc", 3, NULL, 0, &idx));
    assert(idx == 0);

    // 标准测试用例 1
    // text: "substring searching algorithm"
    // pattern: "search"
    const unsigned char t1[] = "substring searching algorithm";
    const unsigned char p1[] = "search";
    assert(sunday_search_u8(t1, 29, p1, 6, &idx));
    assert(idx == 10);

    // 测试用例 2: 大步长跳跃
    // text: "abcdefghijklmn"
    // pattern: "xyz"
    const unsigned char t2[] = "abcdefghijklmn";
    const unsigned char p2[] = "xyz";
    assert(sunday_search_u8(t2, 14, p2, 3, &idx));
    assert(idx == SIZE_MAX);

    // 匹配在末尾
    const unsigned char p3[] = "algorithm";
    assert(sunday_search_u8(t1, 29, p3, 9, &idx));
    assert(idx == 20);

    return 0;
}
```

## 复杂度分析

- **时间复杂度**：
  - **平均情况**：$O(n / m)$。在通常的自然语言或代码文本检索中，下一个字符 $T[i + m]$ 不在模式串中的概率极高，每次跳跃步长平均达到 $m + 1$，实测平均速度往往优于 KMP 和 BM 简化版。
  - **最坏情况**：$O(nm)$。在极端周期性对抗样例下可能发生退化。
- **空间复杂度**：$O(1)$。仅在栈上分配大小为 256 的固定跳转表，完全无需堆内存分配。

## 延伸思考 / 模式总结

Sunday 算法的绝妙之处在于“目光放得更远一步”。通过把考察点直接前瞻到当前窗口之外的第一个字符，以极小的代码实现复杂度实现了比 BM 坏字符规则更激进的大跨度跳步，是工程上轻量级快速匹配的首选实现方案之一。
