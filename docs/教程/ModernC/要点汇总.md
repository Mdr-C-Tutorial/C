## 第 1 章：入门

::: tip [要点 1 #2](/教程/ModernC/01_入门)
不要恐慌。（译者注：原文：“Don't panic.”，出自《银河系漫游指南》）
:::

C 是一种命令式编程语言。
:::

::: tip [要点 1.2 #1](/教程/ModernC/01_入门#_1-2-编译和运行)
C 是一种编译型编程语言。
:::

::: tip [要点 1.2 #2](/教程/ModernC/01_入门#_1-2-编译和运行)
正确的 C 程序可以在不同平台之间移植。
:::

::: tip [要点 1.2 #3](/教程/ModernC/01_入门#_1-2-编译和运行)
C 程序应当干净利落地完成编译，不产生警告。
:::

## 第 2 章：程序的基本结构

::: tip [要点 2.1 #1](/教程/ModernC/02_程序的基本结构#_2-1-文法)
同一个标点字符可以用于多种不同目的。
:::

::: tip [要点 2.2 #1](/教程/ModernC/02_程序的基本结构#_2-2-声明)
程序中的所有标识符都必须声明。
:::

::: tip [要点 2.2 #2](/教程/ModernC/02_程序的基本结构#_2-2-声明)
一个标识符可以有多个相互一致的声明。
:::

::: tip [要点 2.2 #3](/教程/ModernC/02_程序的基本结构#_2-2-声明)
声明仅在其出现的作用域内有效。
:::

::: tip [要点 2.3 #1](/教程/ModernC/02_程序的基本结构#_2-3-定义)
声明说明标识符，定义说明对象。
:::

::: tip [要点 2.3 #2](/教程/ModernC/02_程序的基本结构#_2-3-定义)
对象在初始化的同时得到定义。
:::

::: tip [要点 2.3 #3](/教程/ModernC/02_程序的基本结构#_2-3-定义)
初始化器中缺少的元素默认为 `0`。（译者注：此处的“0”应当理解为与该元素类型相对应的“零值（Zero Value）”。整数为 `0`，浮点数为 `0.0`，指针为 NULL，等等。）
:::

::: tip [要点 2.3 #4](/教程/ModernC/02_程序的基本结构#_2-3-定义)
对于含有 n 个元素的数组，第一个元素的索引是 0，最后一个元素的索引是 n-1。
:::

::: tip [要点 2.3 #5](/教程/ModernC/02_程序的基本结构#_2-3-定义)
每个对象或函数都必须恰好有一个定义。
:::

::: tip [要点 2.4.1 #1](/教程/ModernC/02_程序的基本结构#_2-4-1-迭代)
范围迭代应当用 `for` 语句编写。
:::

::: tip [要点 2.4.1 #2](/教程/ModernC/02_程序的基本结构#_2-4-1-迭代)
循环对象应当定义在 `for` 的起始部分中。
:::

## 第 3 章：一切都与控制有关

::: tip [要点 3.1 #1](/教程/ModernC/03_一切都与控制有关#_3-1-条件执行)
值 0 表示逻辑假。
:::

::: tip [要点 3.1 #2](/教程/ModernC/03_一切都与控制有关#_3-1-条件执行)
任何不等于 0 的值都表示逻辑真。
:::

::: tip [要点 3.1 #3](/教程/ModernC/03_一切都与控制有关#_3-1-条件执行)
不要与 `0`、`false` 或 `true` 作比较。
:::

::: tip [要点 3.1 #4](/教程/ModernC/03_一切都与控制有关#_3-1-条件执行)
所有标量都有真值。
:::

::: tip [要点 3.3 #1](/教程/ModernC/03_一切都与控制有关#_3-3-多路选择)
`case` 值必须是整数常量表达式。
:::

::: tip [要点 3.3 #2](/教程/ModernC/03_一切都与控制有关#_3-3-多路选择)
每个 `switch` 语句中的 `case` 值必须唯一。
:::

::: tip [要点 3.3 #3](/教程/ModernC/03_一切都与控制有关#_3-3-多路选择)
`case` 标签不得跳过对象定义。
:::

## 第 4 章：表达计算

::: tip [要点 4.1 #1](/教程/ModernC/04_表达计算#_4-1-操作数与运算符)
`size_t` 类型表示范围 `[0, SIZE_MAX]` 内的值。
:::

::: tip [要点 4.2.1 #1](/教程/ModernC/04_表达计算#_4-2-1-、-和)
无符号算术始终是良好定义的。
:::

::: tip [要点 4.2.1 #2](/教程/ModernC/04_表达计算#_4-2-1-、-和)
如果数学上的正确结果可以表示为 `size_t`，那么 `size_t` 上的 `+`、`-` 和 `*` 运算就会给出该结果。
:::

::: tip [要点 4.2.2 #1](/教程/ModernC/04_表达计算#_4-2-2-除法与余数)
对于无符号值，`a == (a/b) * b + (a%b)`。
:::

::: tip [要点 4.2.2 #2](/教程/ModernC/04_表达计算#_4-2-2-除法与余数)
只有第二个操作数不为 0 时，无符号 `/` 和 `%` 才是良好定义的。
:::

::: tip [要点 4.2.2 #3](/教程/ModernC/04_表达计算#_4-2-2-除法与余数)
`size_t` 算术会隐式地以 `SIZE_MAX + 1` 为模进行计算。
:::

::: tip [要点 4.2.2 #4](/教程/ModernC/04_表达计算#_4-2-2-除法与余数)
发生溢出时，无符号算术会回绕。
:::

::: tip [要点 4.2.2 #5](/教程/ModernC/04_表达计算#_4-2-2-除法与余数)
无符号 `/` 和 `%` 的结果始终不大于操作数。
:::

::: tip [要点 4.2.2 #6](/教程/ModernC/04_表达计算#_4-2-2-除法与余数)
无符号 `/` 和 `%` 不会溢出。
:::

::: tip [要点 4.3 #1](/教程/ModernC/04_表达计算#_4-3-修改对象的运算符)
一个运算符的所有字符必须彼此直接相连。
:::

::: tip [要点 4.3 #2](/教程/ModernC/04_表达计算#_4-3-修改对象的运算符)
值表达式中的副作用是邪恶的。
:::

::: tip [要点 4.3 #3](/教程/ModernC/04_表达计算#_4-3-修改对象的运算符)
绝不要在一个语句中修改一个以上的对象。
:::

::: tip [要点 4.4.1 #1](/教程/ModernC/04_表达计算#_4-4-1-比较)
比较运算符返回值 `false` 或 `true`。
:::

::: tip [要点 4.4.2 #1](/教程/ModernC/04_表达计算#_4-4-2-逻辑)
逻辑运算符返回值 `false` 或 `true`。
:::

::: tip [要点 4.6 #1](/教程/ModernC/04_表达计算#_4-6-求值顺序)
`&&`、`||`、`?:` 和 `,` 首先对第一个操作数求值。
:::

::: tip [要点 4.6 #2](/教程/ModernC/04_表达计算#_4-6-求值顺序)
不要使用 `,` 运算符。
:::

::: tip [要点 4.6 #3](/教程/ModernC/04_表达计算#_4-6-求值顺序)
大多数运算符不会为其操作数定序。
:::

::: tip [要点 4.6 #4](/教程/ModernC/04_表达计算#_4-6-求值顺序)
函数调用不会为其实参表达式定序。
:::

::: tip [要点 4.6 #5](/教程/ModernC/04_表达计算#_4-6-求值顺序)
表达式中的函数调用不应带有副作用。
:::

## 第 5 章：基本值与数据

::: tip [要点 5 #1](/教程/ModernC/05_基本值与数据)
C 程序首先围绕值推理，而不是围绕值的表示推理。
:::

::: tip [要点 5.1.1 #1](/教程/ModernC/05_基本值与数据#_5-1-1-值)
所有值都是数，或者能够转换为数。
:::

::: tip [要点 5.1.2 #1](/教程/ModernC/05_基本值与数据#_5-1-2-类型)
所有值都有一个静态确定的类型。
:::

::: tip [要点 5.1.2 #2](/教程/ModernC/05_基本值与数据#_5-1-2-类型)
可对一个值执行哪些操作，由它的类型决定。
:::

::: tip [要点 5.1.2 #3](/教程/ModernC/05_基本值与数据#_5-1-2-类型)
一个值的类型决定所有操作的结果。
:::

::: tip [要点 5.1.3 #1](/教程/ModernC/05_基本值与数据#_5-1-3-二进制表示与抽象状态机)
一个类型的二进制表示决定所有操作的结果。
:::

::: tip [要点 5.1.3 #2](/教程/ModernC/05_基本值与数据#_5-1-3-二进制表示与抽象状态机)
一个类型的二进制表示是可观察的。
:::

::: tip [要点 5.1.3 #3（如同规则）](/教程/ModernC/05_基本值与数据#_5-1-3-二进制表示与抽象状态机)
程序的执行，如同遵循抽象状态机。
:::

::: tip [要点 5.1.4 #1](/教程/ModernC/05_基本值与数据#_5-1-4-优化)
类型决定优化机会。
:::

::: tip [要点 5.2 #1](/教程/ModernC/05_基本值与数据#_5-2-基本类型)
执行算术之前，窄整数会提升为 <code>signed int</code>。
:::

::: tip [要点 5.2 #2](/教程/ModernC/05_基本值与数据#_5-2-基本类型)
四类基本类型各有三种互不相同、无需提升的类型。
:::

::: tip [要点 5.2 #3](/教程/ModernC/05_基本值与数据#_5-2-基本类型)
大小、基数或序数应使用 <code>size_t</code>。
:::

::: tip [要点 5.2 #4](/教程/ModernC/05_基本值与数据#_5-2-基本类型)
对不可能为负的小数量使用 <code>unsigned</code>。
:::

::: tip [要点 5.2 #5](/教程/ModernC/05_基本值与数据#_5-2-基本类型)
对带符号的小数量使用 <code>signed</code>。
:::

::: tip [要点 5.2 #6](/教程/ModernC/05_基本值与数据#_5-2-基本类型)
对带符号的大差值使用 <code>ptrdiff_t</code>。
:::

::: tip [要点 5.2 #7](/教程/ModernC/05_基本值与数据#_5-2-基本类型)
浮点计算使用 <code>double</code>。
:::

::: tip [要点 5.2 #8](/教程/ModernC/05_基本值与数据#_5-2-基本类型)
复数计算使用 <code>double complex</code>。
:::

::: tip [要点 5.3 #1](/教程/ModernC/05_基本值与数据#_5-3-指定值)
相邻的字符串字面量会连接在一起。
:::

::: tip [要点 5.3 #2](/教程/ModernC/05_基本值与数据#_5-3-指定值)
数值字面量从不为负。
:::

::: tip [要点 5.3 #3](/教程/ModernC/05_基本值与数据#_5-3-指定值)
十进制整数字面量是有符号的。
:::

::: tip [要点 5.3 #4](/教程/ModernC/05_基本值与数据#_5-3-指定值)
十进制整数字面量采用三种有符号类型中第一个能够容纳其值的类型。
:::

::: tip [要点 5.3 #5](/教程/ModernC/05_基本值与数据#_5-3-指定值)
同一个值可以具有不同类型。
:::

::: tip [要点 5.3 #6](/教程/ModernC/05_基本值与数据#_5-3-指定值)
不要用二进制、八进制或十六进制字面量表示负值。
:::

::: tip [要点 5.3 #7](/教程/ModernC/05_基本值与数据#_5-3-指定值)
负值应使用十进制字面量。
:::

::: tip [要点 5.3 #8](/教程/ModernC/05_基本值与数据#_5-3-指定值)
不同字面量可以具有相同的值。
:::

::: tip [要点 5.3 #9](/教程/ModernC/05_基本值与数据#_5-3-指定值)
十进制浮点字面量的实际值可能不同于其字面值。
:::

::: tip [要点 5.3 #A](/教程/ModernC/05_基本值与数据#_5-3-指定值)
字面量具有值、类型和二进制表示。
:::

::: tip [要点 5.3.1 #1](/教程/ModernC/05_基本值与数据#_5-3-1-复数常量)
<code>I</code> 保留用于虚数单位。
:::

::: tip [要点 5.4 #1](/教程/ModernC/05_基本值与数据#_5-4-隐式转换)
一元 <code>-</code> 和 <code>+</code> 的类型，就是其提升后操作数的类型。
:::

::: tip [要点 5.4 #2](/教程/ModernC/05_基本值与数据#_5-4-隐式转换)
避免窄化转换。
:::

::: tip [要点 5.4 #3](/教程/ModernC/05_基本值与数据#_5-4-隐式转换)
不要用窄类型执行算术。
:::

::: tip [要点 5.4 #4](/教程/ModernC/05_基本值与数据#_5-4-隐式转换)
避免对符号性不同的操作数执行操作。
:::

::: tip [要点 5.4 #5](/教程/ModernC/05_基本值与数据#_5-4-隐式转换)
只要能够做到，就使用无符号类型。
:::

::: tip [要点 5.4 #6](/教程/ModernC/05_基本值与数据#_5-4-隐式转换)
选择算术类型时，应确保隐式转换无害。
:::

::: tip [要点 5.5 #1](/教程/ModernC/05_基本值与数据#_5-5-初始化器)
所有对象都应初始化。
:::

::: tip [要点 5.5 #2](/教程/ModernC/05_基本值与数据#_5-5-初始化器)
所有聚合数据类型都应使用指派初始化器。
:::

::: tip [要点 5.5 #3](/教程/ModernC/05_基本值与数据#_5-5-初始化器)
<code>{ }</code> 对所有对象都是有效的初始化器。
:::

::: tip [要点 5.6 #1](/教程/ModernC/05_基本值与数据#_5-6-具名常量)
具有特定含义的所有常量都必须命名。
:::

::: tip [要点 5.6 #2](/教程/ModernC/05_基本值与数据#_5-6-具名常量)
含义不同的所有常量都必须彼此区分。
:::

::: tip [要点 5.6.1 #1](/教程/ModernC/05_基本值与数据#_5-6-1-只读对象)
具有 <code>const</code> 限定类型的对象是只读的。
:::

::: tip [要点 5.6.1 #2](/教程/ModernC/05_基本值与数据#_5-6-1-只读对象)
字符串字面量是只读的。
:::

::: tip [要点 5.6.2 #1](/教程/ModernC/05_基本值与数据#_5-6-2-枚举)
枚举常量要么具有显式指定的值，要么具有按位置确定的值。
:::

::: tip [要点 5.6.2 #2](/教程/ModernC/05_基本值与数据#_5-6-2-枚举)
如果简单枚举类型的所有枚举常量都能装入 <code>signed int</code>，这些常量就具有该类型。
:::

::: tip [要点 5.6.2 #3](/教程/ModernC/05_基本值与数据#_5-6-2-枚举)
整数常量表达式只能对声明为 <code>constexpr</code> 的对象求值。
:::

::: tip [要点 5.6.2 #4](/教程/ModernC/05_基本值与数据#_5-6-2-枚举)
如果枚举常量无法装入 <code>signed int</code>，那么只要可能，枚举类型就会调整为能够存放所有枚举常量的类型。
:::

::: tip [要点 5.6.2 #5](/教程/ModernC/05_基本值与数据#_5-6-2-枚举)
如果枚举常量无法装入 <code>signed int</code>，这些常量就采用枚举类型。
:::

::: tip [要点 5.6.2 #6](/教程/ModernC/05_基本值与数据#_5-6-2-枚举)
如果枚举常量有可能无法全部装入 <code>signed int</code>，就应指定枚举类型的底层整数类型。
:::

::: tip [要点 5.6.3 #1](/教程/ModernC/05_基本值与数据#_5-6-3-宏)
宏名全部使用大写字母。
:::

::: tip [要点 5.6.4 #1](/教程/ModernC/05_基本值与数据#_5-6-4-复合字面量)
复合字面量定义一个对象。
:::

::: tip [要点 5.6.4 #2](/教程/ModernC/05_基本值与数据#_5-6-4-复合字面量)
不要把结尾分号藏进宏里。
:::

::: tip [要点 5.6.4 #3](/教程/ModernC/05_基本值与数据#_5-6-4-复合字面量)
把宏的续行标记右对齐到同一列。
:::

::: tip [要点 5.6.5 #1](/教程/ModernC/05_基本值与数据#_5-6-5-constexpr-构造)
<code>constexpr</code> 的初始化器必须精确适配。
:::

::: tip [要点 5.7 #1](/教程/ModernC/05_基本值与数据#_5-7-二进制表示)
同一个值可以具有不同的二进制表示。
:::

::: tip [要点 5.7.1 #1](/教程/ModernC/05_基本值与数据#_5-7-1-无符号整数)
任何整数类型的最大值都具有 2ᵖ − 1 的形式。
:::

::: tip [要点 5.7.1 #2](/教程/ModernC/05_基本值与数据#_5-7-1-无符号整数)
无符号整数类型上的算术由其精度决定。
:::

::: tip [要点 5.7.3 #1](/教程/ModernC/05_基本值与数据#_5-7-3-移位运算符)
移位操作的第二个操作数必须小于精度。
:::

::: tip [要点 5.7.5 #1](/教程/ModernC/05_基本值与数据#_5-7-5-有符号整数)
正值的表示与符号性无关。
:::

::: tip [要点 5.7.5 #2](/教程/ModernC/05_基本值与数据#_5-7-5-有符号整数)
抽象状态机一旦到达未定义状态，就不能再对后续执行作出任何假设。
:::

::: tip [要点 5.7.5 #3](/教程/ModernC/05_基本值与数据#_5-7-5-有符号整数)
避免所有操作产生未定义行为，是你的责任。
:::

::: tip [要点 5.7.5 #4](/教程/ModernC/05_基本值与数据#_5-7-5-有符号整数)
如果程序状态到达具有未定义行为的操作，执行就已经失效。
:::

::: tip [要点 5.7.5 #5](/教程/ModernC/05_基本值与数据#_5-7-5-有符号整数)
有符号算术可能以恶劣方式触发陷阱。
:::

::: tip [要点 5.7.5 #6](/教程/ModernC/05_基本值与数据#_5-7-5-有符号整数)
<code>INT_MIN &lt; -INT_MAX</code>。
:::

::: tip [要点 5.7.5 #7](/教程/ModernC/05_基本值与数据#_5-7-5-有符号整数)
有符号算术中的取负可能溢出。
:::

::: tip [要点 5.7.5 #8](/教程/ModernC/05_基本值与数据#_5-7-5-有符号整数)
位操作应使用无符号类型。
:::

::: tip [要点 5.7.6 #1](/教程/ModernC/05_基本值与数据#_5-7-6-固定宽度整数类型)
如果提供了类型 <code>uintN_t</code>，它就是宽度和精度都恰为 N 位的无符号整数类型。
:::

::: tip [要点 5.7.6 #2](/教程/ModernC/05_基本值与数据#_5-7-6-固定宽度整数类型)
如果提供了类型 <code>intN_t</code>，它就是宽度恰为 N 位、精度为 N − 1 的有符号整数类型。
:::

::: tip [要点 5.7.6 #3](/教程/ModernC/05_基本值与数据#_5-7-6-固定宽度整数类型)

::: tip [要点 6.3.1 #1](/教程/ModernC/06_派生数据类型#_6-3-1-通过名称访问字段的简单结构体)

## 第 11 章：指针

::: tip [要点 11.1.1 #1](/教程/ModernC/11_指针#_11-1-1-取地址运算符与间接运算符)

::: tip [要点 11.1.2 #1](/教程/ModernC/11_指针#_11-1-2-指针加法)

::: tip [要点 11.1.2 #2](/教程/ModernC/11_指针#_11-1-2-指针加法)

::: tip [要点 11.1.3 #2](/教程/ModernC/11_指针#_11-1-3-指针减法与指针差)

::: tip [要点 11.1.3 #3](/教程/ModernC/11_指针#_11-1-3-指针减法与指针差)

::: tip [要点 11.1.3 #4](/教程/ModernC/11_指针#_11-1-3-指针减法与指针差)

::: tip [要点 11.1.4 #1](/教程/ModernC/11_指针#_11-1-4-指针的有效性)

::: tip [要点 11.1.4 #2](/教程/ModernC/11_指针#_11-1-4-指针的有效性)

::: tip [要点 11.1.4 #3](/教程/ModernC/11_指针#_11-1-4-指针的有效性)

::: tip [要点 11.1.4 #4](/教程/ModernC/11_指针#_11-1-4-指针的有效性)

::: tip [要点 11.1.4 #5](/教程/ModernC/11_指针#_11-1-4-指针的有效性)
指针必须指向有效对象、刚好越过该对象一个位置，或者为空。
:::

::: tip [要点 11.1.4 #6](/教程/ModernC/11_指针#_11-1-4-指针的有效性)
如果程序执行计算出的指针值超出数组对象边界（也不是刚好越过一个元素），则执行失败。

::: tip [要点 11.1.5 #1](/教程/ModernC/11_指针#_11-1-5-空指针)

::: tip [要点 11.2 #1](/教程/ModernC/11_指针#_11-2-指针与结构体)

::: tip [要点 11.3.1 #1](/教程/ModernC/11_指针#_11-3-1-数组访问与指针访问相同)

::: tip [要点 11.3.1 #2：数组退化](/教程/ModernC/11_指针#_11-3-1-数组访问与指针访问相同)

::: tip [要点 11.3.2 #1](/教程/ModernC/11_指针#_11-3-2-数组形参与指针形参相同)

::: tip [要点 11.3.2 #2](/教程/ModernC/11_指针#_11-3-2-数组形参与指针形参相同)
只有数组形参的最内层维度会被改写。

::: tip [要点 11.3.2 #3](/教程/ModernC/11_指针#_11-3-2-数组形参与指针形参相同)
长度形参应当声明在数组形参之前。

::: tip [要点 11.3.2 #4](/教程/ModernC/11_指针#_11-3-2-数组形参与指针形参相同)

## 第 12 章：C 内存模型

::: tip [要点 12 #1](/教程/ModernC/12_C内存模型)
基础类型不同的指针类型彼此不同。
:::

::: tip [要点 12.1 #1](/教程/ModernC/12_C内存模型#_12-1-统一内存模型)
按照定义，`sizeof(char)` 等于 `1`。
:::

::: tip [要点 12.1 #2](/教程/ModernC/12_C内存模型#_12-1-统一内存模型)
任何对象 `A` 都可以视为 `unsigned char[sizeof A]`。
:::

::: tip [要点 12.1 #3](/教程/ModernC/12_C内存模型#_12-1-统一内存模型)
指向字符类型的指针具有特殊地位。
:::

::: tip [要点 12.1 #4](/教程/ModernC/12_C内存模型#_12-1-统一内存模型)
字符和字符串数据使用 `char` 类型。
:::

::: tip [要点 12.1 #5](/教程/ModernC/12_C内存模型#_12-1-统一内存模型)
所有对象类型都以 `unsigned char` 类型作为基本单元。
:::

::: tip [要点 12.1 #6](/教程/ModernC/12_C内存模型#_12-1-统一内存模型)
`sizeof` 运算符可以用于对象和对象类型。
:::

::: tip [要点 12.1 #7](/教程/ModernC/12_C内存模型#_12-1-统一内存模型)
类型 `T` 的所有对象都具有大小 `sizeof(T)`。
:::

::: tip [要点 12.2 #1](/教程/ModernC/12_C内存模型#_12-2-联合体)
算术类型各个表示数字在内存中的顺序由实现定义。
:::

::: tip [要点 12.2 #2](/教程/ModernC/12_C内存模型#_12-2-联合体)
在大多数体系结构上，`CHAR_BIT` 等于 `8`，`UCHAR_MAX` 等于 `255`。
:::

::: tip [要点 12.3 #1：别名](/教程/ModernC/12_C内存模型#_12-3-内存与状态)
除字符类型外，只有基础类型相同的指针才能形成别名。
:::

::: tip [要点 12.3 #2](/教程/ModernC/12_C内存模型#_12-3-内存与状态)
避免使用 `&` 运算符。
:::

::: tip [要点 12.4 #1](/教程/ModernC/12_C内存模型#_12-4-指向非特定对象的指针)
任何对象指针都能与 `void*` 相互转换。
:::

::: tip [要点 12.4 #2](/教程/ModernC/12_C内存模型#_12-4-指向非特定对象的指针)
对象具有存储、类型和值。
:::

::: tip [要点 12.4 #3](/教程/ModernC/12_C内存模型#_12-4-指向非特定对象的指针)
把对象指针转换成 `void*`，再转换回原来的类型，是恒等操作。
:::

::: tip [要点 12.4 #4：第二项“避免”原则](/教程/ModernC/12_C内存模型#_12-4-指向非特定对象的指针)
避免使用 `void*`。
:::

::: tip [要点 12.5 #1](/教程/ModernC/12_C内存模型#_12-5-显式转换)
不要使用强制转换。
:::

::: tip [要点 12.6 #1：有效类型](/教程/ModernC/12_C内存模型#_12-6-有效类型)
必须通过对象的有效类型，或者通过指向字符类型的指针访问对象。
:::

::: tip [要点 12.6 #2](/教程/ModernC/12_C内存模型#_12-6-有效类型)
只要相应字节表示构成访问类型的有效值，具有有效联合体类型的对象就可以随时访问任何成员。
:::

::: tip [要点 12.6 #3](/教程/ModernC/12_C内存模型#_12-6-有效类型)
具名对象或复合字面量的有效类型，就是其声明中的类型。
:::

::: tip [要点 12.6 #4](/教程/ModernC/12_C内存模型#_12-6-有效类型)
具名对象与复合字面量必须通过声明类型，或者通过指向字符类型的指针访问。

## 第 13 章：存储

::: tip [要点 13.1 #1](/教程/ModernC/13_存储#_13-1-malloc-及其同伴)
调用分配函数时，只能请求严格大于 `0` 的大小。
:::

::: tip [要点 13.1 #2](/教程/ModernC/13_存储#_13-1-malloc-及其同伴)
分配失败会产生空指针。
:::

::: tip [要点 13.1 #3](/教程/ModernC/13_存储#_13-1-malloc-及其同伴)
优先使用 `strndup`，而不是 `strdup`。
:::

::: tip [要点 13.1 #4](/教程/ModernC/13_存储#_13-1-malloc-及其同伴)
不要强制转换 `malloc` 及其同伴的返回值。
:::

::: tip [要点 13.1 #5](/教程/ModernC/13_存储#_13-1-malloc-及其同伴)
通过 `malloc` 分配的存储没有初始化，也没有类型。
:::

::: tip [要点 13.1.1 #1](/教程/ModernC/13_存储#_13-1-1-数组大小可变的完整示例)
`malloc` 通过返回空指针值表示失败。
:::

::: tip [要点 13.1.2 #1](/教程/ModernC/13_存储#_13-1-2-保证动态分配一致)
每次分配都必须对应一次释放。
:::

::: tip [要点 13.1.2 #2](/教程/ModernC/13_存储#_13-1-2-保证动态分配一致)
每次调用 `free`，都必须对应一次 `malloc`、`calloc`、`aligned_alloc` 或 `realloc`。
:::

::: tip [要点 13.1.2 #3](/教程/ModernC/13_存储#_13-1-2-保证动态分配一致)
只能把 `malloc`、`calloc`、`aligned_alloc` 或 `realloc` 原样返回的指针传给 `free`。
:::

::: tip [要点 13.1.3 #1](/教程/ModernC/13_存储#_13-1-3-柔性数组成员)
带有柔性数组成员的结构体对象，必须拥有足以访问整个结构体的存储。
:::

::: tip [要点 13.1.3 #2](/教程/ModernC/13_存储#_13-1-3-柔性数组成员)
长度成员与柔性数组成员之间的一致性必须手工维护。
:::

::: tip [要点 13.2 #1](/教程/ModernC/13_存储#_13-2-存储期、生存期与可见性)
标识符只在其作用域内可见，而且可见性从声明处开始。
:::

::: tip [要点 13.2 #2](/教程/ModernC/13_存储#_13-2-存储期、生存期与可见性)
标识符的可见性可能被从属作用域中的同名标识符遮蔽。
:::

::: tip [要点 13.2 #3](/教程/ModernC/13_存储#_13-2-存储期、生存期与可见性)
具名对象的每一项定义都会创建一个彼此不同的新对象。
:::

::: tip [要点 13.2 #4](/教程/ModernC/13_存储#_13-2-存储期、生存期与可见性)
只读对象字面量可以相互重叠。
:::

::: tip [要点 13.2 #5](/教程/ModernC/13_存储#_13-2-存储期、生存期与可见性)
对象具有生存期；在生存期之外不能访问该对象。
:::

::: tip [要点 13.2 #6](/教程/ModernC/13_存储#_13-2-存储期、生存期与可见性)
如果程序执行在对象生存期之外引用该对象，则执行失败。
:::

::: tip [要点 13.2 #7](/教程/ModernC/13_存储#_13-2-存储期、生存期与可见性)
复合字面量的生存期，与在同一语境中按相同存储类声明的具名对象相同。
:::

::: tip [要点 13.2.1 #1](/教程/ModernC/13_存储#_13-2-1-静态存储期)
具有静态存储期的对象始终会初始化。
:::

::: tip [要点 13.2.2 #1](/教程/ModernC/13_存储#_13-2-2-自动存储期)
除 VLA 或临时对象外，自动对象的生存期与定义所在块的执行相对应。
:::

::: tip [要点 13.2.2 #2](/教程/ModernC/13_存储#_13-2-2-自动存储期)
每次递归调用都会为自动对象创建一个新的局部实例。
:::

::: tip [要点 13.2.2 #3](/教程/ModernC/13_存储#_13-2-2-自动存储期)
`&` 运算符不能用于以 `register` 声明的对象。
:::

::: tip [要点 13.2.2 #4](/教程/ModernC/13_存储#_13-2-2-自动存储期)
以 `register` 声明的对象不能形成别名。
:::

::: tip [要点 13.2.2 #5](/教程/ModernC/13_存储#_13-2-2-自动存储期)
在性能关键代码中，把非数组的局部对象声明为 `register`。
:::

::: tip [要点 13.2.2 #6](/教程/ModernC/13_存储#_13-2-2-自动存储期)
存储类为 `register` 的数组没有用处。
:::

::: tip [要点 13.2.2 #7](/教程/ModernC/13_存储#_13-2-2-自动存储期)
具有临时生存期的对象只读。
:::

::: tip [要点 13.2.2 #8](/教程/ModernC/13_存储#_13-2-2-自动存储期)
临时生存期终于外围完整表达式结束之时。
:::

::: tip [要点 13.3 #1](/教程/ModernC/13_存储#_13-3-插叙-在定义前使用对象)
对于非 VLA 对象，生存期始于进入定义所在作用域，终于离开该作用域。
:::

::: tip [要点 13.3 #2](/教程/ModernC/13_存储#_13-3-插叙-在定义前使用对象)
每次执行遇到定义时，都会对自动对象和复合字面量的初始化器求值。
:::

::: tip [要点 13.3 #3](/教程/ModernC/13_存储#_13-3-插叙-在定义前使用对象)
VLA 的生存期始于执行遇到定义，终于离开可见作用域。
:::

::: tip [要点 13.4 #1](/教程/ModernC/13_存储#_13-4-初始化)
具有静态或线程存储期的对象会默认初始化。
:::

::: tip [要点 13.4 #2](/教程/ModernC/13_存储#_13-4-初始化)
具有自动或分配存储期的对象必须显式初始化。
:::

::: tip [要点 13.4 #3](/教程/ModernC/13_存储#_13-4-初始化)
系统地为每一种数据类型提供初始化函数。

::: tip [要点 19.5 #3](/教程/ModernC/19_控制流的变化#_19-5-长跳转)

::: tip [要点 19.5 #4](/教程/ModernC/19_控制流的变化#_19-5-长跳转)

::: tip [要点 19.5 #5](/教程/ModernC/19_控制流的变化#_19-5-长跳转)

::: tip [要点 19.5 #6](/教程/ModernC/19_控制流的变化#_19-5-长跳转)

::: tip [要点 19.5 #8](/教程/ModernC/19_控制流的变化#_19-5-长跳转)

::: tip [要点 19.5 #9](/教程/ModernC/19_控制流的变化#_19-5-长跳转)

::: tip [要点 19.5 #A](/教程/ModernC/19_控制流的变化#_19-5-长跳转)

::: tip [要点 19.5 #B](/教程/ModernC/19_控制流的变化#_19-5-长跳转)

::: tip [要点 19.6 #1](/教程/ModernC/19_控制流的变化#_19-6-信号处理函数)

:::

::: tip [要点 19.6 #2](/教程/ModernC/19_控制流的变化#_19-6-信号处理函数)

:::

::: tip [要点 19.6 #3](/教程/ModernC/19_控制流的变化#_19-6-信号处理函数)
从信号处理函数返回后，执行在中断发生的确切位置恢复。
:::

::: tip [要点 19.6 #4](/教程/ModernC/19_控制流的变化#_19-6-信号处理函数)
任何一条 C 语句都可能对应多条处理器指令。
:::

::: tip [要点 19.6 #5](/教程/ModernC/19_控制流的变化#_19-6-信号处理函数)
信号处理函数需要操作不可中断的类型。
:::

::: tip [要点 19.6 #6](/教程/ModernC/19_控制流的变化#_19-6-信号处理函数)
`sig_atomic_t` 类型的对象不应用作计数器。
:::

::: tip [要点 19.6 #7](/教程/ModernC/19_控制流的变化#_19-6-信号处理函数)
除非另有明确规定，否则 C 库函数并非异步信号安全。
:::

## 第 20 章：线程

::: tip [要点 20.1 #1](/教程/ModernC/20_线程#_20-1-简单的线程间控制)
如果线程 T0 写入非原子对象，而另一个线程 T1 同时读取或写入该对象，执行就会失败。
:::

::: tip [要点 20.1 #2](/教程/ModernC/20_线程#_20-1-简单的线程间控制)
在不同线程的执行看来，原子对象上的标准操作不可分割，并且可线性化。
:::

::: tip [要点 20.1 #3](/教程/ModernC/20_线程#_20-1-简单的线程间控制)
声明原子对象时，请使用说明符句法 `_Atomic(T)`。
:::

::: tip [要点 20.1 #4](/教程/ModernC/20_线程#_20-1-简单的线程间控制)
不存在原子数组类型。
:::

::: tip [要点 20.1 #5](/教程/ModernC/20_线程#_20-1-简单的线程间控制)
原子对象是强制排除竞态条件的首选工具。
:::

::: tip [要点 20.2 #1](/教程/ModernC/20_线程#_20-2-无竞态的初始化与销毁)
正确初始化的 `FILE*` 可以由多个线程无竞态地使用。
:::

::: tip [要点 20.2 #2](/教程/ModernC/20_线程#_20-2-无竞态的初始化与销毁)
并发写操作应当一次打印完整的一行。
:::

::: tip [要点 20.2 #3](/教程/ModernC/20_线程#_20-2-无竞态的初始化与销毁)
销毁和解分配共享动态对象需要格外谨慎。
:::

::: tip [要点 20.3 #1](/教程/ModernC/20_线程#_20-3-线程局部数据)
通过函数实参传递线程特定数据。
:::

::: tip [要点 20.3 #2](/教程/ModernC/20_线程#_20-3-线程局部数据)
在线程的局部对象中保存线程特定状态。
:::

::: tip [要点 20.3 #3](/教程/ModernC/20_线程#_20-3-线程局部数据)
`thread_local` 对象在每个线程中都有一个独立实例。
:::

::: tip [要点 20.3 #4](/教程/ModernC/20_线程#_20-3-线程局部数据)
如果能在编译期确定初始化，请使用 `thread_local`。
:::

::: tip [要点 20.4 #1](/教程/ModernC/20_线程#_20-4-临界数据与临界区)
互斥量操作提供线性化性。
:::

::: tip [要点 20.4 #2](/教程/ModernC/20_线程#_20-4-临界数据与临界区)
每个互斥量都必须用 `mtx_init` 初始化。
:::

::: tip [要点 20.4 #3](/教程/ModernC/20_线程#_20-4-临界数据与临界区)
持有非递归互斥量的线程，不得再为该互斥量调用任何锁定函数。
:::

::: tip [要点 20.4 #4](/教程/ModernC/20_线程#_20-4-临界数据与临界区)
持有递归互斥量的线程调用 `mtx_unlock` 的次数达到获取锁的次数后，该互斥量才会释放。
:::

::: tip [要点 20.4 #5](/教程/ModernC/20_线程#_20-4-临界数据与临界区)
线程终止之前，必须释放其锁定的互斥量。
:::

::: tip [要点 20.4 #6](/教程/ModernC/20_线程#_20-4-临界数据与临界区)
线程只能对自己持有的互斥量调用 `mtx_unlock`。
:::

::: tip [要点 20.4 #7](/教程/ModernC/20_线程#_20-4-临界数据与临界区)
每次成功锁定互斥量，都恰好对应一次 `mtx_unlock` 调用。
:::

::: tip [要点 20.4 #8](/教程/ModernC/20_线程#_20-4-临界数据与临界区)
互斥量必须在生存期末尾销毁。
:::

::: tip [要点 20.5 #1](/教程/ModernC/20_线程#_20-5-通过条件量通信)
从 `cnd_t` 等待返回后，必须再次检查表达式。
:::

::: tip [要点 20.5 #2](/教程/ModernC/20_线程#_20-5-通过条件量通信)
同一个条件量在同一时刻只能与一个互斥量配合使用。
:::

::: tip [要点 20.5 #3](/教程/ModernC/20_线程#_20-5-通过条件量通信)
`cnd_t` 必须动态初始化。
:::

::: tip [要点 20.5 #4](/教程/ModernC/20_线程#_20-5-通过条件量通信)
`cnd_t` 必须在生存期末尾销毁。
:::

::: tip [要点 20.6 #1](/教程/ModernC/20_线程#_20-6-更复杂的线程管理)
从 `main` 返回或调用 `exit` 会终止所有线程。
:::

::: tip [要点 20.6 #2](/教程/ModernC/20_线程#_20-6-更复杂的线程管理)
线程阻塞于 `mtx_t` 或 `cnd_t` 时，会释放处理资源。
:::

::: tip [要点 20.7 #1](/教程/ModernC/20_线程#_20-7-保证活性)
需要锁定多个互斥量的临界区，应当始终以相同顺序锁定这些互斥量。
:::

::: tip [要点 20.7 #2](/教程/ModernC/20_线程#_20-7-保证活性)
为了避免死锁，请优先使用 `cnd_timedwait`，而不是 `cnd_wait`。
:::

## 第 21 章：原子访问与内存一致性

::: tip [要点 21 #1](/教程/ModernC/21_原子访问与内存一致性)
每次求值都有作用。
:::

::: tip [要点 21.1 #1](/教程/ModernC/21_原子访问与内存一致性#_21-1-先于-关系)
如果 `F` 先序于 `E`，那么 $F \rightarrow E$。
:::

::: tip [要点 21.1 #2](/教程/ModernC/21_原子访问与内存一致性#_21-1-先于-关系)
对原子对象 `X` 的所有修改按某种顺序进行，该顺序与每个操作 `X` 的线程内部的“先序于”关系一致。
:::

::: tip [要点 21.1 #3](/教程/ModernC/21_原子访问与内存一致性#_21-1-先于-关系)
如果线程 $T_E$ 中的获取操作 `E` 读到了另一线程 $T_F$ 中释放操作 `F` 写入的值，那么 `E` 与 `F` 同步。
:::

::: tip [要点 21.1 #4](/教程/ModernC/21_原子访问与内存一致性#_21-1-先于-关系)
如果 `F` 与 `E` 同步，那么所有先于 `F` 发生的作用 `X`，都必须在所有发生于 `E` 之后的求值 `G` 处可见。
:::

::: tip [要点 21.1 #5](/教程/ModernC/21_原子访问与内存一致性#_21-1-先于-关系)
只有存在一条把两次求值连接起来的定序与同步链条，才能断定一次求值先于另一次发生。
:::

::: tip [要点 21.1 #6](/教程/ModernC/21_原子访问与内存一致性#_21-1-先于-关系)
如果求值 `F` 先于 `E` 发生，那么所有已知先于 `F` 发生的作用，也已知先于 `E` 发生。
:::

::: tip [要点 21.2 #1](/教程/ModernC/21_原子访问与内存一致性#_21-2-提供同步的-c-库调用)
受同一个互斥量保护的临界区顺序发生。
:::

::: tip [要点 21.2 #2](/教程/ModernC/21_原子访问与内存一致性#_21-2-提供同步的-c-库调用)
在受互斥量 `mut` 保护的临界区中，此前所有受 `mut` 保护的临界区的作用均可见。
:::

::: tip [要点 21.2 #3](/教程/ModernC/21_原子访问与内存一致性#_21-2-提供同步的-c-库调用)
`cnd_wait` 和 `cnd_timedwait` 对互斥量具有释放—获取语义。
:::

::: tip [要点 21.2 #4](/教程/ModernC/21_原子访问与内存一致性#_21-2-提供同步的-c-库调用)
`cnd_signal` 和 `cnd_broadcast` 调用通过互斥量同步。
:::

::: tip [要点 21.2 #5](/教程/ModernC/21_原子访问与内存一致性#_21-2-提供同步的-c-库调用)
`cnd_signal` 和 `cnd_broadcast` 应当在受等待方所用同一互斥量保护的临界区内调用。
:::

::: tip [要点 21.3 #1](/教程/ModernC/21_原子访问与内存一致性#_21-3-顺序一致性)
具有顺序一致性的所有原子操作，都处于同一个全局修改顺序中，与它们作用于哪个原子对象无关。
:::

::: tip [要点 21.3 #2](/教程/ModernC/21_原子访问与内存一致性#_21-3-顺序一致性)
除非另有说明，所有原子运算符及函数接口都具有顺序一致性。
:::

::: tip [要点 21.4 #1](/教程/ModernC/21_原子访问与内存一致性#_21-4-其他一致性模型)
名称附加 `_explicit` 的原子对象同步函数接口，允许指定一致性模型。
:::
