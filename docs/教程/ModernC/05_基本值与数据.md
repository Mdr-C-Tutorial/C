# 第 5 章 基本值与数据

[[toc]]

本章涵盖：

- 理解抽象状态机
- 使用类型和值
- 初始化对象
- 使用具名常量
- 类型的二进制表示

现在，我们要把关注点从“如何完成操作”（语句和表达式）转向 C 程序所操作的事物：**值**和**数据**。一个具体程序在某一时刻必须用某种形式表示值。人类也采用类似的策略：如今，我们用印度-阿拉伯数字系统，以十进制表示法把数字写在纸上。不过，我们还有其他书写数字的系统，例如罗马数字（i、ii、iii、iv，等等）或文字记数法。知道单词 <i>twelve</i> 表示值 12，并不是一个微不足道的认知步骤；它也提醒我们，欧洲语言并非只用十进制系统表示数。英语和德语混入了十二进制，法语则混入了十六进制与二十进制。对于像我这样母语并非法语的人来说，要立刻把 <i>quatre vingt quinze</i>（四乘二十再加十五）同值 95 联系起来，可能并不容易。

同样，计算机中值的表示也会因体系结构而呈现不同的“文化”，也可能由程序员赋予该值的类型决定。因此，若想编写可移植代码，我们首先应当围绕值推理，而非围绕表示推理。

如果你已经具备一定的 C 使用经验，也熟悉字节和位的操作，那么在本章的大部分内容中，你需要努力主动“忘掉”这些知识。执着于自己计算机上值的具体表示，往往妨碍理解，远多于带来帮助。

::: tip 要点 5 #1
C 程序首先围绕值推理，而不是围绕值的表示推理。
:::

在大多数情况下，某个值究竟采用何种表示，不应成为你的关注点。编译器会安排值与表示之间的双向转换。

本章将说明这种转换的各个组成部分应当如何协作。通常，你会在 C 的抽象状态机（第 5.1 节）这个理想世界中对程序进行“论证”。它提供了一幅程序执行图景，基本独立于程序运行的平台。该机器状态的组成部分，也就是对象，都有固定的解释（其类型），并且具有随时间变化的值。第 5.2 节介绍 C 的基本类型；第 5.3 节说明如何写出这些基本类型的特定值；第 5.4 节说明类型如何在表达式中组合；第 5.5 节说明怎样确保对象一开始就具有期望的值；第 5.6 节说明怎样为反复出现的值命名；第 5.7 节则说明抽象状态机如何表示这些值。

## 5.1 抽象状态机

C 程序可以视为一种操纵值的机器：它操纵程序中各对象在给定时刻所具有的具体值，也操纵表达式计算所得的中间值。来看一个基本示例：

~~~c
double x = 5.0;
double y = 3.0;
...
x = (x * 1.5) - y;
printf("x is %g\n", x);
~~~

这里有两个对象 <code>x</code> 和 <code>y</code>，它们的初值分别为 <code>5.0</code> 和 <code>3.0</code>。第 4 行计算了若干表达式：

~~~c
x
~~~

它对 <code>x</code> 求值，得到值 <code>5.0</code>；

~~~c
(5.0 * 1.5)
~~~

它产生值 <code>7.5</code>；

~~~c
y
~~~

它对 <code>y</code> 求值，得到值 <code>3.0</code>；

~~~c
7.5 - 3.0
~~~

它产生值 <code>4.5</code>；

~~~c
x = 4.5
~~~

它把 <code>x</code> 的值改为 <code>4.5</code>；

~~~c
x
~~~

它再次对 <code>x</code> 求值，但这一次得到值 <code>4.5</code>；最后，

~~~c
printf("x is %g\n", 4.5)
~~~

向终端输出一行文本。

并非所有操作及其结果值都能从程序内部观察到。只有当这些结果存入可寻址内存，或写入输出设备时，它们才可观察。在这个示例中，<code>printf</code> 语句通过求取对象 <code>x</code> 的值，再把该值的字符串表示写到终端，在一定程度上“观察”了上一行所做的事情。其他子表达式及其结果（例如乘法和减法）本身却不可观察，因为我们从未定义一个用于保存这些值的对象。

C 编译器可以在称为“**优化**”的过程中省略任何步骤，但前提是最终结果仍然实现。就这个小示例而言，基本有两种可能。第一种是，程序后面不再使用对象 <code>x</code>，它获得的值只对 <code>printf</code> 语句有意义。此时，这段代码的唯一效果就是向终端输出，编译器完全可以（而且确实会）把整段代码替换成等价形式：

~~~c
printf("x is 4.5\n");
~~~

也就是说，编译器在编译期完成所有计算，生成的可执行程序只会打印一个固定字符串。其余代码，乃至对象定义，都会消失。

第二种可能是，程序后面还会使用 <code>x</code>。此时，一个像样的编译器可能生成近似于以下形式的代码：

~~~c
double x = 4.5;
printf("x is 4.5\n");
~~~

也可能生成：

~~~c
printf("x is 4.5\n");
double x = 4.5;
~~~

因为以后使用 <code>x</code> 时，赋值发生在 <code>printf</code> 之前还是之后并不重要。

要使优化有效，C 编译器只需生成一个能够复现**可观察状态**的可执行程序。可观察状态由某些对象（以及稍后将介绍的类似实体）的内容和输出构成，并且会随着程序执行而演变。整个状态变化机制称为“**抽象状态机**”。

为了说明抽象状态机，我们首先需要考察值（当前处于什么状态）、类型（该状态表示什么）以及表示（如何区分各个状态）这些概念。正如“抽象”一词所暗示的那样，C 的机制允许不同平台按照自身需求和能力，以不同方式实现给定程序的抽象状态机。这种宽容性正是 C 具备优化潜力的关键之一。

### 5.1.1 值

C 中的值是一种抽象实体，它通常超越你的程序、该程序的具体实现，以及某次程序运行中该值所采用的表示。例如，值及概念 0 在所有 C 平台上都应当产生相同效果：把这个值加到另一个值 <code>x</code> 上，结果仍是 <code>x</code>；在控制表达式中求取值 0，总会触发控制语句的假分支。

到目前为止，我们见到的值大多是某种数。这并非偶然，而是与 C 的一个核心观念有关。

::: tip 要点 5.1.1 #1
所有值都是数，或者能够转换为数。
:::

这项性质确实涵盖 C 程序所处理的一切值，无论它们是打印的字符或文本、真值、测量结果，还是所研究的关系。应当把这些数看作数学实体，它们独立于程序及其具体实现。

一次程序执行的数据，由某一时刻所有对象的全部值共同组成。程序执行的状态取决于：

- 可执行程序；
- 当前执行位置；
- 数据；
- 外部介入，例如来自用户的输入和输出。

如果抽去最后一点，那么同一个可执行程序从同一个执行位置、以相同数据开始运行，必定得到相同结果。但由于 C 程序应当能够在系统之间移植，我们所要求的还不止这些。我们不希望计算结果依赖可执行程序（它特定于平台），而希望它在理想情况下只依赖程序规约本身。实现这种平台独立性的重要一步，就是“**类型**”概念。

### 5.1.2 类型

类型是 C 与值关联的一项附加性质。到目前为止，我们已经见过若干类型，其中最醒目的是 <code>size_t</code>，另外还有 <code>double</code> 和 <code>bool</code>。

::: tip 要点 5.1.2 #1
所有值都有一个静态确定的类型。
:::

::: tip 要点 5.1.2 #2
可对一个值执行哪些操作，由它的类型决定。
:::

::: tip 要点 5.1.2 #3
一个值的类型决定所有操作的结果。
:::

### 5.1.3 二进制表示与抽象状态机

遗憾的是，计算机平台纷繁多样，C 标准无法为给定类型上的所有操作彻底规定结果。例如，标准并未完全规定 <code>double</code> 浮点操作采用何种精度（即浮点表示）。[^10] C 只对表示施加若干性质，使操作结果能够根据两个不同来源预先推导：

- 操作数的值；
- 描述特定平台的若干特征值。

例如，除了操作数之外再考察 <code>SIZE_WIDTH</code> 的值，就可以完全确定 <code>size_t</code> 类型上的操作。[^11] 我们把在给定平台上表示给定类型值的模型，称为该类型的“**二进制表示**”。

::: tip 要点 5.1.3 #1
一个类型的二进制表示决定所有操作的结果。
:::

一般来说，确定这一模型所需的全部信息，都在任意 C 程序的触及范围之内。C 库头文件通过具名值（例如 <code>SIZE_MAX</code>）、运算符和函数调用，提供必要信息。

::: tip 要点 5.1.3 #2
一个类型的二进制表示是可观察的。
:::

二进制表示仍然是一种模型，因而仍属抽象表示：它并不完全决定值如何存入计算机内存、磁盘或其他持久存储设备。后者是“对象表示”。与二进制表示不同，只要我们不打算在主存中拼凑对象的值，也不需要让采用不同平台模型的计算机互相通信，对象表示通常就不值得过分关注。很久以后，在第 12.1 节中，我们会看到：只要对象存放在内存中，并且知道它的地址，我们甚至可以观察其对象表示。

因此，一切计算都由程序所规定的值、类型及其二进制表示确定。程序文本描述了一个**抽象状态机**，用来规制程序怎样从一个状态切换到下一个状态。这些转换仅由值、类型与二进制表示决定。

::: tip 要点 5.1.3 #3（如同规则）
程序的执行，如同遵循抽象状态机。
:::

[^10]: 其他国际标准对这些表示施加了更严格的限制。例如，POSIX 标准强制采用一种特定的符号表示，ISO/IEC/IEEE 60559 [2011] 则规范了浮点表示。
[^11]: C23 以前并没有这个值，我们需要使用 <code>SIZE_MAX</code>（见前文）。<code>SIZE_WIDTH</code> 可以推导出 <code>SIZE_MAX</code>。类似地，既然如今符号表示固定为二补码，只要知道这一点，就能推导所有整数类型的最小值和最大值。

### 5.1.4 优化

具体可执行程序究竟如何遵循抽象状态机的描述，留给编译器开发者自行决定。大多数现代 C 编译器生成的代码并不会逐字逐句地遵循代码处方：它们会在所有可行之处“取巧”，只尊重抽象状态机的可观察状态。例如，由常量值参与的一串加法：

~~~c
x += 5;
/* 与此同时做一些不使用 x 的事情。 */
x += 7;
~~~

在许多情况下，可以如同写成以下形式那样执行：

~~~c
/* 做一些不使用 x 的事情。 */
x += 12;
~~~

或者：

~~~c
x += 12;
/* 做一些不使用 x 的事情。 */
~~~

只要结果不存在可观察差异，编译器就可以改变执行顺序。例如，只要我们不打印 <code>x</code> 的中间值，也不把这个中间值用于其他计算，就可以这样做。

不过，如果编译器无法证明某项操作不会迫使程序终止，那么这种优化也可能被禁止。在这个示例中，关键很大程度上取决于 <code>x</code> 的类型。如果 <code>x</code> 的当前值可能接近该类型的上限，看似无害的操作 <code>x += 7</code> 就可能产生溢出。不同类型以不同方式处理溢出。正如我们已经看到的，无符号类型的溢出不是问题，合并后操作的结果总会与两个分开的操作一致。对于其他类型，例如有符号整数类型（<code>signed</code>）和浮点类型（<code>double</code>），溢出可能引发异常并终止程序。此时，就不能执行这种优化。

如前所述，程序描述与抽象状态机之间允许存在的这种余地，是一项极有价值的特性，通常称为“优化”。再加上相对简单的语言描述，这实际上是 C 能够胜过那些拥有大量花哨功能的其他编程语言的主要原因之一。上述讨论有一个重要结论。

::: tip 要点 5.1.4 #1
类型决定优化机会。
:::

## 5.2 基本类型

C 拥有一系列基本类型，还提供从它们构造“**派生类型**”的手段；我们将在第 6 章介绍派生类型。

主要由于历史原因，基本类型系统略显复杂，指定这些类型的语法也不完全直观。第一层说明完全由语言关键字完成，例如 <code>signed</code>、<code>int</code> 和 <code>double</code>。这一层主要按照 C 的内部机制组织。在此之上还有第二层说明，它通过头文件提供；我们已经见过 <code>size_t</code> 和 <code>bool</code> 等示例。第二层按照类型的语义组织，规定某个类型为程序员提供哪些性质。

我们先从这些类型的第一层说明开始。前面已经讨论过（要点 5.1.1 #1），C 中所有基本值都是数，但数有不同种类。作为首要区分，我们有两大数类，每一类又有两个子类：**无符号整数**、**有符号整数**、**实浮点数**与**复浮点数**。这四个类别各自包含若干类型。它们按“**精度**”区分，精度决定某个类型允许的有效值域。[^12] 表 5.1 概览了 18 种基本类型。

从表中可以看到，有六种类型不能直接参与算术，也就是“**窄类型**”。在算术表达式中考虑它们之前，它们会先被“**提升**”为较宽的类型。如今，在任何现实平台上，这种提升都会得到与窄类型值相同的 <code>signed int</code>，无论原窄类型是否有符号。

::: tip 要点 5.2 #1
执行算术之前，窄整数会提升为 <code>signed int</code>。
:::

请注意，窄整数类型中有两个醒目的成员：<code>char</code> 和 <code>bool</code>。前者是 C 用来处理文本中可打印字符的类型，后者保存真值 <code>false</code> 和 <code>true</code>。如前所述，在 C 看来，即使它们也不过是某种数。其余 12 种无需提升的类型恰好分属四个类别。

::: tip 要点 5.2 #2
四类基本类型各有三种互不相同、无需提升的类型。
:::

与许多人所认为的不同，C 标准并未规定这 12 种类型的精度，只对它们施加约束。它们取决于许多**由实现定义**的因素。

标准确实规定了一件事：各种有符号类型的可能值域，必须按照等级彼此包含：

~~~text
signed char ⊆ short ⊆ int ⊆ long ⊆ long long
~~~

但这种包含不必是严格包含。例如，在许多平台上，<code>int</code> 和 <code>long</code> 的值集合相同，尽管两者仍被视为不同类型。

六种无符号类型也有类似的包含关系：

~~~text
bool ⊆ unsigned char ⊆ unsigned short ⊆ unsigned
     ⊆ unsigned long ⊆ unsigned long long
~~~

不过请记住，无论执行何种算术或比较，窄无符号类型都会提升为 <code>signed int</code>，而不是这幅关系图可能暗示的 <code>unsigned int</code>。

比较有符号类型与无符号类型的范围要困难得多。显然，无符号类型绝不可能包含有符号类型的负值。对于非负值，相同等级的类型具有如下包含关系：

~~~text
有符号类型的非负值 ⊆ 无符号类型的值
~~~

也就是说，对于给定等级，有符号类型的非负值都能装入无符号类型。在你会遇到的任何现代平台上，这都是严格包含：无符号类型拥有一些无法装入有符号类型的值。例如，一对常见的最大值是：<code>signed int</code> 为 2³¹ − 1 = 2,147,483,647，<code>unsigned int</code> 为 2³² − 1 = 4,294,967,295。

整数类型之间的关系取决于平台，因此要以可移植方式为特定用途选择“最佳”类型，可能相当繁琐。幸好，编译器实现可以提供帮助：它给出 <code>size_t</code> 之类的 <code>typedef</code>，用来表示特定性质。

::: tip 要点 5.2 #3
大小、基数或序数应使用 <code>size_t</code>。
:::

无符号类型最为方便，因为只有它们的算术始终按照数学性质中的模运算来定义。无符号溢出不会引发信号，也最利于优化。第 5.7.1 节将更详细地介绍它们。

::: tip 要点 5.2 #4
对不可能为负的小数量使用 <code>unsigned</code>。
:::

如果程序所需的值可能为正或负，但不包含小数部分，应使用有符号类型（见第 5.7.5 节）。

::: tip 要点 5.2 #5
对带符号的小数量使用 <code>signed</code>。
:::

::: tip 要点 5.2 #6
对带符号的大差值使用 <code>ptrdiff_t</code>。
:::

如果要对 <code>0.5</code> 或 <code>3.771’89E+89</code> 之类的值进行小数计算，请使用浮点类型（见第 5.7.8 节）。

::: tip 要点 5.2 #7
浮点计算使用 <code>double</code>。
:::

::: tip 要点 5.2 #8
复数计算使用 <code>double complex</code>。
:::

| <code>size_t</code>    | <code>&lt;stddef.h&gt;</code> |                                                     | “大小”和基数所用类型           |
| <code>ptrdiff_t</code> | <code>&lt;stddef.h&gt;</code> |                                                     | 大小之差所用类型               |
| <code>uintmax_t</code> | <code>&lt;stdint.h&gt;</code> |                                                     | 预处理器使用的无符号整数类型   |
| <code>intmax_t</code>  | <code>&lt;stdint.h&gt;</code> |                                                     | 预处理器使用的有符号整数类型   |
| <code>time_t</code>    | <code>&lt;time.h&gt;</code>   | <code>time(0)</code>、<code>difftime(t1, t0)</code> | 从纪元起计、以秒表示的日历时间 |
| <code>clock_t</code>   | <code>&lt;time.h&gt;</code>   | <code>clock()</code>                                | 处理器时间                     |

C 标准还定义了许多其他类型，其中也包括模拟专门使用场景的算术类型。表 5.2 列出了一部分。中间一对类型表示预处理器执行所有算术或比较时所用的类型。C23 以前，它们是编译器所支持的最大宽度类型；如今这一限制已经放宽，在某些情况下，可能存在更宽的扩展整数类型（见第 5.7.6 节）。

<code>time_t</code> 和 <code>clock_t</code> 用于处理时间。它们属于语义类型，因为时间计算的精度可能因平台而异。若要取得一个以秒为单位、能够参与算术的时间，可以使用 <code>difftime</code> 函数：它计算两个时间戳之差。<code>clock_t</code> 值呈现平台的处理器时钟周期模型，因此其时间单位通常远小于一秒；可以使用 <code>CLOCKS_PER_SEC</code> 把这类值转换为秒。

[^12]: 这里的“精度”仅采用 C 标准所定义的狭义含义，它不同于浮点计算的准确度。

## 5.3 指定值

我们已经见过多种指定数值常量（**字面量**）的方法：

<dl>
<dt><code>123</code>　十进制整数字面量</dt>
<dd>对我们大多数人而言，这是最自然的选择。</dd>

<dt><code>077</code>　八进制整数字面量</dt>
<dd>它由一串数字指定，第一个数字是 <code>0</code>，后续数字介于 <code>0</code> 到 <code>7</code> 之间。例如，<code>077</code> 的值是 63。这种写法如今只有历史价值，很少使用。唯一常用的八进制字面量就是 <code>0</code> 本身。</dd>

<dt><code>0xFFFF</code>　十六进制整数字面量</dt>
<dd>它以 <code>0x</code> 开头，后跟由 <code>0</code>…<code>9</code> 和 <code>a</code>…<code>f</code> 组成的数字序列。例如，<code>0xbeaf</code> 的值是 48,815。<code>a</code>…<code>f</code> 和 <code>x</code> 也可以大写，例如 <code>0XBEAF</code>。</dd>

<dt><code>0b1010</code>　二进制整数字面量</dt>
<dd>它以 <code>0b</code> 开头，后跟由 <code>0</code> 或 <code>1</code> 组成的数字序列。例如，<code>0b1010</code> 的值是 10。开头的 <code>0b</code> 也可以写成 <code>0B</code>。二进制字面量由 C23 引入。</dd>

<dt><code>1.7E-13</code>　十进制浮点字面量</dt>
<dd>带小数点的形式十分熟悉，但它也有带指数的“科学记数法”。一般形式 <code>mEe</code> 解释为 m · 10ᵉ。</dd>

<dt><code>0x1.7aP-13</code>　十六进制浮点字面量</dt>
<dd>这种字面量通常用来描述容易获得精确表示的浮点值。一般形式 <code>0XhPe</code> 解释为 h · 2ᵉ，其中 h 写成十六进制小数，指数 e 仍写成十进制数。</dd>

<dt><code>'a'</code>　整数字符字面量</dt>
<dd>字符放在撇号 <code>'</code> 之间，例如 <code>'a'</code> 或 <code>'?'</code>。它们的值只由 C 标准间接固定。例如，<code>'a'</code> 对应拉丁字母字符 a 的整数编码。字符字面量中的反斜线 <code>\</code> 具有特殊意义；例如，我们已经见过表示换行符的 <code>'\n'</code>。</dd>

<dt><code>"hello"</code>　**字符串字面量**</dt>
<dd>它指定文本，例如 <code>printf</code> 和 <code>puts</code> 函数所需的文本。与字符字面量一样，反斜线 <code>\</code> 具有特殊意义。[^13]</dd>
</dl>

除了最后一种，所有字面量都是数值常量，也就是指定数的常量。[^14] 字符串字面量是例外，它可以指定编译期已知的文本。若不允许把字符串字面量拆成若干段，把大段文本集成到代码里将十分繁琐：

~~~c
puts("first line\n"
     "another line\n"
     "first and "
     "second part of the third line");
~~~

::: tip 要点 5.3 #1
相邻的字符串字面量会连接在一起。
:::

数的规则要稍微复杂一些。

::: tip 要点 5.3 #2
数值字面量从不为负。
:::

也就是说，如果写出 <code>-34</code> 或 <code>-1.5E-23</code>，开头的符号并不是数字的一部分，而是作用于其后数字的取负运算符。很快就会看到，这一点在何处至关重要。听起来虽然古怪，但指数中的负号确实属于浮点字面量的一部分。

我们已经看到（要点 5.1.2 #1），所有字面量不仅有值，还有类型。不要把“字面量具有正值”与其类型混为一谈；它的类型完全可能是有符号类型。

::: tip 要点 5.3 #3
十进制整数字面量是有符号的。
:::

这是一项重要性质：我们大概会期望表达式 <code>-1</code> 是一个有符号负值。

为了确定整数字面量的确切类型，C 总是采用“首个适配”规则。

::: tip 要点 5.3 #4
十进制整数字面量采用三种有符号类型中第一个能够容纳其值的类型。
:::

这条规则可能产生令人惊讶的效果。假设某个平台上 <code>signed</code> 的最小值是 −2¹⁵ = −32,768，最大值是 2¹⁵ − 1 = 32,767。字面量 <code>32’768</code> 无法装入 <code>signed</code>，所以它的类型是 <code>signed long</code>。因此，表达式 <code>-32’768</code> 的类型是 <code>signed long</code>。于是，在这样的平台上，<code>signed</code> 类型的最小值无法写成一个字面量。 

::: details 练习 15
证明：如果 <code>signed long long</code> 的最小值和最大值具有类似性质，那么该平台的最小整数值无法写成一个字面量与负号的组合。
:::

::: tip 要点 5.3 #5
同一个值可以具有不同类型。
:::

推导二进制、八进制或十六进制字面量的类型要更复杂一些。如果值无法装入有符号类型，这些字面量也可以采用无符号类型。在前面的示例中，十六进制字面量 <code>0x7FFF</code> 的值是 32,767，因此类型是 <code>signed</code>。与十进制字面量不同，字面量 <code>0x8000</code>（以十六进制写出的值 32,768）是 <code>unsigned</code>，表达式 <code>-0x8000</code> 仍然是 <code>unsigned</code>。

::: details 练习 16
证明：如果 <code>unsigned</code> 的最大值是 2¹⁶ − 1，那么 <code>-0x8000</code> 的值仍是 32,768。
:::

::: tip 要点 5.3 #6
不要用二进制、八进制或十六进制字面量表示负值。
:::

因此，负值只剩下一种选择。

::: tip 要点 5.3 #7
负值应使用十进制字面量。
:::

**表 5.3　假定 <code>signed</code> 和 <code>unsigned</code> 采用常见的 32 位表示时，若干字面量及其类型**

|                   字面量 x |             值 | 类型                     |        −x 的值 |
| -------------------------: | -------------: | ------------------------ | -------------: |
| <code>2’147’483’647</code> | +2,147,483,647 | <code>signed</code>      | −2,147,483,647 |
| <code>2’147’483’648</code> | +2,147,483,648 | <code>signed long</code> | −2,147,483,648 |
| <code>4’294’967’295</code> | +4,294,967,295 | <code>signed long</code> | −4,294,967,295 |
|   <code>0x7FFF’FFFF</code> | +2,147,483,647 | <code>signed</code>      | −2,147,483,647 |
|   <code>0x8000’0000</code> | +2,147,483,648 | <code>unsigned</code>    | +2,147,483,648 |
|   <code>0xFFFF’FFFF</code> | +4,294,967,295 | <code>unsigned</code>    |             +1 |
|             <code>1</code> |             +1 | <code>signed</code>      |             −1 |
|            <code>1U</code> |             +1 | <code>unsigned</code>    | +4,294,967,295 |

一个常见错误是把十六进制字面量赋给 <code>signed</code>，并期望它表示负值。考虑声明 <code>int x = 0xFFFF’FFFF</code>。这种写法假定十六进制值具有与有符号值 −1 相同的二进制表示。在采用 32 位 <code>signed</code> 的大多数体系结构上，这一点成立（但并非全部）。然而，没有任何规则保证实际值 +4,294,967,295 会转换成值 −1。表 5.3 给出了一些值得注意的字面量、值和类型。

因此，可选前缀（<code>0</code>、<code>0b</code> 或 <code>0x</code>）不仅指定读取整数字面量时所用的进制，还可能间接影响推导出的类型。可以在字面量末尾追加后缀来改变这种推导结果。

**表 5.4　整数字面量的后缀及其类型**

| 后缀                               | 类型                                           |
| ---------------------------------- | ---------------------------------------------- |
| <code>l</code> 或 <code>L</code>   | 至少为 <code>long</code>                       |
| <code>ll</code> 或 <code>LL</code> | <code>long long</code>                         |
| <code>wb</code> 或 <code>WB</code> | 对某个足够大的 N，采用 <code>_BitInt(N)</code> |
| <code>u</code> 或 <code>U</code>   | 强制采用无符号类型                             |

例如，<code>1U</code> 的值为 1，类型为 <code>unsigned</code>；<code>1L</code> 的类型是 <code>signed long</code>；<code>1ULL</code> 的值同样为 1，但类型是 <code>unsigned long long</code>。请注意，本书用等宽字体表示 <code>1ULL</code> 之类的 C 字面量，以区别于用普通字体表示的数学值 1。

::: details 练习 17
证明：表达式 <code>-1U</code>、<code>-1UL</code> 和 <code>-1ULL</code> 分别具有三种无需提升的无符号类型，并分别取这些类型的最大值。
:::

有了后缀，就可以强制整数字面量采用某个最低等级的类型。对于十进制整数字面量，如果有一个 <code>l</code> 或 <code>L</code>，那么值能装入时类型为 <code>long</code>，否则为 <code>long long</code>。如果有两个（<code>ll</code> 或 <code>LL</code>），类型固定为 <code>long long</code>。对于带前缀的整数字面量（<code>0</code>、<code>0b</code> 或 <code>0x</code>），视其值而定，这些后缀仍可能得到 <code>unsigned long</code> 或 <code>unsigned long long</code>。要强制采用无符号类型，可以把 <code>u</code> 或 <code>U</code> 加入后缀。

C23 引入的后缀 <code>wb</code> 或 <code>WB</code> 强制字面量采用特定的位精确类型。它可以与 <code>u</code> 或 <code>U</code> 组合；无论采用什么进制，只有这种后缀能保证得到指定符号性的类型。我们稍后会在第 5.7.7 节介绍这些类型。

请记住，值 0 十分重要。它重要到拥有许多等价写法：<code>0</code>、<code>0x0</code> 和 <code>'\0'</code> 都是同一个值，即类型为 <code>signed int</code> 的 0。零没有十进制整数之外的特殊写法：<code>0.0</code> 是值 0 的十进制写法，但它被视为类型为 <code>double</code> 的浮点值。

::: tip 要点 5.3 #8
不同字面量可以具有相同的值。
:::

对于整数，这条规则看起来近乎不言自明；对于浮点字面量，却没有那么明显。浮点值只是其字面量所表示之值的近似，因为小数部分的二进制位可能被截断或舍入。

::: tip 要点 5.3 #9
十进制浮点字面量的实际值可能不同于其字面值。
:::

例如，在我的机器上，字面量 <code>0.2</code> 的值是：

~~~text
0.200,000,000,000,000,011,1
~~~

因此，字面量 <code>0.2</code> 和 <code>0.200’000’000’000’000’011’1</code> 具有相同的值。

十六进制浮点字面量旨在更好地对应浮点值的二进制表示。事实上，在大多数现代体系结构上，只要这种字面量的位数不过多，它就会与字面值精确对应。遗憾的是，这些怪物对普通人几乎不可读。例如，考虑两个字面量：

~~~text
0x1.9999’9AP-3
0xC.CCCC’CCCC’CCCC’CCDP-6
~~~

它们分别对应：

~~~text
1.600,000,023,84 × 2⁻³
12.800,000,000,000,000,000,2 × 2⁻⁶
~~~

因此，以十进制浮点数表示时，它们的值近似为：

~~~text
0.200,000,002,98
0.200,000,000,000,000,000,003
~~~

两个字面量的值非常接近，但其十六进制浮点字面量表示看起来却相距甚远。

最后，浮点字面量后面可以跟 <code>f</code> 或 <code>F</code>，表示 <code>float</code>；也可以跟 <code>l</code> 或 <code>L</code>，表示 <code>long double</code>。没有后缀时，类型为 <code>double</code>。请注意，对于同一个字面文本，不同字面量类型通常会得到不同的值。下面是一个典型示例：

|        | <code>float</code>           | <code>double</code>                 | <code>long double</code>                |
| ------ | ---------------------------- | ----------------------------------- | --------------------------------------- |
| 字面量 | <code>0.2F</code>            | <code>0.2</code>                    | <code>0.2L</code>                       |
| 值     | <code>0x1.9999’9AP-3F</code> | <code>0x1.9999’9999’9999AP-3</code> | <code>0xC.CCCC’CCCC’CCCC’CCDP-6L</code> |

::: tip 要点 5.3 #A
字面量具有值、类型和二进制表示。
:::

[^13]: 在 <code>printf</code> 函数的语境中，另一个字符也会变得“特殊”：<code>%</code>。如果想用 <code>printf</code> 打印字面字符 <code>%</code>，必须把它写两遍。
[^14]: 你可能已经注意到，这份清单没有列出复数。第 5.3.1 节会介绍怎样指定复数。

### 5.3.1 复数常量

并非所有 C 平台都一定支持复数类型。可以检查 <code>__STDC_NO_COMPLEX__</code> 来确认这一点。要获得复数类型的完整支持，应包含头文件 <code>&lt;complex.h&gt;</code>。如果数值函数使用了 <code>&lt;tgmath.h&gt;</code>，这一包含已经隐式完成。

遗憾的是，C 没有直接指定复数类型值的标准字面量。它只提供若干宏，[^18] 让这类类型更容易使用。

指定复数值的第一种方式是宏 <code>CMPLX</code>，它把两个浮点值——实部和虚部——组合成一个复数值。例如，<code>CMPLX(0.5, 0.5)</code> 是一个 <code>double complex</code> 值，实部与虚部均为二分之一。类似地，还有用于 <code>float complex</code> 的 <code>CMPLXF</code>，以及用于 <code>long double complex</code> 的 <code>CMPLXL</code>。

另一种更方便的方式由宏 <code>I</code> 提供。它表示一个类型为 <code>float complex</code> 的常量值，使 <code>I\*I</code> 的值为 −1。程序经常使用由单个大写字母构成的宏名表示在整个程序中固定不变的数。单独来看，这并不是高明的主意（单字母名称的数量有限），而你尤其应当避开 <code>I</code>。

::: tip 要点 5.3.1 #1
<code>I</code> 保留用于虚数单位。
:::

可以使用 <code>I</code>，以接近通常数学记法的方式指定复数类型常量。例如，<code>0.5 + 0.5\*I</code> 的类型是 <code>double complex</code>，<code>0.5F + 0.5F\*I</code> 的类型是 <code>float complex</code>。如果实部和虚部混用了例如 <code>float</code> 与 <code>double</code> 字面量，编译器会把结果隐式转换为两种类型中较宽的那一种。另一种编码复数常量的方式是使用复数字面量：在浮点字面量后附加一个 <code>i</code>，例如 <code>0.5i</code> 或 <code>0.5IF</code>。尽管如今已有广泛支持，遗憾的是，这种字面量形式（尚）未标准化，因此不能依赖它。

::: info 挑战 5：复数
你能否把求导程序（挑战 2）扩展到复数域，也就是编写接收并返回 <code>double complex</code> 值的函数？
:::

[^18]: 第 5.6.3 节将说明宏究竟是什么。现在，只需把它们看作编译器赋予某些特定性质的名称。

## 5.4 隐式转换

从示例中可以看到，操作数的类型会影响运算符表达式的类型，例如 <code>-1</code> 和 <code>-1U</code>。前者是 <code>signed int</code>，后者是 <code>unsigned int</code>。对初学者而言，后者尤其令人意外：<code>unsigned int</code> 没有负值，因此 <code>-1U</code> 的值是一个很大的正整数。

::: tip 要点 5.4 #1
一元 <code>-</code> 和 <code>+</code> 的类型，就是其提升后操作数的类型。
:::

因此，这两个运算符通常不会改变类型。在它们确实改变类型的场合，我们必须依靠 C 的隐式转换策略：把具有特定类型的值转到所需类型。仍假定 −2,147,483,648 和 2,147,483,647 分别是 <code>signed int</code> 的最小值与最大值，来看以下示例：

~~~c
double         a = 1;              // 无害：值能装入该类型
signed short   b = -1;             // 无害：值能装入该类型
signed int     c = 0x8000’0000;    // 危险：值对该类型过大
signed int     d = -0x8000’0000;   // 危险：值对该类型过大
signed int     e = -2’147’483’648; // 无害：值能装入该类型
unsigned short g = 0x8000’0000;    // 丢失信息：结果值为 0
~~~

<code>a</code> 和 <code>b</code> 的初始化无害。相应值完全位于目标类型的范围内，因此 C 编译器可以静默地转换它们。

接下来，对 <code>c</code> 和 <code>d</code> 的两次转换都有问题。正如已经看到的，<code>0x8000’0000</code> 的类型是 <code>unsigned int</code>，无法装入 <code>signed int</code>。所以，<code>c</code> 得到一个由实现定义的值；我们必须知道平台决定怎样处理这种情况。它可能只是复用右侧值的位模式，也可能终止程序。与所有由实现定义的性质一样，平台应当把所选方案写入文档；但要注意，这种选择可能随编译器的新版本改变，也可能由编译器实参切换。

对于 <code>d</code>，情况甚至更加复杂。<code>0x8000’0000</code> 的值是 2,147,483,648，我们可能以为 <code>-0x8000’0000</code> 就是相应负值。但由于 <code>-0x8000’0000</code> 的实际结果仍是 2,147,483,648，它会遇到与 <code>c</code> 相同的问题。

::: details 练习 19
假定 <code>unsigned int</code> 的最大值是 <code>0xFFFF’FFFF</code>，证明 <code>-0x8000’0000 == 0x8000’0000</code>。
:::

而 <code>e</code> 又是无害的。因为我们使用了 <code>-2’147’483’648</code>：这是一个取负后的十进制字面量，类型为 <code>signed long</code>，实际值也正合预期。这个值能装入 <code>signed int</code>，所以转换毫无问题。

最后一个关于 <code>g</code> 的示例，其后果较为含混。对无符号类型而言，过大的值按照模转换。具体到这里，如果假定 <code>unsigned short</code> 的最大值是 2¹⁶ − 1，结果值就是 0。这样的“窄化”转换是否符合预期，往往难以判断。

::: tip 要点 5.4 #2
避免窄化转换。
:::

::: tip 要点 5.4 #3
不要用窄类型执行算术。
:::

对于加法和乘法等具有两个操作数的运算符，类型规则还会更复杂，因为两个操作数可能具有不同类型。下面是一些涉及浮点类型的操作：

~~~c
1       + 0.0  // 无害；double
1       + I    // 无害；complex float
INT_MAX + 0.0F // 可能损失精度；float
INT_MAX + I    // 可能损失精度；complex float
INT_MAX + 0.0  // 通常无害；double
~~~

前两个示例无害：整数字面量 1 的值完全能装入 <code>double</code> 或 <code>complex float</code>。事实上，在大多数这样的混合操作中，只要一种类型的范围能装入另一种类型，结果就采用范围较宽的类型。

接下来两个示例有问题，因为 <code>INT_MAX</code>（<code>signed int</code> 的最大值）通常无法装入 <code>float</code> 或 <code>complex float</code>。例如，在我的机器上，<code>INT_MAX + 0.0F</code> 与 <code>INT_MAX + 1.0F</code> 相同。最后一行说明，在大多数平台上，使用 <code>double</code> 执行该操作不会出问题。不过，在现有或未来采用 64 位 <code>int</code> 的平台上，仍可能出现类似的精度问题。

由于不同整数类型的值域并不存在严格的包含关系，推导混合有符号值和无符号值之操作的类型可能极其棘手：

~~~c
-1   < 0   // true，无害，符号性相同
-1L  < 0   // true，无害，符号性相同
-1U  < 0U  // false，无害，符号性相同
-1   < 0U  // false，危险，符号性混合
-1U  < 0   // false，危险，符号性混合
-1L  < 0U  // 结果依平台而定，危险，符号性相同或混合
-1LL < 0UL // 结果依平台而定，危险，符号性相同或混合
~~~

前三项比较是无害的，因为即使混用了不同类型的操作数，也没有混合符号性。对于这些情况，各种可能值的范围彼此整齐地包含，C 只需把另一个类型转换成较宽类型，再在该类型中比较。

接下来两项比较的结果明确无误，却可能不符合缺乏经验者的预期。事实上，两项比较中的所有操作数都会转换为 <code>unsigned int</code>。因此，两个取负后的值都转换成很大的无符号值，比较结果为 <code>false</code>。

最后两项比较的问题更大。在满足

~~~text
INT_WIDTH < LONG_WIDTH
~~~

的平台上，<code>0U</code> 会转换成 <code>0L</code>，因此倒数第二项比较为 <code>true</code>。而在满足

~~~text
INT_WIDTH == LONG_WIDTH
~~~

的平台上，<code>-1L</code> 会转换成 <code>-1U</code>（即 <code>UINT_MAX</code>），因此该比较为 <code>false</code>。最后一项比较也有类似结论，但要注意，这两项比较很可能并不会得到相同结果。

最后两项这样的示例，可能引发支持或反对有符号类型与无符号类型的无休止争论。但它们只说明一件事：混合有符号操作数与无符号操作数时，语义并不总是清晰。有些情况下，无论选择哪一种隐式转换，都会产生问题。

::: tip 要点 5.4 #4
避免对符号性不同的操作数执行操作。
:::

::: tip 要点 5.4 #5
只要能够做到，就使用无符号类型。
:::

::: tip 要点 5.4 #6
选择算术类型时，应确保隐式转换无害。
:::

## 5.5 初始化器

我们已经看到（第 2.3 节），初始化器是对象定义的重要组成部分。初始化器有助于保证程序执行始终处于已定义状态，使我们每次访问对象时，它都具有一个确定抽象状态机状态的已知值。

::: tip 要点 5.5 #1
所有对象都应初始化。
:::

这条规则唯一的例外，应当只留给必须高度优化的代码。[^20] 对于目前我们能够编写的大部分代码，现代编译器都能把一个值追溯到其最后一次赋值或初始化。多余的初始化或赋值会被直接优化掉。

对于整数和浮点数等标量类型，初始化器只包含一个可以转换到相应类型的表达式。我们已经见过许多这样的示例。初始化表达式外也可以选择性地加上 <code>{}</code>：

~~~c
double a = 7.8;
double b = 2 * a;
double c = { 7.8 };
double d = { 0 };
~~~

其他类型的初始化器必须包含这些 <code>{}</code>。例如，数组初始化器包含各个元素的初始化器，每项后面都有逗号：

~~~c
double A[] = { 7.8, };
double B[3] = { 2 * A[0], 7, 33, };
double C[] = { [0] = 6, [3] = 1, };
~~~

~~~text
      [0]
A  double 7.8

      [0]         [1]         [2]
B  double 15.6  double 7.0  double 33.0

      [0]        [1]        [2]        [3]
C  double 6.0  double 0.0  double 0.0  double 1.0
~~~

如前所述，如果没有长度说明，数组就具有“**不完整类型**”。随后，初始化器会补全该类型，彻底确定数组长度。这里，<code>A</code> 只有一个元素，<code>C</code> 则有四个元素。对于前两个初始化器，标量初始化作用于哪个元素，由它在列表中的位置推导；例如，<code>B[1]</code> 初始化为 7。<code>C</code> 采用的形式称为“指派初始化器”。它们远为可取，因为即使声明发生小幅变化，也更容易保持代码稳健。

::: tip 要点 5.5 #2
所有聚合数据类型都应使用指派初始化器。
:::

如果不知道怎样初始化类型 <code>T</code> 的对象，**默认初始化器**：

~~~c
T a = { }
~~~

总能完成任务。

::: tip 要点 5.5 #3
<code>{ }</code> 对所有对象都是有效的初始化器。
:::

这项特性直到 C23 才引入；此前必须使用 <code>{0}</code>，并且要经过相当复杂的推理才能说明它为什么有效。默认初始化器也可以用于变长数组（见第 6.1.3 节），而变长数组过去没有初始化器语法。

在初始化器中，我们经常需要指定一些对程序具有特定含义的值。

[^20]: 自 C23 起，即使变长数组（VLA；见第 6.1.3 节）也可以用默认初始化器初始化。

## 5.6 具名常量

即使在小程序中，也经常会遇到这样的问题：某些特殊值反复出现在代码各处，用于特定目的。一旦这些值因某种原因发生变化，程序就会支离破碎。来看一个人为构造的情境：我们有几个字符串数组，[^21] 并希望对它们执行一些操作。

~~~c
char const*const bird[3] = {
  "raven",
  "magpie",
  "jay",
};
char const*const pronoun[3] = {
  "we",
  "you",
  "they",
};
char const*const ordinal[3] = {
  "first",
  "second",
  "third",
};
...
for (unsigned i = 0; i < 3; ++i)
  printf("Corvid %u is the %s\n", i, bird[i]);
...
for (unsigned i = 0; i < 3; ++i)
  printf("%s plural pronoun is %s\n", ordinal[i], pronoun[i]);
~~~

这里在多处使用常量 3，而它具有三种彼此并无多少关联的“含义”。例如，在鸦科鸟类集合中增加一种鸟，需要分别修改两处代码。在真实环境里，代码中可能有更多位置依赖这个特定值；对于大型代码库，维护工作会相当繁琐。

::: tip 要点 5.6 #1
具有特定含义的所有常量都必须命名。
:::

同样重要的是，应当区分那些恰好相等、但含义不同的常量。

::: tip 要点 5.6 #2
含义不同的所有常量都必须彼此区分。
:::

早期 C 用来指定具名常量的手段少得出奇，它的术语甚至使“哪些构造实际上会产生编译期常量”这个问题充满混乱。因此，我们首先要理清术语（第 5.6.1 节），然后考察 C 在 C23 以前唯一真正的具名常量：枚举常量（第 5.6.2 节）。后者有助于把示例中几个用途不同的 3 替换成更具说明力的内容。第二种通用机制以简单的文本替换补充了这一功能：宏（第 5.6.3 节）。只有当替换内容由前文所见基本类型的字面量组成时，宏才会产生编译期常量。最后，我们还会区分一种称为复合字面量的无名临时对象（第 5.6.4 节），以及 C23 新增的 <code>constexpr</code> 对象；后者同样可以充当真正的具名或无名常量（第 5.6.5 节）。

[^21]: 这里用类型为 <code>char const\*const</code> 的指针引用字符串。稍后会看到这种具体技巧如何工作。

### 5.6.1 只读对象

不要把“常量”一词与不可修改的对象混为一谈；“常量”在 C 中具有非常明确的含义。例如，在前面的代码中，按照这里的术语，<code>bird</code>、<code>pronoun</code> 和 <code>ordinal</code> 都不是常量，而是 <code>const</code> **限定**的对象。这个限定符规定我们无权改变该对象。对于 <code>bird</code>，数组项和实际字符串都不能修改；如果试图修改，编译器应当给出诊断。

::: tip 要点 5.6.1 #1
具有 <code>const</code> 限定类型的对象是只读的。
:::

这并不意味着编译器或运行时系统绝不会改变这种对象的值：程序的其他部分可能以不带该限定的方式看到同一对象，并对它进行修改。你不能直接改写银行账户余额（只能读取它），并不意味着余额会永远不变。

还有一类只读对象，它们的类型却不幸没有保护它们免遭修改：字符串字面量。

::: tip 要点 5.6.1 #2
字符串字面量是只读的。
:::

如果今天才引入字符串字面量，它的类型几乎肯定会是 <code>char const[]</code>，也就是由 <code>const</code> 限定字符组成的数组。遗憾的是，<code>const</code> 关键字加入 C 语言的时间远晚于字符串字面量；为保持向后兼容，事情就这样保留了下来。[^22]

<code>bird</code> 这样的数组还使用了另一种处理字符串字面量的技术。它使用**指针**类型 <code>char const\*const</code> “引用”字符串字面量。这样的数组可以表示为：

~~~text
         [0]                [1]                [2]
bird  char const*const   char const*const   char const*const
          ↓                  ↓                   ↓
       "raven"            "magpie"              "jay"
~~~

也就是说，字符串字面量本身并不存储在 <code>bird</code> 数组内部，而是存放在其他位置；<code>bird</code> 只引用那些位置。很久以后，我们会在第 6.2 节和第 11 章看到这种机制如何工作。

自 C23 起，还有一种由关键字 <code>constexpr</code> 标示的构造，它同样会产生只读对象。但与仅由 <code>const</code> 限定的对象不同，这些对象保证永不改变，其值在编译期已知。主要区别可以从以下示例中看出：

~~~c
extern double const factor;
constexpr double π = 3.141’592’653’589’793’238’46;
~~~

<code>factor</code> 的声明只告诉我们（以及编译器）：某处存在一个我们无权改变的 <code>double</code> 对象。何时、何地确定它的值并未指定。另一方面，<code>π</code> 的值随声明一并给出，并且在整个程序编译期间保持稳定。稍后将更详细地介绍 <code>constexpr</code>。[^23]

[^22]: 还存在第三类只读对象：临时对象。第 13.2.2 节将介绍它们。
[^23]: 还要注意，现代平台应当支持使用 π 这样的非拉丁字符。如果编译器不支持，请考虑升级到更新的平台。

### 5.6.2 枚举

C 有一种简单机制，可以像示例所需的那样为小整数命名，这种机制称为“**枚举**”：

~~~c
enum corvid { magpie, raven, jay, corvid_num, };
char const*const bird[corvid_num] = {
  [raven] = "raven",
  [magpie] = "magpie",
  [jay] = "jay",
};
...
for (unsigned i = 0; i < corvid_num; ++i)
  printf("Corvid %u is the %s\n", i, bird[i]);
~~~

这段代码声明了一个新的整数类型 <code>enum corvid</code>，我们知道它有四个不同的值。你可能已经猜到，按位置确定的值从 0 开始：在示例中，<code>magpie</code> 的值为 0，<code>raven</code> 为 1，<code>jay</code> 为 2，<code>corvid_num</code> 为 3。最后这个 3 显然就是我们关注的那个 3。

::: tip 要点 5.6.2 #1
枚举常量要么具有显式指定的值，要么具有按位置确定的值。
:::

~~~text
           [magpie]             [raven]              [jay]
bird    char const*const     char const*const     char const*const
              ↓                   ↓                    ↓
          "magpie"             "raven"                "jay"
~~~

请注意，这里数组项的顺序与之前不同。这正是枚举方法的优点之一：无须人工跟踪数组使用的顺序。枚举类型中固定的次序会自动完成这件事。

现在，如果想增加另一种鸦科鸟，只需把它放进列表中 <code>corvid_num</code> 之前的任意位置。

**清单 5.1　一个枚举类型及其相关字符串数组**

~~~c
enum corvid { magpie, raven, jay, chough, corvid_num, };
char const*const bird[corvid_num] = {
  [chough] = "chough",
  [raven] = "raven",
  [magpie] = "magpie",
  [jay] = "jay",
};
~~~

对于这里给出的枚举类型，与大多数其他窄类型一样，声明该类型的对象其实没有多少吸引力；它们无论如何都会在索引和算术中转换为 <code>signed</code> 或 <code>unsigned</code>。甚至枚举常量本身也未必采用枚举类型。

::: tip 要点 5.6.2 #2
如果简单枚举类型的所有枚举常量都能装入 <code>signed int</code>，这些常量就具有该类型。
:::

因此，对于较小的值，真正有用的是常量，而不是新创建的类型。我们甚至无须为类型名提供**标记**，就能为所需的任意 <code>signed int</code> 常量命名：

~~~c
enum { p0 = 1, p1 = 2*p0, p2 = 2*p1, p3 = 2*p2, };
~~~

定义这些常量时，可以使用“**整数常量表达式**”（ICE）。ICE 提供编译期整数值，所受限制十分严格。它的值不仅必须能在编译期确定（不允许函数调用），而且值的计算不能把普通对象的求值作为操作数：

~~~c
signed const o42 = 42;
constexpr signed c42 = 42;
enum {
  b42 = 42,       // 正确：42 是字面量。
  c52 = o42 + 10, // 错误：o42 是对象。
  b52 = b42 + 10, // 正确：b42 不是对象。
  d52 = c42 + 10, // 正确：c42 是具名常量。
};
~~~

这里，<code>o42</code> 是对象，尽管具有 <code>const</code> 限定；因此，<code>c52</code> 的表达式不是“整数常量表达式”。而 <code>constexpr</code> 对象 <code>c42</code> 可以自由用于这种语境。

::: tip 要点 5.6.2 #3
整数常量表达式只能对声明为 <code>constexpr</code> 的对象求值。
:::

因此，从原则上说，ICE 可以由整数与枚举字面量、枚举常量、<code>constexpr</code> 对象、<code>alignof</code>[^24] 与 <code>offsetof</code> 子表达式，以及某些 <code>sizeof</code> 子表达式上的任意操作组成。[^25]

C23 以前，即使某个值是 ICE，要用它定义枚举常量，也必须确保该值能装入 <code>signed int</code>。C23 改变了这一点。

::: tip 要点 5.6.2 #4
如果枚举常量无法装入 <code>signed int</code>，那么只要可能，枚举类型就会调整为能够存放所有枚举常量的类型。
:::

::: tip 要点 5.6.2 #5
如果枚举常量无法装入 <code>signed int</code>，这些常量就采用枚举类型。
:::

请注意，完全可能不存在能够容纳所有常量值的类型：

~~~c
enum tooLarge { minimus = LLONG_MIN, maximus = ULLONG_MAX, };
~~~

除非编译器找到一种比 <code>signed long long</code> 更宽的扩展整数类型，否则这一行很可能无法编译。

枚举类型会自动调整这一事实，在我们并不真正关心类型时可能很方便：

~~~c
enum wide { minimal = LONG_MIN, maximal = LONG_MAX, };
typedef enum wide wide;
~~~

<code>long</code> 是否比 <code>signed</code> 更宽取决于平台，所以 <code>wide</code> 的底层类型也可能视情况成为其中任意一种。C23 还引入了新语法，可以强制采用特定的底层类型：

~~~c
enum wider : long { minimer = LONG_MIN, maximer = LONG_MAX, };
typedef enum wider wider;
~~~

冒号后跟整数类型表示底层类型；即使各值原本都能装入 <code>signed</code>，这也会强制枚举常量采用枚举类型：

~~~c
enum narrow : unsigned char { zero, one, };
typedef enum narrow narrow;
~~~

枚举类型会调整到足以容纳其全部常量，这项性质可能对类型的使用者产生意外影响，大概不应滥用。因此，只要能够做到，最好显式指定底层整数类型。

::: tip 要点 5.6.2 #6
如果枚举常量有可能无法全部装入 <code>signed int</code>，就应指定枚举类型的底层整数类型。
:::

当底层类型既可能是有符号类型，也可能是无符号类型时，这一点尤其重要：

~~~c
enum large { down = 0, up = 0xFFFF’FFFF, }; // 有歧义，不要使用
typedef enum large large;
~~~

这里，常量 <code>0xFFFF’FFFF</code> 可能采用 <code>signed</code>、<code>unsigned</code>、<code>signed long</code>、<code>unsigned long</code>、<code>signed long long</code> 或 <code>unsigned long long</code> 中的任意类型，具体取决于 <code>signed int</code> 的宽度；底层整数类型因而也可能成为其中任意一种。对于偶尔阅读代码的人，最好明确写出意图：

~~~c
enum eInt : signed int { dInt = 0, uInt = 0xFFFF’FFFF, };
typedef enum eInt eInt;
enum eSig : typeof(4’294’967’295) {
  dSig = 0,
  uSig = 4’294’967’295,
};
typedef enum eSig eSig;
enum e32 : uint32_t { d32 = 0, u32 = 0xFFFF’FFFF, };
typedef enum e32 e32;
~~~

只有当 <code>signed int</code> 的宽度大于 32 时，<code>eInt</code> 的第一个定义才能编译。<code>eSig</code> 的第二个定义使用 <code>typeof</code> 特性（很久以后，第 18 章会更详细地介绍它），明确表示我们需要十进制常量的类型；该类型始终有符号。<code>e32</code> 的第三个定义使用类型定义 <code>uint32_t</code>（见后文），表示所求类型是宽度至少为 32 的无符号类型。

[^24]: 自 C23 起使用 <code>alignof</code>；此前使用 <code>_Alignof</code>。
[^25]: 第 12.7 节和第 12.1 节将分别处理后两个概念。

### 5.6.3 宏

C23 以前，除 <code>signed int</code> 之外，C 语言没有其他机制可以严格声明其他类型的常量。C 提供的是另一种强大机制：对程序代码执行文本替换，也就是“**宏**”。宏由预处理器指令 <code>#define</code> 引入：

~~~c
# define M_PI 3.141’592’653’589’793’238’46
~~~

这个宏定义会使后续程序代码中的标识符 <code>M_PI</code> 替换为该 <code>double</code> 常量。这样的宏定义由五个不同部分组成：

1. 起始字符 <code>#</code>，它必须是该行第一个非空白字符；
2. 关键字 <code>define</code>；
3. 要声明的标识符，这里是 <code>M_PI</code>；
4. 替换文本，这里是 <code>3.141’592’653’589’793’238’46</code>；
5. 结尾的换行符。

借助这个技巧，我们可以为 <code>unsigned</code>、<code>size_t</code> 和 <code>double</code> 常量声明文本替换。事实上，由实现规定的 <code>size_t</code> 上限 <code>SIZE_MAX</code>，以及已经见过的许多其他系统特性，也都以这种方式定义：

~~~text
EXIT_SUCCESS、not_eq、complex……
~~~

本书通常用深红色印刷这些 C 标准宏。

C 标准中这些示例的拼写，并不能代表绝大多数软件项目普遍采用的约定。多数项目都有相当严格的规则，使宏在周围代码中一望可知。

::: tip 要点 5.6.3 #1
宏名全部使用大写字母。
:::

只有在理由充分时才偏离这条规则，尤其是在达到第 3 层之前不要偏离。

### 5.6.4 复合字面量

对于没有字面量可描述其常量的类型，事情会变得更复杂。在宏的替换侧，我们必须使用“复合字面量”。复合字面量具有如下形式：

~~~c
(T){ INIT }
~~~

也就是括号中的类型，后跟一个初始化器。下面是一个示例：

~~~c
# define CORVID_NAME /**/                    \
(char const*const[corvid_num]){              \
  [chough] = "chough",                       \
  [raven] = "raven",                         \
  [magpie] = "magpie",                       \
  [jay] = "jay",                             \
}
~~~

有了它，就可以省略 <code>bird</code> 数组，并重写循环：

~~~c
for (unsigned i = 0; i < corvid_num; ++i)
  printf("Corvid %u is the %s\n", i, CORVID_NAME[i]);
~~~

宏定义中的复合字面量可以帮助我们声明行为近似于所选类型常量的事物，但它并不是前面所讨论意义上的常量。

::: tip 要点 5.6.4 #1
复合字面量定义一个对象。
:::

总的来说，这种形式的宏有若干陷阱：

- 到目前为止所介绍的复合字面量不适用于 ICE。
- 就这里声明具名常量的目的而言，类型 <code>T</code> 应当具有 <code>const</code> **限定**。这使优化器拥有更多余地，为这种宏替换生成良好的二进制代码。
- 宏名与复合字面量的 <code>()</code> 之间必须至少有一个空格；这里用 <code>/\*\*/</code> 注释表示。否则，它会解释为函数式宏定义的开头。很久以后我们会介绍函数式宏。
- 行尾最后一个字符可以是反斜线 <code>&bsol;</code>，用来把宏定义延续到下一行。
- 宏定义末尾绝不能有 <code>;</code>。请记住，这一切都只是文本替换。

::: tip 要点 5.6.4 #2
不要把结尾分号藏进宏里。
:::

此外，为了让宏易读，请体谅偶尔阅读你代码的可怜人。

::: tip 要点 5.6.4 #3
把宏的续行标记右对齐到同一列。
:::

从示例可以看出，这有助于一眼辨明整个宏定义的范围。

### 5.6.5 <code>constexpr</code> 构造

在某些语境中，这些技巧并没有多大帮助。例如，我们可能需要为复杂类型提供具名常量，并把它用作文件作用域中的初始化器；这里的初始化器必须是常量表达式。C23 引入了 <code>constexpr</code> 构造，它既可以用于声明，也可以用于复合字面量。与前面宏 <code>M_PI</code> 等价的声明如下：

~~~c
constexpr double π = 3.141’592’653’589’793’238’46;
~~~

使用这样的 <code>constexpr</code> 有一个优点：常量在声明处就会接受编译期检查；导致值发生改变的转换属于错误。例如：

~~~c
constexpr unsigned πflat = 3.141’592’653’589’793’238’46; // 错误
~~~

这会产生编译错误，因为右侧转换为左侧的 <code>unsigned</code> 类型时，小数点后的有效数字丢失。

::: tip 要点 5.6.5 #1
<code>constexpr</code> 的初始化器必须精确适配。
:::

<code>constexpr</code> 也可用于复合字面量：

~~~c
# define CORVID_NAMES /**/                   \
(constexpr char[8][corvid_num]){             \
  [chough] = "chough",                       \
  [raven] = "raven",                         \
  [magpie] = "magpie",                       \
  [jay] = "jay",                             \
}
~~~

请注意，这里改成了一个包含 <code>corvid_num</code> 个元素的数组，而每个元素又是一个含 8 个字符的数组。每个 8 字符数组用指定值初始化，随后以零填充到末尾。因此，整个复合字面量可以概略表示如下：

~~~text
 [magpie]          [raven]           [jay]           [chough]
char const[8]    char const[8]    char const[8]    char const[8]
~~~

例如，第一个数组元素本身也是数组，可以表示为：

~~~text
   [0]             [1]             [2]             [3]
char const 'm'  char const 'a'  char const 'g'  char const 'p'  …
   [4]             [5]             [6]             [7]
char const 'i'  char const 'e'  char const 0    char const 0
~~~

借助 <code>constexpr</code>，编译器现在知道所有这些字符都不打算在执行期间发生改变，并且会隐含 <code>const</code> 限定。编译器可以利用这项知识提高程序效率——可能使程序在某种意义上更快，也可能减少空间占用。如果直接索引隐藏在宏后的数组（例如 <code>CORVID_NAMES[raven]</code>），就不需要整个数组；编译器可以只直接使用相应字符串字面量（这里是 <code>"raven"</code>）。更进一步，编译器可以让所有索引为 <code>raven</code> 的出现位置共享同一个字符串字面量 <code>"raven"</code>，让所有索引为 <code>magpie</code> 的位置共享另一个字面量，依此类推。

## 5.7 二进制表示

类型的二进制表示是一种模型，用来描述该类型可能具有的值。它不同于内存中的对象表示；对象表示描述的是给定类型的值在物理存储中或多或少具体的存放方式。

::: tip 要点 5.7 #1
同一个值可以具有不同的二进制表示。
:::

### 5.7.1 无符号整数

我们已经看到，无符号整数类型是这样一类算术类型：标准算术操作可以用简洁、封闭的数学方式描述。正如要点 4.2.2 #4 所述，它们对算术操作封闭。用数学术语说，它们实现了一个环 ℤ<sub>N</sub>，也就是对某个数 N 取模所得的整数集合。可表示值为 0, …, N − 1。最大值 N − 1 完全决定这种无符号整数类型；该值通过名称以 <code>_MAX</code> 结尾的宏提供。对于基本无符号整数类型，这些宏是 <code>UINT_MAX</code>、<code>ULONG_MAX</code> 和 <code>ULLONG_MAX</code>，由 <code>&lt;limits.h&gt;</code> 提供。已经见过的 <code>size_t</code> 上限是来自 <code>&lt;stdint.h&gt;</code> 的 <code>SIZE_MAX</code>。

非负整数值的二进制表示始终名副其实：这样的数由称为“**位**”的二进制数字 b₀、b₁、…、b<sub>p−1</sub> 表示。每一位的值均为 0 或 1。该数的值按下式计算：

~~~text
             p−1
(1)           Σ  bᵢ · 2ⁱ
              i=0
~~~

这种二进制表示中的 p 称为底层类型的“**精度**”；对于无符号类型，它也等于宽度。所有无符号类型的这些值，都可以由相应宏确定，例如 <code>UINT_WIDTH</code>、<code>ULONG_WIDTH</code> 和 <code>ULLONG_WIDTH</code>。b₀ 称为**最低有效位**（LSB），b<sub>p−1</sub> 称为**最高有效位**（MSB）。

在所有值为 1 的位 bᵢ 中，索引 i 最小者称为“**置位的最低有效位**”，索引最高者称为“**置位的最高有效位**”。例如，对于精度 p = 16 的无符号类型，值 240 的 b₄、b₅、b₆ 与 b₇ 均为 1。二进制表示中的其他所有位都为 0；置位的最低有效位是 b₄，置位的最高有效位是 b₇。由式 (1) 立即可见，2ᵖ 是该类型无法表示的第一个值。因此 N = 2ᵖ，并有如下结论。

::: tip 要点 5.7.1 #1
任何整数类型的最大值都具有 2ᵖ − 1 的形式。
:::

请注意，在讨论非负值的表示时，我们尚未涉及类型的符号性。这些规则同等适用于有符号类型与无符号类型。幸运的是，对于无符号类型，前面的内容已经足以完整描述这种类型。

::: tip 要点 5.7.1 #2
无符号整数类型上的算术由其精度决定。
:::

最后，表 5.5 列出本书常用若干标量类型的界限。

### 5.7.2 位集合与逐位运算符

无符号类型这种简单的二进制表示，使我们能够把它们用于另一种与算术没有直接关系的目的：表示位集合。位集合是对无符号值的另一种解释。我们假定该值表示基本集合 V = {0, …, p − 1} 的一个子集；如果位 bᵢ 存在，就把元素 i 视为集合成员。

有三个二元运算符作用于位集合：<code>|</code>、<code>&amp;</code> 和 <code>^</code>。它们分别表示集合并 A ∪ B、集合交 A ∩ B 和对称差 A△B。来看一个示例：取 A = 240，表示 {4, 5, 6, 7}；再取 B = 287，表示位集合 {0, 1, 2, 3, 4, 8}，如表 5.6 所示。计算这些操作的结果时，不需要知道基本集合的总大小，因而也不需要知道精度 p。与算术运算符一样，它们分别还有对应的赋值运算符 <code>&amp;=</code>、<code>|=</code> 和 <code>^=</code>。

如果包含头文件 <code>&lt;iso646.h&gt;</code>，所有这些运算符也都可以用标识符写出：<code>bitor</code>、<code>bitand</code>、<code>xor</code>、<code>or_eq</code>、<code>and_eq</code>、<code>xor_eq</code> 和 <code>compl</code>。位集合的典型用途之一是标志，也就是控制程序某些设置的对象：

~~~c
enum corvid { magpie, raven, jay, chough, corvid_num, };
#define FLOCK_MAGPIE 1U
#define FLOCK_RAVEN 2U
#define FLOCK_JAY 4U
#define FLOCK_CHOUGH 8U
#define FLOCK_EMPTY 0U
#define FLOCK_FULL 15U
int main(void) {
  unsigned flock = FLOCK_EMPTY;
  ...
  if (something) flock |= FLOCK_JAY;
  ...
  if (flock&FLOCK_CHOUGH)
    do_something_chough_specific(flock);
}
~~~

这里，每种鸦科鸟对应的常量都是 2 的幂，因此其二进制表示中恰有一位置位。于是，鸟群中的成员关系可以通过运算符处理：<code>|=</code> 向 <code>flock</code> 加入一种鸟；把 <code>&amp;</code> 与某个常量结合，则可检验特定鸟类是否存在。

请注意运算符 <code>&amp;</code> 与 <code>&amp;&amp;</code>、<code>|</code> 与 <code>||</code> 的相似性。如果把无符号值中的每一位 bᵢ 都视为真值，那么 <code>&amp;</code> 会同时对各实参的所有位执行逻辑与。这是一个很好的类比，有助于记住这些运算符的具体拼写。另一方面，请牢记 <code>||</code> 和 <code>&amp;&amp;</code> 采用短路求值，因此一定要把它们与逐位运算符明确区分。

自 C23 起，头文件 <code>&lt;stdbit.h&gt;</code> 提供了另一组位操作。其中包括：用 <code>stdc_count_ones</code> 统计值为 1 的位数（集合的大小）；用 <code>stdc_has_single_bit</code> 检测是否恰有一位为 1（集合是否为单元素集合）；用 <code>stdc_bit_width</code> 给出值为 1 的最高编号位；以及用 <code>stdc_bit_floor</code> 返回包含最高编号元素的单元素集合。由于这个头文件在 C23 中才新增，你的平台可能尚未提供。另一个新特性是预处理器测试 <code>__has_include</code>，可以查询是否能找到某个头文件：

~~~c
#if !__has_include(<stdbit.h>)
# error "this file needs the <stdbit.h> header"
#endif
~~~

### 5.7.3 移位运算符

下一组运算符在两种无符号值解释之间架起桥梁：一种把无符号值解释为数，另一种把它解释为位集合。左移操作 <code>&lt;&lt;</code> 对应于把数值乘以相应的 2 的幂。例如，对于 A = 240，也就是集合 {4, 5, 6, 7}，<code>A &lt;&lt; 2</code> 等于 240 · 2² = 240 · 4 = 960，表示集合 {6, 7, 8, 9}。结果中无法装入该类型二进制表示的位会被直接丢弃。在这个示例中，<code>A &lt;&lt; 9</code> 原本对应集合 {13, 14, 15, 16}（值为 122,880）；但由于不存在第 16 位，结果集合为 {13, 14, 15}，值为 57,344。

因此，对这种移位操作而言，精度 p 再次成为关键。无法装入的位会丢失，p 还限制了右操作数的可能值。

::: tip 要点 5.7.3 #1
移位操作的第二个操作数必须小于精度。
:::

还有一个类似的右移操作 <code>&gt;&gt;</code>，它把二进制表示向较低有效位移动。与此类似，它对应除以 2 的某个幂后所得的整数商。位置小于或等于移位值的位会从结果中丢弃。请注意，对这项操作而言，类型精度并不重要。

::: details 练习 32
证明：操作 <code>x&gt;&gt;n</code> 中“丢失”的位，对应余数 <code>x % (1ULL &lt;&lt; n)</code>。
:::

还有对应的赋值运算符 <code>&lt;&lt;=</code> 和 <code>&gt;&gt;=</code>。

左移运算符 <code>&lt;&lt;</code> 的主要用途，是指定 2 的幂。在示例中，现在可以替换这些 <code>#define</code>：

~~~c
#define FLOCK_MAGPIE (1U << magpie)
#define FLOCK_RAVEN (1U << raven)
#define FLOCK_JAY (1U << jay)
#define FLOCK_CHOUGH (1U << chough)
#define FLOCK_EMPTY 0U
#define FLOCK_FULL ((1U << corvid_num)-1)
~~~

这样一来，即使枚举发生变化，示例也更加稳健。

### 5.7.4 布尔值

C 中的布尔数据类型也视为无符号类型。请记住，它只有 <code>false</code> 和 <code>true</code> 两个值，分别对应 0 和 1，因此没有负值。C23 以前，名称 <code>bool</code>[^33] 以及常量 <code>false</code> 和 <code>true</code> 只能通过包含 <code>&lt;stdbool.h&gt;</code> 获得。如果必须维护旧代码库，或者需要保证对旧系统的向后兼容，仍应包含该头文件；在不需要它的系统上，这样做也不应造成伤害。

把 <code>bool</code> 视为无符号类型，多少有些牵强。向该类型的对象赋值并不遵循要点 4.2.2 #3 的模规则，而是遵循布尔值的特殊规则（要点 3.1 #1）。

你可能很少需要 <code>bool</code> 对象。只有在想要确保赋值时值总会归约为 <code>false</code> 或 <code>true</code> 时，它们才有用。早期 C 没有布尔类型，遗憾的是，许多经验丰富的 C 程序员至今仍不使用它。

[^33]: 此前，基本类型称为 <code>_Bool</code>。为了与旧源代码保持向后兼容，这个名称仍被保留，但新代码不应使用它。

### 5.7.5 有符号整数

有符号类型比无符号类型略为复杂。C 实现必须决定两件事：

- 算术溢出时会发生什么？
- 如何表示有符号类型的符号？

有符号类型与无符号类型按整数转换等级成对出现，但表 5.1 中有两个显著例外：<code>char</code> 和 <code>bool</code>。有符号类型的二进制表示受到前面所见包含关系图的约束。

::: tip 要点 5.7.5 #1
正值的表示与符号性无关。
:::

换言之，有符号类型的正值与相应无符号类型中的同一个值具有相同表示。正因如此，任何整数类型的最大值才能如此简单地表示（要点 5.7.1 #1）：有符号类型同样具有精度 p，由它确定该类型的最大值。

标准接下来规定，有符号类型还包含一个附加位，即“**符号位**”。它为 0 时，值为正；它为 1 时，值为负。历史上，人们曾用不同方式借助符号位得到负数；C23 对此作出澄清，如今只允许以“**二补码**”作为符号表示。

从前还存在“**符号与量值**”和“**反码**”表示，但如今它们只剩历史意义，或仅与奇异系统有关。在符号与量值表示中，量值取正值，符号位只表示前面有一个负号。反码则取相应正值，再把所有位逐位取反。这两种表示都有一个缺点：有两个值求值为 0，也就是正 0 和负 0。由于现役平台已不采用这些表示，它们已经从 C 标准中移除；你只应在历史书或心怀恶意的招聘测试中遇到它们。

二补码表示执行的算术与我们在无符号类型中看到的完全相同，只是把无符号值的上半区（最高位为 1 的那些值）解释为负数。下面两个函数基本足以把无符号值解释为有符号值：

~~~c
bool is_negative(unsigned a) {
  constexpr unsigned int_max = UINT_MAX/2;
  return a > int_max;
}
bool is_signed_less(unsigned a, unsigned b) {
  if (is_negative(a) != is_negative(b)) return a > b;
  else return a < b;
}
~~~

**表 5.7　16 位无符号整数类型中的取负**

| 操作            |     值 | b₁₅ … b₀                         |
| --------------- | -----: | -------------------------------- |
| A               |    240 | <code>0b00000000’11110000</code> |
| <code>~A</code> | 65,295 | <code>0b11111111’00001111</code> |
| +1              |      1 | <code>0b00000000’00000001</code> |
| <code>-A</code> | 65,296 | <code>0b11111111’00010000</code> |

表 5.7 展示了怎样构造值 240 的负值。对于无符号类型，<code>-A</code> 可以计算为 <code>~A + 1</code>。

::: details 练习 34
证明：对于无符号算术，<code>A + ~A</code> 是最大值。
:::

::: details 练习 35
证明：对于无符号算术，<code>A + ~A</code> 是 −1。
:::

::: details 练习 36
证明：对于无符号算术，<code>A + (~A + 1) == 0</code>。
:::

二补码表示对有符号类型与无符号类型执行完全相同的位操作，只把最高位置位的表示解释为负数。

这样一来，有符号整数算术多少又能表现良好。遗憾的是，有一个陷阱使有符号算术的结果难以预测：溢出。无符号值必须回绕，而有符号溢出的行为**未定义**。下面两个循环看起来非常相似：

~~~c
for (unsigned i = 1; i; ++i) do_something();
for ( signed i = 1; i; ++i) do_something();
~~~

第一个循环会怎样运行，我们十分清楚：计数对象递增到 <code>UINT_MAX</code>，然后回绕为 0。这个过程可能需要一些时间，但在 <code>UINT_MAX-1</code> 次迭代后，循环会停止，因为 <code>i</code> 已经达到 0。

第二个循环看起来相似。但由于这里的溢出行为未定义，编译器可以假装它永远不会发生。编译器还知道起始值为正，因此可以假定：只要程序具有已定义行为，<code>i</code> 就永远不会为负或为 0。如同规则（要点 5.1.3 #3）允许它把第二个循环优化为：

~~~c
while (true) do_something();
~~~

没错，这是一个无限循环。要使代码有效，唯一的可能是 <code>do_something</code> 具有副作用，从而让程序执行取得进展。编译器还可以假定循环后的执行位置永远无法到达：要么循环无限继续，要么循环到达某个使执行终止的内部状态。第 15.4 节会更详细地讨论这种情况。

::: tip 要点 5.7.5 #2
抽象状态机一旦到达未定义状态，就不能再对后续执行作出任何假设。
:::

不仅编译器可以随意处理操作本身（“未定义？那就由我定义。”），还可以假定程序永远不会到达这种状态，并据此推导结论。

程序到达未定义状态，通常称为程序“具有”或“表现出”**未定义行为**。这种说法不太理想；在许多情况下，程序根本不会“表现出”任何肉眼可见的怪异迹象。恰恰相反，糟糕的事情可能持续很久，而你甚至毫无察觉。

::: tip 要点 5.7.5 #3
避免所有操作产生未定义行为，是你的责任。
:::

更糟的是，在某些平台上采用某些标准编译器选项时，执行结果看起来完全正确。由于行为未定义，在这种平台上，有符号整数算术可能碰巧与无符号算术基本相同。但更换平台、编译器或某些选项，就可能改变一切。一个正常运行多年的程序，会突然毫无征兆地崩溃。

后文将尽量避免反复谈论“未定义行为”，而统称为“程序失效”，因为对程序而言，真正重要的正是失效。这样的失效通常不可靠（常称为“拜占庭式”）：执行中的任何组成部分都不再可信。可能产生的影响，从毫无迹象到切实损害平台或数据，无所不包。本书将用整整一章讨论程序失效（第 15 章）。

::: tip 要点 5.7.5 #4
如果程序状态到达具有未定义行为的操作，执行就已经失效。
:::

到本节以前，我们讨论的内容基本都具有良好定义的行为，因此抽象状态机始终处于良好定义的状态。有符号算术改变了这一点；只要并非必要，就应避免它。如果程序在正常结束之前突然终止，我们就称程序“触发**陷阱**”（或简称“陷入”）。

::: warning 要点 5.7.5 #5
有符号算术可能以恶劣方式触发陷阱。
:::

对于有符号类型，连取负都可能溢出。我们已经看到，<code>INT_MAX</code> 除符号位外的所有位都置为 1。<code>INT_MIN</code> 具有“下一个”表示：符号位置为 1，其他所有位为 0。相应值并不是 <code>-INT_MAX</code>。

::: details 练习 37
证明 <code>INT_MIN+INT_MAX</code> 为 −1。
:::

::: tip 要点 5.7.5 #6
<code>INT_MIN &lt; -INT_MAX</code>。
:::

换言之，正值 <code>-INT_MIN</code> 越出界限，因为该操作的值大于 <code>INT_MAX</code>。

::: warning 要点 5.7.5 #7
有符号算术中的取负可能溢出。
:::

对于有符号类型，位操作作用于二进制表示；移位操作因而变得极为混乱。对负值执行这种操作究竟具有何种语义，并不清晰。

::: tip 要点 5.7.5 #8
位操作应使用无符号类型。
:::

### 5.7.6 固定宽度整数类型

可以使用 <code>&lt;limits.h&gt;</code> 中的宏检查目前所见整数类型的宽度（进而检查精度），例如 <code>UINT_WIDTH</code> 和 <code>LONG_WIDTH</code>。C 标准只保证它们具有最低宽度。对于无符号类型，最低精度如下：

| 类型                            | 最低精度 |
| ------------------------------- | -------: |
| <code>bool</code>               |        1 |
| <code>unsigned char</code>      |        8 |
| <code>unsigned short</code>     |       16 |
| <code>unsigned</code>           |       16 |
| <code>unsigned long</code>      |       32 |
| <code>unsigned long long</code> |       64 |

通常情况下，这些保证应当已经提供足够信息；但在某些技术约束下，它们可能仍然不够，或者你希望突出某个特定精度。比如，你想用无符号量表示一个已知最大大小的位集合。如果知道 32 位足以容纳该集合，那么视平台而定，可以选择 <code>unsigned</code>（如果恰有 32 位）或 <code>unsigned long</code>（如果 <code>unsigned</code> 太窄）来表示。

C 标准在 <code>&lt;stdint.h&gt;</code> 中提供了精确宽度整数类型的名称。顾名思义，它们具有规定的精确“宽度”；对于所提供的无符号类型，宽度保证与精度相同。

::: tip 要点 5.7.6 #1
如果提供了类型 <code>uintN_t</code>，它就是宽度和精度都恰为 N 位的无符号整数类型。
:::

::: tip 要点 5.7.6 #2
如果提供了类型 <code>intN_t</code>，它就是宽度恰为 N 位、精度为 N − 1 的有符号整数类型。
:::

如果存在具有相应性质的类型，就必须提供这些 <code>typedef</code>。[^38]

::: tip 要点 5.7.6 #3
对于值 N，如果存在具备所需性质的类型，就必须提供 <code>intN_t</code> 和 <code>uintN_t</code>。
:::

如今，平台通常提供无符号类型 <code>uint8_t</code>、<code>uint16_t</code>、<code>uint32_t</code> 和 <code>uint64_t</code>，以及有符号类型 <code>int8_t</code>、<code>int16_t</code>、<code>int32_t</code> 和 <code>int64_t</code>；还会陆续加入更多类型，例如 <code>uint128_t</code> 和 <code>int128_t</code>。可以分别用无符号类型宏 <code>UINT8_WIDTH</code> … <code>UINT128_WIDTH</code>，以及有符号类型宏 <code>INT8_WIDTH</code> … <code>INT128_WIDTH</code>，测试它们是否存在及其界限。

::: details 练习 39
如果这些宏存在，其值都由类型性质规定。请思考怎样用 N 的闭式公式表达这些值。
:::

要编码所需类型的字面量，可分别使用宏 <code>UINT8_C</code> … <code>UINT64_C</code> 和 <code>INT8_C</code> … <code>INT128_C</code>。例如，在 <code>uint64_t</code> 是 <code>unsigned long</code> 的平台上，<code>INT64_C(1)</code> 通常展开成类似 <code>1UL</code> 的形式。

::: tip 要点 5.7.6 #4
对所提供的任意固定宽度类型，还会提供宽度 <code>_WIDTH</code>、最小值 <code>_MIN</code>（仅有符号类型）、最大值 <code>_MAX</code> 和字面量 <code>_C</code> 宏。
:::

由于我们无法知道固定宽度类型背后的实际类型，很难猜出传给 <code>printf</code> 等函数的正确格式说明符。自 C23 起，可以使用 <code>"wN"</code> 长度说明符完成这项工作，其中 N 是类型宽度：

~~~c
uint32_t n = 78;
int64_t big = (-UINT64_C(1))>>1; // 与 INT64_MAX 的值相同
printf("n is %w32u, and big is %w64d\n", n, big);
~~~

C23 加入宽度宏（以及其他一些说明技巧）后，可以提供甚至无法由宏预处理器完整处理的类型。尤其是，大多数现代桌面计算机都在硬件中支持 128 位类型；如今可以把它们公开为 C 整数类型 <code>int128_t</code> 和 <code>uint128_t</code>。需要处理大型位集合时，这一点格外有趣：

~~~c
#if ULLONG_WIDTH < UINT128_WIDTH // 不要使用 UINT128_MAX
typedef uint128_t wideType;
#else
typedef unsigned long long wideType;
#endif
~~~

宽度保证是一个相对较小的数，因此始终可以据此编写预处理条件。

[^38]: C23 以前，只对 8、16、32 和 64 这几个值作出保证。请注意，即使在 <code>CHAR_BITS</code> 不等于 8 的平台上，唯一保证存在的类型，也只是 N 等于 <code>CHAR_BITS</code> 时的 <code>uintN_t</code> 和 <code>intN_t</code>。

[^40]: 此前，头文件 <code>&lt;inttypes.h&gt;</code> 只提供宏替换。例如，当 N = 64 时，有 <code>PRIb64</code>、<code>PRId64</code>、<code>PRIi64</code>、<code>PRIo64</code>、<code>PRIu64</code>、<code>PRIx64</code> 和 <code>PRIX64</code>，分别对应 <code>printf</code> 格式 <code>"%b"</code>、<code>"%d"</code>、<code>"%i"</code>、<code>"%o"</code>、<code>"%u"</code>、<code>"%x"</code> 和 <code>"%X"</code>。

### 5.7.7 位精确整数类型

前面所见的精确宽度整数类型只对某些特定位数存在，通常只对 2 的幂存在。对于必须精确装入一定数量位的量，C23 引入了位精确整数类型。它们使用 <code>_BitInt</code> 关键字指定：

~~~c
unsigned _BitInt(3) u3 = 7wbu; // 值 0, ..., 3, ... ,7
signed _BitInt(3)   s3 = 3wb;  // 值 -4, ..., 0, ..., 3
       _BitInt(3)   s3 = 3wb;  // 相同
~~~

这里还能看到，这些类型也有字面量：数字字面量的后缀含有 <code>wb</code> 或 <code>WB</code>，还可以与 <code>u</code> 或 <code>U</code> 组合。它们的特殊之处在于，字面量采用能够表示该值的最小宽度类型。例如：

- <code>7wbu</code> 需要 3 位表示值 7，并且是无符号的，所以类型是 <code>unsigned _BitInt(3)</code>。
- <code>3wb</code> 需要 2 位表示值 3，并为符号保留 1 位，所以类型是 <code>signed _BitInt(3)</code>。
- <code>3wbu</code> 需要 2 位表示该值，但不需要符号位，所以类型是 <code>signed _BitInt(2)</code>。

这些类型总是在操作数的最大宽度内计算。例如，在：

~~~c
u3 + 1wbu
~~~

第一个操作数宽 3 位，第二个宽 1 位。因此，操作结果的类型是 <code>unsigned _BitInt(3)</code>；对于这里选取的值，加法的数学结果 8 会回绕，最终得到值 0。

这些类型的一种可能用途，是构造需要具有特定宽度的常量：

~~~c
constexpr unsigned _BitInt(3) max3u = -1;         // 0b111
constexpr unsigned _BitInt(4) max4u = -1;         // 0b1111
constexpr unsigned _BitInt(4) high4u= max4u-max3u;// 0b1000
constexpr signed _BitInt(4) max4s = max3u;        // 0b0111
constexpr signed _BitInt(4) min4s = ~max4s;       // 0b1000
~~~

这类类型对所有宽度都存在：无符号类型从 1 开始，有符号类型从 2 开始，直到 <code>&lt;limits.h&gt;</code> 中定义的 <code>BITINT_MAXWIDTH</code>；该最大宽度始终大于或等于 <code>unsigned long long</code> 的宽度 <code>ULLONG_WIDTH</code>。这使我们能够为所有整数值写出具有精确值和符号性的字面量。例如，下面这个庞然大物是一个精度为 127 位、因而类型为 <code>_BitInt(128)</code> 的有符号整数字面量：

~~~c
0x7FFF’FFFF’FFFF’FFFF’FFFF’FFFF’FFFF’FFFFwb
~~~

因此，只要该类型存在（<code>BITINT_MAXWIDTH ≥ 128</code>），即使不支持 <code>int128_t</code> 类型自身的字面量，也可以用它初始化 <code>int128_t</code> 对象。

### 5.7.8 浮点数据

整数分别接近数学中的 ℕ（无符号）或 ℤ（有符号）概念，而浮点类型则接近 ℝ（非复数）或 ℂ（复数）。它们与这些数学概念的差异体现在两个方面。首先，可表示内容受到大小限制；这与整数类型的情况相似。例如，头文件 <code>&lt;float.h&gt;</code> 中有常量 <code>DBL_MIN</code> 和 <code>DBL_MAX</code>，给出 <code>double</code> 的最小值和最大值。但要注意，这里的 <code>DBL_MIN</code> 是严格大于 <code>0.0</code> 的最小数；最小的负 <code>double</code> 值是 <code>-DBL_MAX</code>。

不过，当我们想在物理系统中表示实数（ℝ）时，还会遇到另一个困难：实数的展开可能没有尽头。例如，值 1/3 在十进制表示中会无限重复数字 3；π 是“超越数”，在任何表示中都会无限展开，而且不会以任何方式循环。

C 和其他编程语言通过截断展开来处理这些困难。截断位置是“浮动”的（名称由此而来），取决于所讨论数的量级。

用一种稍加简化的观点，浮点值由以下内容计算：

| 记号      | 含义                |
| --------- | ------------------- |
| s         | 符号（±1）          |
| e         | 指数，一个整数      |
| f₁, …, fₚ | 尾数位，值为 0 或 1 |

指数满足 e<sub>min</sub> ≤ e ≤ e<sub>max</sub>。p 是尾数中的位数，称为“精度”。浮点值由下式给出：

~~~text
                 p
        s · 2ᵉ · Σ fₖ · 2⁻ᵏ
                k=1
~~~

p、e<sub>min</sub> 和 e<sub>max</sub> 的值依赖类型，因此不在每个数中显式表示。可以通过 <code>DBL_MANT_DIG</code>（p，典型值 53）、<code>DBL_MIN_EXP</code>（e<sub>min</sub>，−1,021）与 <code>DBL_MAX_EXP</code>（e<sub>max</sub>，1,024）等宏取得它们。

例如，假设某个数满足 s = −1、e = −2、f₁ = 1、f₂ = 0、f₃ = 1，那么其值为：

~~~text
−1 · 2⁻² · (f₁·2⁻¹ + f₂·2⁻² + f₃·2⁻³)
= −1 · 1/4 · (1/2 + 1/8)
= −5/32
~~~

对应十进制值 −0.15625。从这个计算还可以看出，浮点值总能表示成一个以 2 的某次幂为分母的分数。

::: details 练习 41
证明：所有满足 e > p 的可表示浮点值，都是 2<sup>e−p</sup> 的倍数。
:::

对这种浮点表示，需要牢记的一件要事是：中间计算可能截断值。

::: warning 要点 5.7.8 #1
浮点操作既不满足结合律，也不满足交换律和分配律。
:::

因此，浮点数基本失去了纯数学中熟悉的所有优美代数性质。当我们操作数量级相差很大的值时，由此产生的问题格外突出。

::: details 练习 42
打印下列表达式的结果：<code>1.0E-13 + 1.0E-13</code>，以及 <code>(1.0E-13 + (1.0E-13 + 1.0)) - 1.0</code>。
:::

例如，把一个指数小于 −p 的极小浮点值 <code>x</code> 加到值 <code>y &gt; 1</code> 上，结果仍只是 <code>y</code>。因此，如果不作进一步研究，实际上很难断言两次计算是否具有“相同”结果。这类研究往往本身就是前沿课题，所以我们不能指望轻易断言相等或不等，只能说明结果彼此“接近”。

::: warning 要点 5.7.8 #2
绝不要比较浮点值是否相等。
:::

复数类型的表示十分直接，与由相应实浮点类型的两个元素组成的数组完全相同。要访问复数的实部和虚部，头文件 <code>&lt;tgmath.h&gt;</code> 还提供两个类型泛型宏：<code>creal</code> 和 <code>cimag</code>。对于三种复数类型中任意一种类型的 <code>z</code>，都有 <code>z == creal(z) + cimag(z)\*I</code>。[^43]

[^43]: 第 8.1.2 节将介绍这种函数式宏。

## 小结

- C 程序在一个基本独立于具体运行计算机的抽象状态机中运行。
- C 的所有基本类型都是某种数，但并非所有基本类型都能直接用于算术。
- 值具有类型和二进制表示。
- 必要时，值的类型会隐式转换，以满足具体使用位置的需要。
- 对象在第一次使用之前必须显式初始化。
- 只要不发生溢出，整数计算就会得到精确值。
- 浮点计算只能得到近似结果，并在一定数量的二进制位之后截断。
