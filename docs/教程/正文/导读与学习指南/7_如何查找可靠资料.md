# 7. 如何查找可靠资料

## 1. 阅读诊断和日志

先完整阅读诊断，找到首条错误及其源代码位置。可以让 AI 帮助解释诊断，但应同时提供最小代码、编译命令和完整输出，并用修改后的实际构建结果验证解释。

## 2. 使用搜索引擎

[**Google**](https://google.com/)，[**Bing**](https://cn.bing.com/)

搜索时带上准确的接口名、诊断原文、编译器名称和标准版本；先缩小问题，再寻找资料。

## 3. 博客只能作为线索

可以发博客分享自己的心得或提出自己的疑问。但 CSDN 这种地方还是少逛为妙。

## 4. 手册、标准与代码

自然语言是注释，代码更重要。

## 5. 证据顺序

遇到语言或库接口问题时，优先核对标准文本和标准库参考资料；遇到编译器支持问题时，再看对应实现的官方文档；实验结果用于验证当前环境，不能单独证明所有实现都具有相同行为。

## 6. 实践

- 在 C 参考手册中查找 `printf`、`malloc`、`strlen` 和 `assert`。
- 为一条编译器诊断制作只保留必要代码的最小复现。
- 搜索同一问题时，对比标准资料、实现文档和博客给出的结论。
