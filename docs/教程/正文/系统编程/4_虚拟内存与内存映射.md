# 4. 虚拟内存与内存映射

[第 2 章](/教程/正文/系统编程/2_文件描述符与非缓冲IO)的 mycat 把文件一块块读进缓冲区，再写到标准输出。这一页走另一条路：请内核把一个文件直接接进进程的地址空间，此后读写那片内存就等于读写文件。走通这条路之前，先要弄清进程看到的地址到底是什么。同一个程序两次运行打印的地址不同，两个进程里的同一个地址装着不同的数据，`malloc` 拿到一大块内存之后进程的驻留集几乎没有变化，这三件事背后是同一套机制。

读完这一页，读者能对着 `/proc/self/maps` 说出一个地址落在哪一段，能用 `mmap` 映射文件并在 `MAP_SHARED` 与 `MAP_PRIVATE` 之间做选择，能用 `mprotect` 做出越界一个字节就崩溃的分配器，也能判断一段代码该用 `read` 还是 `mmap`。本页的程序都在 `code/系统编程/4_虚拟内存与内存映射/` 下，正文只贴关键部分。

## 1. 每个进程一个地址空间

先看一个十几行的程序。它打印一个全局对象的地址、一个堆上对象的地址和一个局部对象的地址：

```c
#define _POSIX_C_SOURCE 200809L

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int g_counter = 1;

/* 带参数运行时把 g_counter 设成参数值，并在最后多停一秒，
 * 这样同时启动两个进程时，两边的输出能对得上 */
int main(int argc, char *argv[]) {
    int local = 2;
    void *heap = malloc(16);
    if (heap == NULL) {
        return EXIT_FAILURE;
    }
    if (argc > 1) {
        g_counter = atoi(argv[1]);
    }

    printf("&g_counter = %p（值 %d）\n", (void *)&g_counter, g_counter);
    printf("heap       = %p\n", heap);
    printf("&local     = %p\n", (void *)&local);

    if (argc > 1) {
        sleep(1);
    }
    free(heap);
    return 0;
}
```

连续运行两次：

::: terminal title="bash - aslr"

```console
$ ./aslr
&g_counter = 0x55ca55ec5038（值 1）
heap       = 0x55ca838332a0
&local     = 0x7ffc3a0b8c24
$ ./aslr
&g_counter = 0x564c9a6b3038（值 1）
heap       = 0x564cbd33c2a0
&local     = 0x7ffc8e817054
```

:::

同一个可执行文件、同一段代码，两次打印的地址没有一处相同。这是地址空间布局随机化 (address space layout randomization, ASLR)：内核在每次 `exec` 时给程序挑一个随机的起始位置，栈、共享库、堆都跟着平移。它让攻击者难以预知某个函数或某块数据落在哪里。

关掉随机化，地址就固定了。`setarch` 的 `-R` 选项做这件事：

::: terminal title="bash - setarch -R"

```console
$ setarch $(uname -m) -R ./aslr
&g_counter = 0x555555558038（值 1）
heap       = 0x5555555592a0
&local     = 0x7fffffffea34
$ setarch $(uname -m) -R ./aslr
&g_counter = 0x555555558038（值 1）
heap       = 0x5555555592a0
&local     = 0x7fffffffea34
```

:::

两次的输出逐字节相同。可见地址不同不是程序的行为，而是内核每次装载程序时摆放位置不同。教程后面的程序有时要看具体地址，加上 `setarch $(uname -m) -R` 就稳定了；平时写程序不能依赖任何具体地址。

地址固定之后，还可以做一件事：同时运行两个进程，让它们打印同一批地址。`same_addr.sh` 做这个实验，两边都用参数把 `g_counter` 改成不同的值：

::: terminal title="bash - same_addr.sh"

```console
$ ./same_addr.sh
进程 1（g_counter = 11）：
&g_counter = 0x555555558038（值 11）
heap       = 0x5555555592a0
&local     = 0x7fffffffea24
进程 2（g_counter = 22）：
&g_counter = 0x555555558038（值 22）
heap       = 0x5555555592a0
&local     = 0x7fffffffea24
```

:::

两边的三个地址一模一样，可 `g_counter` 的值一个是 11、一个是 22，互不干扰。同一个虚拟地址在不同进程里对应不同的存储，这不是巧合，而是虚拟内存的基本设计：每个进程都有自己的地址空间，地址只在那个进程内有意义。

::: concept sys-vm-address-space title="虚拟地址空间"

每个进程拥有一个独立的虚拟地址空间。程序里出现的指针值是虚拟地址 (virtual address)，CPU 每次访问内存都要经过内存管理单元 (memory management unit, MMU) 把它翻译成物理地址 (physical address)。两个进程里数值相同的虚拟地址，可以对应不同的物理页；同一个物理页也可以同时出现在多个进程的地址空间里，`mmap` 的共享映射和第 5 章的写时复制都建立在这条性质上。

:::

翻译以页为单位进行。内核把物理内存切成固定大小的页框 (page frame)，把每个进程的地址空间切成同样大小的页 (page)，页表 (page table) 记录每个虚拟页对应哪个物理页框。页的大小由体系结构决定，程序可以用 `sysconf(_SC_PAGESIZE)` 查到：

```c
#include <unistd.h>

long page = sysconf(_SC_PAGESIZE); /* 本页的机器上是 4096 */
```

这个值后面反复用到：`mmap` 的偏移量必须是它的整数倍，`mprotect` 的地址要对齐到它，缺页的次数也按它计算。程序里不写死 4096，总是查一次。

## 2. 读懂 /proc/self/maps

地址空间里有哪些段、每段从哪到哪、对应哪个文件，内核把这张表放在 `/proc/PID/maps` 里。自己的进程直接读 `/proc/self/maps`。下面的程序把几类典型对象的地址打印出来，再到 maps 里找出包含这个地址的那一行：

```c
#define _POSIX_C_SOURCE 200809L

#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

int g_init = 42;  /* .data：有初值的全局对象 */
int g_bss;        /* .bss：没有初值的全局对象 */
static int s_bss; /* .bss：没有初值的静态对象 */

/* 在 /proc/self/maps 里找包含 addr 的那一行并打印 */
static void show_mapping(const char *what, const void *addr) {
    FILE *fp = fopen("/proc/self/maps", "r");
    if (fp == NULL) {
        perror("fopen");
        exit(EXIT_FAILURE);
    }
    char line[512];
    while (fgets(line, sizeof line, fp) != NULL) {
        unsigned long start;
        unsigned long end;
        if (sscanf(line, "%lx-%lx", &start, &end) != 2) {
            continue;
        }
        unsigned long a = (unsigned long)addr;
        if (a >= start && a < end) {
            shorten_path(line); /* 把工作目录前缀换成 .，输出短一些 */
            printf("%-8s %p  %s", what, addr, line);
            break;
        }
    }
    fclose(fp);
}

int main(int argc, char *argv[]) {
    int local = 7;
    void *small = malloc(1000);
    void *big = malloc(1024 * 1024);
    if (small == NULL || big == NULL) {
        return EXIT_FAILURE;
    }

    show_mapping("main", (const void *)main);
    show_mapping("g_init", &g_init);
    show_mapping("g_bss", &g_bss);
    show_mapping("s_bss", &s_bss);
    show_mapping("small", small);
    show_mapping("big", big);
    show_mapping("local", &local);

    if (argc > 1) {
        dump_all(); /* 加 -a 参数时打印完整的 maps */
    }

    free(big);
    free(small);
    return 0;
}
```

设备号、i 节点号和最后一段的路径在不同机器、不同次运行时不同，地址一列在关掉随机化后是稳定的。

主函数落在一个 `r-xp` 映射里，这一段的偏移是 `0x1000`，说明它是可执行文件里第二个可加载段。字符串常量和 `const` 对象落在紧挨其上的 `r--p` 段里，只读、不可执行。`g_init` 有初值，`g_bss` 和 `s_bss` 没有初值，三者却落在同一行 `rw-p` 映射里：

```text
555555558000-555555559000 rw-p 00003000 ... ./layout
```

这是链接器和内核合作的结果。`.data` 和 `.bss` 在可执行文件里属于同一个可读写段，装载时整段映射一次，`.bss` 的部分在文件里不占空间，映射时补零。第一部分的 [15.3 存储期与链接](/教程/正文/语法和标准库/15_声明_名称与生存期/15_3_存储期与链接) 从语言角度分了静态存储期和分配存储期，这里看到的是它在地址空间里的样子：静态存储期的对象在程序启动时就摆在固定的几段里，分配存储期的对象则出现在 `[heap]` 或匿名的映射里。

`small` 是 `malloc(1000)` 的结果，地址在 `[heap]` 里；`big` 是 `malloc(1024 * 1024)` 的结果，地址在一段没有名字的匿名映射里，两者相差很远。原因在第 5 节。`local` 在 `[stack]`。映射的这一段从 `0x7ffffffde000` 到 `0x7ffffffff000`，当前只有 132 KiB：栈向下增长，用到更低的地址时内核再把那一段接上，能长到多大由 `ulimit -s` 决定，本机是 8 MiB。

可执行文件和 `libc.so.6` 都被拆成好几段，权限各不相同。代码段是 `r-xp`，只读常量段是 `r--p`，可写数据段是 `rw-p`。同一块只读的代码页可以同时映射进几十个进程，物理内存里只有一份；可写的数据段则各自私有。

`[vdso]` 是内核映射进每个进程的一小段代码，`clock_gettime` 之类的调用从这里直接返回，不进内核，第 6 章会用到它。`[vvar]` 是 vDSO 读取内核数据用的页面。`[heap]` 是最初的堆，再往后的大块分配不一定还在这段里。

## 3. 按需分配与缺页

`malloc` 返回一个指针，程序马上就能用，但内核在 `malloc` 返回的那一刻并没有把物理内存交出去。它只修改了进程的页表，记下这一段虚拟地址将来对应哪些页，物理页框等到真正访问时才分配。第一次访问某个虚拟页时，CPU 在页表里找不到有效的表项，触发一个缺页 (page fault)，内核接管 CPU，补上映射，再从出错的那条指令继续执行。程序感觉不到这一停顿。

```mermaid
flowchart LR
    A["虚拟页：首次访问"] --> B["页表项无效"]
    B --> C["缺页异常，进入内核"]
    C --> D["分配页框或读入文件页"]
    D --> E["填写页表项"]
    E --> F["返回出错指令，重新执行"]
```

缺页分两种。所需的页已经在内存里（比如零页、页缓存里的文件页、或被写时复制过的页），内核只需要建立映射，这叫次要缺页 (minor fault)；需要从磁盘把内容读进来，叫主要缺页 (major fault)。`getrusage` 把两种分别记在 `ru_minflt` 和 `ru_majflt` 里，`/proc/self/status` 里的 `VmRSS` 记录当前驻留集大小 (resident set size, RSS)，即真正占了物理内存的部分。

下面的程序把这三样一起观察。它分配 32 MiB，先看 `malloc` 返回后的数字，再逐页写一个字节，再看一遍：

```c
#define _POSIX_C_SOURCE 200809L

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/prctl.h>
#include <sys/resource.h>
#include <unistd.h>

#define SIZE (32UL * 1024 * 1024)

struct sample {
    long vm_size; /* 虚拟地址空间大小，KiB */
    long rss;     /* 驻留集大小，KiB */
    long minflt;
    long majflt;
};

static struct sample take(void) {
    /* 读 /proc/self/status 的 VmSize、VmRSS，再取 getrusage 的两个缺页计数 */
    struct sample s = {0, 0, 0, 0};
    struct rusage ru;
    if (getrusage(RUSAGE_SELF, &ru) == -1) {
        perror("getrusage");
        exit(EXIT_FAILURE);
    }
    s.minflt = ru.ru_minflt;
    s.majflt = ru.ru_majflt;

    FILE *fp = fopen("/proc/self/status", "r");
    if (fp == NULL) {
        perror("fopen");
        exit(EXIT_FAILURE);
    }
    char line[256];
    while (fgets(line, sizeof line, fp) != NULL) {
        if (strncmp(line, "VmSize:", 7) == 0) {
            sscanf(line + 7, "%ld", &s.vm_size);
        } else if (strncmp(line, "VmRSS:", 6) == 0) {
            sscanf(line + 6, "%ld", &s.rss);
        }
    }
    fclose(fp);
    return s;
}

int main(void) {
    long page = sysconf(_SC_PAGESIZE);

    /* 关掉透明大页：这台机器的 THP 是 always，一次缺页可能装进 2 MiB，
     * 那样缺页次数就对不上 4 KiB 的页数了 */
    if (prctl(PR_SET_THP_DISABLE, 1, 0, 0, 0) == -1) {
        perror("prctl");
        return EXIT_FAILURE;
    }

    struct sample a = take();

    char *p = malloc(SIZE);
    if (p == NULL) {
        perror("malloc");
        return EXIT_FAILURE;
    }
    struct sample b = take();

    for (size_t off = 0; off < SIZE; off += (size_t)page) {
        p[off] = 1;
    }
    struct sample c = take();

    report("启动时", a);
    report("malloc 32 MiB 返回后", b);
    report("每页写 1 字节后", c);
    printf("页大小 %ld，共 %lu 页；写入阶段 minflt 增加 %ld\n", page,
           SIZE / (unsigned long)page, c.minflt - b.minflt);
    free(p);
    return 0;
}
```

`malloc` 返回时，`VmSize` 一次涨了 32772 KiB，正好是 32 MiB 加上分配器多要的一个页；`VmRSS` 只涨了两百多 KiB，缺页只多了 10 次。32 MiB 的地址范围已经划进进程，物理内存一页也没有多占。逐页写一遍之后，`VmRSS` 涨到 34 MiB 左右，缺页增加 8191 次，正好比 32 MiB 除以 4096 少一页。

少的那一页是因为 `malloc` 返回时就已经碰过开头：分配器把自己的块头放在块的前几个字节，写块头时那一页已经驻留了。用 `mincore`（Linux 专有，`_GNU_SOURCE`）查一遍，`malloc` 刚返回时 8192 页里只有第 0 页在内存中。

::: concept sys-vm-demand title="按需分配"

`malloc` 返回的地址范围已经属于进程，但对应的物理页框在第一次访问时才分配，这一步由缺页异常完成。判断一个进程实际占了多少内存要看 RSS，不能看申请了多少字节；申请成功也不代表内存已经到手。Linux 默认允许过量分配 (overcommit)，若干进程一起把内存用超时，内核的 OOM killer 会挑一个进程杀掉。

:::

上面程序里的 `prctl(PR_SET_THP_DISABLE, 1, ...)`（Linux 专有）是为了让缺页计数和 4 KiB 的页对得上。这台机器的透明大页 (transparent huge page, THP) 设置是 `always`，内核对连续的大块匿名内存可能一次映射 2 MiB，这时写满 32 MiB 只产生几十次缺页。关掉 THP 之后，一次缺页正好对应一个 4 KiB 页，计数才和页数一致。读者在自己机器上做实验时先看一眼 `/sys/kernel/mm/transparent_hugepage/enabled`，缺页次数远小于页数的就是这个原因。

## 4. 用 mmap 映射文件

缺页机制不只为堆服务。内核可以把一个文件的一段接到地址空间里，访问这片内存就是访问文件里的对应位置，这份映射叫内存映射 (memory mapping)。

```c
#include <sys/mman.h>

void *mmap(void *addr, size_t length, int prot, int flags, int fd, off_t offset);
int munmap(void *addr, size_t length);
```

`addr` 传 `NULL` 让内核挑地址，`length` 是映射的字节数，`fd` 是打开的文件，`offset` 是文件里的起始位置。`prot` 和 `flags` 决定这片内存怎么用：

| `prot` | 含义 |
| --- | --- |
| `PROT_READ` | 可读 |
| `PROT_WRITE` | 可写 |
| `PROT_EXEC` | 可执行 |
| `PROT_NONE` | 不可访问，任何访问都触发 `SIGSEGV` |

| `flags` | 含义 |
| --- | --- |
| `MAP_SHARED` | 修改对其他映射同一文件的进程可见，并会写回文件 |
| `MAP_PRIVATE` | 写时复制，修改只在本进程可见，不写回文件 |
| `MAP_ANONYMOUS` | 不关联文件，得到一段清零的内存，`fd` 传 -1 |

`mmap` 失败时返回 `MAP_FAILED`（值为 `(void *)-1`），不是 `NULL`，判断写成 `p == MAP_FAILED`。`offset` 必须是页大小的整数倍，否则得到 `EINVAL`。

最简单的用法是把整个文件映射进来数行数。`mapcount` 映射文件，逐字节数换行，然后与 `wc -l` 对照：

```c
#define _POSIX_C_SOURCE 200809L

#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>
#include <sys/stat.h>
#include <unistd.h>

int main(int argc, char *argv[]) {
    int fd = open(argv[1], O_RDONLY | O_CLOEXEC);
    if (fd == -1) {
        perror(argv[1]);
        return EXIT_FAILURE;
    }
    struct stat st;
    if (fstat(fd, &st) == -1) {
        perror("fstat");
        return EXIT_FAILURE;
    }

    char *p = mmap(NULL, (size_t)st.st_size, PROT_READ, MAP_PRIVATE, fd, 0);
    if (p == MAP_FAILED) {
        perror("mmap");
        return EXIT_FAILURE;
    }

    long lines = 0;
    for (off_t i = 0; i < st.st_size; i++) {
        if (p[i] == '\n') {
            lines++;
        }
    }
    printf("%ld\n", lines);

    if (munmap(p, (size_t)st.st_size) == -1) {
        perror("munmap");
        return EXIT_FAILURE;
    }
    close(fd);
    return 0;
}
```

::: terminal title="bash - mapcount"

```console
$ seq 1 200000 > big.txt
$ wc -l big.txt
200000 big.txt
$ ./mapcount big.txt
200000
```

:::

映射建立之后，文件内容按页读进内存，`p[i]` 的访问触发的是次要缺页（文件页已在页缓存里）或主要缺页（需要读盘），不再是 `read` 系统调用。`filemap` 把映射那一行从 maps 里找出来：

::: terminal title="bash - filemap"

```text

7f2fe4f03000-7f2fe503e000 r--p 00000000 08:04 2507167                    ./big.txt
```

:::

文件有 1288895 字节，占不满 315 页。映射长度向上取整到 4096 的整数倍，于是 maps 里这一行正好是 315 页。最后一页里超出文件末尾的那几个字节读到 0，再往后的页根本不在映射里。

### 4.1 MAP_SHARED 与 MAP_PRIVATE

文件映射最要紧的选择是 `MAP_SHARED` 还是 `MAP_PRIVATE`。下面的程序以读写方式打开文件，按参数选择标志，改掉第一个字节，再打印本进程看到的内容：

```c
int flags = shared ? MAP_SHARED : MAP_PRIVATE;
char *p = mmap(NULL, (size_t)st.st_size, PROT_READ | PROT_WRITE, flags, fd, 0);
if (p == MAP_FAILED) {
    perror("mmap");
    return EXIT_FAILURE;
}

printf("映射前看到：%c\n", p[0]);
p[0] = 'X';
printf("改完后本进程看到：%c\n", p[0]);

if (shared && msync(p, (size_t)st.st_size, MS_SYNC) == -1) {
    perror("msync");
    return EXIT_FAILURE;
}
```

两种模式各跑一次，文件内容分别是：

```console
改完后本进程看到：X
$ cat n1.txt

```

:::

::: terminal title="bash - mapwrite private"

```console

改完后本进程看到：X
```

同样的代码、同样把 `p[0]` 改成 `X`，`MAP_SHARED` 的改动出现在文件里，`MAP_PRIVATE` 的改动只留在本进程。前者写的是页缓存里的那一页，其他进程读同一个文件立刻能看到，`msync` 只负责把它写回磁盘；后者在第一次写时才复制出一份私有副本，之后的读写都在副本上。

::: compare left-title="MAP_PRIVATE：文件不变" right-title="MAP_SHARED：改动写回文件"

::: concept sys-vm-cow title="写时复制"

`MAP_PRIVATE` 的映射在建立时并不复制文件内容，页表项先指向页缓存里的同一批页，并被标成只读。任何一方写入时触发缺页，内核复制这一页，把写方的页表项改为指向新页框并恢复可写，此后两边的修改彼此不可见。第 5 章的 `fork` 用同一套机制复制地址空间：父子进程先共享全部物理页，谁写谁复制。

:::

`MAP_PRIVATE` 还有一个用处：即使文件以只读方式打开，也可以映射成 `PROT_READ | PROT_WRITE`，因为写的永远是私有副本。上面的 `mapwrite` 用 `O_RDWR` 打开是为了让 `MAP_SHARED` 也能跑。

映射建立之后文件被截短，再访问被截掉部分对应的页，进程收到 `SIGBUS`（总线错误），shell 报 `Bus error`，退出状态 135。这和数组越界的 `SIGSEGV` 不是同一个信号。

## 5. 匿名映射与 malloc 的内存来源

不关联文件的映射叫匿名映射 (anonymous mapping)。`MAP_PRIVATE | MAP_ANONYMOUS` 得到的是一段清零的内存，内核保证里面的字节全是 0，不需要 `memset`。这正是 `malloc` 拿大块内存时用的手段：

```c
char *p = mmap(NULL, SIZE, PROT_READ | PROT_WRITE, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
if (p == MAP_FAILED) {
    perror("mmap");
    return EXIT_FAILURE;
}
```

`anon` 程序映射 16 KiB 后逐字节检查，非零字节数是 0：

::: terminal title="bash - anon"

```console
$ ./anon
匿名映射 16384 字节，非零字节数 0
写入后读出：hello anonymous
munmap 返回 0
```

:::

`MAP_SHARED | MAP_ANONYMOUS` 得到一段可以在父子进程之间共享的内存，这是 `fork` 之后最简单的共享手段。`shared_counter` 用参数选择两种标志，子进程写入 42，父进程等待后读同一个指针：

::: terminal title="bash - shared_counter"

```console
$ ./shared_counter shared
子进程写了 42，父进程看到 42
$ ./shared_counter private
子进程写了 42，父进程看到 0
```

:::

`MAP_SHARED` 的匿名映射在第 7 章的共享内存里会正式用到，第 5 章讲 `fork` 时也会回到这里。

`malloc` 从内核拿内存有两条路：小块从堆顶扩展，大块直接 `mmap`。分界线由分配器的阈值决定，glibc 默认是 128 KiB。下面的程序依次分配 1000 字节、1 MiB、1 MiB，每次分配后立刻释放：

```c
int main(void) {
    static const size_t sizes[] = {1000, 1024 * 1024, 1024 * 1024};

    for (size_t i = 0; i < sizeof sizes / sizeof sizes[0]; i++) {
        char *p = malloc(sizes[i]);
        if (p == NULL) {
            return EXIT_FAILURE;
        }
        p[0] = 'x'; /* 碰一下，避免只看到分配、看不到实际使用 */
        printf("malloc(%zu) = %p\n", sizes[i], (void *)p);
        free(p);
        printf("free 完成\n");
    }
    return 0;
}
```

::: terminal title="bash - malloc_trace"

```console
$ ./malloc_trace
malloc(1000) = 0x55b97c8302a0
free 完成
malloc(1048576) = 0x7fa2e580f010
free 完成
malloc(1048576) = 0x55b97c8316a0
free 完成
```

:::

第一次分配的地址以 `0x55b9` 开头，在堆里；第二次以 `0x7fa2` 开头，在一段匿名映射里；第三次又回到了堆。用 `strace` 只看内存相关的系统调用，能看清每一步：

::: terminal title="bash - strace -e trace=brk,mmap,munmap ./malloc_trace（节选）"

```text
brk(NULL)                               = 0x55ce1924d000
brk(0x55ce1926e000)                     = 0x55ce1926e000
mmap(NULL, 1052672, PROT_READ|PROT_WRITE, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0) = 0x7ff0683cb000
munmap(0x7ff0683cb000, 1052672)         = 0
brk(0x55ce1936f000)                     = 0x55ce1936f000
```

:::

`malloc(1000)` 没有单独的 `mmap`，堆顶通过 `brk` 从 `0x55ce1924d000` 长到 `0x55ce1926e000`，涨了 132 KiB，够分配器切出很多小块。`malloc(1 MiB)` 直接 `mmap` 了 1052672 字节，比 1 MiB 多一个页，多出来的是分配器自己的块头。`free` 之后，这块用 `munmap` 还给了内核。第二次 `malloc(1 MiB)` 只让 `brk` 又涨了 1052672 字节，没有再 `mmap`。

原因在 glibc 的动态阈值。默认阈值是 128 KiB，大于等于它的分配走 `mmap`。这样一块被释放时，分配器把阈值提高到这块的大小，于是下一次同样大小的分配改从堆里切，不再 `mmap`。阈值最高能涨到 32 MiB（64 位机器上）。重复这个实验时，第二次分配的位置和第一次不同，就是这个机制在起作用，不是程序写错了。

::: details glibc 的 mmap 阈值与堆裁剪

`malloc` 判断走哪条路，看的是 `M_MMAP_THRESHOLD`，默认 128 KiB。释放一块由 `mmap` 得来、大小超过当前阈值但不超过上限的块时，阈值会提高到这块的大小；上限在 64 位机器上是 32 MiB，32 位机器上是 512 KiB。一旦用 `mallopt` 显式设置过 `M_MMAP_THRESHOLD`、`M_TRIM_THRESHOLD`、`M_TOP_PAD` 或 `M_MMAP_MAX`，动态调整就关闭。

堆顶的空闲空间要积到 `M_TRIM_THRESHOLD`（默认 128 KiB）以上，`free` 才会用 `brk` 把内存还给内核。所以大量小对象的程序释放之后，`VmRSS` 往往不会立刻下降。

这两个阈值都能用 `mallopt` 改，也可以在启动程序时用环境变量 `MALLOC_MMAP_THRESHOLD_`、`MALLOC_TRIM_THRESHOLD_` 调整。多数程序不需要动它们，需要压内存占用时才考虑。

:::

::: tip 用环境变量关掉动态阈值

做实验时如果希望每次大块分配都走 `mmap`，在命令前加一个环境变量：`MALLOC_MMAP_THRESHOLD_=131072 ./malloc_trace`。设了它，动态调整就失效，第二次 1 MiB 分配仍然走 `mmap`。

:::

## 6. 内存保护与段错误

页表项里除了物理页框号，还有权限位。`mprotect` 改的就是这些位：

```c
#include <sys/mman.h>

int mprotect(void *addr, size_t len, int prot);
```

`addr` 必须是某一页的起始地址，`len` 会向上取整到整页。保护的粒度是页，不能只保护一个对象中间的几个字节。

下面的程序映射一页，先写一个字节，再把它改成只读，然后按参数决定写不写：

```c
int do_write = argc > 1 && strcmp(argv[1], "write") == 0;
long page = sysconf(_SC_PAGESIZE);
char *p = mmap(NULL, (size_t)page, PROT_READ | PROT_WRITE,
               MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
if (p == MAP_FAILED) {
    perror("mmap");
    return EXIT_FAILURE;
}
p[0] = 'A';
printf("写入前：p[0] = %c\n", p[0]);
fflush(stdout);

if (mprotect(p, (size_t)page, PROT_READ) == -1) {
    perror("mprotect");
    return EXIT_FAILURE;
}
printf("已改成只读，准备写入\n");
fflush(stdout);

if (do_write) {
    p[0] = 'B';
    printf("这行不会执行：p[0] = %c\n", p[0]);
}
printf("没有写入，正常退出\n");
```

两次运行的结果：

::: terminal title="bash - mprotect_segv"

```console
$ ./mprotect_segv
写入前：p[0] = A
已改成只读，准备写入
没有写入，正常退出
$ echo $?
0
$ ./mprotect_segv write
写入前：p[0] = A
已改成只读，准备写入
Segmentation fault
$ echo $?
139
```

:::

第二次运行在写 `p[0]` 的那条指令上被内核终止。页表项没有写权限，写操作触发缺页，内核一看是权限违例而不是正常的缺页，直接给进程发 `SIGSEGV` (segmentation fault)。shell 打印 `Segmentation fault`，退出状态是 139，即 128 加 11。`printf` 排在写入之后的那些行永远执行不到，所以输出到「已改成只读」就断了。

保护以页为单位，这一点做实验时很容易碰到：把两页映射里的第二页改成只读，第一页照样能写。

::: terminal title="bash - pagegran"

```console
$ ./pagegran
第一页可写：a
第一页改成 A，仍然可写
第二页读到 b
$ ./pagegran write
第一页可写：a
第一页改成 A，仍然可写
尝试写第二页
Segmentation fault
```

:::

这个性质被用来做保护页 (guard page)：在一段分配的一端放一页 `PROT_NONE`，越界一个字节就会立刻崩溃，而不是悄悄改坏旁边的数据。线程库给每根线程栈也放了这样一页，栈长过界时以 `SIGSEGV` 报出来，而不是踩进相邻的映射。习题 40407 就是用这个办法抓出一个差一错误。

`PROT_EXEC` 控制可执行权限。现代的加固习惯是同一段内存不要同时可写和可执行，即 W^X，这样注入的代码无法直接运行；JIT 编译器会在写完代码后把页改成可执行。

## 7. 什么时候用 mmap

`mmap` 看上去比 `read` 省事，一个调用就能拿到整个文件，还少一次拷贝。实际写程序时，先看数据怎么用。

顺序读一个文件，用 `read` 加一个缓冲区就够了，代码短，也不慢。把第 2 章 3.2 节那个 mycat（64 KiB 缓冲区）和 mmapcat 放在一个 22 MiB 的文件上对比系统调用次数：

```c
static int write_all(int fd, const void *buf, size_t len) { /* 同第 2 章 */ }

int main(int argc, char *argv[]) {
    int fd = open(argv[1], O_RDONLY | O_CLOEXEC);
    /* fstat 得到 st.st_size，省略错误检查 */
    char *p = mmap(NULL, (size_t)st.st_size, PROT_READ, MAP_PRIVATE, fd, 0);
    if (p == MAP_FAILED) {
        perror("mmap");
        return EXIT_FAILURE;
    }
    if (write_all(STDOUT_FILENO, p, (size_t)st.st_size) == -1) {
        perror("write");
        return EXIT_FAILURE;
    }
    munmap(p, (size_t)st.st_size);
    close(fd);
    return 0;
}
```

::: terminal title="bash - strace -c 对比（22 MiB 文件）"

```text
mmapcat：
% time     seconds  usecs/call     calls    errors syscall
------ ----------- ----------- --------- --------- ----------------
  0.00    0.000000           0         1           read
  0.00    0.000000           0         1           write
------ ----------- ----------- --------- --------- ----------------
100.00    0.000000           0         2           total

mycat（缓冲区 64 KiB）：
% time     seconds  usecs/call     calls    errors syscall
------ ----------- ----------- --------- --------- ----------------
 79.35    0.006409          18       352           read
 20.00    0.001615           4       350           write
------ ----------- ----------- --------- --------- ----------------
100.00    0.008077          11       702           total
```

:::

mmapcat 只有一次 `write`，一次把 22 MiB 全交出去；那唯一一次 `read` 是动态链接器读取 ELF 头，不是读文件内容。mycat 要读 352 次、写 350 次。系统调用次数差了两个数量级，但两者的实际耗时并不按这个比例差，因为 mmapcat 的每次缺页都要内核填页表，`write` 到管道时还要把数据从页缓存搬到管道缓冲区。系统调用次数只是故事的一部分。

::: warning 管道和套接字不能映射

`mmap` 的第一个参数是文件描述符，但只有支持映射的对象才行。管道、套接字、终端这类没有文件偏移量的对象，`mmap` 返回 `MAP_FAILED`，`errno` 为 `ENODEV`。想把管道里的数据映射进来做不到，只能 `read`。

:::

作者对选型的判断：

1. 顺序读、顺序写、一次性的处理，用 `read` 加 64 KiB 缓冲区。实现简单，出错路径少，性能与 `mmap` 在同一量级。
2. 大文件的随机访问，或者按偏移定位的数据文件，用 `mmap`。SQLite 的 `mmap_size` 选项就是这个思路：数据库按页组织，需要哪一页就映射哪一页，省掉页缓存到用户缓冲区的拷贝，项目案例的 [6.3 B 树与存储引擎](/教程/正文/项目案例/SQLite/6_3_B树与存储引擎) 讲了页式存储。注意 `mmap` 只对读密集的查询有明显好处，写入前 SQLite 仍然要把页复制到私有内存。
3. 多个进程要看到彼此对同一份数据的修改，用 `MAP_SHARED` 映射同一个文件。只读共享不必特别处理：`MAP_PRIVATE` 映射同一个文件的多个进程也共用页缓存里的同一批页，物理内存里只有一份。
4. 需要一块清零的大内存，用 `MAP_PRIVATE | MAP_ANONYMOUS`，不必经过 `malloc`。

代价也要算进去。每次首次访问一页都是一次缺页，随机访问一个小文件时，缺页的开销可能超过拷贝；`munmap` 要拆掉页表项并让相关的 TLB 项失效，频繁映射、解除映射的小块不如直接用 `malloc`；文件在映射期间被别的进程截短会得到 `SIGBUS`，程序必须先想好这种情况怎么处理。

`posix_madvise` 可以把访问模式告诉内核，让预读更积极或更保守：

```c
#include <sys/mman.h>

posix_madvise(p, len, POSIX_MADV_SEQUENTIAL); /* 顺序访问，预读积极一些 */
```

它只是建议，内核可以不理，程序的正确性不能依赖它。真要把一段内存锁在物理内存里不让它换出，用 `mlock`，它受 `RLIMIT_MEMLOCK` 限制，普通用户能锁的量很小。
