# 9.3 用户数据报协议（UDP）

## 1. 什么是 UDP

### 1.1 UDP 的作用和特点

用户数据报协议 (User Datagram Protocol, UDP) 是一种无连接的传输层协议。与 TCP 相比，它有以下特点：

1. 无连接：通信前不需要握手建立连接，结束时也不需要断开连接。

2. 简单性：UDP 的首部只有 8 字节，数据包的开销较小，适合用于实时传输和广播等场景。

3. 不可靠性：UDP 不保证数据包一定到达，也不保证到达的顺序，数据包还可能重复。需要可靠传输的应用，要自行实现确认和重传。

## 2. UDP 的基本功能

### 2.1 数据传输

UDP 的基本功能是将数据从一个端点传输到另一个端点。应用程序每次交给它的数据，UDP 只加上源端口和目标端口等首部信息，作为一个数据包通过网络传输，自身并不对数据分段。UDP 不关心数据包的顺序和可靠性。

## 3. UDP 的特点和不可靠性

### 3.1 无连接

UDP 是一种无连接的协议，它不需要像 TCP 那样进行连接的建立和断开，因此通信的开销较低。这使得 UDP 适用于需要快速数据传输的场景，如音频和视频流。

### 3.2 不可靠性

UDP 的不可靠性表现在以下方面：

1. 丢包：UDP 数据包在传输过程中可能会丢失，不提供重传机制。
2. 乱序：数据包可能以不同的顺序到达目标端，应用层需要自行处理数据包的顺序问题。
3. 重复：UDP 数据包可能会被重复传输，接收端需要处理重复数据包。

## 4. C 语言中的 UDP 编程

1. 创建套接字
   在 C 语言中，可以使用 Socket API 来创建 UDP 套接字，套接字是网络通信的端点，用于数据传输。UDP 套接字可以通过 socket 函数创建。
2. 数据传输
   数据传输可以使用 sendto 函数来发送 UDP 数据包，需要指定目标地址和端口。接收数据则使用 recvfrom 函数，接收方会获得数据包的源地址和端口信息。
3. 接收数据
   UDP 套接字默认是阻塞的，如果没有数据可接收，recvfrom 函数会一直等待，直到有数据包到达。如果提供的缓冲区比数据包小，多出的部分会被丢弃。应用层需要自行处理接收到的数据包，包括解析数据和处理不可靠性问题。

## 5. 习题

UDP 没有连接、没有重传，程序要自己补的东西比 TCP 多。下面四道题按「一条数据报的边界」展开：怎么发、怎么收、收到了什么、丢了怎么知道。

<Exercise id="40918" :d="1" :w="1">

正文说 UDP 保留消息边界。写一个最小的收发对：发送端用一次 `sendto` 发出 `hello`（5 字节），再发一次空的 `sendto`（长度为 0）；接收端用 64 字节缓冲区连续 `recvfrom`，把每次的返回值、源端口和 `errno` 都打印出来（`SO_RCVTIMEO` 设 500 毫秒，以便在收完两条之后退出）。

要求：

1. 接收端第一次、第二次 `recvfrom` 各返回多少？第二次返回 0 是「对端关闭」还是「收到了一条空数据报」？
2. 把接收缓冲区改成 3 字节，重发 `hello`。`recvfrom` 返回 3 还是 5？剩下两个字节到哪里去了？再读一次会得到什么？
3. 发送端不 `bind` 时，`getsockname` 在 `sendto` 前后各返回什么？把它打印出来。

验收：第 1 问是 5 和 0，且第二次不是连接关闭——UDP 没有「连接关闭」这个事件，返回 0 只表示数据报的负载长度为 0。第 2 问里缓冲区 3 字节时 `recvfrom` 返回 3，内容只有 `hel`，多出的字节直接丢弃，下一次 `recvfrom` 超时返回 -1、`errno` 为 `EAGAIN`，而不是读到剩下的两个字节。第 3 问中 `sendto` 之前 `getsockname` 给出端口 0、地址 `0.0.0.0`，之后由内核分配了一个临时端口。

</Exercise>

写一个 `udpecho PORT`：绑定 `127.0.0.1:PORT`，每收到一条数据报就原样发回给来源地址，并在标准输出打印 `N bytes from IP:PORT`。再写一个客户端，依次发送 10、100、1000、2000 字节，打印每条回显的长度。

要求：

1. 客户端的四次 `recvfrom` 各返回多少？1000 字节那条会不会像 TCP 那样被拆成几次读取？
2. 把客户端的接收缓冲区改成 512 字节，重发 1000 字节那条。返回值是多少，回显内容还剩多少？
3. 用 `MSG_TRUNC` 标志再收一次同样的数据报，返回值变成多少？由此说明 `MSG_TRUNC` 改变了什么、没改变什么。

验收：第 1 问中四次回显长度依次是 10、100、1000、2000，1000 字节只对应一次 `recvfrom`（`lo` 的 MTU 是 65536，不会分片）。第 2 问返回缓冲区的长度 512，内容被截断，多出的部分丢弃，剩下的字节不会留到下一次读取。第 3 问带 `MSG_TRUNC` 时返回值变成原始数据报长度 1000，但缓冲区里仍然只有 512 字节，所以它只改变返回值、不改变搬进缓冲区的数据量。

</Exercise>

<Exercise id="40920" :d="4" :w="3">

UDP 套接字也可以 `connect`，它不发报文，只给套接字记下默认对端。写一个程序验证连接过的 UDP 套接字与未连接的差别：

1. 用一个没人监听的端口（`127.0.0.1:23999`）作目标。未连接的套接字连续 `sendto` 两次，分别打印返回值和 `errno`；然后用 `recvfrom` 读一次（设 1 秒超时），打印结果。
2. 新建一个套接字，`connect` 到同一个端口。打印 `connect` 的返回值。连续 `send` 两次，再 `recv` 一次，打印每一步的返回值与 `errno`。
3. 用 `/proc/net/snmp` 的 `Udp:` 行读 `NoPorts` 计数，在第 2 步前后各读一次，说明这个计数增加了几次、每次对应哪个动作。

验收：第 1 问两次 `sendto` 都返回 1，`recvfrom` 超时返回 -1、`errno` 为 `EAGAIN`。第 2 问中 `connect` 返回 0（目标端口没有监听也照样成功），第一次 `send` 返回 1，第二次 `send` 返回 -1、`errno` 为 `ECONNREFUSED`，随后的 `recv` 也返回 -1、`ECONNREFUSED`，之后的 `recv` 才回到 `EAGAIN`。第 3 问的正确观察是未连接的两次 `sendto` 同样让 `NoPorts` 涨（各一次），这与「未连接就收不到 ICMP 错误」并不矛盾：报文回到了本机，只是没有已连接套接字可以挂这个错误，痕迹只留在计数器里；`connect` 之后那次 `send` 让计数再涨一，而这次错误被记到了套接字上，于是 `errno` 才读得到 `ECONNREFUSED`。

回答时要说清：为什么未连接的套接字拿不到 `ECONNREFUSED`，而连接过的可以？这对「服务器没启动」这类故障的诊断有什么影响？

</Exercise>

<Exercise id="40921" :d="5" :w="4">

接收缓冲区不够时 UDP 会静默丢包。写一对程序：`udpsink PORT SECONDS` 在指定时间内**故意不读**（先 `sleep`），之后再用 65536 字节缓冲区把队列里的数据报全部读出来并计数；`udpsrc HOST PORT SIZE COUNT` 连续发 `COUNT` 条 `SIZE` 字节的数据报，每条之间不睡眠。

按 `SIZE` 为 100、1400、4000 各跑一次 `COUNT` 为 5000，`SO_RCVBUF` 用 `setsockopt` 设成 4096，记录：

1. 发送端 `sendto` 有多少次返回失败？失败时 `errno` 是什么？它在什么时刻开始失败？
2. 接收端实际收到多少条？`/proc/net/snmp` 的 `Udp:` 行里 `InErrors` 与 `RcvbufErrors` 各增加了多少？两者相等吗？
3. `SIZE` 为 4000 时，`sendto` 的返回值是 4000 还是 4008？为什么这里有一个容易弄错的差值？
4. 把 `SO_RCVBUF` 改成 262144 后重跑 1400 字节那组。丢包数下降了多少？`setsockopt` 设的值和 `getsockopt` 读回的值为什么不一样？

验收：第 1 问中 `sendto` 在本机回环上基本都成功（返回的是传进去的长度），失败出现在接收端而不是发送端——UDP 的排队发生在接收队列里。第 2 问里 `InErrors` 与 `RcvbufErrors` 的增量相等，都等于「发了 5000 条、真正收到 N 条」的差额，两个计数在这里指同一件事；`InDatagrams` 的增量与 `recvfrom` 成功返回的条数相等，说明它数的是数据报而不是 IP 分片。第 3 问里 `sendto` 的返回值等于负载长度 4000，而 UDP 首部里写的长度是 4008，差的是 8 字节 UDP 首部。第 4 问里 `getsockopt` 读回的值约为设置值的两倍，这是 Linux 把内核记账开销算进去的结果，设置值与读回值本来就不要求相等。

最后一问：既然 UDP 会这样静默丢包，应用层要怎么知道「对面收到了多少」？给出两种做法（一种靠协议自己带序号，一种靠应用层回执），各说一句适用场景。

</Exercise>
