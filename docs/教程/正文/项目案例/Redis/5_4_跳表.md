# 5.4 源码阅读：Redis 跳表

Redis 的有序集合（Sorted Set / ZSET）是其实用性最高的数据结构之一。无论是游戏积分排行榜、带权重的任务调度队列，还是各类按时间戳排序的事件流，都能凭借有序集合在常数或对数时间内完成按分值检索、区间切片与排名统计。支撑这一系列高效特性的底层核心，正是一套经过工程深度裁剪与定制的**跳表**（skiplist）。

从算法理论走入工业级生产系统，Redis 对跳表做出了诸多富有洞察力的改动：引入跨度（span）以支持 $O(\log N)$ 的排名计算、采用单次内存分配消除指针跳跃、以及利用双重索引化解成员检索与区间排序的固有张力。

> 源码基于 Redis 8.x（`t_zset.c` 与 `server.h`）。跳表的完整实现集中在 `t_zset.c` 前部约 900 行代码中。

## 1. 为什么用跳表

### 1.1 核心思想

在经典数据结构中，若想兼顾排序存储与快速检索，最直接的选择往往是平衡二叉搜索树（如红黑树或 AVL 树）。然而平衡树为了维持严格的平衡条件，插入与删除时常常需要伴随复杂的节点变色与树旋转，范围查询也必须依赖树的中序遍历，在内存指针跳转与缓存局部性上面临挑战。

跳表则另辟蹊径，它以一条纯粹的有序链表为地基，在上方逐层搭建起多级由稀到密的“快速通道”。检索目标时，指针从最高层的稀疏索引出发向前探查；一旦发现下一节点的键值已超过目标，便原地下降一层继续前进，直至在最底层的全量链表中精准定位。由于各层节点的向上跃迁由伪随机数控制并呈几何分布递减，整个跳表的查找、插入与删除操作都能在期望时间 $O(\log N)$ 内完成，同时天然保留了底层链表对连续区间顺序扫描的优良局部性。

::: generate skiplist-intro kind=explanation concepts=skiplist-node-struct,skiplist-struct

面向有链表和二叉搜索树基础的 C 学习者，解释跳表的核心思想：在有序链表上建立多层"快速通道"索引，每一层都是下一层的子集，从顶层开始查找可以跳过大量节点，将 O(N) 的链表查找降到 O(log N)。用电梯楼层或地铁快线的类比帮助理解。

:::

### 1.2 Redis 为什么选择跳表

Redis 作者 antirez 曾公开详述过为何选用跳表替代平衡二叉树来实现有序集合：

1. **内存开销高度可调**：跳表节点的高层指针数量由几何分布概率参数控制。通过调低高层跃迁的概率（Redis 取 $p = 0.25$），跳表的平均指针开销能够压制得比多数平衡树更轻盈。
2. **范围遍历极其自然**：有序集合的高频操作包括 `ZRANGE`、`ZREVRANGE` 等区间切片。在跳表中定位到区间起点后，后续的扫描完全退化为平直的双向链表遍历，对 CPU 缓存预取极其友好，无需处理复杂的树遍历回溯。
3. **工程实现与调试简洁**：相较于红黑树数十种繁琐的旋转与重着色分支，跳表的插入与删除在结构拓扑上始终只是纯粹的链表指针重挂，代码阅读与并发改造的心理门槛显著更低。

::: generate skiplist-vs-bst kind=comparison concepts=skiplist-node-struct,skiplist-struct

面向有数据结构基础的读者，对比跳表和平衡二叉搜索树（红黑树/AVL树）在以下维度的差异：时间复杂度（查找/插入/删除均为 O(log N)）、实现复杂度、范围查询效率、内存开销、并发友好度。结论是二者性能相当，但跳表在工程上更简单。

:::

## 2. 数据结构

### 2.1 跳表节点

::: concept skiplist-node-struct title="zskiplistNode 结构"

```c
typedef struct zskiplistNode {
    double score;                       // 分数，排序的依据
    struct zskiplistNode *backward;     // 后退指针，仅在第 0 层
    struct zskiplistLevel {
        struct zskiplistNode *forward;  // 前进指针
        unsigned long span;             // 跨度：到 forward 节点的距离（相邻节点为 1）
    } level[];                          // 柔性数组，长度 = 该节点的层数
    // sds ele 嵌入在 level[] 之后（单次分配）
} zskiplistNode;
```

每个节点由以下核心字段构成：

- **score**：`double` 精度的分数值，作为排序的第一关键字。
- **ele**：成员字符串（SDS），作为分数值相同情况下的第二排序关键字（按二进制字典序排序）。在现代 Redis 实现中，SDS 字符串直接以内联形式紧随结构体分配，避免额外的间接指针寻址。
- **backward**：后退指针，专门设置在第 0 层，用于支持从链表尾部向头部反向遍历（如 `ZREVRANGE`）。
- **level[]**：柔性数组成员。其实际长度对应节点分配的层数。每一层包含一个指向前驱节点的 `forward` 前进指针，以及一个记录跃迁距离的 `span` 跨度值。

:::

`span`（跨度）是 Redis 对学术界跳表设计的关键工程创新。教科书跳表仅包含前进指针，只能判断“下一个节点是谁”。Redis 在各层的前进指针旁增加了 `span`，专门记录**当前节点沿此层前进指针到达下一个节点时跨越了多少个最底层基础节点**（相邻两节点间的跨度为 1）。沿着查找路径把沿途跨越的 `span` 逐项累加，就能直接算出目标节点在整个集合中的绝对名次（Rank），一举将 `ZRANK` 从全表扫描的 $O(N)$ 降至 $O(\log N)$。

为了降低内存碎片与寻址延迟，节点的内存分配在 `zslCreateNode` 中被打包为单次连续分配：

```c
static zskiplistNode *zslCreateNode(zskiplist *zsl, int level,
                                     double score, sds ele) {
    size_t node_size = sizeof(zskiplistNode)
                     + level * sizeof(struct zskiplistLevel);
    size_t sds_buf_size = sds_hdr_len + ele_len + 1;
    size_t total_size = node_size + sds_buf_size;

    // 一次 malloc 分配 node + level[] + 嵌入的 sds
    zskiplistNode *zn = zmalloc_usable(total_size, &usable);

    zn->score = score;
    zn->backward = NULL;

    // 在 node 末尾就地构造 sds
    char *sds_buf = (char*)zn + node_size;
    sds embedded_sds = sdsnewplacement(sds_buf, sds_buf_size,
                                        sds_type, ele, ele_len);
    // 层数和 sds 偏移存入 level[0].span（第 0 层的 span 字段复用为元信息）
    zslSetNodeInfo(zn, level, sds_offset);
    return zn;
}
```

结构体本体、变长柔性数组 `level[]` 以及存储成员内容的 SDS 缓冲区全部挤入同一块连续的堆内存中。释放节点时也只需调用一次 `zfree`，极大减少了小对象高频创建释放造成的内存碎片。

### 2.2 跳表本体

::: concept skiplist-struct title="zskiplist 结构"

```c
typedef struct zskiplist {
    struct zskiplistNode *header, *tail;  // 头节点（哨兵）和尾节点
    unsigned long length;                  // 节点总数（不含 header）
    int level;                             // 当前最高层数
    size_t alloc_size;                     // 跟踪内存占用
} zskiplist;
```

- **header**：固定拥有 `ZSKIPLIST_MAXLEVEL`（32 层）的哨兵节点。它不保存任何有效业务数据，仅作为所有高低层索引的前行起点，彻底规避了链表头部的空指针特判。
- **tail**：指向跳表中排名最末的节点，提供常数时间 $O(1)$ 的末梢反向定位。
- **level**：记录当前整个跳表中实际存在的最大节点层数。每次查找只需从这个实际最高层启动向下探查，无需盲目从第 32 层遍历空指针。

:::

### 2.3 有序集合的双重索引

完整的有序集合数据类型并未单纯依赖跳表，而是采用了跳表与哈希表的双剑合璧：

```c
typedef struct zset {
    dict *dict;       // ele -> score 的哈希表，O(1) 按成员查分数
    zskiplist *zsl;   // score -> ele 的跳表，支持排序和范围查询
} zset;
```

同一个成员元素在内存中只存在一份物理 SDS 字符串，字典和跳表共同引用它的地址。当执行 `ZSCORE` 时，系统直接走哈希表在 $O(1)$ 时间内拿到分值；当执行 `ZRANGE` 或 `ZRANK` 时，则交由跳表以 $O(\log N)$ 时间展开排序与跨度计算。两者各扬所长，在空间零冗余的前提下兼顾了两种截然不同的访问范式。

## 3. 随机层数

::: concept random-level title="zslRandomLevel 的几何分布"

```c
#define ZSKIPLIST_MAXLEVEL 32
#define ZSKIPLIST_P 0.25

static int zslRandomLevel(void) {
    static const int threshold = ZSKIPLIST_P * RAND_MAX;
    int level = 1;
    while (random() < threshold)
        level += 1;
    return (level < ZSKIPLIST_MAXLEVEL) ? level : ZSKIPLIST_MAXLEVEL;
}
```

每个节点初始化时都至少拥有第 1 层；此后每次通过抛掷硬币式的伪随机判定，以 $p = 0.25$ 的概率尝试向上晋升一层，直到掷出不满足条件或达到最大层数上限 32。这是一个经典的参数为 $p=0.25$ 的几何分布：

- 100% 的节点拥有第 1 层；
- 25% 的节点能晋升到第 2 层；
- 6.25% 的节点能晋升到第 3 层；
- 依此类推，第 $k$ 层的期望节点数为 $N \times 0.25^{k-1}$。

在 $p=0.25$ 的设定下，整个跳表平均每个节点消耗的指针数量仅为 $\frac{1}{1 - p} \approx 1.33$ 个，相比 $p=0.5$（平均 2 个指针）节省了大量内存。而 32 层的上限足以稳固支撑 $4^{32} = 2^{64}$ 规模的巨量元素，在实际物理内存容量内永无溢出之虞。

:::

::: generate random-level-vis kind=explanation concepts=random-level

面向 C 学习者，用一个 8 节点的例子直观展示 zslRandomLevel 产生的跳表结构：大部分节点只有 1 层，少数有 2 层，极少数有 3 层或更多。解释为什么 p=0.25（而不是 0.5）是一个好的权衡：更少的指针意味着更低的内存开销，同时查找效率只略有降低。计算平均每个节点的指针数为 1/(1-p) = 1.33 个。

:::

## 4. 插入

::: concept insert-invariant title="插入算法的核心不变量"

跳表插入的核心在于维护两组辅助上下文：
- `update[i]`：在第 $i$ 层中，新节点应当紧跟其后的那个前驱节点。
- `rank[i]`：从哨兵头节点出发，沿着检索阶梯走到 `update[i]` 时沿途累加跨越的底层节点总数（即前驱节点在全局中的绝对名次）。

整个插入过程严密地分为三步：首先自顶向下沿阶梯寻查插入槽位，填满 `update[]` 与 `rank[]`；随后掷骰生成随机层数并完成节点内存分配；最后在各层逐级穿针引线挂接指针，并精确重算各层的 `span` 跨度。

:::

`zslInsert` 负责协调高阶调用，而 `zslInsertNode` 承载了全部核心指针调度：

```c
zskiplistNode *zslInsert(zskiplist *zsl, double score, sds ele) {
    int level = zslRandomLevel();
    zskiplistNode *node = zslCreateNode(zsl, level, score, ele);
    zslInsertNode(zsl, node);
    return node;
}
```

### 4.1 查找插入位置

```c
static void zslInsertNode(zskiplist *zsl, zskiplistNode *node) {
    zskiplistNode *update[ZSKIPLIST_MAXLEVEL];
    unsigned long rank[ZSKIPLIST_MAXLEVEL];
    zskiplistNode *x;
    int i, level;
    double score = node->score;
    sds ele = zslGetNodeElement(node);
    level = zslGetNodeInfo(node)->levels;

    // 从最高层开始，逐层下降，找到每层的前驱节点
    x = zsl->header;
    for (i = zsl->level-1; i >= 0; i--) {
        rank[i] = i == (zsl->level-1) ? 0 : rank[i+1];
        while (zslCompareWithNode(score, ele, x->level[i].forward) > 0) {
            rank[i] += zslGetNodeSpanAtLevel(x, i);
            x = x->level[i].forward;
        }
        update[i] = x;
    }
```

查找路径呈现出典型的由左上至右下的“阶梯式扫描”。在每一层，指针尽可能向前探查：只要前方节点的分数小于目标分值（或分值相同时字符串字典序小于目标），就继续跨步前进，同时将前进指针上的 `span` 累加进 `rank[i]`；一旦前方节点已大于目标或到达链表尾端，便停下当前层的脚步，记录 `update[i] = x`，并垂直下降一层继续前进。

### 4.2 链接新节点

```c
    // 如果新节点层数超过当前最高层，补充 update 和 rank
    if (level > zsl->level) {
        for (i = zsl->level; i < level; i++) {
            rank[i] = 0;
            update[i] = zsl->header;
            zslSetNodeSpanAtLevel(update[i], i, zsl->length);
        }
        zsl->level = level;
    }

    // 逐层插入
    for (i = 0; i < level; i++) {
        node->level[i].forward = update[i]->level[i].forward;
        update[i]->level[i].forward = node;

        // 新节点的 span = 原 span - 已跨越的距离
        zslSetNodeSpanAtLevel(node, i,
            zslGetNodeSpanAtLevel(update[i], i) - (rank[0] - rank[i]));
        // 前驱的 span = 已跨越的距离 + 1
        zslSetNodeSpanAtLevel(update[i], i, (rank[0] - rank[i]) + 1);
    }

    // 未被新节点覆盖的高层，span 只需 +1
    for (i = level; i < zsl->level; i++) {
        zslIncrNodeSpanAtLevel(update[i], i, 1);
    }
```

跨度 `span` 的数学重算公式是理解跳表排名的关键所在。新节点插入在 `update[i]` 与其原本的后继节点之间，将原本由 `update[i]` 一跨到底的距离切分为了前后两段：

- 前半段：从 `update[i]` 到新节点，距离恰好是 `(rank[0] - rank[i]) + 1`（其中 `+1` 计入新节点自身）。
- 后半段：从新节点到原后继节点，跨度为原跨度减去前半段消耗的间距。
- 高层调整：对于超出新节点自身高度、但仍在跳表有效高度范围内的顶层，新节点的加入只是在它们的跨越区间内平添了一个底层实体，因此只需直接给前驱的 `span` 执行加 1。

### 4.3 更新后退指针与边界

```c
    node->backward = (update[0] == zsl->header) ? NULL : update[0];
    if (node->level[0].forward)
        node->level[0].forward->backward = node;
    else
        zsl->tail = node;

    zsl->length++;
}
```

后退指针仅在最底层的第 0 层进行维护，形成一条严格的双向链表结构。如果新节点恰好插入在表尾（其后继为空），则顺势将跳表的 `tail` 指针刷新为当前节点。至此，节点总计数 `length` 累加，新节点正式融入跳表。

## 5. 删除

::: concept delete-invariant title="删除算法的不变量"

删除操作与插入在结构上呈现出严密的对偶性：同样是先沿阶梯定位各层的受影响前驱集合 `update[]`，随后逐层脱链并重新缝合指针。跨度 `span` 的更新也是插入的镜像逻辑——前驱原本跨越的距离与被删节点向后跨越的距离合并，同时减去被删节点自身占据的 1 个单位位置。

:::

删除流程由定位前驱的 `zslDelete` 与实际解绑的 `zslUnlinkNode` 协同完成：

```c
static void zslUnlinkNode(zskiplist *zsl, zskiplistNode *x,
                           zskiplistNode **update) {
    for (int i = 0; i < zsl->level; i++) {
        if (update[i]->level[i].forward == x) {
            // 这一层直接链接到 x，合并 span 并跳过 x
            zslIncrNodeSpanAtLevel(update[i], i,
                zslGetNodeSpanAtLevel(x, i) - 1);
            update[i]->level[i].forward = x->level[i].forward;
        } else {
            // 这一层没有链接到 x（x 的层数不够高），只需 span-1
            zslDecrNodeSpanAtLevel(update[i], i, 1);
        }
    }

    // 更新后退指针
    if (x->level[0].forward)
        x->level[0].forward->backward = x->backward;
    else
        zsl->tail = x->backward;

    // 如果删除的是最高层节点，降低跳表层数
    while (zsl->level > 1 &&
           zsl->header->level[zsl->level-1].forward == NULL)
        zsl->level--;

    zsl->length--;
}
```

代码中的 `if/else` 严谨处理了节点高度不一的情况：若被删节点 `x` 只有 2 层，而跳表当前总高度为 5 层，那么在第 3 至 5 层中，`update[i]` 的前进指针实际上直接凌空跃过了 `x`。在这些高层，前进指针无需变动，只需将跨度减 1，以反映底层物理节点减少了一个实体。

完成各层脱链后，代码修复底层的 `backward` 指针与 `tail` 指针。如果刚刚被移除的节点恰好是跳表中独占最高层的孤本，循环还会自动递减 `zsl->level`，收缩跳表的有效高度。

而在日常业务的高频分值变动中，`zslUpdateScore` 包含了一项精巧的就地优化路径：如果修改后的分值仍然严格保持在当前节点的前驱与后继分值之间（相对拓扑位置未变），系统将直接原地覆写 `node->score`，彻底省去了摘链、重算跨度以及再次插入的整套对数开销。

## 6. 排名与范围查询

### 6.1 排名查询

`zslGetRank` 利用 span 累加实现 O(log N) 的排名计算：

```c
unsigned long zslGetRank(zskiplist *zsl, double score, sds ele) {
    zskiplistNode *x;
    unsigned long rank = 0;

    x = zsl->header;
    for (int i = zsl->level-1; i >= 0; i--) {
        while (zslCompareWithNode(score, ele, x->level[i].forward) >= 0) {
            rank += zslGetNodeSpanAtLevel(x, i);
            x = x->level[i].forward;
        }
        if (x != zsl->header &&
            zslCompareWithNode(score, ele, x) == 0)
            return rank;
    }
    return 0;  // 未找到
}
```

查找路径与插入逻辑相同，采用自顶向下的阶梯式遍历。在每一层向前推进时，只要前方节点的分数小于等于目标（若分数相同则字典序小于等于目标），就向右前进并累加对应层的 `span` 跨度。到达目标节点时，累加值正是从哨兵头节点到该节点的绝对距离，也就是以 1 为起点的全局名次（1-based rank）。若遍历结束仍未匹配，则返回 0 表示元素不存在。

与之互为逆运算的 `zslGetElementByRank` 则反其道而行之：给定目标名次，它从最高层出发，沿途比较各层跨度与剩余名次，在对数时间内直接定位到指定排名的节点对象。

### 6.2 范围查询

`zslNthInRange` 负责在指定的分数范围内定位第 N 个元素。它的检索策略兼顾了范围边界判定与步进局部性：

1. 先用 `zslIsInRange` 进行常数时间 $O(1)$ 的快速拒绝：仅需检查给定区间的端点与跳表的最小/最大节点，若毫无交集则直接返回 `NULL`；
2. 从最高层开始沿阶梯搜索，快速收敛到落在该范围内的第一个边界节点；
3. 如果调用方要求的偏移量 $N$ 较小（小于阈值 `ZSKIPLIST_MAX_SEARCH = 10`），代码直接沿最底层的第 0 层链表平稳步进，充分利用连续内存的缓存红利；
4. 如果偏移量 $N$ 较大，则继续借助高层索引的大跨度指针跳跃穿透。

```c
zskiplistNode *zslNthInRange(zskiplist *zsl, zrangespec *range,
                              long n, unsigned long *out_rank) {
    if (!zslIsInRange(zsl, range)) return NULL;

    // 在最高层找到范围边界
    x = zsl->header;
    i = zsl->level - 1;
    while (x->level[i].forward &&
           !zslValueGteMin(x->level[i].forward->score, range)) {
        edge_rank += zslGetNodeSpanAtLevel(x, i);
        x = x->level[i].forward;
    }
    // 记住此节点以备大偏移量时使用
    last_highest_level_node = x;

    // 继续在低层精确定位
    for (i = zsl->level - 2; i >= 0; i--) {
        while (x->level[i].forward &&
               !zslValueGteMin(x->level[i].forward->score, range)) {
            edge_rank += zslGetNodeSpanAtLevel(x, i);
            x = x->level[i].forward;
        }
    }

    // 小偏移：逐节点走
    if (n < ZSKIPLIST_MAX_SEARCH) {
        for (i = 0; i < n + 1; i++)
            x = x->level[0].forward;
    } else {
        // 大偏移：从高层节点跳跃
        x = zslGetElementByRankFromNode(last_highest_level_node,
                                         zsl->level - 1, rank_diff);
    }
    // ...
}
```

当 $n$ 为负数时，函数会先将游标定位到区间的右边界，然后沿着底层双向链表的 `backward` 指针逆向回溯，以此自然支撑 `ZREVRANGEBYSCORE` 等反向区间命令。

## 7. 从命令到跳表操作

有序集合的常用命令与跳表操作有着清晰的映射关系：

| Redis 命令 | 操作 | 跳表函数 |
|:---|:---|:---|
| `ZADD key score member` | 插入/更新分数 | `zslInsert` 或 `zslUpdateScore` |
| `ZREM key member` | 删除 | `zslDelete` |
| `ZSCORE key member` | 查分数 | 不走跳表，走 `dict` 哈希表 |
| `ZRANK key member` | 查排名 | 先用 `dict` 找到节点，再用 `zslGetRankByNode` |
| `ZRANGE key start stop` | 按排名范围 | `zslGetElementByRank` + 遍历 |
| `ZRANGEBYSCORE key min max` | 按分数范围 | `zslNthInRange` + 遍历 |
| `ZRANGEBYLEX key min max` | 按字典序范围 | `zslNthInLexRange` + 遍历 |
| `ZCARD key` | 元素总数 | `zsl->length`，O(1) |

跳表与哈希表协同构成了完整的双重索引体系：哈希表负责在常数时间 $O(1)$ 内按成员名称直接定位到节点（驱动 `ZSCORE` 查询与 `ZREM` 的快速寻址）；跳表则负责以 $O(\log N)$ 时间组织有序排列，支持排名统计与区间检索。二者共同持有同一个 SDS 成员字符串的指针，既保证了数据访问的双向极速，又彻底杜绝了重复存储的内存浪费。
