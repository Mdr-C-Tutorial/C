# 6.1 源码阅读：SQLite 架构概述

SQLite 是一个无服务器、零配置、支持事务的 SQL 数据库引擎。一个数据库就是一个文件，整个引擎是一个 C 库：没有独立的服务进程，也没有网络协议，链接进程序即可使用。SQLite 的实现约 15 万行 C 代码，部署在几乎所有手机、浏览器和操作系统中，是部署量最大的数据库引擎。

本文自顶向下介绍 SQLite 的架构：一条 SQL 语句从进入 API 到读写磁盘要经过哪些层，每一层使用了哪些关键的 C 数据结构。

> 源码：<https://sqlite.org/src>，公有领域（Public Domain）。本文基于 SQLite 3.46 版本的合并源码（amalgamation）。

## 1. 为什么读 SQLite

SQLite 适合作为阅读 C 语言工程代码的范例，原因有以下几点：

- 官方提供合并源码 `sqlite3.c`，一个文件包含全部实现，便于阅读和搜索。
- 除标准 C 库和操作系统接口外，不依赖任何第三方库。
- 查找表、字节码虚拟机、B-tree 存储引擎、跨平台 VFS 抽象等技术集中在同一个项目中。
- 测试达到 100% 分支覆盖，测试代码量是实现代码的数百倍。

## 2. 架构总览

::: concept sqlite-architecture title="SQLite 的分层架构"

SQLite 的实现从上到下分为八层。最上层是面向用户的 C API，最下层是操作系统的文件 I/O。一条 SQL 语句自顶向下流过每一层，最终变成对磁盘文件的读写操作：

| 层 | 职责 | 核心源文件 |
|:---|:---|:---|
| 接口层 (Interface) | 公开 API，管理数据库连接 | `main.c`, `prepare.c`, `vdbeapi.c` |
| 词法分析 (Tokenizer) | 将 SQL 文本切分为 token | `tokenize.c` |
| 语法分析 (Parser) | 将 token 流解析为语法树 | `parse.y` (经 Lemon 生成 `parse.c`) |
| 代码生成 (Code Generator) | 将语法树翻译为字节码 | `build.c`, `select.c`, `where.c`, `expr.c` |
| 虚拟机 (VDBE) | 执行字节码指令 | `vdbe.c`, `vdbeaux.c` |
| B-tree | 管理数据页的树形索引 | `btree.c` |
| Pager | 页缓存、事务、崩溃恢复 | `pager.c`, `wal.c` |
| OS 接口 (VFS) | 抽象文件和锁操作 | `os_unix.c`, `os_win.c` |

:::

::: generate sqlite-arch-explain kind=explanation concepts=sqlite-architecture

面向正在学习 C 语言的读者，用通俗的类比解释 SQLite 分层架构的设计思路：为什么要分这么多层，每层只做一件事有什么好处。可以类比编译器的前端/后端分离，或者网络协议栈的分层。强调这种分层在 C 语言中通过头文件接口和函数指针实现，而不是面向对象语言的继承。

:::

::: generate sqlite-vs-clientserver kind=comparison concepts=sqlite-architecture

面向有一定编程经验的读者，将 SQLite 的嵌入式架构与传统客户端-服务器数据库（如 PostgreSQL、MySQL）进行对比。说明 SQLite 没有独立的服务进程、没有网络通信、没有用户认证层；整个数据库引擎作为库函数运行在应用进程内部。解释这种架构的优势（零部署成本、零延迟）和限制（不适合高并发写入），点到为止。

:::

### 2.1 接口层

接口层是用户直接接触的部分。SQLite 的公开 API 都以 `sqlite3_` 为前缀，声明在 `sqlite3.h` 中，主要实现在 `main.c`、`prepare.c` 和 `vdbeapi.c` 中。

下面四个函数覆盖了一条 SQL 语句的完整生命周期：

```c
int sqlite3_open(const char *filename, sqlite3 **ppDb);
int sqlite3_prepare_v2(sqlite3 *db, const char *zSql, int nByte,
                       sqlite3_stmt **ppStmt, const char **pzTail);
int sqlite3_step(sqlite3_stmt *pStmt);
int sqlite3_finalize(sqlite3_stmt *pStmt);
```

`sqlite3_open` 打开（或创建）一个数据库文件，返回一个 `sqlite3 *` 连接句柄。内部实现 `openDatabase` 展示了典型的 C 语言资源初始化模式：

```c
static int openDatabase(
  const char *zFilename,
  sqlite3 **ppDb,
  unsigned int flags,
  const char *zVfs
){
  sqlite3 *db;
  int rc;

  *ppDb = 0;
  rc = sqlite3_initialize();
  if( rc ) return rc;

  /* 分配并零初始化 sqlite3 结构体 */
  db = sqlite3MallocZero( sizeof(sqlite3) );
  if( db==0 ) goto opendb_out;

  /* ... 设置互斥锁、编码、默认页大小 ... */
  /* ... 打开 B-tree 存储、加载 schema ... */

opendb_out:
  /* ... 释放互斥锁、整理错误码 ... */
  *ppDb = db;
  return rc;
}
```

`goto opendb_out` 是 C 语言处理多步初始化失败的常用写法：清理逻辑集中在函数末尾的 `opendb_out` 标签处，不必在每个出错点重复编写释放代码。

### 2.2 词法分析器

词法分析器在 `tokenize.c` 中实现，核心是一个函数 `sqlite3GetToken`，负责从 SQL 字符串中识别出下一个 token 并返回其长度和类型。

SQLite 的词法分析器是手写的，没有使用 lex/flex 等工具生成。它用**字符分类查找表** `aiClass[]` 把每个字节映射到 31 种字符分类（character class）之一，再对分类做 switch 分发：

```c
#define CC_SPACE    7    /* 空白字符 */
#define CC_MINUS   11    /* '-'，可能是减号或 SQL 注释 */
#define CC_SLASH   16    /* '/'，可能是除号或 C 风格注释 */
#define CC_LT      12    /* '<'，可能是 < 或 <= 或 <> */
#define CC_DIGIT    3    /* 数字 */
#define CC_KYWD0    1    /* 关键字首字母 */
/* ... 共 31 种分类 ... */
```

```c
int sqlite3GetToken(const unsigned char *z, int *tokenType){
  int i;
  switch( aiClass[*z] ){
    case CC_SPACE: {
      for(i=1; sqlite3Isspace(z[i]); i++){}
      *tokenType = TK_SPACE;
      return i;
    }
    case CC_MINUS: {
      if( z[1]=='-' ){
        /* SQL 注释：-- 直到行尾 */
        for(i=2; z[i]!=0 && z[i]!='\n'; i++){}
        *tokenType = TK_SPACE;   /* 注释按空白处理 */
        return i;
      }
      *tokenType = TK_MINUS;
      return 1;
    }
    case CC_LT: {
      if( z[1]=='=' ){
        *tokenType = TK_LE;   /* <= */
        return 2;
      }else if( z[1]=='>' ){
        *tokenType = TK_NE;   /* <> */
        return 2;
      }else{
        *tokenType = TK_LT;   /* < */
        return 1;
      }
    }
    /* ... 其余分类 ... */
  }
}
```

先查表再分发的原因见源码注释：

> a switch() on aiClass[c] is implemented using a lookup table, whereas a switch() directly on c uses a binary search. The lookup table is much faster.

直接对字符值做 switch 时，case 标签稀疏地分布在 0–255 之间，编译器通常生成二分查找；字符分类是 0–30 的连续小整数，编译器可以生成按下标直接跳转的跳转表，快得多。

### 2.3 语法分析器

SQLite 的语法分析器由 **Lemon** 解析器生成器生成，Lemon 是 SQLite 作者 D. Richard Hipp 自己编写的工具。输入文件 `parse.y` 定义了 SQL 的 LALR(1) 文法，Lemon 将其编译为 `parse.c`。

Lemon 与 yacc/bison 的主要区别如下：

- 不使用全局对象，所有状态通过参数传递（线程安全）。
- 解析器不负责 token 读取——外部代码调用 `sqlite3Parser(pEngine, tokenType, token)` 逐个送入 token。
- 语法动作中直接构建内部数据结构（`Select`、`Expr`、`SrcList` 等），而非生成通用 AST。

`tokenize.c` 中的 `sqlite3RunParser` 函数将词法分析器和语法分析器串联起来：

```c
int sqlite3RunParser(Parse *pParse, const char *zSql){
  void *pEngine;               /* Lemon 生成的解析器实例 */
  int tokenType;
  int n;

  pEngine = sqlite3ParserAlloc(sqlite3Malloc, pParse);

  while( 1 ){
    n = sqlite3GetToken((u8*)zSql, &tokenType);

    if( tokenType==TK_SPACE ){
      zSql += n;
      continue;                /* 跳过空白和注释 */
    }
    /* ... 处理窗口函数关键字等特殊情况 ... */

    sqlite3Parser(pEngine, tokenType, ...);  /* 送入解析器 */
    zSql += n;

    if( /*解析完成或出错*/ ) break;
  }

  sqlite3ParserFree(pEngine, sqlite3_free);
  return pParse->nErr;
}
```

这是一个**词法驱动循环**：反复调用 `sqlite3GetToken` 取出下一个 token，跳过空白和注释后送入 Lemon 解析器。

### 2.4 代码生成器

代码生成器是 SQLite 中代码量最大的部分，分布在多个源文件中：

| 文件 | 职责 |
|:---|:---|
| `select.c` | SELECT 语句的代码生成 |
| `where.c` | WHERE 子句优化和代码生成 |
| `expr.c` | 表达式求值的代码生成 |
| `build.c` | CREATE TABLE、CREATE INDEX 等 DDL |
| `insert.c` | INSERT 语句 |
| `update.c` | UPDATE 语句 |
| `delete.c` | DELETE 语句 |

代码生成器读取语法分析器构建的内部结构（`Select`、`Expr` 等），将其翻译为 VDBE 字节码指令序列。这一步还包括**查询优化**——`where.c` 负责选择最优的索引访问路径。

### 2.5 虚拟机 (VDBE)

VDBE（Virtual Database Engine）是 SQLite 的执行引擎。它是一个基于寄存器的字节码虚拟机，原理与 JVM 或 Python 解释器相近，但指令操作的是数据库的行、列和游标。

每条编译好的 SQL 语句对应一个 `Vdbe` 结构体（在公开 API 中类型为 `sqlite3_stmt *`），其中存放着字节码程序和执行状态：

```c
struct Vdbe {
  sqlite3 *db;            /* 所属的数据库连接 */
  Vdbe **ppVPrev,*pVNext; /* 连接上所有 VDBE 的双向链表 */
  Parse *pParse;          /* 创建此 VDBE 的解析上下文 */
  int nMem;               /* 已分配的寄存器数量 */
  int nCursor;            /* 游标槽位数量 */
  int pc;                 /* 程序计数器 */
  int rc;                 /* 返回值 */
  Op *aOp;                /* 字节码指令数组 */
  int nOp;                /* 指令数量 */
  Mem *aMem;              /* 寄存器数组 */
  VdbeCursor **apCsr;     /* 游标数组 */
  Mem *pResultRow;        /* 当前输出行 */
  /* ... */
};
```

用户每次调用 `sqlite3_step()` 时，VDBE 从 `pc`（程序计数器）处继续执行字节码，直到产生一行结果（返回 `SQLITE_ROW`）或执行完毕（返回 `SQLITE_DONE`）。

`vdbe.c` 的核心是一个巨大的 switch 循环，每种操作码（opcode）对应一个 case 分支。操作码超过 180 种，例如 `OP_OpenRead`（打开游标）、`OP_Column`（读取列值）、`OP_ResultRow`（输出一行）。

### 2.6 B-tree 层

B-tree 层（`btree.c`）管理数据库文件中的数据组织。SQLite 的每个表和索引都是一棵独立的 B-tree。更准确地说，表是 B+ tree，只有叶节点存储完整的行数据；索引是 B-tree，内部节点也存储键。

B-tree 层向 VDBE 提供**游标**接口，VDBE 通过游标在 B-tree 中定位、遍历和修改记录。游标的基本操作包括：

- `sqlite3BtreeTableMoveto` / `sqlite3BtreeIndexMoveto`：在表 / 索引中移动到指定键
- `sqlite3BtreeNext` / `sqlite3BtreePrevious`：移动到下一条 / 上一条
- `sqlite3BtreeInsert`：插入记录
- `sqlite3BtreeDelete`：删除记录

### 2.7 Pager 层

Pager（`pager.c`）是 B-tree 和磁盘之间的中间层，负责三件事：

1. **页缓存**：将磁盘页面缓存在内存中，减少 I/O。
2. **事务管理**：实现原子提交——要么全部写入成功，要么数据库文件不变。
3. **崩溃恢复**：通过日志（rollback journal 或 WAL）保证即使进程崩溃或断电，数据库也不会损坏。

SQLite 支持两种日志模式：传统的回滚日志（rollback journal）和预写式日志（Write-Ahead Logging，WAL）。WAL 模式允许读写并发。

### 2.8 OS 接口 (VFS)

VFS（Virtual File System）是 SQLite 最底层的抽象，定义为 `sqlite3_vfs` 结构体。它把与操作系统相关的操作（文件打开与关闭、读写、加锁、获取时间等）封装在一组函数指针后面：

```c
struct sqlite3_vfs {
  int iVersion;
  int szOsFile;
  int mxPathname;
  sqlite3_vfs *pNext;
  const char *zName;
  void *pAppData;
  int (*xOpen)(sqlite3_vfs*, const char*, sqlite3_file*, int, int*);
  int (*xDelete)(sqlite3_vfs*, const char*, int);
  int (*xAccess)(sqlite3_vfs*, const char*, int, int*);
  int (*xFullPathname)(sqlite3_vfs*, const char*, int, char*);
  /* ... */
};
```

SQLite 提供了 `os_unix.c`（POSIX 系统）和 `os_win.c`（Windows）两套内置 VFS 实现。用户也可以注册自定义 VFS，例如把数据库存放在内存中、对磁盘 I/O 加密，或者在嵌入式系统上适配特殊的文件系统。

通过函数指针实现多态，是 C 语言中替代面向对象继承的常用做法。

## 3. 核心数据结构

::: concept sqlite-handle title="sqlite3 连接句柄"

`sqlite3` 结构体是整个数据库连接的中枢。它持有：连接的文件系统接口（`pVfs`）、所有活跃的虚拟机（`pVdbe`链表）、打开的数据库后端（`aDb` 数组，支持 ATTACH 多个数据库文件）、错误状态、以及各种运行时限制。

```c
struct sqlite3 {
  sqlite3_vfs *pVfs;            /* 文件系统接口 */
  struct Vdbe *pVdbe;           /* 活跃虚拟机链表 */
  Db *aDb;                      /* 所有数据库后端 */
  int nDb;                      /* 当前使用的后端数量 */
  u64 flags;                    /* 行为控制标志 */
  i64 lastRowid;                /* 最近一次 INSERT 的 ROWID */
  int errCode;                  /* 最近的错误码 */
  u8 autoCommit;                /* 自动提交标志 */
  u8 enc;                       /* 文本编码 (UTF-8/16) */
  int nVdbeActive;              /* 正在运行的 VDBE 数量 */
  int aLimit[SQLITE_N_LIMIT];   /* 各种上限 */
  /* ... 共约 90 个成员 ... */
};
```

对比 kilo 编辑器的全局 `editorConfig`，SQLite 的 `sqlite3` 结构体也是"一个结构体装下所有状态"的模式，但它不是全局变量——它通过指针在函数间传递，允许一个进程同时打开多个独立的数据库连接。

:::

除 `sqlite3` 外，另外两个频繁出现的核心结构体：

- **`Vdbe`**（即 `sqlite3_stmt *`）：已编译的 SQL 语句。持有字节码程序、寄存器、游标、程序计数器。每次 `sqlite3_prepare_v2` 创建一个，`sqlite3_finalize` 销毁一个。
- **`Parse`**：解析上下文。只在 `sqlite3_prepare_v2` 执行期间存在，作为词法分析器、语法分析器和代码生成器之间共享状态的载体。

```c
struct Parse {
  sqlite3 *db;         /* 所属的数据库连接 */
  Vdbe *pVdbe;         /* 正在构建的虚拟机 */
  int rc;              /* 返回码 */
  u8 nested;           /* 嵌套调用深度 */
  u8 isMultiWrite;     /* 是否可能修改多行 */
  /* ... */
};
```

`Parse` 是“上下文对象”模式：把多个阶段共享的状态打包在一个结构体中传递，而不是使用全局对象或过多的函数参数。

::: generate sqlite-handle-explain kind=explanation concepts=sqlite-handle

面向学习 C 语言的读者，解释 sqlite3 结构体作为"连接句柄"的角色：它如何将 VFS、VDBE 链表、数据库后端等不同子系统串联起来；为什么选择指针传递而非全局变量（支持多连接）；为什么 API 中暴露为不透明指针 `sqlite3 *`（信息隐藏、ABI 稳定性）。

:::

## 4. 一条查询的生命周期

::: concept prepare-step-finalize title="prepare / step / finalize 三阶段生命周期"

SQLite 将 SQL 语句的处理分为三个显式的阶段：

1. **Prepare**（编译）：`sqlite3_prepare_v2` 将 SQL 文本经过词法分析、语法分析、代码生成，编译为 VDBE 字节码程序，返回一个 `sqlite3_stmt *`。
2. **Step**（执行）：`sqlite3_step` 驱动 VDBE 执行字节码。对于 SELECT，每次调用返回一行结果；对于 INSERT/UPDATE/DELETE，一次调用完成全部操作。
3. **Finalize**（释放）：`sqlite3_finalize` 释放编译后的语句占用的所有资源。

这个三阶段模型意味着同一条 SQL 可以被编译一次、执行多次（配合 `sqlite3_reset` 重置状态），避免重复解析和编译的开销。

:::

一个典型的使用流程如下：

```c
sqlite3 *db;
sqlite3_stmt *stmt;

sqlite3_open("test.db", &db);

/* Prepare：编译 SQL → 字节码 */
sqlite3_prepare_v2(db,
    "SELECT name FROM users WHERE id = ?;",
    -1, &stmt, NULL);
sqlite3_bind_int(stmt, 1, 42);  /* 绑定参数 */

/* Step：逐行获取结果 */
while( sqlite3_step(stmt) == SQLITE_ROW ){
    const char *name = (const char *)sqlite3_column_text(stmt, 0);
    printf("name = %s\n", name);
}

/* Finalize：释放资源 */
sqlite3_finalize(stmt);
sqlite3_close(db);
```

`sqlite3_bind_int` 把参数 `?` 绑定到具体的值。参数值不经过 SQL 文本拼接，因此可以避免 SQL 注入；同一条编译好的语句也可以反复绑定不同参数执行。

::: generate select-query-walkthrough kind=example concepts=prepare-step-finalize,sqlite-architecture

面向正在学习 C 语言的读者，以一条简单的 `SELECT name FROM users WHERE id = 42;` 为例，逐步追踪它从 API 调用到磁盘读取的完整路径：

1. 应用调用 sqlite3_prepare_v2，传入 SQL 字符串；
2. tokenize.c 中的 sqlite3GetToken 将 SQL 切分为 SELECT、name、FROM、users、WHERE、id、=、42 等 token；
3. Lemon 解析器将 token 流解析为 Select/Expr 等内部结构；
4. 代码生成器（select.c、where.c）将其翻译为一组 VDBE 字节码指令——大致包括：打开 users 表的游标、用索引定位 id=42 的行、读取 name 列、输出结果行；
5. 应用调用 sqlite3_step，VDBE 开始执行字节码：OP_OpenRead 打开 B-tree 游标，OP_SeekGE 在 B-tree 中定位，B-tree 层请求 Pager 层加载对应的磁盘页，Pager 通过 VFS 读取文件；
6. 找到匹配行后，OP_Column 读取 name 列的值，OP_ResultRow 暂停虚拟机并返回 SQLITE_ROW；
7. 应用调用 sqlite3_column_text 读取结果，再次调用 sqlite3_step，VDBE 继续执行直到返回 SQLITE_DONE；
8. 应用调用 sqlite3_finalize 释放资源。

用日常语言而不是晦涩的术语解释每一步，帮助读者建立"SQL 在计算机里到底是怎么运行的"这一直觉。

:::

## 5. 词法分析器详解

词法分析器是 SQLite 中代码最短、最独立的子系统之一（`tokenize.c` 约 900 行），适合作为源码阅读的起点。

### 5.1 字符分类系统

如 2.2 节所述，SQLite 不直接对字符值做 switch，而是先通过查找表 `aiClass` 把每个字节映射到 0–30 的字符分类编号。

`aiClass` 是一个 256 字节的静态数组，在编译时初始化。例如空格、制表符、换行符等空白字符都映射到 `CC_SPACE`（7），所有数字都映射到 `CC_DIGIT`（3）。switch 因此只有 31 个连续的 case，编译器可以生成跳转表而不是二分查找。

### 5.2 多字符运算符的处理

单字符 token（括号、逗号、分号等）的处理很直接：返回长度 1 和对应类型。SQL 还有许多多字符运算符（`<=`、`<>`、`!=`、`||`、`--`、`/*...*/`），词法分析器通过**前瞻一个字符**来识别：

```c
case CC_LT: {
  if( (c=z[1])=='=' ){
    *tokenType = TK_LE;     /* <= */
    return 2;
  }else if( c=='>' ){
    *tokenType = TK_NE;     /* <> */
    return 2;
  }else if( c=='<' ){
    *tokenType = TK_LSHIFT;  /* << */
    return 2;
  }else{
    *tokenType = TK_LT;      /* < */
    return 1;
  }
}
```

`CC_MINUS` 的情况：减号 `-` 后面如果紧跟另一个减号，就构成 SQL 注释 `--`：

```c
case CC_MINUS: {
  if( z[1]=='-' ){
    for(i=2; (c=z[i])!=0 && c!='\n'; i++){}
    *tokenType = TK_SPACE;   /* 注释按空白处理 */
    return i;                 /* 注释延续到行尾 */
  }
  *tokenType = TK_MINUS;
  return 1;
}
```

### 5.3 词法分析器与解析器的交互

`sqlite3RunParser` 函数连接词法分析器和语法分析器，它的工作是一个简单的循环：

1. 调用 `sqlite3GetToken` 获取下一个 token 的类型和长度。
2. 跳过空白和注释。
3. 将 token 送入 Lemon 生成的解析器 `sqlite3Parser`。
4. 重复直到 SQL 字符串耗尽或解析器报告完成/出错。

这种由词法分析循环向解析器逐个送入 token 的“外部驱动”模式，比 yacc 由解析器内部调用 `yylex` 拉取 token 的模式更灵活。例如，SQLite 可以在送入 token 之前，根据上下文判断 `WINDOW`、`OVER`、`FILTER` 是否应作为关键字处理。

### 7.3 综合与挑战

<Exercise id="50655" :d="6" :w="5">

把 §2 的前四层缩成一个能跑的小程序 `minisql.c`，只支持一种查询：

```text
SELECT <列名> FROM <表名> WHERE <列名> <比较符> <整数>;
```

其中比较符是 `>`、`>=`、`<`、`<=`、`=` 之一。内存表有三行：`Alice 25`、`Bob 35`、`Charlie 40`，列名为 `name` 与 `age`。程序分四段，接口自己定：

1. 词法：把输入切成标识符、整数、比较符、分号四类 token，给出每类的长度。
2. 语法：检查 token 顺序，构建 `struct Select { char col[32]; char table[32]; int op; long val; }`；出错时打印出错处的字节偏移。
3. 代码生成：把结构体翻译成一条指令数组，至少包含 `OPEN`、`REWIND`、`COLUMN`、`COMPARE_JUMP`、`RESULT`、`NEXT`、`HALT`，跳转目标写成数组下标。
4. 执行：用内存表执行指令数组，遇到 `RESULT` 打印一行并暂停，下次调用从下一条继续；`COLUMN` 按列名从 `name` 与 `age` 中取值。

验收：`SELECT name FROM users WHERE age > 30` 输出 Bob、Charlie；把 `>` 改成 `<=` 输出 Alice；`SELECT name FROM users WHERE age >` 打印出错位置，位置由你的实现定义但要在报告里说明；把执行器改成一次跑到底后，再调用一次能从暂停处继续。代码在 `-Wall -Wextra` 下无警告。

</Exercise>
