# 9.2 项目搭建

本教程教学如何搭建您的操作系统项目，好的项目结构可以更方便地协助你开发

## 1. 使用现成的开发模板

- Plos-clan Multiboot i386 [multiboot-xmake-template](https://github.com/plos-clan/multiboot-xmake-template) \
   适用于 32 位 LegacyBIOS 引导的操作系统

  > 注意：不适用于现代 PC 机，您需要一台支持旧版 MBR 引导的电脑

- Plos-clan Limine x86_64 [limine-xmake-template](https://github.com/plos-clan/limine-xmake-template) \
   适用于 64 位 UEFI 引导的操作系统
  > 适用于所有现代的 PC 机，但是编写 64 位系统会很难

## 2. 自制引导程序

### 2.1 MBR LegacyBIOS 引导方式

通常你们需要的准备工作要求更多，且编写后的操作系统运行的介质非常有限

可以借鉴《30 天自制操作系统》的 MBR 软盘引导程序

### 2.2 GPT UEFI BIOS 引导方式

可以使用 EDK2 开发套件或采用自己编写 EFI 程序

引导器可以获取到内存布局表后传入内核，即可开始引导。

因系统信息，文件读取等都有 UEFI 接口提供，所以编写相对简单一些

建一个最小内核工程，只用 9.1 节第 2 节列出的工具，把「源码 → 32 位 ELF → 可加载二进制」这条链跑通。目录自定，文件与要求如下。

`boot.asm`（nasm，`BITS 32`）：

- 定义 `_start`，先 `cli`，把 `esp` 指向 `stack_top`，再 `call kernel_main`；返回后原地 `hlt` 循环。
- 在 `.bss` 里用 `resb 16384` 开一段栈，用 `ALIGN 16` 对齐，标出 `stack_bottom` 与 `stack_top`。

`main.c`：

- 定义 `void kernel_main(void)`，向 `0xB8000` 处写入 `'O'` 与 `'K'` 两个字符、属性字节 `0x0F`，然后死循环。

`link.ld`：

- `ENTRY(_start)`，起始地址 `1M`，依次放 `.text`、`.rodata`、`.data`、`.bss`（含 `COMMON`）。

构建命令按顺序是 `nasm -f elf32 boot.asm -o boot.o`、`zig cc -target x86-freestanding-none -O2 -ffreestanding -Wall -Wextra -c main.c -o main.o`、`zig cc -target x86-freestanding-none -nostdlib -Wl,-T,link.ld -o kernel.elf boot.o main.o`，最后 `objcopy -O binary kernel.elf kernel.bin`。

验收：

1. `readelf -h kernel.elf` 显示 `Class: ELF32`、`Machine: Intel 80386`、入口 `0x100000`。
2. `nm -u kernel.elf` 没有任何输出，说明内核不依赖任何外部符号。
3. `objcopy` 生成的 `kernel.bin` 小于 4 KiB，`size kernel.elf` 里 `bss` 约 16384 字节而不占文件体积，说明原因。
4. 把 `main.c` 里的死循环换成 `return;`，重新链接，说明为什么栈上压入的返回地址仍然有效（`kernel_main` 是由汇编 `call` 进来的）。

提示：本地实测的参考值是 `text=50`、`bss=16384`、`kernel.bin` 50 字节。写完后用验收第 3 条的数字对照，差距过大时先查链接脚本里的起始地址。

</Exercise>

9.1 节第 3 节提到，正文里标注的函数注明了它原本定义在哪个源文件，是为了方便读者安排结构。把这条建议变成一次实验。

(1) 写 `kmalloc.h`，里面直接给出函数定义：

```c
#ifndef KMALLOC_H
#define KMALLOC_H

#include <stdint.h>

uint32_t kmalloc(uint32_t size) {
    static uint32_t top = 0x00100000u;
    uint32_t addr = top;
    top += size;
    return addr;
}

#endif
```

再写 `a.c`（`main` 里调用两次并打印）与 `b.c`（导出 `next_block`，里面调用一次），两者都 `#include "kmalloc.h"`。用 `gcc -std=c17 -Wall -Wextra a.c b.c -o dup.exe` 编译，记录完整的链接错误，指出报错里出现的是哪两个目标文件。

(2) 把定义搬进 `kmalloc.c`，头文件只留声明，再把三个文件一起编译。确认能链接，`a.exe` 打印两次递增的地址。

(3) 改回「定义在头文件、函数前加 `static inline`」。这时 `a.c` 与 `b.c` 一起编译链接都不报错，但两个源文件各自持有一份 `top`。运行下面的 `main`：

```c
uint32_t next_block(void);

int main(void) {
    uint32_t p = kmalloc(16);
    uint32_t q = kmalloc(16);
    uint32_t r = next_block();
    printf("a: 0x%X 0x%X
", p, q);
    printf("b: 0x%X
", r);
    return 0;
}
```

实测输出是 `a: 0x100000 0x100010` 与 `b: 0x100000`。解释 `r` 为什么回到 `0x100000`，以及这种写法在操作系统里为什么危险（提示：两个模块各自认为自己在分配物理页框）。

(4) 头文件里的 `static` 对象与 `extern` 声明各适合什么场合？用一句话回答，并指出 9.6 节里 `extern page_directory_t *current_directory;` 属于哪一种。

验收：第 (1) 问的报错包含 `multiple definition of 'kmalloc'` 并列出两个 `.o`；第 (3) 问的输出与上面一致，解释落在「每个翻译单元一份对象」上。

2.2 节说「引导器可以获取到内存布局表后传入内核」。把这次交接做完整：写一个 `boot_info` 结构，一个写出它的加载器，一个读取并校验它的内核，两者用文件模拟内存交接。

```c
#define BOOT_INFO_MAGIC 0x4D445242u
#define MAX_ENTRIES 8u

typedef struct {
    uint64_t base;
    uint64_t length;
    uint32_t type;      /* 1=可用, 2=保留, 3=ACPI */
    uint32_t reserved;
} mem_entry;

typedef struct {
    uint32_t magic;
    uint32_t count;
    mem_entry entries[MAX_ENTRIES];
} boot_info;
```

(1) `loader.c` 写出一份 `boot.bin`：`magic` 正确，`count` 为 3，三项依次是 `{0, 0xA0000, 1}`、`{0xA0000, 0x60000, 2}`、`{0x100000, 0x3F000000, 1}`。`kernel.c` 读回整个结构，按下面的规则校验，然后打印：

```text
valid=1 usable=1008 MiB
```

`usable` 是所有 `type == 1` 项的 `length` 之和，按 MiB 向下取整。

(2) 校验规则四条：`magic` 不对拒绝；`count > MAX_ENTRIES` 拒绝；某项 `length == 0` 拒绝；某项 `base + length` 回绕（结果小于 `base`）拒绝。在 `main` 里依次构造四种坏数据，输出必须是：

```text
overflow valid=0
zero length valid=0
count too large valid=0
bad magic valid=0
```

`base + length` 的回绕用 `base = UINT64_MAX - 16`、`length = 64` 构造。

(3) 说明 `base + length` 这一条为什么必须用无符号 64 位算、不能先转成 `uint32_t`。再说明 `count` 那条为什么必须在读 `entries` 之前检查，而不是读完再判断。

(4) 结构里留了一个 `reserved` 字段。说明引导协议里为什么常留这样的字段，以及内核读到非 0 值时应当怎么处理。

验收：第一问一行、第二问四行都逐字一致；`loader.c` 与 `kernel.c` 都只用标准 C，`boot.bin` 的大小等于 `sizeof(boot_info)`（本机为 200 字节）；第 (3) 问的两条都点到具体出错方式（回绕、越界读）。

</Exercise>
