# 9.12 疑难解答

对于操作系统开发过程中发生的各种错误进行疑难解答

## 1. 虚拟机 / 实体机突然重启

发生了 `TripleFault` 异常，需要检查你的操作系统源码

- 是否配置了 `IDT` 中断描述符表
- 中断向量号对应的 `IDT` 表项是否为空
- 是否正确处理了 `DoubleFault` 异常

## 2. DoubleFault 异常

发生了一次中断异常时候并没有及时处理导致中断内又发生了一次异常。

- 需检查上一次中断异常的向量号，错误码等各项信息。
- 处理其他异常的代码是否有漏洞
- 执行环境已经被彻底破坏，一般的异常处理程序无法解决

::: warning 特别注意

双重异常时我们默认当前的执行环境已经被彻底破坏，所以处理时候与其他的中断异常不相同

- 你需要事先准备好一块完全可用的 1kb 区域用作双重异常的专属栈区，发生双重异常时需要将 rsp 切换到该区域

- 需要准备双重异常专用的页表，发生时切换到该页表
- 双重异常内仅作一些简单的信息输出，不要尝试恢复 (因为你已经无法恢复异常了)

:::

## 3. PageFault (最常见)

页异常，这里需要你根据 `cr2` 寄存器存储的异常地址来判断

### 3.1 NotPresent

- 如果地址为 `0`, 代表发生了空指针异常，检查你的源码中是否缺少空指针检查。
- 地址过小 (如小于 `100` 字节等) 也可能发生了空指针异常。
- 需要检查 `cr2` 的地址是否被映射。

::: warning 警告

如果发现 cr2 地址过于离谱，需要检查程序是否 "跑飞了"

:::

### 3.2 UserMode

- 用户态程序写入或读取了内核区域的内存

## 4. GeneralProtectionFault

通用保护性异常，一般是产生了非法操作导致的 CPU 异常

- 写入了一些不可用内存 (如未初始化设备直接写入设备 MMIO)
- 调度器切换上下文不正确导致寄存器混乱
- 控制寄存器的标志位设置不正确

## 5. InvalidOpcode

非法操作码异常，一般是 CPU 遇到了未知指令导致的

- CPU 可能将数据当作指令执行了
- 确保指令没有问题的情况下检查是否动用了 x86 扩展指令集，但是 CPU 不支持扩展指令集
- 如检查出 CPU 支持扩展指令集但仍然发生此错误，需要检查该扩展指令集需不需要额外进行启用操作
- `syscall` 指令需要设置 `MSR` 使能才可以使用，不然也会发生该错误

## 6. 部分实体机跑不起来我的 OS

电脑与电脑之间硬件的实现亦有差距，无法保证所有硬件厂商都会乖乖按照标准制作。

- 换一种稳妥的方法实现一些有争议的区域

::: warning 注意

永远不要写死一些地址，不同实体机甚至是虚拟机之间的内存布局都大相径庭。可以通过如 `ACPI` `cpuid` 等获取的地址不要写死，你无法假定这块地址在所有的环境中是永远不会被占用的

:::

## 7. 习题

### 7.1 巩固

<Exercise id="50009" :d="1" :w="1">

缺页异常 (Page Fault) 在 `cr2` 之外还会压入一个 32 位错误码，各位的含义如下：

- 第 0 位 P：为 0 表示页不存在，为 1 表示页存在但访问被拒绝；
- 第 1 位 W：为 1 表示这次访问是写；
- 第 2 位 U：为 1 表示访问来自用户态；
- 第 3 位 RSVD：为 1 表示页表项里的保留位被置了 1；
- 第 4 位 ID：为 1 表示这次访问是取指。

写一个 C 程序 `pf_decode.c`，实现 `void pf_decode(uint32_t err)`，按「不存在 / 写 / 用户态 / 保留位 / 取指」的顺序打印置位的项，其他位为 0 时打印什么都没置。用下面六个值测试，把输出填成表：

```text
0x0  0x2  0x4  0x6  0x7  0x10
```

然后回答：

(1) 本页第 3.1 节说的 NotPresent 情形，错误码的最低两位是什么？

(2) 第 3.2 节的 UserMode 情形对应哪几个值？为什么它一定同时带 U 位？

(3) `cr2` 为 `0`、错误码为 `0x2` 时，最可能是什么代码造成的？错误码为 `0x0` 时呢？

</Exercise>

(1) 定义 `struct fault { unsigned vec; unsigned err; uint32_t eip; unsigned cs; uint32_t cr2; }` 和一个从上面这种行里解析出结构体的函数（`sscanf` 加固定格式即可）。

(2) 按本页第 1～5 节的判据写 `const char *diagnose(const struct fault *f)`，至少区分下面几种情况，每种返回一句结论和一句下一步该查什么：

- `vec=13`、`err` 为 0：对照本页第 4 节的三条，说明最可能是哪一条被违反；
- `vec=14`、`err` 的 P 位为 0 且 `cr2` 小于 4096：空指针；
- `vec=14`、`err` 的 P 位为 0 且 `cr2` 落在内核区间、`cs` 的 RPL 为 3：用户态越界访问；
- `vec=14`、`err` 的 P 位为 1：已映射但权限不符，说明是写只读页还是用户态碰内核页；
- `vec=6`：按本页第 5 节判断是取指跑飞还是扩展指令未启用。

另外留一个入口 `const char *diagnose_boot(int printed_anything, int reboot_count)`：内核一行现场都没打印、机器反复重启时，按第 1 节判断为 `TripleFault`，并列出该查的三处；打印过现场却仍重启时，说明 `#DF` 的处理本身有问题。

(3) 用上面四行输入跑一遍，把输出贴出来。再自己补两行，让 `diagnose` 的另外两个分支各被走到一次，并对 `diagnose_boot(0, 5)` 与 `diagnose_boot(1, 5)` 各调用一次。

(4) `cs` 的低 2 位是 RPL。说明为什么分诊时要看它，只看 `cr2` 会漏掉什么。

</Exercise>

### 7.2 编程

<Exercise id="50011" :d="3" :w="3">

正文要求双重异常时切换到一块 1 KiB 的专属栈。32 位保护模式的任务状态段里虽然有 `esp0`，但 CPU 只在特权级变化时才从它取栈，同一个内核里发生的 `#DF` 不会触发换栈，所以要么配任务门让 CPU 换任务，要么在 `#DF` 入口用一小段汇编自己换 `esp`。本题先做后一种，再对照前一种。

(1) 写一个 `#DF` 的入口存根 `isr8_df`：进入后把 `esp` 指向静态数组 `df_stack[1024]` 的顶端，把原来的 `esp` 保存到一个全局对象里，然后调用 C 处理函数 `df_handler(uint32_t old_esp, uint32_t err)`。给出汇编与 C 两侧的声明。

(2) 处理函数只打印 `err`、`old_esp` 和 `cr2`，然后 `cli` 加 `hlt` 死循环。说明为什么这里不能 `iret`，也不能调用可能睡眠或加锁的函数。

(3) 说明 `df_stack` 为什么必须 `__attribute__((aligned(4)))` 且用 `static` 存储期，不能是局部数组。

(4) 给出 IDT 第 8 号表项指向 `isr8_df` 的初始化代码。

(5) 对照方案：x86-64 的 IDT 表项有位 32～34 可以选 IST，硬件会在进入时自动换栈。说明 32 位模式下为什么没有这个便利，以及换成任务门时需要额外准备什么。

(6) 在这块 1 KiB 的栈上，处理函数能安全使用多少字节？`printf` 一类的格式化输出会不会吃掉大半？给出你的估算和理由。

</Exercise>

页错误处理要区分「按需分配」与「真的出错」。下面的骨架用来实现前者，其中 `read_cr2` 是要你自己写的三行内联汇编：

```c
static inline uint32_t read_cr2(void)
{
    uint32_t v;
    __asm__ volatile("mov %%cr2, %0" : "=r"(v));
    return v;
}

void page_fault_handler(registers_t *regs, uint32_t err)
{
    uint32_t addr = read_cr2();
    /* ... */
}
```

要求：

(1) 从错误码取出 P、W、U 三位，写成 `pf_flags`，并给出三个 `enum` 值。

(2) 实现按需分配：P 为 0、`addr` 落在用户堆区间 `[USER_START, USER_HEAP_END)`、且映射不存在时，分配一个页框、建立映射、刷新 TLB 后返回。其余情况打印诊断信息：错误码、`cr2`、出错指令地址（`regs->eip`）、当前进程号，然后终止该进程。

(3) 用 `code/项目/mdrOS/memory.h` 里的接口把上面用到的东西对上：`get_page`、`alloc_frame`、`flush_tlb` 各取什么参数，`get_page` 的 `make` 参数取 1 会做什么。`USER_START` 与 `USER_HEAP_END` 也在这个头文件里。

(4) 对本页第 3.1 节列出的三种情形各构造一个用例，写出 `cr2` 与错误码，说明处理函数的分支走向。

(5) 用户态程序访问内核区域会得到 U 位为 1、P 位为 1 的错误码。说明为什么这条路径不能走按需分配，即使 `addr` 落在某个已经映射的区间。
