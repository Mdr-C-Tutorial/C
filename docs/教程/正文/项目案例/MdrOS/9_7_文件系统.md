# 9.7 文件系统与虚拟抽象

在操作系统中，底层存储介质（如软盘、机械硬盘、SATA SSD 或 NVMe 驱动器）以固定的物理块或逻辑扇区（LBA）为单位组织数据。然而，直接面向连续扇区号编写读写代码对于应用程序而言极其晦涩且脆弱。

文件系统（File System）正是构建在块设备驱动之上的核心软件层。它的主要职责在于有效、安全且结构化地管理非易失性存储资源，将杂乱离散的磁盘扇区抽象为具备层次结构的目录树与连续的逻辑数据流（即文件）。

在现代操作系统生态中，根据应用场景、容错级别与存储介质特性的不同，演进出多样化的文件系统规范：
- **FAT 家族（FAT12、FAT16、FAT32 / VFAT）**：基于文件分配表（File Allocation Table）构建的链式存储结构，逻辑简明、跨平台通用性极佳，是自制操作系统最初期挂载与读取内核资源的理想靶标；
- **Unix / Linux 原生系统（ext2、ext3、ext4、Btrfs、XFS）**：基于索引节点（Inode）与多级间接块构建，现代版本引入了日志事务机制（Journaling）与写时复制（COW），提供极高的可靠性与吞吐性能；
- **内存与特殊介质文件系统（RAMFS、tmpfs、ISO9660 光盘系统、NFS 网络文件系统）**：将非磁盘载体或网络协议透明封装为标准的文件操作形态。

## 1. 核心存储单元与数据抽象

在文件系统的体系设计中，存在两项最为基本的逻辑构成元素：

- **文件（File）**：文件是持久化存储在逻辑层面的最小独立管理单元。对上层应用程序而言，文件表现为一段可以随机寻址、按需截断的连续字节序列；对底层文件系统而言，文件由两部分构成：一是存储具体内容的物理数据块（或簇 Cluster），二是描述该文件属性的元数据（Metadata，包含文件名、尺寸、创建/访问时间戳以及访问权限等）。
- **目录（Directory）**：目录是构建树状命名空间的容器。在类 Unix 系统设计中，“目录也被抽象为一种特殊的文件”，其数据块内部存储着该层级下所有子文件与子目录的目录项记录（Directory Entries），记录了文件名与其物理节点索引（如起始簇号或 Inode 编号）之间的对应关系。

## 2. 虚拟文件系统（VFS）架构

当操作系统需要同时支持多种异构文件系统（例如根目录采用 ext4，挂载的 U 盘为 FAT32，配置信息存放在内存文件系统）时，若直接让上层系统调用处理每种文件系统的底层差异，内核代码将陷入无法维护的混乱。

为此，现代内核引入了**虚拟文件系统（Virtual File System，简称 VFS）**作为统一抽象层：

- **抽象接口与多态分发**：VFS 自身并不直接负责磁盘扇区的数据编排，而是定义了一组标准的抽象节点结构（如 `vfs_node` / `inode`）以及挂载在节点上的函数指针操作表（如包含 `open`、`read`、`write`、`readdir` 的 `vfs_ops`）。
- **统一挂载模型（Mounting）**：所有的物理文件系统或伪文件系统，只需实现这套函数指针契约，便可通过挂载机制与全局命名空间树绑定。当用户程序调用统一的 `read()` 系统调用时，VFS 根据路径走查自动路由到目标节点，并借助函数指针分发至具体文件系统的驱动实现。

## 3. 广义设备与伪文件系统（devfs / pipefs）

类 Unix 系统最为深邃的设计理念之一便是“一切皆文件”（Everything is a file）。基于 VFS 强大的多态分发能力，操作系统可以将许多非持久化的系统资源与外设接口无缝接入文件树：

- **设备文件系统（devfs）**：将底层外设控制器（如用于交互的串行终端 `/dev/console`、始终产生零字节流的伪设备 `/dev/zero`、随机数源 `/dev/urandom` 等）统一呈现为 `/dev` 目录下的特殊文件。驱动开发者只需为该设备实现 `read` 或 `write` 操作函数，应用程序即可通过常规的文件 I/O 接口与底层硬件通信；
- **管道文件系统（pipefs）**：将进程间通信（IPC）机制中的管道抽象为内存中的一组读写双端节点。数据通过环形缓冲区在内存中暂存与流转，对上层执行读写的进程而言，其操作逻辑与读写常规磁盘文件完全一致。

## 4. 习题

这一页只给了文件系统的骨架：文件与目录是什么、VFS 起什么作用、devfs 与 pipefs 为什么能当成文件。要写一个能挂载、能读出内容的文件系统，还差三样东西：磁盘上的数据结构、路径到节点的查找、以及把节点操作接到一组函数指针上。下面四道题沿这条线走，前两道在主机上练数据结构和目录项的解析，后两道把它们连成一个小 VFS。

### 4.2 编程

<Exercise id="50044" :d="4" :w="4">

把 9.7 的三节连起来：VFS 是统一接口，devfs 与 pipefs 是「把一切做成文件」的两个例子。在主机上写 `vfs.c`，不要用系统文件接口冒充，自己定义节点与操作表：

```c
struct vfs_node;

struct vfs_ops {
    long (*read)(struct vfs_node *n, void *buf, size_t count);
    long (*write)(struct vfs_node *n, const void *buf, size_t count);
    int (*readdir)(struct vfs_node *n, size_t index, char *name, size_t cap);
};

struct vfs_node {
    const char *name;
    int is_dir;
    const struct vfs_ops *ops;
    void *data;
    struct vfs_node *children;
    struct vfs_node *sibling;
};
```

要求：

(1) 实现 `vfs_open(path)`：在挂载表里找最长的前缀（`/dev` 比 `/` 长），把剩余路径按 `/` 切开逐级查孩子。挂载点要判边界，`/devx/motd` 不能匹配 `/dev`。

(2) 实现 ramfs：`struct ram_file { char text[32]; size_t len; }` 挂在节点的 `data` 上，`read`、`write` 都按 `len` 截断。在 `/etc/motd` 放一段文字，读出打印。

(3) 实现 devfs 的两个节点：`/dev/zero` 的 `read` 往缓冲区写 0，`/dev/console` 的 `write` 直接 `fwrite` 到标准输出。两者各自不提供另一个方向的函数，调用方要检查函数指针是否为空。

(4) 实现 pipefs 的最小版本：`pipe_create()` 返回一读一写两个节点，共用 128 字节的环形缓冲区。满时 `write` 返回已写入的字节数，空时 `read` 返回 0。

(5) `main` 依次演示：读 `/etc/motd`、读 `/dev/zero` 四字节、往 `/dev/console` 写一行。然后按下面的顺序操作管道，每一步都打印返回值与当前缓冲区里的字节数：

```text
write 300 字节          -> 128
read 50 字节            -> 50
write 剩下的 172 字节    -> 50
read 100 字节           -> 100
write 剩下的 122 字节    -> 100
read 200 字节           -> 128
write 剩下的 22 字节     -> 22
read 100 字节           -> 22
read 10 字节            -> 0
```

验收：`/devx/motd` 查到空；上面九步的返回值与注释一致；读出的 300 字节与写入数据逐字节相等，散列均为 `0x69A1C951`（数据为 `data[i] = (uint8_t)(i * 37 + 11)`）。

</Exercise>

### 4.3 综合与挑战

<Exercise id="50045" :d="5" :w="5">

给上一题的 VFS 加挂载与卸载，并写一个能放进内核的路径解析器。

(1) 挂载表从固定数组改成用 `kmalloc` 与 `kfree` 分配的双向链表（主机上用 `malloc` 代替）。挂载点要能嵌套：挂 `/`，再挂 `/dev`，再挂 `/dev/shm`，`vfs_open("/dev/shm/a.txt")` 要走到第三层。

(2) 给每个节点加 `refs` 计数，`vfs_open` 加一，`vfs_close` 减一。`vfs_unmount(path)` 只允许卸载没有打开文件的挂载点，有引用时返回 `-EBUSY`（自己定义这个常量）。

(3) 路径解析改成迭代版。要求 `/a/./b/../c` 规范化为 `/a/c`，`..` 在根处停在根。写出你的规范化函数与它处理空段、`.`、`..` 的分支。

(4) 压力测试：建 200 个目录、名字长 10 个字符、深度 8 层，随机打开 10000 次，打印命中次数与耗时。用 `-O2` 与 `-O0` 各跑一次，说明差距主要来自哪里。

(5) 与 Linux 对照：`/proc/mounts` 的内容来自内核的挂载链表，卸载用引用计数拒绝忙的挂载点。说明为什么卸载一个还有打开文件的挂载点会出事，内核里除了引用计数还需要什么才能安全卸载。

验收：嵌套挂载能解析；`vfs_unmount("/dev")` 在 `/dev/zero` 还被引用时返回 `-EBUSY`，释放后成功；`/a/./b/../c` 规范化成 `/a/c`；`-Wall -Wextra` 无警告。

</Exercise>
