# 9.7 文件系统

在操作系统中，处理持久化存储信息的程序叫做文件系统 (FileSystem)。
文件系统负责有效合理的管理所有逻辑存储单元 (也就是文件 File)。
市面上主流的文件系统有：

- FAT12 FAT16 FAT32(VFAT)
- ISO9660 NFS RAMFS
- NTFS Btrfs XFS
- ext2 ext3 ext4

还有更多，教程就不一一列举了

## 1. 存储单元

- 文件是文件系统中抽象出的一个概念，是最小的信息管理存储单元，通常具备大小，文件名，创建/修改日期，类型等特性

- 文件夹是由许多个文件组成的集合，通常为一个节点

## 2. VFS

`Virtual File System` 虚拟文件系统

它并不履行任何文件系统的实际功能，准确来说它更像是一个统一的操作接口。 \
所有具体文件系统都将挂载到 VFS 上

> Linux 内核就是采用了这种方式，但具体实现更为复杂

## 3. devfs pipefs

是沿袭类 unix 产生的虚拟文件系统，秉承所有的接口都可以用文件系统完成。

## 4. 习题

这一页只给了文件系统的骨架：文件与目录是什么、VFS 起什么作用、devfs 与 pipefs 为什么能当成文件。要写一个能挂载、能读出内容的文件系统，还差三样东西：磁盘上的数据结构、路径到节点的查找、以及把节点操作接到一组函数指针上。下面四道题沿这条线走，前两道在主机上练数据结构和目录项的解析，后两道把它们连成一个小 VFS。

SYSTEM.BIN 1200 字节，簇链 5 -> 7 -> 8

### 4.2 编程

<Exercise id="50044" :d="4" :w="4">

把 9.7 的三节连起来：VFS 是统一接口，devfs 与 pipefs 是「把一切做成文件」的两个例子。在主机上写 `vfs.c`，不要用系统文件接口冒充，自己定义节点与操作表：

```c
struct vfs_node;

struct vfs_ops {
    long (*read)(struct vfs_node *n, void *buf, size_t count);
    long (*write)(struct vfs_node *n, const void *buf, size_t count);
    int (*readdir)(struct vfs_node *n, size_t index, char *name, size_t cap);
};

struct vfs_node {
    const char *name;
    int is_dir;
    const struct vfs_ops *ops;
    void *data;
    struct vfs_node *children;
    struct vfs_node *sibling;
};
```

要求：

(1) 实现 `vfs_open(path)`：在挂载表里找最长的前缀（`/dev` 比 `/` 长），把剩余路径按 `/` 切开逐级查孩子。挂载点要判边界，`/devx/motd` 不能匹配 `/dev`。

(2) 实现 ramfs：`struct ram_file { char text[32]; size_t len; }` 挂在节点的 `data` 上，`read`、`write` 都按 `len` 截断。在 `/etc/motd` 放一段文字，读出打印。

(3) 实现 devfs 的两个节点：`/dev/zero` 的 `read` 往缓冲区写 0，`/dev/console` 的 `write` 直接 `fwrite` 到标准输出。两者各自不提供另一个方向的函数，调用方要检查函数指针是否为空。

(4) 实现 pipefs 的最小版本：`pipe_create()` 返回一读一写两个节点，共用 128 字节的环形缓冲区。满时 `write` 返回已写入的字节数，空时 `read` 返回 0。

(5) `main` 依次演示：读 `/etc/motd`、读 `/dev/zero` 四字节、往 `/dev/console` 写一行。然后按下面的顺序操作管道，每一步都打印返回值与当前缓冲区里的字节数：

```text
write 300 字节          -> 128
read 50 字节            -> 50
write 剩下的 172 字节    -> 50
read 100 字节           -> 100
write 剩下的 122 字节    -> 100
read 200 字节           -> 128
write 剩下的 22 字节     -> 22
read 100 字节           -> 22
read 10 字节            -> 0
```

验收：`/devx/motd` 查到空；上面九步的返回值与注释一致；读出的 300 字节与写入数据逐字节相等，散列均为 `0x69A1C951`（数据为 `data[i] = (uint8_t)(i * 37 + 11)`）。

</Exercise>

### 4.3 综合与挑战

<Exercise id="50045" :d="5" :w="5">

给上一题的 VFS 加挂载与卸载，并写一个能放进内核的路径解析器。

(1) 挂载表从固定数组改成用 `kmalloc` 与 `kfree` 分配的双向链表（主机上用 `malloc` 代替）。挂载点要能嵌套：挂 `/`，再挂 `/dev`，再挂 `/dev/shm`，`vfs_open("/dev/shm/a.txt")` 要走到第三层。

(2) 给每个节点加 `refs` 计数，`vfs_open` 加一，`vfs_close` 减一。`vfs_unmount(path)` 只允许卸载没有打开文件的挂载点，有引用时返回 `-EBUSY`（自己定义这个常量）。

(3) 路径解析改成迭代版。要求 `/a/./b/../c` 规范化为 `/a/c`，`..` 在根处停在根。写出你的规范化函数与它处理空段、`.`、`..` 的分支。

(4) 压力测试：建 200 个目录、名字长 10 个字符、深度 8 层，随机打开 10000 次，打印命中次数与耗时。用 `-O2` 与 `-O0` 各跑一次，说明差距主要来自哪里。

(5) 与 Linux 对照：`/proc/mounts` 的内容来自内核的挂载链表，卸载用引用计数拒绝忙的挂载点。说明为什么卸载一个还有打开文件的挂载点会出事，内核里除了引用计数还需要什么才能安全卸载。

验收：嵌套挂载能解析；`vfs_unmount("/dev")` 在 `/dev/zero` 还被引用时返回 `-EBUSY`，释放后成功；`/a/./b/../c` 规范化成 `/a/c`；`-Wall -Wextra` 无警告。

</Exercise>
