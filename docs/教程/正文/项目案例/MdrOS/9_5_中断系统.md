# 9.5 中断体系与异常处理

在操作系统内核中，中断与异常机制是整个系统感知外部硬件事件、维系多任务并发调度以及构筑特权级安全边界的枢纽。处理器的正常执行流往往是确定且线性的，而外部物理设备的数据输入、时钟节拍的周期性到达以及算术除零或缺页等突发状态，都要求处理器能够在纳秒级的时间内暂停当前任务，平滑转入特权上下文予以响应，随后再无缝恢复先前的计算。

可以说，正是中断子系统的运转，才驱动了外设 I/O 响应、内存按需加载以及抢占式进程调度等核心行为。

## 1. 中断架构核心机制

x86 架构将中断与异常统一抽象为一组编号在 `0～255` 之间的中断向量。在不同的 CPU 执行模式下，寻址这组向量的具体硬件结构存在显著差异。

### 1.1 中断描述符表（IDT）

在 32 位保护模式与 64 位长模式下，CPU 借由中断描述符表（Interrupt Descriptor Table，简称 IDT）来管理所有中断与异常的处理入口。

IDT 表具有如下核心特征：
- **线性基址任意重定位**：IDT 可以驻留在物理内存或分页后的线性地址空间的任意位置，处理器通过加载到 `IDTR` 寄存器中的信息进行寻址。`IDTR` 包含了 IDT 的基地址以及 16 位的界限长度（Limit，表示 IDT 字节长度减 1）。为了获得最佳的总线访问效率，IDT 基地址通常按 8 字节边界对齐。
- **描述符并非指针，而是门结构**：IDT 中的表项被称为“门描述符”（Gate Descriptor）。在保护模式下，门描述符占 8 字节，包含目标代码段选择子、处理函数的段内偏移地址、特权级属性以及存在位（Present）。
- **门描述符的三种主要类型**：
  1. **中断门（Interrupt Gate）**：进入中断例程时，硬件会自动清零 `EFLAGS` 寄存器中的 `IF` 标志位以禁用可屏蔽中断，防止同级或低级中断重入破坏未保存的上下文，待执行 `iret` 指令恢复现场时再自动复原 `IF` 位；
  2. **陷阱门（Trap Gate）**：进入例程时保留 `IF` 标志位的当前状态，允许后续可屏蔽中断继续打断，常用于断点调试或系统调用；
  3. **任务门（Task Gate）**：利用硬件任务状态段（TSS）实现完整的硬件级任务切换，现代系统由于软件上下文切换效率更高，已较少使用任务门。
- **特权级防护规则**：门描述符中定义了描述符特权级（DPL）。当由用户空间通过 `int <vector>` 软件指令尝试触发中断时，CPU 会严密校验当前特权级（CPL）是否不低于门描述符的 DPL，从而防止非特权代码越权直接调用敏感的底层例程。

#### 1.1.1 历史渊源：实模式中断向量表（IVT）

在 16 位实模式下，承担中断索引任务的结构被称为中断向量表（Interrupt Vector Table，简称 IVT）。与 IDT 不同，IVT 的物理基地址由硬件固化在内存最底部的 `0x00000000` 至 `0x000003FF` 区间，恰好占 1 KiB 空间。256 个向量每项占用 4 字节，由 2 字节的段基地址和 2 字节的段内偏移构成一个远指针。由于实模式缺乏特权级隔离机制，IVT 表项不包含任何访问控制与存在位检查。

### 1.2 处理器内部异常（Exceptions）

异常属于 CPU 内部检测到的非可屏蔽事件，通常由正在执行的指令直接触发。依据架构规范，Intel 将前 32 个中断向量（向量号 0～31）严格保留为系统级异常：

- **错误（Fault）**：发生在引起异常的指令执行之前，通常可以被修复并重新执行该指令（如缺页异常 Page Fault，向量 14）；
- **陷阱（Trap）**：发生在引起异常的指令执行之后，返回地址指向下一条指令（如单步调试陷阱或溢出检查）；
- **中止（Abort）**：发生致命硬件故障或不可恢复的逻辑错误，处理程序通常无法恢复原任务的继续执行。

在异常嵌套处理的时序中，存在两类特殊的升级状态：
- **双重错误（Double Fault，向量 8）**：当处理器在尝试触发某个既有异常处理例程期间，再度引发了另一个无法协同的异常，CPU 会转向执行双重错误处理函数；
- **三重错误（Triple Fault）**：若在双重错误处理函数的加载或执行过程中又引发了新的致命错误，CPU 将判定系统已陷入不可逆的崩溃状态，随即拉低处理器的关机引脚信号，导致物理主板直接硬重启。

### 1.3 外部硬件中断（IRQ）与控制器演进

外部硬件中断（Interrupt Request，简称 IRQ）由处理器外部的外设控制器产生，用于通知内核设备数据已就绪或传输已完成。硬件中断属于可屏蔽中断，其投递受 `EFLAGS.IF` 控制位支配。

在 x86 系统发展史中，中断路由架构经历了关键迭代：

#### 1.3.1 8259A 可编程中断控制器（PIC）

在经典 PC/AT 架构中，系统通过两片 8259A 芯片级联来管理 15 条硬件中断线。其配置逻辑简单，通过少数几组 I/O 端口即可完成向量重映射与掩码读写。然而，8259A 仅支持单处理器环境，硬件中断只能以串行方式送往单个 CPU 核心，无法适应现代多核处理器的并发需求。

#### 1.3.2 高级可编程中断控制器（APIC）

为了支持对称多处理（SMP），现代 PC 引入了 APIC 架构，由集成在各 CPU 核心内部的 Local APIC 以及主板芯片组上的 I/O APIC 协同构成。I/O APIC 负责将外设的物理引脚中断重定向并动态分发给特定的 CPU 核心，Local APIC 则负责处理核间中断（IPI）以及高精度本地时钟中断。有关 APIC 的深入细节可参见 [**ACPI 与高级中断控制器**](/教程/正文/项目案例/MdrOS/9_9_ACPI#_2-apic)。

> **PCI 消息传递中断（MSI / MSI-X）**  
> 在现代 PCI/PCIe 总线体系中，外设逐渐淘汰了物理中断引脚，转而通过向指定的主机内存物理地址执行写入操作（Message Signaled Interrupts）来直接触发中断。这种机制免除了总线仲裁与中断线共享的寻址开销，极大提升了多设备并发时的响应吞吐。

### 1.4 软件中断与系统调用接口

软件中断是由内核或应用程序主动执行诸如 `int <vector>` 等机器指令而显式触发的执行流转移：

```asm
int <vector> ; x86 触发软中断的指令，vector 代表预设的中断向量号
```

软件中断在指令层面由软件自发引发，不受 `EFLAGS.IF` 屏蔽位的限制，即便在 `cli` 关闭中断的状态下执行 `int` 指令，CPU 依然会强制执行门描述符寻址。经典 Unix 系统正是借由特定软中断向量（如 `0x80`）实现由用户态特权级向内核态的主动陷入。
