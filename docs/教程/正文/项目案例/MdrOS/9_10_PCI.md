# 9.10 PCI

外设部件互连标准 (Peripheral Component Interconnect)

很多外围设备的通信都要通过 PCI 总线进行，诸如 显卡/声卡/网卡/USB 接口/硬盘 等

## 1. PCIe

PCI-Express(peripheral component interconnect express) 是一种高速串行计算机扩展总线标准，它原来的名称为“3GIO”，是由英特尔在 2001 年提出的，旨在替代旧的 PCI，PCI-X 和 AGP 总线标准。

PCI-Express 是用来互联诸如计算和通信平台应用中外围设备的第三代高性能 I/O 总线。第一代包括 ISA、EISA、VESA 和微通道（Micro Channel）总线，而第二代总线则包括了 PCI、AGP 和 PCI-X。PCIe 是一种能够应用于移动设备、台式电脑、工作站、服务器、嵌入式计算和通信平台等所有周边的 I/O 设备互联的总线。

### 2.1 巩固

<Exercise id="50001" :d="1" :w="2">

PCIe 用串行的点对点连接，PCI 用共享的并行总线，两者的电气形式完全不同，可软件看到的配置空间却是同一套布局。

(1) 说明配置空间保持不变对操作系统意味着什么：驱动里「按偏移读配置空间」的那部分代码，从 PCI 设备迁到 PCIe 设备上需要改吗？改的是哪一部分？

(2) 配置空间用一对 I/O 端口访问：先把 32 位地址写到 `0xCF8`，再从 `0xCFC` 读写一个 32 位字。地址格式如下，位号从 0 数起：

- 第 31 位：使能位，必须为 1；
- 第 23～16 位：总线号；
- 第 15～11 位：设备号；
- 第 10～8 位：功能号；
- 第 7～2 位：寄存器号，以 4 字节为单位，即字节偏移除以 4；
- 第 1、0 位：固定为 0。

写出 `uint32_t pci_cfg_addr(unsigned bus, unsigned dev, unsigned func, unsigned off)`，`off` 以字节计。

(3) 用 `main` 按 `%08x` 打印下面四组输入的结果，与右列核对：

```text

(0,    2,    0, 0x10)   80001004
(0,    0x1f, 7, 0x3c)   8000ff0f
(0xff, 0,    0, 0x08)   80ff0002
```

(4) `off` 不是 4 的倍数时，这个地址指向哪个寄存器？函数应当怎么处理这种输入？

<Exercise id="50003" :d="3" :w="4">

确定基址寄存器 (Base Address Register, BAR) 的大小。配置空间偏移 `0x10`～`0x24` 是 6 个 BAR，每个 32 位。做法是向 BAR 写入全 1，再读回：能保持为 1 的位不可写，读回 0 的位属于地址空间，据此算出大小。存储器 BAR 的低 4 位是标志，其中位 0 为 0、位 2～1 为 `10` 时表示 64 位 BAR，此时高 32 位占用下一个 BAR 的位置；I/O BAR 的位 0 为 1，低 2 位是标志。探测前要保存原值，探测后写回。

实现下面的接口并写一个 `main`，对指定功能打印 6 个 BAR 的类型、基址和大小：

```c
struct pci_bar {
    int is_io;
    int is_64;
    uint64_t base;
    uint64_t size;
};

int pci_bar_probe(unsigned bus, unsigned dev, unsigned func, unsigned index,
                  struct pci_bar *out);
```

要求：

(1) 大小为 0 表示该 BAR 未实现，函数返回 0；`index` 指向 64 位 BAR 的低半部分时，返回 1 并跳过下一个 BAR。

(2) 探测前后各读一次 BAR，确认写回后原值不变。

(3) 在 QEMU 的 e1000 设备上验收：BAR0 是存储器 BAR，大小 128 KiB；BAR1 是 I/O BAR，大小 64 字节。核对办法是在 QEMU 监视器里执行 `info pci`，它会列出每个设备的 BAR 与大小。

(4) 探测时先清掉命令寄存器（偏移 `0x04`）的位 1 和位 0，探测完再恢复。说明不清这两位时，写入全 1 可能对正在工作的设备造成什么后果。

(5) 说明为什么读回值里为 0 的位表示「这一段地址由本 BAR 占用」，据此算出的 `(~(mask & ~0xF) + 1)` 为什么一定是 2 的幂。`mask` 里第 0～3 位是标志位，必须先用 `& ~0xF` 清掉，否则算出来的大小会多出几十字节。

</Exercise>

### 2.3 综合与挑战

<Exercise id="50004" :d="5" :w="4">

找到 AHCI 控制器并读出它的寄存器区。AHCI 控制器的基类为 `0x01`（大容量存储控制器）、子类为 `0x06`（SATA）、编程接口为 `0x01`（AHCI 1.0）。它的 BAR5 是 ABAR（AHCI Base Address Register），指向一段存储器映射的寄存器区。

要求：

(1) 在 `pci_scan` 的基础上加过滤，打印所有匹配的功能号，并取出其 BAR5 的基址与大小。

(2) 把 ABAR 映射到内核地址空间，按 32 位读偏移 `0x00` 的 `CAP` 与偏移 `0x10` 的 `VS`。`CAP` 的低 5 位加 1 是端口数量，`VS` 的高 16 位是主版本号，低 16 位是次版本号。在 QEMU 的 `-device ich9-ahci` 上验收：端口数量不少于你挂上去的磁盘数，主版本号为 1。

(3) 取到的 BAR5 是物理地址。说明为什么不能直接把它当虚拟地址解引用（除非这段已经恒等映射），以及映射时必须选不可缓存、不可写合并的属性。提示：如果 CPU 把两次相邻的寄存器写合并成一次，或者把一次读的结果留在缓存里，控制器会漏掉写、状态位会读到旧值。

(4) 区分 BAR5 与 9.11 里的 `AHCI_BASE`：前者是控制器寄存器区的物理地址，后者是驱动自己放命令表的内存起始地址。分别给出取得这两个地址的代码，并说明为什么前者必须从配置空间读，后者可以由驱动自己挑。

(5) `CAP` 的第 31 位是 `S64A`，表示控制器能否处理 64 位物理地址。读出这一位，并说明它为 0 时，9.11 里把 `ctbau` 写成高 32 位的做法会有什么问题。

(6) `CAP` 的位 12～8 是 `NCS`，存的是命令槽数减一；位 4～0 是 `NP`，存的是端口数减一。用同一个函数把这两个数解出来，并在 QEMU 上核对：`NCS + 1` 应当不小于 1，`NP + 1` 应当等于 ABAR 之后那段寄存器区里能看到的端口数。

</Exercise>
