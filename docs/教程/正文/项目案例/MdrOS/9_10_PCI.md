# 9.10 PCI 与外设总线架构

在个人计算机体系中，处理器与高速外设（如网卡、声卡、图形显示适配器、NVMe/SATA 硬盘控制器及 USB 主控制器）之间的大规模数据流转，均依赖外设总线系统连接。

早期计算机依赖 ISA、EISA 等老式总线，外设的 I/O 端口、中断引脚与 DMA 通道往往需要通过主板跳线手动指定，极易引发资源冲突。**外设部件互连标准（Peripheral Component Interconnect，简称 PCI）** 的确立，正式引入了标准化的总线枚举、即插即用（Plug and Play）与地址空间动态重定位机制，成为现代系统感知并驱动外部硬件的基础协议。

## 1. 总线拓扑与 PCIe 演进

随微处理器主频与外设吞吐需求的飞跃，传统的并行 PCI 总线逐渐面临信号反射、总线时钟偏斜（Clock Skew）以及所有设备共享总线带宽的物理瓶颈。

英特尔随后推出了第三代 I/O 总线技术 **PCI Express（简称 PCIe）**：
- **物理层的串行跃迁**：PCIe 在电气层面将共享式的并行总线彻底重塑为点对点（Point-to-Point）的双向全双工差分串行链路。各个设备独占通道（Lanes，如 x1、x4、x16），彻底消除了并行干扰；
- **软件视角的无缝兼容**：虽然 PCIe 与传统 PCI 的电气特性截然不同，但系统软件所观察到的逻辑拓扑与**配置空间（Configuration Space）** 规范完全兼容。这意味着操作系统内核针对 PCI 编写的设备枚举、BAR 基址探测与状态寄存器解析代码，在 PCIe 设备上依然可以直接运转。

## 2. PCI 配置空间与 BDF 寻址

在 PCI 架构下，整机的所有外设通过“总线（Bus）- 设备（Device）- 功能（Function）”（简称 **BDF**）的三维坐标系进行唯一寻址：
- **总线号（Bus 0～255）**：系统中最多可存在 256 条逻辑总线；
- **设备号（Device 0～31）**：每条总线上最多连接 32 个物理设备；
- **功能号（Function 0～7）**：每个物理设备内部最多集成 8 个逻辑功能实体（即多功能设备 Multifunction Device）。

每个 PCI 功能实体均由硬件固化了一段 256 字节的**标准配置空间（Configuration Space）**（PCIe 扩展至 4096 字节）。在传统的 x86 架构中，CPU 通过芯片组预留的一对 32 位 I/O 端口来访问这一空间：
- **配置地址端口 `0xCF8`（CONFIG_ADDRESS）**：写入一个 32 位的寻址字，其中最高位为使能位（必须置 1），第 23～16 位为总线号，第 15～11 位为设备号，第 10～8 位为功能号，第 7～2 位为目标双字寄存器在配置空间内的偏移（字节偏移除以 4）；
- **配置数据端口 `0xCFC`（CONFIG_DATA）**：根据写入 `0xCF8` 的地址，向该端口读写具体的 32 位配置数据。

### 2.1 标准配置空间头部（Type 0 Header）

配置空间的前 16 字节对于所有常规设备具有标准统一的布局，内核借此完成设备自检与身份识别：

| 偏移（Offset） | 字段长度 | 字段含义 |
| :--- | :--- | :--- |
| `0x00` | 16 位 | **厂商号（Vendor ID）**：硬件厂商唯一标识。若读回全 1（`0xFFFF`），说明该 BDF 上无物理设备存在 |
| `0x02` | 16 位 | **设备号（Device ID）**：厂商赋予该型号芯片的专属产品代号 |
| `0x08` | 8 位 | **版本 ID（Revision ID）**：芯片硬件步进与改版标识 |
| `0x09` | 8 位 | **编程接口（Prog IF）**：进一步细化控制器所遵循的通用驱动规范（如 AHCI、UHCI/EHCI 等） |
| `0x0A` | 8 位 | **子类别（Subclass）**：外设所属的细分类型（如 SATA 控制器） |
| `0x0B` | 8 位 | **基类别（Base Class）**：外设所属的大分类（如 `0x01` 存储控制器、`0x02` 网络控制器、`0x03` 显示控制器） |
| `0x0E` | 8 位 | **首部类型（Header Type）**：第 7 位为 1 表示该物理设备为多功能设备，软件需遍历其功能 1～7；若为 0 则可直接跳过后续功能探测 |

### 2.2 基址寄存器（BAR）与 MMIO 资源探测

在配置空间的 `0x10` 至 `0x24` 范围内，排列着 6 个 **基址寄存器（Base Address Registers，简称 BAR）**。BAR 是外设向操作系统声明其所需的物理内存（MMIO）或 I/O 端口地址空间大小的硬件中介：

1. **类型判别**：BAR 的最低位（bit 0）用于区分资源类型：为 1 表示 I/O 端口映射，为 0 表示内存映射（MMIO）。在 MMIO 模式下，bit 2～1 为 `10` 时代表该 BAR 扩展为 64 位寻址，此时它与紧随其后的下一个 BAR 共同构成一个 64 位的物理地址基准。
2. **硬件尺寸探测算法**：操作系统为了探测某外设控制器究竟需要多大尺寸的内存映射区间，通常采用标准的写入反读算法：
   - 临时禁用该设备在命令寄存器中的 I/O 与内存响应位，防止探测时发生虚假响应；
   - 保存 BAR 的初始基址；
   - 向目标 BAR 写入全 1（`0xFFFFFFFF`）；
   - 再次读出该 BAR 的数值：硬件内部会自动将自身不需要的低位地址线强制置 0，软件通过位屏蔽提取出为 0 的位数，执行按位取反加 1（`~(mask & ~0xF) + 1`），即可计算出该 BAR 所要求的精确字节尺寸；
   - 探测完毕后，恢复设备的原有基地址与命令寄存器。
3. **MMIO 的页表映射属性**：当内核为设备的 MMIO 寄存器（例如 AHCI 控制器的 ABAR）建立虚拟内存映射时，**必须在页表项中显式关闭 CPU 的内部缓存（设置为不可缓存 Uncacheable 或写透模式）**。如果允许 CPU 缓存 MMIO 区间，处理器的预取、写合并与延迟回写机制将导致硬件控制器的真实寄存器漏写，使驱动程序读取到过时的虚假硬件状态。

    int is_io;
    int is_64;

    uint64_t size;

int pci_bar_probe(unsigned bus, unsigned dev, unsigned func, unsigned index,
