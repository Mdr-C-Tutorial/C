# 9.8 多任务机制与进程调度

多任务并发是现代操作系统的基石。内核通过在时间维度上对处理器算力进行精密复用，在单核或多核硬件之上交替推演多个执行流，使上层应用获得宏观上并行推演的执行体验。

在多任务子系统的构建中，内核需要协同解决特权级隔离、执行流上下文保护、硬件栈切换以及调度算法等多层技术挑战。

## 1. 系统内核进程与空闲任务（IDLE）

在 x86 的四级特权环模型中，内核进程常驻于最高特权级 Ring 0（R0）。这类进程享有无限制的硬件寻址与控制权限，负责执行驱动中断底半部、内存回收与常驻内核服务。

其中，最为特殊的系统进程当属**空闲进程（IDLE 进程）**：
- **自举首发**：IDLE 进程是内核引导过程中由系统手工初始化构建的第 0 号进程（PID 0），它是整机唯一不通过 `fork` 机制克隆衍生的特权执行实体；
- **调度垫底**：IDLE 拥有系统中的最低调度优先级。当就绪队列中所有就绪任务均陷入等待或执行完毕时，调度器才将 CPU 算力分派给 IDLE；
- **节能循环**：操作系统完成全局硬件初始化后，IDLE 进程并不会退出销毁，而是在核内主循环中反复执行 `hlt` 汇编指令，挂起处理器流水线以大幅降低 CPU 功耗与发热，直到下一个硬件中断将其唤醒；
- **对称多核绑定**：在对称多处理（SMP）架构下，主核心 CPU0 初始化完成后，会为每一个从核心（AP）分别拉起独立的 IDLE 任务实例，以便各核心在空闲时独立休眠。

## 2. 用户态进程与特权隔离

运行在最低特权级 Ring 3（R3）的进程构成了上层应用程序的执行主体。处于 R3 的代码受到硬件 MMU 与 CPU 特权控制器的双重严密防护：既无法直接执行特权指令（如 `cli`、`sti`、`hlt`、`lgdt` 等），也无法触碰被标记为内核特权级的虚拟地址区间。

### 2.1 特权级跃迁与内核栈切换

在 x86 体系结构下，CPU 无法通过普通的跳转或调用指令直接在 Ring 3 与 Ring 0 之间切换，必须通过受控的硬件机制完成跨特权级跃迁：

- **从 R3 陷入 R0（中断与系统调用）**：当用户程序触发软中断（如 `int 0x80`）、系统调用或产生硬件外部中断时，CPU 必须立即离开不受信任的用户栈，切换至受保护的内核栈。为了防止用户栈指针非法导致内核崩溃，CPU 会自动查询当前任务状态段（TSS）中预先填写的 `ss0` 与 `esp0`，切换至专属于该进程的内核栈，并在该栈上自动依序压入用户态的 `ss`、`esp`、`eflags`、`cs` 与 `eip` 寄存器镜像。
- **从 R0 下降至 R3（特权降级）**：新进程创建后，内核通常在进程内核栈中预先伪造一个中断返回栈帧（包含用户程序的入口地址 `eip`、用户栈顶 `esp`、属性标志以及 RPL=3 的代码段与数据段选择子）。随后，内核调用 `switch_to_user_mode` 辅助例程清理现场，并执行 `iret`（中断返回）指令。硬件根据栈上弹出的段选择子检测到特权级发生跨越，自动切换特权级并激活 R3 执行流。

### 2.2 TSS 在现代内核中的实际分工

**任务状态段（Task State Segment，简称 TSS）** 是 x86 硬件设计中专用于硬件级任务切换的古老结构，其内部包含了所有通用寄存器、段寄存器以及 `cr3` 的硬件镜像槽位。

在现代操作系统设计中，硬件任务切换机制由于无法跨架构移植、执行开销过大且难以支持丰富的软件策略已被全面弃用，取而代之的是由软件维护的**进程控制块（Process Control Block，简称 PCB）**。PCB 仅在必要时保存少数字符与通用寄存器，同时承载了诸如 PID、虚拟内存空间映射、打开文件描述符表以及时间片计数等软件属性。

但在 x86 保护模式下，TSS 结构依然不可或缺：内核仍必须在 GDT 中注册至少一个 TSS 描述符并使用 `ltr` 指令将其装入 CPU。**在现代系统中，TSS 的核心使命被收敛为单一职责：在 R3 陷入 R0 时，为硬件提供合法的内核栈基址（`esp0` 与 `ss0`）。**

## 3. 任务调度策略与上下文切换

任务调度器是操作系统的中央指挥部，负责在就绪队列中裁定下一个获取处理器执行权的任务：

- **时间片轮转（Round-Robin）**：内核定时器（如 PIT 或 APIC Timer）以恒定频率周期性向 CPU 发送时钟中断。中断处理函数递减当前任务的时间片计数，一旦时间片耗尽，即唤醒调度器执行任务轮换。
- **上下文切换的两大支柱**：
  1. **寄存器上下文迁移**：通过软件汇编将当前任务执行现场的通用寄存器、程序计数器与栈指针压入旧任务的内核栈或保存至 PCB，再从新任务的栈或 PCB 中恢复新上下文；
  2. **地址空间切换**：若切换发生在不同的进程之间，调度器必须将新进程的页目录物理基地址加载到 `CR3` 寄存器。这一操作会触发 MMU 的硬件转换后援缓冲器（TLB）局部刷新，使 CPU 的线性地址空间瞬间切换为新进程的内存布局。

## 4. 进程与线程的抽象分野

从底层资源视角审视，进程与线程的核心差异体现在地址空间的分立与共享：

- **进程（Process）** 是系统进行资源分配和内存隔离的独立单元。每个进程拥有专属的页目录（独立 `CR3`）。即使两个不同进程访问数值完全一致的线性虚拟地址（例如 `0x08048000`），经由各自独立的二级页表走查后，也将映射到完全不同的物理页框中，从而从硬件层面实现内存隔离。
- **线程（Thread）** 是 CPU 进行时间片调度的最小执行单元。属于同一进程的所有线程共享相同的页目录与地址空间，各个线程拥有独立的私有栈空间与寄存器上下文，但在访问全局数据与堆内存时彼此可见。因此，线程间的上下文切换省去了重载 `CR3` 这一耗时操作，显著提升了并发交互的吞吐效率。
