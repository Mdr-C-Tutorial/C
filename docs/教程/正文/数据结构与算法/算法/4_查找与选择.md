# 4. 查找与选择

在无序数组中查找目标值或求第 $k$ 小元素需要扫描全部元素；而一旦挖掘出数据的**有序性（单调性）**或利用**围绕枢轴的分区性质**，我们就能以 $O(\log n)$ 完成有序查找与单调答案求解，并以平均 $O(n)$ 的线性时间选出任意顺序统计量。

## 1. 半开区间二分查找：`lower_bound` 与 `upper_bound`

二分查找虽然思想简单，但若混用闭区间 `[left, right]` 与半开区间 `[left, right)`，或者仅考虑“找到任意一个相等元素”，面对重复元素和越界输入时极易出现死循环或下标差一错误。

工程上最稳健的范式是统一采用**左闭右开区间 `[left, right)`**（初始为 `[0, count)`），并将二分查找形式化为**寻找单调布尔谓词的分界点**：

- **下界查找 (`lower_bound`)**：在非递减数组 `items[0..count)` 中，返回第一个满足 `items[i] >= target` 的下标（若所有元素都小于 `target`，则返回 `count`）。
  - **循环不变式**：在每次迭代开始前，对所有 $i < \text{left}$ 恒有 $\text{items}[i] < \text{target}$；对所有 $j \ge \text{right}$ 恒有 $\text{items}[j] \ge \text{target}$。
  - **区间收缩**：取中点 $\text{mid} = \text{left} + (\text{right} - \text{left}) / 2$。若 $\text{items}[\text{mid}] < \text{target}$，说明 $\text{mid}$ 及其左侧都不可能是答案，令 $\text{left} = \text{mid} + 1$；否则 $\text{mid}$ 满足条件，令 $\text{right} = \text{mid}$。
  - **终止性与复杂度**：由于 $\text{left} < \text{right}$ 时恒有 $\text{left} \le \text{mid} < \text{right}$，无论是 $\text{left} = \text{mid} + 1$ 还是 $\text{right} = \text{mid}$，区间长度 $\text{right} - \text{left}$ 在每步都严格减小且大致减半，至多经过 $\lfloor \log_2 n \rfloor + 1$ 次比较后必有 $\text{left} == \text{right}$，此时 $\text{left}$ 即为分界下标，时间复杂度为 $O(\log n)$。
- **上界查找 (`upper_bound`)**：返回第一个满足 `items[i] > target` 的下标（若不存在则返回 `count`）。只需将左半区判定条件由 `items[mid] < target` 改为 `items[mid] <= target`。目标值 `target` 在数组中的出现次数恰好等于 `upper_bound(target) - lower_bound(target)`。

::: warning 为什么不能写 `(left + right) / 2`

当 `left` 和 `right` 为 `size_t`（或较大正整数）且二者之和超过类型最大值 `SIZE_MAX` 时，`left + right` 会发生无符号回绕（或有符号溢出 UB），得出错误的中点下标。写成 `left + (right - left) / 2` 在 `left <= right` 时永远不会溢出。

:::

## 2. 单调谓词上的答案二分 (Binary Search on Answer)

许多最优化问题要求计算“满足某项产能或容量条件所需的**最小时间 / 最小代价 $T$**”。如果判定函数 $\text{check}(t)$（判断在时间 $t$ 内能否完成目标）关于 $t$ 具有**单调性**：

$$\forall t_1 \le t_2, \quad \text{check}(t_1) \implies \text{check}(t_2)$$

那么可行解集合形如 $[T^*, +\infty)$，原优化问题就直接归约为在整数区间 $[0, R]$ 上对单调谓词 $\text{check}(t)$ 执行 `lower_bound`！

在 C 语言实现答案二分时，需要注意两个防溢出细节：

1. **安全确定搜索上界 $R$**：不要直接用“最慢机器耗时 $\times$ 目标件数”（可能超出 `uint64_t`）。可以先挑选最快的一台机器 $t_{\min} = \min_i \text{time}_i$，其单独完成 `target` 件耗时为 $t_{\min} \times \text{target}$（可在乘法前用 `target > UINT64_MAX / t_min` 检查溢出；或者从 `high = 1` 开始每次翻倍直到 `check(high)` 为真）。
2. **判定函数内的饱和累加**：在 `check(mid)` 中累加各台机器产量 $\sum \lfloor \text{mid} / \text{time}_i \rfloor$ 时，一旦部分和已经达到或超过 `target`（即 `sum >= target - produced`），应立即返回 `true`，既避免无意义的后续循环，又防止多个大数相加发生 `uint64_t` 回绕。

## 3. 顺序统计量与快速选择 (Quickselect)

若要在含 $n$ 个元素的无序数组中找出排序后下标为 `order`（$0 \le \text{order} < n$）的元素，完全排序需 $O(n \log n)$，而 Hoare 提出的**快速选择 (Quickselect)** 算法只需平均 $O(n)$ 时间：

1. 从当前搜索闭区间 `[left, right]` 中选取一个枢轴值 `pivot`，通过**三路分区 (3-Way Partition / Dutch National Flag)** 将区间原地划分为三段：
   - `[left, lt - 1]`：严格小于 `pivot`；
   - `[lt, gt]`：等于 `pivot`；
   - `[gt + 1, right]`：严格大于 `pivot`。
2. 比较目标秩 `order` 与 `[lt, gt]` 的关系：
   - 若 `lt <= order && order <= gt`，说明目标元素恰等于 `pivot`，直接返回；
   - 若 `order < lt`，令 `right = lt - 1` 仅在左半区继续迭代；
   - 若 `order > gt`，令 `left = gt + 1` 仅在右半区继续迭代。

与快速排序要递归处理左右两侧不同，快速选择每次**只进入一个分支**。在平均情况下每次将区间缩减为常数比例，递推式 $T(n) = T(\alpha n) + O(n)$（$0 < \alpha < 1$）按几何级数求和得期望时间复杂度 $O(n)$，且尾递归改写为循环后额外空间复杂度为 $O(1)$（最坏情况为每次选到极值时的 $O(n^2)$）。

## 4. C 语言实现示例：二分上下界与三路分区快速选择

```c
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>

static size_t lower_bound_i64(const int64_t *a, size_t n, int64_t target) {
    size_t left = 0, right = n;
    while (left < right) {
        size_t mid = left + (right - left) / 2;
        if (a[mid] < target) {
            left = mid + 1;
        } else {
            right = mid;
        }
    }
    return left;
}

static size_t upper_bound_i64(const int64_t *a, size_t n, int64_t target) {
    size_t left = 0, right = n;
    while (left < right) {
        size_t mid = left + (right - left) / 2;
        if (a[mid] <= target) {
            left = mid + 1;
        } else {
            right = mid;
        }
    }
    return left;
}

static void swap_i64(int64_t *x, int64_t *y) {
    int64_t tmp = *x;
    *x = *y;
    *y = tmp;
}

static int64_t quickselect_i64(int64_t *a, size_t n, size_t order) {
    size_t left = 0, right = n - 1;
    while (left < right) {
        int64_t pivot = a[left + (right - left) / 2];
        size_t lt = left, i = left, gt = right;
        while (i <= gt) {
            if (a[i] < pivot) {
                swap_i64(&a[lt++], &a[i++]);
            } else if (a[i] > pivot) {
                swap_i64(&a[i], &a[gt--]);
            } else {
                i++;
            }
        }
        if (order < lt) {
            right = lt - 1;
        } else if (order > gt) {
            left = gt + 1;
        } else {
            return pivot;
        }
    }
    return a[left];
}

int main(void) {
    int64_t sorted[] = {10, 20, 20, 20, 35, 50};
    size_t n = sizeof(sorted) / sizeof(sorted[0]);
    printf("lower_bound(20) = %zu, upper_bound(20) = %zu\n",
           lower_bound_i64(sorted, n, 20),
           upper_bound_i64(sorted, n, 20));

    int64_t unsorted[] = {42, 15, 8, 42, 23, 4, 16};
    printf("order 3 (0-based) = %lld\n",
           (long long)quickselect_i64(unsorted, 7, 3));
    return 0;
}
```

运行结果：

::: terminal

lower_bound(20) = 1, upper_bound(20) = 4
order 3 (0-based) = 16

:::

有若干台机器并行生产同一种产品。第 `i` 台机器每生产一件产品需要 `machine_times[i]` 个时间单位。实现：

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

bool minimum_production_time(
    const uint64_t *machine_times,
    size_t machine_count,
    uint64_t target,
    uint64_t *out_time
);
```

要求：

1. 返回生产至少 `target` 件产品所需的最短时间。
2. `target` 为 0 时结果为 0，此时机器数组可以为空。
3. `target` 大于 0 时至少有一台机器，并且每个生产时间都必须大于 0。
4. 不能通过“最慢或最快机器耗时乘以目标件数”直接构造可能溢出的上界。
5. 累加各机器产量时不得溢出；达到目标后应立即停止累加。
6. 参数无效或答案不能用 `uint64_t` 表示时返回 `false`，并保持输出对象不变。
7. 使用答案二分，时间复杂度为 $O(m\log T)$，其中 $m$ 为机器数量，$T$ 为答案。

</Exercise>
