# 6. 排序算法 (Sorting Algorithms)

## 1. 引言

### 1.1 排序的定义与重要性

排序（Sorting）是将一组数据元素按照特定顺序（通常是数字顺序或字典顺序）重新排列的过程。

* **输入**：$n$ 个数的序列 $\langle a_1, a_2, \dots, a_n \rangle$。
* **输出**：原序列的一个重排 $\langle a'_1, a'_2, \dots, a'_n \rangle$，满足 $a'_1 \leq a'_2 \leq \dots \leq a'_n$。

排序是计算机科学中最基本的操作之一，广泛用于数据库优化、二分查找预处理、数据压缩和图形渲染等领域。

### 1.2 排序算法的分类

* **比较排序 vs 非比较排序**：前者通过元素间的比较决定顺序，后者利用数据本身的特性（如计数值）。
* **内部排序 vs 外部排序**：前者数据全部加载到内存，后者数据量过大需借助外部存储（磁盘）。
* **递归排序 vs 非递归排序**。

### 1.3 评价标准

#### 1.3.1 时间复杂度

* **最好情况**：数据已经有序时。
* **最坏情况**：数据完全逆序或特定排列时。
* **平均情况**：随机数据的期望运行时间。
* 通常关注渐进上界 $O(n^2)$ 或 $O(n \log n)$。

#### 1.3.2 空间复杂度

算法执行过程中所需的额外内存空间。理想情况是 $O(1)$。

#### 1.3.3 稳定性 (Stability)

如果两个相等的元素 $A$ 和 $B$ 在排序前的序列中 $A$ 在 $B$ 前面，排序后 $A$ 依然在 $B$ 前面，则称算法是稳定的。这在多关键字排序（如先按分数排，再按名字排）中非常重要。

#### 1.3.4 原地排序 (In-place)

除了输入数组外，只需要常数阶 $O(1)$ 的额外空间。

## 2. 简单排序算法

### 2.1 冒泡排序（Bubble Sort）

#### 2.1.1 算法原理

重复遍历要排序的数列，每次比较相邻的两个元素，如果它们的顺序错误就把它们交换过来。

#### 2.1.2 算法实现

```c
void bubbleSort(int nums[], int size) {
    // 外循环：未排序区间为 [0, i]
    for (int i = size - 1; i > 0; i--) {
        // 内循环：将未排序区间 [0, i] 中的最大元素交换至该区间的最右端
        for (int j = 0; j < i; j++) {
            if (nums[j] > nums[j + 1]) {
                int temp = nums[j];
                nums[j] = nums[j + 1];
                nums[j + 1] = temp;
            }
        }
    }
}
```

#### 2.1.3 复杂度分析

* 时间：平均 $O(n^2)$，最坏 $O(n^2)$，最好 $O(n)$（需要 2.1.4 的标志位优化，上面的实现总是 $O(n^2)$）。
* 空间：$O(1)$。
* 稳定性：稳定。

#### 2.1.4 优化方案

设置标志位 `swapped`，如果一轮遍历中没有交换，直接结束；记录最后一次交换的位置，减少遍历范围（鸡尾酒排序是其变种）。

### 2.2 选择排序（Selection Sort）

#### 2.2.1 算法原理

每一次从待排序的数据元素中选出最小（或最大）的一个元素，存放在序列的起始位置。

#### 2.2.2 算法实现

```c
void selectionSort(int nums[], int n) {
    // 外循环：未排序区间为 [i, n-1]
    for (int i = 0; i < n - 1; i++) {
        // 内循环：找到未排序区间内的最小元素
        int k = i;
        for (int j = i + 1; j < n; j++) {
            if (nums[j] < nums[k])
                k = j; // 记录最小元素的索引
        }
        // 将该最小元素与未排序区间的首个元素交换
        int temp = nums[i];
        nums[i] = nums[k];
        nums[k] = temp;
    }
}
```

#### 2.2.3 复杂度分析

* 时间：无论数据状况如何，均为 $O(n^2)$。
* 空间：$O(1)$。
* 稳定性：**不稳定**（例如序列 `[5, 5, 2]`，交换第一个 5 和 2 会破坏两个 5 的相对顺序）。

### 2.3 插入排序（Insertion Sort）

#### 2.3.1 算法原理

构建有序序列，对于未排序数据，在已排序序列中从后向前扫描，找到相应位置并插入。类似于打扑克牌整理手牌。

#### 2.3.2 算法实现

```c
/* 插入排序 */
void insertionSort(int nums[], int size) {
    // 外循环：已排序区间为 [0, i-1]
    for (int i = 1; i < size; i++) {
        int base = nums[i], j = i - 1;
        // 内循环：将 base 插入到已排序区间 [0, i-1] 中的正确位置
        while (j >= 0 && nums[j] > base) {
            // 将 nums[j] 向右移动一位
            nums[j + 1] = nums[j];
            j--;
        }
        // 将 base 赋值到正确位置
        nums[j + 1] = base;
    }
}
```

#### 2.3.3 复杂度分析

* 时间：平均 $O(n^2)$，最坏 $O(n^2)$，最好 $O(n)$（接近有序时效率极高）。
* 空间：$O(1)$。
* 稳定性：稳定。

#### 2.3.4 二分插入排序

在查找插入位置时使用二分查找，将比较次数减少到 $O(n \log n)$，但移动次数仍为 $O(n^2)$。

### 2.4 希尔排序（Shell Sort）

#### 2.4.1 算法原理

插入排序的改进版（缩小增量排序）。先将整个待排序的记录序列分割成为若干子序列分别进行直接插入排序，待整个序列中的记录“基本有序”时，再对全体记录进行一次直接插入排序。

#### 2.4.2 算法实现

希尔排序的核心在于增量序列（Gap Sequence）的选择。常见的增量序列包括：
- **Shell 原始增量序列**：$n/2, n/4, \dots, 1$（最坏时间复杂度为 $\Theta(n^2)$）；
- **Knuth 增量序列**：$h_1 = 1, h_{k+1} = 3h_k + 1$（即 $1, 4, 13, 40, 121, \dots$），其最坏时间复杂度为 $O(n^{1.5})$；
- **Sedgewick 增量序列**：通过 $9(4^k - 2^k) + 1$ 与 $4^{k+1} - 6 \cdot 2^k + 1$ 交叉生成，最坏时间复杂度可优化至 $O(n^{4/3})$。

下面展示基于 Knuth 增量序列的标准实现：

```c
/* 希尔排序（基于 Knuth 增量序列：h = 3*h + 1） */
void shellSort(int nums[], int size) {
    if (nums == NULL || size <= 1) {
        return;
    }

    // 1. 计算最大有效增量
    int h = 1;
    while (h < size / 3) {
        h = 3 * h + 1; // 1, 4, 13, 40, 121, ...
    }

    // 2. 逐步缩小增量直至 h = 1
    while (h >= 1) {
        // 对每个间隔为 h 的子序列执行插入排序
        for (int i = h; i < size; i++) {
            int base = nums[i];
            int j = i - h;
            // 将大于 base 的元素向后移动 h 步
            while (j >= 0 && nums[j] > base) {
                nums[j + h] = nums[j];
                j -= h;
            }
            nums[j + h] = base;
        }
        h /= 3; // 缩小增量
    }
}
```

#### 2.4.3 复杂度分析

* 时间：取决于增量序列，平均可达 $O(n^{1.3})$ 或 $O(n \log^2 n)$。突破了 $O(n^2)$ 的限制。
* 稳定性：**不稳定**。

## 3. 高效排序算法

### 3.1 归并排序（Merge Sort）

#### 3.1.1 分治思想

将数组分成两半，分别对它们进行排序，然后将两个有序数组合并成一个有序数组。

#### 3.1.2 算法实现

* **分解**：$O(1)$。
* **解决**：递归调用。
* **合并**：$O(n)$。

```c
/* 合并左子数组和右子数组 */
void merge(int *nums, int left, int mid, int right) {
    // 左子数组区间为 [left, mid], 右子数组区间为 [mid+1, right]
    // 创建一个临时数组 tmp ，用于存放合并后的结果
    int tmpSize = right - left + 1;
    int *tmp = (int *)malloc(tmpSize * sizeof(int));
    // 初始化左子数组和右子数组的起始索引
    int i = left, j = mid + 1, k = 0;
    // 当左右子数组都还有元素时，进行比较并将较小的元素复制到临时数组中
    while (i <= mid && j <= right) {
        if (nums[i] <= nums[j]) {
            tmp[k++] = nums[i++];
        } else {
            tmp[k++] = nums[j++];
        }
    }
    // 将左子数组和右子数组的剩余元素复制到临时数组中
    while (i <= mid) {
        tmp[k++] = nums[i++];
    }
    while (j <= right) {
        tmp[k++] = nums[j++];
    }
    // 将临时数组 tmp 中的元素复制回原数组 nums 的对应区间
    for (k = 0; k < tmpSize; ++k) {
        nums[left + k] = tmp[k];
    }
    // 释放内存
    free(tmp);
}

/* 归并排序 */
void mergeSort(int *nums, int left, int right) {
    // 终止条件
    if (left >= right)
        return; // 当子数组长度为 1 时终止递归
    // 划分阶段
    int mid = left + (right - left) / 2;    // 计算中点
    mergeSort(nums, left, mid);      // 递归左子数组
    mergeSort(nums, mid + 1, right); // 递归右子数组
    // 合并阶段
    merge(nums, left, mid, right);
}
```

#### 3.1.3 复杂度分析

* 时间：严格的 $O(n \log n)$。
* 空间：$O(n)$（需要辅助数组），这是其主要缺点。
* 稳定性：稳定。

#### 3.1.4 空间优化

可以使用原地归并（实现极其复杂且常数大）。在数组规模较小时切换为插入排序也是常见的优化，但它减少的是递归开销，不节省空间。

### 3.2 快速排序（Quick Sort）

#### 3.2.1 分治思想

通过一个“基准”（Pivot）将数组分为两部分：比基准小的放在左边，比基准大的放在右边。然后递归排序。

#### 3.2.2 分区操作 (Partition)

* **Lomuto 分区**：单向扫描，实现简单。
* **Hoare 分区**：双向扫描，效率略高，交换次数少。

#### 3.2.3 算法实现

```c
/* 元素交换 */
void swap(int nums[], int i, int j) {
    int tmp = nums[i];
    nums[i] = nums[j];
    nums[j] = tmp;
}

/* 哨兵划分 */
int partition(int nums[], int left, int right) {
    // 以 nums[left] 为基准数
    int i = left, j = right;
    while (i < j) {
        while (i < j && nums[j] >= nums[left]) {
            j--; // 从右向左找首个小于基准数的元素
        }
        while (i < j && nums[i] <= nums[left]) {
            i++; // 从左向右找首个大于基准数的元素
        }
        // 交换这两个元素
        swap(nums, i, j);
    }
    // 将基准数交换至两子数组的分界线
    swap(nums, i, left);
    // 返回基准数的索引
    return i;
}

/* 快速排序 */
void quickSort(int nums[], int left, int right) {
    // 子数组长度为 1 时终止递归
    if (left >= right) {
        return;
    }
    // 哨兵划分
    int pivot = partition(nums, left, right);
    // 递归左子数组、右子数组
    quickSort(nums, left, pivot - 1);
    quickSort(nums, pivot + 1, right);
}
```

#### 3.2.4 复杂度分析

* 时间：平均 $O(n \log n)$，最坏 $O(n^2)$（当数据有序且每次选第一个为基准时）。
* 空间：平均 $O(\log n)$（递归栈空间），最坏 $O(n)$。若每次先递归处理较短的子数组、用循环处理较长的子数组，可以保证递归深度不超过 $O(\log n)$。
* 稳定性：**不稳定**。

#### 3.2.5 随机化快排

每次随机选取 Pivot，可以从概率上避免最坏情况的发生。

#### 3.2.6 三路快排 (3-Way Quick Sort)

将数组分为三部分：`< Pivot`、`= Pivot`、`> Pivot`。对包含大量重复元素的数组非常高效，当不同键值只有常数个时，复杂度降为 $O(n)$。

### 3.3 堆排序（Heap Sort）

#### 3.3.1 堆的概念

利用堆（Heap）这种数据结构。通常使用大顶堆（Max-Heap），堆顶为最大元素。

#### 3.3.2 堆的构建

* `Heapify`：调整节点使其满足堆性质。
* `Build-Heap`：从最后一个非叶子节点开始往前，对每个节点向下调整（即下面代码中的 `siftDown`），时间 $O(n)$。

#### 3.3.3 算法实现

1. 构建大顶堆。
2. 将堆顶元素与末尾元素交换。
3. 堆尺寸减 1，对新的堆顶进行 Heapify。
4. 重复直到堆尺寸为 1。

```c
/* 堆的长度为 n ，从节点 i 开始，从顶至底堆化 */
void siftDown(int nums[], int n, int i) {
    while (1) {
        // 判断节点 i, l, r 中值最大的节点，记为 ma
        int l = 2 * i + 1;
        int r = 2 * i + 2;
        int ma = i;
        if (l < n && nums[l] > nums[ma])
            ma = l;
        if (r < n && nums[r] > nums[ma])
            ma = r;
        // 若节点 i 最大或索引 l, r 越界，则无须继续堆化，跳出
        if (ma == i) {
            break;
        }
        // 交换两节点
        int temp = nums[i];
        nums[i] = nums[ma];
        nums[ma] = temp;
        // 循环向下堆化
        i = ma;
    }
}

/* 堆排序 */
void heapSort(int nums[], int n) {
    // 建堆操作：堆化除叶节点以外的其他所有节点
    for (int i = n / 2 - 1; i >= 0; --i) {
        siftDown(nums, n, i);
    }
    // 从堆中提取最大元素，循环 n-1 轮
    for (int i = n - 1; i > 0; --i) {
        // 交换根节点与最右叶节点（交换首元素与尾元素）
        int tmp = nums[0];
        nums[0] = nums[i];
        nums[i] = tmp;
        // 以根节点为起点，从顶至底进行堆化
        siftDown(nums, i, 0);
    }
}
```

#### 3.3.4 复杂度分析

* 时间：严格的 $O(n \log n)$。
* 空间：$O(1)$。
* 稳定性：**不稳定**。

## 4. 特殊排序算法（线性时间排序）

### 4.1 计数排序（Counting Sort）

#### 4.1.1 算法原理

统计每个整数在序列中出现的次数，进而推导出每个数字在有序序列中的索引。

#### 4.1.2 算法实现

需要一个大小为 $m$ （数据范围）的辅助数组 `counter`。下面的简单实现要求元素均为非负整数。

```c
/* 计数排序 */
// 简单实现，无法用于排序对象
void countingSortNaive(int nums[], int size) {
    // 1. 统计数组最大元素 m
    int m = 0;
    for (int i = 0; i < size; i++) {
        if (nums[i] > m) {
            m = nums[i];
        }
    }
    // 2. 统计各数字的出现次数
    // counter[num] 代表 num 的出现次数
    int *counter = calloc(m + 1, sizeof(int));
    for (int i = 0; i < size; i++) {
        counter[nums[i]]++;
    }
    // 3. 遍历 counter ，将各元素填入原数组 nums
    int i = 0;
    for (int num = 0; num < m + 1; num++) {
        for (int j = 0; j < counter[num]; j++, i++) {
            nums[i] = num;
        }
    }
    // 4. 释放内存
    free(counter);
}
```

#### 4.1.3 适用场景

适用于量大但范围小（$m$ 较小）的整数排序。

#### 4.1.4 复杂度分析

* 时间：$O(n + m)$。
* 空间：$O(m)$。
* 稳定性：稳定。

### 4.2 基数排序（Radix Sort）

#### 4.2.1 算法原理

将整数按位数切割成不同的数字，然后按每个位数分别排序。

#### 4.2.2 LSD 与 MSD

* **LSD (Least Significant Digit)**：从低位到高位排序。
* **MSD (Most Significant Digit)**：从高位到低位排序（需递归）。

#### 4.2.3 算法实现

通常每一位的排序使用**计数排序**作为子过程。下面的实现要求元素均为非负整数。

```c
/* 获取元素 num 的第 k 位，其中 exp = 10^(k-1) */
int digit(int num, int exp) {
    // 传入 exp 而非 k 可以避免在此重复执行昂贵的次方计算
    return (num / exp) % 10;
}

/* 计数排序（根据 nums 第 k 位排序） */
void countingSortDigit(int nums[], int size, int exp) {
    // 十进制的位范围为 0~9 ，因此需要长度为 10 的桶数组
    int *counter = (int *)malloc((sizeof(int) * 10));
    memset(counter, 0, sizeof(int) * 10); // 初始化为 0
    // 统计 0~9 各数字的出现次数
    for (int i = 0; i < size; i++) {
        // 获取 nums[i] 第 k 位，记为 d
        int d = digit(nums[i], exp);
        // 统计数字 d 的出现次数
        counter[d]++;
    }
    // 求前缀和，将“出现个数”转换为“数组索引”
    for (int i = 1; i < 10; i++) {
        counter[i] += counter[i - 1];
    }
    // 倒序遍历，根据桶内统计结果，将各元素填入 res
    int *res = (int *)malloc(sizeof(int) * size);
    for (int i = size - 1; i >= 0; i--) {
        int d = digit(nums[i], exp);
        int j = counter[d] - 1; // 获取 d 在数组中的索引 j
        res[j] = nums[i];       // 将当前元素填入索引 j
        counter[d]--;           // 将 d 的数量减 1
    }
    // 使用结果覆盖原数组 nums
    for (int i = 0; i < size; i++) {
        nums[i] = res[i];
    }
    // 释放内存
    free(res);
    free(counter);
}

/* 基数排序 */
void radixSort(int nums[], int size) {
    // 获取数组的最大元素，用于判断最大位数
    int max = INT32_MIN;
    for (int i = 0; i < size; i++) {
        if (nums[i] > max) {
            max = nums[i];
        }
    }
    // 按照从低位到高位的顺序遍历
    for (int exp = 1; max >= exp; exp *= 10)
        // 对数组元素的第 k 位执行计数排序
        // k = 1 -> exp = 1
        // k = 2 -> exp = 10
        // 即 exp = 10^(k-1)
        countingSortDigit(nums, size, exp);
}
```

#### 4.2.4 复杂度分析

* 时间：$O(k(n+b))$，其中 $k$ 是最大值的位数，$b$ 是进制（上面的实现中 $b = 10$）。
* 稳定性：稳定。

### 4.3 桶排序（Bucket Sort）

#### 4.3.1 算法原理

将数据分发到有限数量的桶里。每个桶再分别排序（通常使用插入排序）。

#### 4.3.2 算法实现

映射函数 $f(x)$ 决定放入哪个桶。下面的实现要求元素在 $[0, 1)$ 内，取 $f(x) = \lfloor kx \rfloor$，桶内用标准库的 `qsort` 排序。

```c
static int cmp_float(const void *a, const void *b) {
    float x = *(const float *)a;
    float y = *(const float *)b;
    return (x > y) - (x < y);
}

/* 桶排序 */
void bucketSort(float nums[], int n) {
    int k = n / 2;
    if (k < 1) {
        k = 1;
    }
    int *sizes = malloc(k * sizeof(int));          // 记录每个桶的大小
    float **buckets = malloc(k * sizeof(float *)); // 动态数组的数组（桶）
    // 为每个桶预分配足够的空间
    for (int i = 0; i < k; ++i) {
        buckets[i] = (float *)malloc(n * sizeof(float));
        sizes[i] = 0;
    }
    // 1. 将数组元素分配到各个桶中
    for (int i = 0; i < n; ++i) {
        int idx = (int)(nums[i] * k);
        if (idx >= k) {
            idx = k - 1;
        }
        buckets[idx][sizes[idx]++] = nums[i];
    }
    // 2. 对各个桶执行排序
    for (int i = 0; i < k; ++i) {
        qsort(buckets[i], sizes[i], sizeof(float), cmp_float);
    }
    // 3. 合并排序后的桶
    int idx = 0;
    for (int i = 0; i < k; ++i) {
        for (int j = 0; j < sizes[i]; ++j) {
            nums[idx++] = buckets[i][j];
        }
        // 释放内存
        free(buckets[i]);
    }
    free(buckets);
    free(sizes);
}
```

#### 4.3.3 复杂度分析

* 时间：如果数据均匀分布，平均 $O(n)$。最坏情况（所有数据进一个桶）退化为桶内排序算法的复杂度。
* 空间：$O(n+k)$。上面的实现为简单起见给每个桶都预分配了 $n$ 个元素的空间，实际占用 $O(nk)$。

#### 4.3.4 与其他排序的结合

常用于浮点数排序或外部排序的预处理。

## 5. 排序算法的理论分析

### 5.1 比较排序的下界

在基于比较的排序模型（Comparison Model）中，算法只能通过元素间的相对大小比较（如 $a_i \le a_j$ 或 $a_i > a_j$）获取信息，不能直接检查键的位模式或数字值。

#### 5.1.1 决策树模型

任何基于比较的排序算法都可以形式化为一棵**二叉决策树 (Decision Tree)**：
1. **内部节点**：代表一次比较操作 $a_i \le a_j$。比较的两个可能结果对应左分支与右分支。
2. **叶节点**：代表一种唯一的排列置换结果 $\pi = (p_1, p_2, \dots, p_n)$，表示输入元素按此置换重排后即为有序序列。
3. **执行路径**：对于任意特定的输入序列，算法从决策树的根节点出发，根据每次比较的结果选择分支下行，最终到达某个叶节点。从根到该叶节点的路径长度，即为算法在该输入上执行的比较次数。

#### 5.1.2 信息论与叶节点数约束

对于包含 $n$ 个互异元素的序列，可能出现的初始排列一共有 $n!$ 种。一个正确的排序算法必须能够正确区分每一种可能的初始排列，因此决策树中可达叶节点的数量 $L$ 必须至少等于所有可能排列的总数：
$$L \ge n!$$

#### 5.1.3 下界证明

高度为 $h$ 的二叉树最多只能拥有 $2^h$ 个叶节点。因此必须满足：
$$2^h \ge L \ge n!$$
两边取以 2 为底的对数，可得最坏情况下的比较次数 $h$ 必须满足：
$$h \ge \log_2(n!)$$

根据斯特林近似公式（Stirling's Approximation）：
$$n! = \sqrt{2\pi n} \left(\frac{n}{e}\right)^n \left(1 + O\left(\frac{1}{n}\right)\right)$$
取对数展开：
$$\log_2(n!) = \sum_{i=1}^{n} \log_2 i \ge \sum_{i=\lceil n/2 \rceil}^{n} \log_2 i \ge \frac{n}{2} \log_2\left(\frac{n}{2}\right) = \frac{n}{2} (\log_2 n - 1) = \Omega(n \log n)$$

**定理**：任何基于比较的排序算法在最坏情况下都需要进行 $\Omega(n \log n)$ 次比较。即使允许三向比较（$<, =, >$ 分别对应三叉树分支），三叉树的高度仍受限于 $3^h \ge n! \implies h \ge \log_3(n!) = \frac{\log_2(n!)}{\log_2 3} = \Omega(n \log n)$。因此，归并排序与堆排序在渐近意义下已经达到了比较排序的最优理论下界。

### 5.2 排序算法的稳定性分析

排序算法的**稳定性 (Stability)** 是指：如果待排序序列中存在两个相等的键 $A$ 和 $B$，且在原序列中 $A$ 位于 $B$ 之前，那么排序完成后 $A$ 依然必须位于 $B$ 之前。

1. **为什么稳定性至关重要**：
   - **多关键字复合排序**：在实际业务中经常需要按多个维度依次排序（例如“先按部门编号升序排列，部门相同的按工龄降序排列”）。如果使用的排序算法是稳定的，我们只需先按次要关键字（工龄）排序，再对结果按主要关键字（部门）进行稳定排序，后一次排序不会破坏前一次排序的相对有序性；若算法不稳定，则前一次排序的结果会被打乱。
   - **基数排序的基础依赖**：LSD（低位优先）基数排序必须依赖各轮计数排序的严格稳定性，否则高位有序后低位的相对次序被打乱，整个算法将完全失效。
2. **算法不稳定性的根源剖析**：
   - **选择排序的不稳定性**：选择排序每轮从无序区间选出极值与区间首元素交换，这种“长距离跨越交换”极易打破相等元素的相对次序。例如序列 `[5a, 5b, 2]`，第一轮选择最小元素 `2` 与首元素 `5a` 交换，得到 `[2, 5b, 5a]`，原本在前的 `5a` 被排到了 `5b` 的后面。
   - **快速排序的不稳定性**：在双指针扫描分区或 Lomuto 分区中，为了将元素划分到轴点两侧，跨区域的元素交换不考虑原有的前后位置关系，可能将靠前的相等元素直接扔到靠后相等元素的右侧。
   - **堆排序的不稳定性**：完全二叉树的父子节点索引关系为 $2i+1$，在自顶向下建堆和弹出堆顶下沉调整时，父节点与孩子节点的大跨度交换会直接破坏同层及跨层同值结点的先后顺序。

### 5.3 自适应排序与有序性度量

经典的时间复杂度往往只关注输入规模 $n$。然而在现实工程中，许多输入序列已经具备一定程度的有序性。**自适应排序 (Adaptive Sort)** 指算法能自动感知输入的局部或全局有序性，并在数据近乎有序时自动降级到更低的运行时间（如接近 $O(n)$）。

度量序列预排序程度（Presortedness）的经典指标包括：
- **逆序对总数 (Inversions)**：
  $$I = \#\{(i, j) \mid i < j \land A[i] > A[j]\}$$
  完全有序时 $I = 0$，完全逆序时 $I = \frac{n(n-1)}{2}$。
- **插入排序的自适应性**：
  直接插入排序在将第 $i$ 个元素向前插入时，其内循环移动的次数严格等于当前元素前面的逆序对数。因此，插入排序的总运行时间为 $\Theta(n + I)$。当数据已基本有序（$I = O(n)$）时，插入排序的运行时间为严格的线性时间 $\Theta(n)$，表现远优于快速排序。
- **游程数量 (Runs)**：
  连续非递减或非递增的子序列段数。现代工业级排序（如 Timsort）正是通过探测自然游程来实现高效自适应的。

### 5.4 排序算法的实际性能比较

渐近复杂度相同的算法（如快速排序、堆排序、归并排序均为 $O(n \log n)$），在现代计算机体系结构上的实测性能往往相差数倍。这种差距源于硬件缓存与指令流水线的交互：

1. **CPU 缓存局部性（Cache Locality）**：
   - **快速排序（空间局部性极佳）**：双指针连续向中间扫描，访问的内存地址严格相邻。这极大迎合了现代 CPU 的缓存行预取（Cache Line Prefetching），缓存命中率高，且内循环指令极为精简。
   - **堆排序（缓存局部性差）**：堆排序在数组中按父子节点访问，索引跨度呈 $2i+1$ 指数倍跳跃。当数组规模超出 CPU L3 缓存大小时，每次堆下沉比较几乎都会引发一次昂贵的 Cache Miss 与内存总线等待，因此其实测速度通常只有快排的 $1/3 \sim 1/2$。
2. **辅助内存开销与带宽**：
   - 归并排序在合并阶段需要额外的临时内存数组进行双向搬运，频繁的内存分配与额外数据复制加重了内存总线带宽负担；但在单链表排序中，归并排序无需额外内存且无需随机寻址，成为链表排序的首选。

## 6. 排序算法的应用与变种

### 6.1 外部排序

当待排序的数据量极大（如数十吉字节甚至太字节）、无法全部装入计算机内存时，必须借助外存（硬盘/SSD）进行**外部排序 (External Sorting)**。外部排序的核心矛盾是外存 I/O 的访问延迟远高于内存计算延迟。

#### 6.1.1 多路归并 (Multi-way Merge)

典型的外部排序分为两个阶段：
1. **生成初始顺串（Run Generation）**：将外存文件分块读入内存（每块大小不超过可用内存容量 $M$），在内存中使用高效内部排序排好后写回外存，形成若干有序段（称为**顺串 / Runs**）。
2. **多路归并（Multi-way Merge）**：若采用两两归并，归并趟数过多会导致重复读写外存。工程上采用 $k$ 路归并：在内存中建立一个大小为 $k$ 的**败者树 (Loser Tree)** 或最小堆，每次从 $k$ 个外存顺串的缓冲区中读取最小元素输出，使归并趟数降低至：
   $$S = \lceil \log_k m \rceil$$
   （其中 $m$ 为初始顺串总数），从而成倍减少整个过程的外存 I/O 遍数。

#### 6.1.2 置换选择 (Replacement Selection)

为了进一步减少外存归并趟数，可以在内存中使用容量为 $M$ 的最小堆执行**置换选择排序 (Replacement Selection)**：
- 只要从外存读入的新元素不小于刚刚输出到当前顺串的最小值，就可以将其加入堆中继续生成当前顺串；
- 只有小于当前顺串输出值的元素才被冻结、留给下一个顺串。
- 数学分析表明，在随机输入序列下，置换选择算法生成的初始顺串平均长度可达 **$2M$**（两倍内存容量），使初始顺串总数减半，显著降低后续多路归并的树高。

### 6.2 字符串排序

对大规模字符串序列排序时，若按常规比较排序每次调用 `strcmp`，每次比较可能都需要从头比对多个公共前缀字符，导致总时间复杂度恶化为 $O(L \cdot n \log n)$（其中 $L$ 为字符串最大长度）。

#### 6.2.1 三向切分字符串快速排序

**三向切分字符串快速排序（Bentley-Sedgewick 算法）** 将快速排序与基数排序的思想完美融合：
- 在当前递归阶段，算法只比较所有字符串在第 $d$ 个字符位置上的字符值（设为基准字符 $v$）；
- 将字符串数组划分为三个连续子区间：
  1. 第 $d$ 个字符**小于** $v$ 的字符串集合（字符指针保持在 $d$ 递归）；
  2. 第 $d$ 个字符**等于** $v$ 的字符串集合（因为该位字符均相同，后续只需向右深入到第 $d+1$ 位字符递归）；
  3. 第 $d$ 个字符**大于** $v$ 的字符串集合（字符指针保持在 $d$ 递归）。
- 该算法不需要分配额外的基数计数桶，完全就地分区，尤其擅长处理含有大量公共前缀的长字符串。

#### 6.2.2 高位优先 (MSD) 与低位优先 (LSD) 字符串排序

- **LSD（低位优先）**：从最右侧（最低位）字符开始，从右向左依次对每一位进行稳定的计数排序。适合所有字符串长度完全一致的场景（如定长车牌号、固定哈希摘要），时间复杂度为严格的 $O(W \cdot n)$。
- **MSD（高位优先）**：从最左侧（最高位）字符开始分桶，类似前缀树递归展开。适合随机且长度差异大的文本序列；但在递归到小规模子集时存在桶开销膨胀问题，实际中通常在子集长度小于阈值时切换为插入排序。

### 6.3 部分排序问题

在很多实际应用中，并不需要将全部元素完全排好序，只需要获取极值或前几名。

#### 6.3.1 Top-K 问题

在海量数据（$n$ 极大）中找出最大的 $K$ 个元素（$K \ll n$）：
1. 在内存中建立一个容量为 $K$ 的**小根堆**；
2. 先将前 $K$ 个元素放入堆中；
3. 顺序遍历后续的 $n - K$ 个元素：若当前元素大于堆顶元素，则弹出堆顶并将新元素压入堆中执行下沉；
4. 遍历结束时，堆中的 $K$ 个元素即为全局最大的 $K$ 个元素。
- **代价分析**：时间复杂度仅为 $O(n \log K)$，空间复杂度仅为 $O(K)$，无需将整个数据集一次性载入内存。

#### 6.3.2 第 K 小元素与快速选择 (Quickselect)

若需找出第 $K$ 小的单一元素，可以使用基于快排分区思想的 **快速选择算法 (Quickselect)**：
- 选择轴点执行一次标准分区，假设轴点最终落在了索引 $p$ 处；
- 若 $p == K$，则目标元素已命中，直接返回；
- 若 $p > K$，说明第 $K$ 小元素必定落在左半部分，**只递归左半区间**；
- 若 $p < K$，说明第 $K$ 小元素必定落在右半部分，**只递归右半区间**。
- **代价分析**：与快速排序需要双侧递归不同，快速选择每次抛弃一半搜索空间，总期望耗时为几何级数 $n + n/2 + n/4 + \dots = O(n)$，平均时间复杂度达到线性时间。最坏情况下通过中位数的中位数（Median-of-Medians / BFPRT）算法可保证最坏情况仍为 $O(n)$。

### 6.4 动态排序问题

#### 6.4.1 动态排序与数据结构

若待处理的数据集是动态变化的（不断有新元素插入或旧元素删除），而系统需要随时查询当前序列的中位数、第 $K$ 极值或区间有序列表，任何离线数组排序每次维护都要花费 $O(n)$ 或 $O(n \log n)$，代价过于高昂。

此时应采用动态有序数据结构：
- **平衡二叉搜索树（AVL 树、红黑树）**：每次插入、删除与查询均为严格的 $O(\log n)$，中序遍历可在 $O(n)$ 时间内有序输出；
- **跳表 (SkipList)**：基于概率分层的有序链表，以常数更小的空间与代码复杂度提供期望 $O(\log n)$ 的插入、删除与范围查找能力；
- **对顶堆（最大堆 + 最小堆）**：维护两个平衡大小的堆，可支持 $O(\log n)$ 插入与 $O(1)$ 获取动态数据流的中位数。

## 7. 实际应用与优化

### 7.1 混合排序算法 (Hybrid Sorts)

纯粹的经典算法往往各有其短板。工业级运行库普遍采用多种基础排序优势互补的**混合排序算法**。

#### 7.1.1 Introsort (内省排序)

由 David Musser 于 1997 年提出，是 C++ 标准库 `std::sort` 的核心底层实现架构：
1. **快排为骨架**：初始阶段以高效的快速排序开展处理，充分享受 CPU 缓存命中率与低常数优势；
2. **堆排为兜底**：跟踪递归调用深度。一旦递归深度超过 $2 \lfloor \log_2 n \rfloor$（说明分区严重倾斜，继续递归将退化为 $\Theta(n^2)$），立即对当前子序列切换为**堆排序**，从而从数学上强制锁定最坏时间复杂度为 $O(n \log n)$；
3. **插入排序收尾**：当快速排序分割出的子区间规模小于阈值（通常为 16）时，不再进行递归，直接返回；在整趟递归退出后，对近乎全局有序的整个数组执行一次自适应的直接插入排序，消除微小子序列频繁递归建栈的开销。

#### 7.1.2 Timsort

由 Tim Peters 于 2002 年为 Python 设计，目前是 Python `list.sort()` 与 Java `Arrays.sort(Object[])` 的工业级默认排序算法：
1. **自然游程识别**：扫描输入数据，自动识别出天然存在的连续非递减或严格递减片段（严格递减片段原地就地翻转为递增），称为**自然游程 (Natural Run)**；
2. **二分插入补齐**：若某个 run 的长度小于设定阈值 `minrun`（通常在 32 到 64 之间），利用二分插入排序将后续元素扩充进来，快速构成一个规范的小有序块；
3. **归并栈与飞奔模式 (Galloping Mode)**：将识别出的 runs 地址与长度压入栈中，通过类似斐波那契数列的不等式约束维护栈内 run 长度的平衡；合并两个相邻 run 时，先通过二分查找跳过无需变动的前缀与后缀，并在连续命中的段落开启飞奔模式（指数跨步搜索），极大降低现实数据中长有序片段的合并比较代价，做到最坏 $O(n \log n)$、最好 $O(n)$ 且严格稳定。

### 7.2 并行排序

随着多核处理器与 GPU 异构计算的普及，**并行排序 (Parallel Sorting)** 成为大规模计算的重要基石：

- **双调排序 (Bitonic Sort)**：
  - 基于比较器网络（Comparator Network）的经典并行排序算法。其比较与交换序列完全是预先确定的（Data-Independent），不依赖运行时的元素内容，完全排除了 CPU 分支预测失败的惩罚。
  - 对于 $n = 2^k$ 个元素，双调排序网络的深度仅为 $O(\log^2 n)$，非常适合在 GPU、FPGA 和 SIMD 向量化指令集上进行极高吞吐的并发硬件流水线实现。
- **并行归并与并行快速排序**：
  - **任务级并行**：在快速排序中，主线程完成第一轮分区后，生成的左右两个独立子区间完全不存在共享数据竞争，可直接分发给不同 CPU 核心的线程并行递归；
  - **数据级并行**：在归并阶段，通过二分查找找到一个有序序列在中点处的分割值在另一个序列中的对应投影点，将两路归并任务正交分解为两个可独立并发执行的子合并任务，使得归并过程本身也能充分利用多核并行算力。

实现稳定的归并排序，排序对象和接口如下：

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

typedef struct {
    int64_t key;
    uint64_t payload;
} SortRecord;

bool stable_merge_sort_records(
    SortRecord *items,
    size_t count
);
```

要求：

1. 排序后 `key` 非递减；当两个键相等时，`payload` 的相对顺序必须与输入一致。
2. `count == 0` 时允许 `items == NULL`；非空输入必须有效。辅助空间分配失败或大小计算溢出时返回 `false`，原数组保持不变。
3. 比较键时只能使用关系运算，不能通过相减得到比较结果，以正确处理 `INT64_MIN` 和 `INT64_MAX`。
4. 实现的时间复杂度为 $O(n\log n)$，额外空间复杂度为 $O(n)$；说明合并时为何在相等键下优先选取左侧记录才能保持稳定性。
5. 使用空数组、单个记录、全部键相等、已经有序、逆序以及包含两个极端键值的输入进行测试。

</Exercise>

外部排序（多路平衡归并与败者树框架）：
