# 9.2 ASCII 码

::: concept ascii-definition title="ASCII 的定义"

ASCII (American Standard Code for Information Interchange) 是一种使用 7 位表示 128 个字符的字符编码标准，把字母、数字、标点符号和控制码映射为数字形式。这种标准化使不同制造商生产的计算机、终端、打印机及其他外围设备能够可靠地交换和处理文本信息。

:::

## 1. 为什么 C 教程要讲 ASCII

::: concept c-charset-guarantees title="C 标准对字符集的保证边界"

C 标准不要求源字符集或执行字符集就是 ASCII，两者的具体内容都由实现定义。标准规定它们都必须包含基本字符集：大小写拉丁字母、十进制数字、一批图形字符、空格，以及若干控制字符。执行字符集中这些字符的具体编码值由实现定义。标准保证十进制数字字符的编码值连续递增，且字符常量和字符串字面量会在翻译阶段映射到执行字符集。

:::

```c
#include <stdio.h>

int main(void) {
    printf("%d\n", '9' - '0');
    return 0;
}
```

输出：

::: terminal

9

:::

::: generate ascii-vs-c-charset kind=explanation concepts=ascii-definition,c-charset-guarantees

面向刚开始学习 C 的读者，用 ASCII 建立“字符可以映射到整数编码”的直观模型，同时划清可移植边界：`'9' - '0'` 得到 `9`，依据的是标准对十进制数字字符连续递增的保证；ASCII 中 `'0'` 的编码值 `0x30` 只是常见实现上的具体数值。说明可移植代码为什么应当依赖标准保证，把 ASCII 码值只当作常见实现上的参考。

:::

## 2. 字符集结构

ASCII 的 128 个字符分为控制字符 (Control Character) 和可打印字符 (Printable Character) 两类。

控制字符的编码值为 0（0x00）至 31（0x1F），以及 127（0x7F）。它们在屏幕上不显示，用途是控制数据传输和设备操作（如打印机、终端），或者格式化文本。常见的控制字符有：

- `NUL`（0x00）：空字符
- `SOH`（0x01）：标题开始
- `ETX`（0x03）：正文结束
- `BEL`（0x07）：响铃
- `BS`（0x08）：退格
- `HT`（0x09）：水平制表符 (Tab)
- `LF`（0x0A）：换行 (Line Feed)
- `CR`（0x0D）：回车 (Carriage Return)
- `ESC`（0x1B）：转义
- `DEL`（0x7F）：删除

可打印字符的编码值为 32（0x20）至 126（0x7E），可以显示在屏幕或纸张上，包括：

- 空格（0x20）
- 数字 `0`（0x30）至 `9`（0x39）
- 大写拉丁字母 `A`（0x41）至 `Z`（0x5A）
- 小写拉丁字母 `a`（0x61）至 `z`（0x7A）
- 其余标点和符号，例如 `! " # $ % & ' ( ) * + , - . /` 和 `{ | } ~`

## 3. 与转义字符的关系

::: concept escape-and-null-char title="转义字符与空字符"

写转义字符时，程序表达的是执行字符集中的字符意图，具体编码值由实现决定。例如 `'\n'` 表示执行字符集中的换行控制字符，通常平台上它对应 `0x0A`；可移植代码应当直接写转义字符。标准要求基本执行字符集中存在一个所有位都为 `0` 的空字符（写为 `'\0'`），用于终止字符串。

:::

```c
char end = '\0';
char newline = '\n';
```

::: generate escape-sequences-intent kind=explanation concepts=escape-and-null-char,c-charset-guarantees

面向刚开始学习 C 的读者，解释为什么可移植代码应使用转义字符本身表达意图，不要在源码里写死编码值；说明 `'\0'` 作为字符串终止符的角色——后续学习字符串库时会反复遇到它，但本节不要展开字符串库细节。

:::

## 5. 习题

<Exercise id="10914" :d="2" :w="2">

下面的程序用 `%d` 打印字符常量（按整数输出），用 `%c` 打印整数运算的结果（按字符输出）。先写出四行输出，不要编译；再回答后面的问题。

```c
#include <stdio.h>

int main(void) {
    printf("%d %d %d\n", 'A', '0', ' ');
    printf("%d %d\n", 'a' - 'A', '9' - '0');
    printf("%d %d %d\n", '\x41' == 'A', '\n', '\0');
    printf("%c%c%c\n", 'A' + 2, '0' + 7, 'z' - 1);
    return 0;
}
```

本机用 `-std=c17 -Wall -Wextra` 编译，输出为：

```text
65 48 32
32 9
1 10 0
C7y
```

1. 第二行开头的 `32` 来自 `'a' - 'A'`，末尾的 `9` 来自 `'9' - '0'`。哪一个结果可以依赖标准？依据是什么？另一个为什么不能？
2. 第三行的 `1` 是标准保证的结果吗？`'\x41'` 与 `'A'` 各自表达什么？在 `'A'` 的编码值不是 0x41 的执行字符集上，这一行还会输出 `1` 吗？
3. 第三行末两项 `10` 和 `0` 来自 `'\n'` 与 `'\0'`。`'\0'` 在所有符合标准的实现上都等于 0，`'\n'` 的数值却由实现决定。要表示一个换行，该写 `'\n'` 还是写 `10`？
4. 第四行用到了 `'A'`～`'Z'`、`'0'`～`'9'`、`'a'`～`'z'` 各自连续这个前提。标准对这三段字符分别作了什么保证？要写出不依赖这个前提的版本，可以怎么做？

</Exercise>

写一个打印 ASCII 表的程序，逐字符输出的函数为：

```c
void print_ascii_row(unsigned char c);
```

每行依次给出：8 位二进制（高 4 位与低 4 位之间空一格）、三位八进制、三位十进制、`0x` 加两位大写十六进制、字符本身。字符一栏的写法：

- `0x20` 写 `[SPACE]`，`0x7F` 写 `[DEL]`；
- `0x00`～`0x1F` 中认出 `NUL`、`BEL`、`BS`、`HT`、`LF`、`CR`、`ESC`，写成 `[NUL]` 这样的缩写，其余统一写 `[control]`；
- `0x21`～`0x7E` 直接输出字符。

再统计 `0x00`～`0x7F` 中 control、space、digit、upper、lower、punct 各有几个，输出可打印字符的总数，最后一行原样输出 `0x20`～`0x7E` 的全部 95 个字符。分类的分界按正文第 2 节：control 是 `0x00`～`0x1F` 与 `0x7F`，space 只有 `0x20`，digit、upper、lower 分别取 `0x30`～`0x39`、`0x41`～`0x5A`、`0x61`～`0x7A`，剩下的可打印字符都算 punct。

下面的程序想按 16 字节一行打印任意字节的十六进制和可打印字符，却把一段含空字符的数据当成了字符串。先按原样编译运行。

```c
#include <stdio.h>

static int is_printable(char c) {
    return c >= 0x20 && c <= 0x7F;
}

static size_t byte_count(const char *data) {
    size_t n = 0;

    while (data[n] != '\0') {
        n++;
    }
    return n;
}

static void hexdump(const char *data) {
    size_t n = byte_count(data);

    for (size_t i = 0; i < n; i += 16) {
        printf("%04X  ", (unsigned)i);
        for (size_t k = 0; k < 16; k++) {
            if (i + k < n) {
                printf("%02X ", data[i + k]);
            } else {
                printf("   ");
            }
            if (k == 7) {
                printf(" ");
            }
        }
        printf(" |");
        for (size_t k = 0; k < 16 && i + k < n; k++) {
            printf("%c", is_printable(data[i + k]) ? data[i + k] : '.');
        }
        printf("|\n");
    }
}

int main(void) {
    const char sample[] = {'A', 'S', 'C', 'I', 'I', ' ', 0x00, 0x1F,
                           0x7F, (char)0xE4, 'o', 'k'};

    hexdump(sample);
    return 0;
}
```

（`%02X` 表示按大写十六进制输出、至少两位、不足两位时在左边补 0。）

(1) _[2.1]_ 用 `-std=c17 -Wall -Wextra` 编译并运行，记下诊断与输出（本机字节栏只有 `41 53 43 49 49 20` 六项，右栏是 `|ASCII |`）。`sample` 有 12 个字节，为什么只打印出 6 个？`hexdump` 的样子不变时，调用处怎么写都解决不了这个问题，原因是什么？

(2) _[5.3]_ 只改一半的版本最容易骗人。给 `hexdump` 加一个 `size_t n` 参数并照传 `sizeof sample`，`byte_count` 删掉，其余不动。本机运行后字节栏变成：

```text
41 53 43 49 49 20 00 1F 7F FFFFFFE4 6F 6B
```

`0xE4` 一项多出了四个 `F`，右栏里 `0x7F` 也被原样打了出来。逐条说明这两处输出分别由哪个缺陷造成，以及为什么「把 `is_printable` 的参数改成 `unsigned char`」并不能自动修好后一处。再把下面这个循环单独编译运行，解释它为什么停不下来，`-Wall -Wextra` 那条「比较恒为真」的警告指的是什么；加上 `-funsigned-char` 编译，循环能否结束：

```c
for (char c = 0; c < 128; c++) {
    putchar(is_printable(c) ? c : '.');
}
```
