# 2.3 声明和初始化

## 1. 声明 (Declaration)

声明是一种引入一个或多个标识符 (Identifier) 到程序中，并指定其含义及属性的 C 语言构造。
最简单的声明包括两部分：**类型说明符 (Type Specifier)** 和**标识符**。

```c
int a;  // "int"是类型说明符，"a"是标识符
```

相同类型的对象可以在一起声明：`类型说明符 标识符 1, 标识符 2, 标识符 3, ... , 标识符 n;`  
但工程实践中不推荐这种做法，尤其是声明中包含指针或复杂初始化式时。

```c
int a, b, c; // 声明三个 int 类型的对象
```

### 1.1 多声明符的顺序与可见性

当一条声明语句中包含多个声明符时，编译器按**从左到右**的顺序依次处理每个声明符。一个标识符在它自身的声明符处理完毕后即进入作用域，因此排在后面的初始化式可以使用前面已经声明的对象，但排在前面的初始化式不能引用后面尚未声明的名字：

```c
int a = 3, b = a + 1; /* 合法：初始化 b 时 a 已经可见 */
/* int c = d, d = 1; */ /* 编译错误：初始化 c 时 d 尚未声明 */
```

此外，修饰符（例如第 8 章将介绍的指针星号 `*`）只作用于紧随其后的单个声明符，而不是整行的类型说明符。每行只声明一个对象能够从排版上杜绝此类歧义。

## 2. 初始化 (Initialization)

对象声明可以通过名为**初始化**的步骤提供其初始值。

```c
int a = 3;
int b = {3}; // 可选地用花括号环绕
```

此后 `a` 和 `b` 的值都为 3。标量对象的花括号初始化器中还可以保留一个尾随逗号（即 `int d = {3,};`），其语义与 `{3}` 完全相同，但花括号内不能提供超过一个初始值（如 `{3, 4}` 违反约束）。

### 2.1 初始化与赋值的区别

初始化与赋值在语法上都使用 `=`，但发生时机和语法规则不同：

1. **初始化**发生在对象创建的同时，语法上允许使用花括号列表（如 `int x = {3};`）。
2. **赋值**发生在对象已经存在之后，是一个表达式运算，右侧必须是普通表达式，不能直接写花括号初始化器列表（如 `x = {3};` 无法通过编译）。

此外，在同一条声明语句中，`=` 只对紧邻它的那个声明符生效：

```c
int a = 3, b, c;           /* 只有 a 被初始化为 3，b 和 c 未初始化 */
int x = 3, y = 4, z = 5;   /* x、y、z 均被显式初始化 */
```

### 2.2 空初始化器 `{}` 与零初始化（C23）

C23 引入了统一的空花括号初始化器 `{}`，用于将任意可初始化的对象（包括标量、数组、结构体等）执行**零初始化 (Zero Initialization)**：整数对象初始化为 `0`，浮点对象初始化为 `0.0`，指针对象初始化为空指针。

```c
int count = {};      /* C23 起合法：count 被零初始化为 0 */
double ratio = {};   /* C23 起合法：ratio 被零初始化为 0.0 */
```

在 C17 及更早的标准中，ISO C 禁止空的初始化器花括号（开启 `-pedantic-errors` 会报错），标量对象应直接写作 `int count = 0;`，聚合类型通常写作 `{0}`。

### 2.3 未初始化对象的风险

在函数体内部声明的普通对象（具有自动存储期，见第 15 章）如果没有显式提供初始化器，其初始值是**不确定的 (Indeterminate)**。在赋予确定值之前读取未初始化的对象（包括诸如 `int self = self;` 这样用自身初始化自身的写法）会触发未定义行为。

::: tip 最佳实践

遵循**声明即初始化**原则：在声明对象的同时给出明确的初始值；若初始值依赖后续计算，也应先初始化为安全的默认值（如 `0`），或将声明推迟到能够直接计算出初值的位置。

:::

<Exercise id="10218" :d="2" :w="2">

下面的声明混用了本页讲过的几种写法。

```c
#include <stdio.h>

int main(void) {
    int a = 3;
    int b = {3};
    int c = (3);
    int d = {3,};
    int e = {3, 4};
    int f = {};

    printf("%d %d %d %d %d %d\n", a, b, c, d, e, f);
    return 0;
}
```

1. 先用 `gcc -std=c17 -Wall -Wextra` 编译，记下警告；再加上 `-pedantic-errors` 编译，记下错误。哪些写法在 C17 下不合法？
2. 在能通过编译的前提下写出输出。`{3,}` 末尾多出的逗号带来了什么？
3. 把 `int a = 3, b, c;` 与 `int a = 3, b = 4, c = 5;` 各写一遍，指出其中哪些对象得到了初始值。
4. 初始化不是赋值：写 `int x = {3};` 合法，而先声明再写 `x = {3};` 不合法。编译核对后者的报错，并说明这两种写法在语义上的区别（初始化发生在对象创建时，赋值发生在对象已经存在之后）。

验收：不加 `-pedantic-errors` 时只出现一条 `excess elements in scalar initializer` 警告，输出为 `3 3 3 3 3 0`；加上 `-pedantic-errors` 后，`{3, 4}` 与 `{}` 各报一条 error；`x = {3};` 的报错是 `expected expression before '{' token`。

<Exercise id="10219" :d="3" :w="3">

同一条声明里的多个声明符按从左到右的顺序处理，初始化式只能使用已经处理过的名字。编译下面的程序。

```c
#include <stdio.h>

int main(void) {
    int a = 3, b = a + 1;
    int *p = &a, q = b * 2;

    printf("%d %d %d %d\n", a, b, (int)sizeof *p, q);
    return 0;
}
```

1. 写出输出。`p` 和 `q` 是同一类型吗？`sizeof *p` 与 `sizeof q` 分别是多少？
2. 单独编译下面的函数，抄下 error 并解释：为什么初始化式里看不到同一行后面才声明的 `base`。

   ```c
   int main(void) {
       int doubled = base * 2, base = 10;
       return doubled + base;
   }
   ```
3. 把 `int a = b, b = 1;` 单独编译，抄下 error。再把它拆成两行、调整顺序，使程序合法并输出 `a = 1, b = 1`。
4. 把 `int *p = &a, q = b * 2;` 拆成两行分别声明。说明为什么本页不推荐 `int *p, q;` 这类写法：星号只修饰紧跟其后的那个声明符。
5. 下面的函数每次调用都返回 1：

   ```c
   int next_id(void) {
       int id = 0;
       id = id + 1;
       return id;
   }
   ```

   调用三次并打印，确认结果。把 `int id = 0;` 改成 `static int id = 0;` 后重新运行，结果变为 1、2、3。用初始化的发生时机解释这一差别。这一问涉及存储期，属于第 15 章的内容，可以跳过。

验收：第 1 问 `printf` 输出 `3 4 4 8`，其中 8 是 `q` 的值，`sizeof *p` 与 `sizeof q` 都是 4；第 4 问拆开后 `sizeof p` 为 8、`sizeof q` 为 4；第 5 问前一种写法三次都打印 1，后一种打印 1、2、3。

</Exercise>

写一个收款程序 `receipt.c`，全部金额用整数分表示，避免浮点误差。

程序里固定以下数据：单价 1250 分，数量 3 件，折扣率 10%，税率 6%（用千分之 60 表示，仍按整数计算）。依次计算小计、折扣、折后金额、税额和应付金额，每项各用一个对象保存，全部在声明处初始化，后续不再出现未初始化的对象。

要求：

1. 每个对象单独一行声明并初始化；唯一的例外是折扣率与税率，要求用 `int discount_rate_percent = {10};` 这种带花括号的写法声明，并在注释里说明花括号在这里起什么作用。
2. 折扣与税额都用整数除法计算，结果四舍五入到分：`(amount * rate + half) / whole` 的形式，除数为 100 或 1000。
3. 用 `gcc -std=c17 -Wall -Wextra -Wconversion` 构建，必须没有任何诊断。
4. 输出五行：`subtotal`、`discount`、`taxable`、`tax`、`payable` 各一行，数值以分为单位。
5. 把数量和单价改成 5 与 725 再运行一次，记录新的结果，并说明换数据时哪些声明需要改、哪些不需要。

验收：第一组数据输出 `subtotal = 3750`、`discount = 375`、`taxable = 3375`、`tax = 203`、`payable = 3578`（税额按四舍五入）；第二组输出 `subtotal = 3625`、`discount = 363`（四舍五入）、`taxable = 3262`、`tax = 196`、`payable = 3458`。
