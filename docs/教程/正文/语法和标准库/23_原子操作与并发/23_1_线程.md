# 23.1 线程

C11 标准引入了线程支持库（`<threads.h>`），提供了标准的多线程编程接口。

## 1. threads.h

### 1.1 线程类型和函数

主要类型：

- `thrd_t`: 线程标识符
- `mtx_t`: 互斥锁
- `cnd_t`: 条件变量
- `tss_t`: 线程局部存储
- `once_flag`: 一次性初始化标记

主要函数：

- `thrd_create()`: 创建线程
- `thrd_join()`: 等待线程结束
- `mtx_init()`: 初始化互斥锁
- `mtx_lock()`: 锁定互斥锁
- `mtx_unlock()`: 解锁互斥锁
- `cnd_signal()`: 发送信号
- `cnd_wait()`: 等待条件变量
- `tss_set()`: 设置线程局部存储
- `tss_get()`: 获取线程局部存储
- `tss_delete()`: 删除线程局部存储

### 1.2 创建线程

使用 `thrd_create` 函数创建新线程：

```c
#include <threads.h>
#include <stdio.h>

int thread_func(void* arg) {
    printf("线程运行中...\n");
    return 0;
}
int main(void) {
    thrd_t thr;
    int result = thrd_create(&thr, thread_func, NULL);
    if (result != thrd_success) {
        printf("创建线程失败\n");
        return 1;
    }
    // 等待线程结束
    thrd_join(thr, NULL);
    return 0;
}
```

输出为：

::: terminal

线程运行中...

:::

### 1.3 互斥锁

保护共享资源：

```c
#include <threads.h>

mtx_t mutex;
int shared_data = 0;

int main(void) {
    // 初始化互斥锁
    if (mtx_init(&mutex, mtx_plain) != thrd_success) {
        return 1;
    }

    // 使用互斥锁
    mtx_lock(&mutex);
    shared_data++; // 临界区
    mtx_unlock(&mutex);

    // 销毁互斥锁
    mtx_destroy(&mutex);
    return 0;
}
```

### 1.4 条件变量

用于线程同步：

```c
#include <threads.h>

mtx_t mutex;
cnd_t cond;
int ready = 0;

int producer(void* arg) {
    mtx_lock(&mutex);
    ready = 1;
    cnd_signal(&cond);
    mtx_unlock(&mutex);
    return 0;
}

int consumer(void* arg) {
    mtx_lock(&mutex);
    while (!ready) {
        cnd_wait(&cond, &mutex);
    }
    mtx_unlock(&mutex);
    return 0;
}
```

### 1.5 线程局部存储

每个线程独有的存储空间：

```c
#include <stdio.h>
#include <stdlib.h>
#include <threads.h>

tss_t key;

void destructor(void* data) {
    free(data);
}

int thread_func(void* arg) {
    int* value = malloc(sizeof(int));
    *value = 42;

    // 设置线程局部存储
    tss_set(key, value);

    // 获取线程局部存储
    int* stored = tss_get(key);
    printf("值：%d\n", *stored);

    return 0;
}

int main(void) {
    // 创建线程局部存储键
    if (tss_create(&key, destructor) != thrd_success) {
        return 1;
    }

    // ... 创建线程等操作 ...

    tss_delete(key);
    return 0;
}
```

### 1.6 一次性初始化

确保初始化代码只执行一次：

```c
#include <stdio.h>
#include <threads.h>

once_flag flag = ONCE_FLAG_INIT;

void init_function(void) {
    // 只执行一次的初始化代码
    printf("初始化...\n");
}

int thread_func(void* arg) {
    call_once(&flag, init_function);
    return 0;
}
```

多个线程调用 `thread_func` 时，`init_function` 只会被调用一次，因此 `初始化...` 只输出一次。

## 2. 返回值和错误处理

`<threads.h>` 中函数的返回值：

- `thrd_success`: 成功
- `thrd_error`: 一般错误
- `thrd_nomem`: 内存不足
- `thrd_timedout`: 超时
- `thrd_busy`: 资源忙

## 3. 其他重要函数

- `thrd_current()`: 获取当前线程标识符
- `thrd_equal()`: 比较两个线程标识符
- `thrd_sleep()`: 线程休眠
- `thrd_yield()`: 让出 CPU 时间片

## 4. 习题

本页的题目围绕线程的创建与回收展开。条件变量和线程局部存储各有专页，这里只用互斥量做最基本的同步。全部题目在 Linux 上用 `gcc -std=c17 -Wall -Wextra` 编译；MinGW 不带 `threads.h`。

### 4.1 巩固

<Exercise id="12305" :d="2" :w="2">

下面的程序创建 4 个线程，每个线程打印自己的编号并返回编号乘 10：

```c
#include <stdio.h>
#include <threads.h>

static int worker(void *arg) {
    thrd_sleep(&(struct timespec){ .tv_nsec = 50000000 }, NULL);
    int id = *(int *)arg;
    printf("worker %d\n", id);
    return id * 10;
}

int main(void) {
    thrd_t t[4];
    int slot = 0;

    for (int i = 0; i < 4; ++i) {
        slot = i;
        thrd_create(&t[i], worker, &slot);
    }
    for (int i = 0; i < 4; ++i) {
        int res = 0;
        thrd_join(t[i], &res);
        printf("t[%d] -> %d\n", i, res);
    }
    return 0;
}
```

要求：

1. 先写出预测的输出，再编译运行。4 行 `worker` 为什么都是同一个编号？`t[0]` 到 `t[3]` 的返回值为什么相同？
2. 修改 `main`，让每个线程拿到自己的编号。验收：`worker 0` 到 `worker 3` 各打印一行（顺序不限），`t[i]` 的返回值为 `i * 10`。只改 `main`，线程函数不动。
3. 去掉线程函数里的 `thrd_sleep`，连跑 5 次，记录 4 行 `worker` 的编号。编号可能重复，也可能各不相同，说明原因。
4. 把线程函数的 `return id * 10;` 换成 `thrd_exit(id * 10);`，其余不动。返回值是否改变？`thrd_exit` 之后的语句还会执行吗？
5. 主线程先用 `thrd_current()` 取得自己的标识符，再在每个线程里调用 `thrd_equal(thrd_current(), main_id)` 并打印结果。验收：主线程打印 1，4 个工作线程都打印 0。标准为什么另外提供 `thrd_equal`，而不要求代码用 `==` 比较两个 `thrd_t`？

验收：第 1 步 4 行都是 `worker 3`、4 个返回值都是 30；第 2 步每个线程打印自己的编号，返回值为 `i * 10`；第 4 步返回值不变；第 5 步主线程为 1、工作线程全为 0。

</Exercise>

### 4.2 编程

<Exercise id="12306" :d="2" :w="2">

下面的程序想用一次性初始化建一张共享表，8 个线程各调用一次 `ensure`：

```c
#include <stdio.h>
#include <threads.h>

static int inited;
static int init_calls;

static void init_table(void) {
    ++init_calls;
    thrd_sleep(&(struct timespec){ .tv_nsec = 100000000 }, NULL);
    inited = 1;
}

static void ensure(void) {
    if (!inited) {
        init_table();
    }
}

static int worker(void *arg) {
    (void)arg;
    ensure();
    return 0;
}

int main(void) {
    thrd_t t[8];

    for (int i = 0; i < 8; ++i) {
        thrd_create(&t[i], worker, NULL);
    }
    for (int i = 0; i < 8; ++i) {
        thrd_join(t[i], NULL);
    }
    printf("init_calls = %d\n", init_calls);
    return 0;
}
```

要求：

1. 连跑 5 次，记录 `init_calls`。8 个线程为什么都进了 `init_table`？
2. 把 `inited` 换成 `atomic_int`，读写改成 `atomic_load` 与 `atomic_store`，再跑 5 次。结果是否改变？原子读写为什么解决不了这个问题？
3. 用 `once_flag` 与 `call_once` 改写 `ensure`，其余不动。验收：`init_calls = 1`。
4. 在 `init_table` 的函数体开头再加一次 `call_once(&flag, init_table)`，用 `timeout 5 ./a.out` 运行，记录退出码。说明程序为什么停在初始化函数里。
5. 把 `call_once` 换成三种手写写法，各跑 5 次并记录 `init_calls`：其一，只把 `inited` 声明为 `atomic_int`，读用 `atomic_load`，写用 `atomic_store`，不加锁；其二，在 `mtx_lock` 之后检查 `inited` 再初始化；其三，在锁外先检查一次，锁内再检查一次（双重检查）。本机第一种为 8，后两种为 1。第一种就是第 2 步的写法。第三种之所以正确，靠的是默认的 `memory_order_seq_cst`：外层那次读到 1 的加载与初始化线程的存储之间存在同步关系，初始化写入因此对它可见。把这几处的内存序都改成 `memory_order_relaxed`，在 `init_table` 里再写一个普通对象 `payload = 42;`，让 `ensure` 的调用者读完 `payload` 再打印。本机仍可能打印 `42`，但这时 `payload` 的读与写已经构成数据竞争，程序行为未定义。

验收：第 1 步 `init_calls = 8`；第 2 步仍为 8；第 3 步为 1；第 5 步第一种为 8，后两种为 1，`relaxed` 版本在本机上看不出错误，能说明它为什么按标准仍然不对即可。

</Exercise>

<Exercise id="12307" :d="4" :w="3" multi>

工作线程睡眠 300 ms 后，把一个受互斥量保护的 `done` 置 1。主线程有三种等待方式：反复调用 `thrd_yield`、反复调用 `thrd_sleep` 睡 10 ms、直接调用 `thrd_join`。

(1) _[2.2]_ 写出前两种写法，用 `clock()` 测 CPU 时间、用 `timespec_get` 测墙钟时间。本机实测 `thrd_yield` 版本墙钟 300 ms、CPU 300 ms，`thrd_sleep` 版本墙钟 302 ms、CPU 0 ms。解释 CPU 时间的差别：`thrd_yield` 只是把时间片让给其他就绪线程，若没有别的可运行线程，调用者立刻被再次调度。

(2) _[3.2]_ 用 `thrd_join` 完成同样的等待，测量 CPU 时间。三种写法都能等到结果，分别适合什么场合？轮询标志的写法里，`done` 为什么必须加锁或声明为原子类型？

(3) _[3.3]_ 在等待循环里调用 `thrd_sleep` 会多出最多 10 ms 的延迟。把睡眠时间改成 100 ms、10 ms、1 ms，记录每周期的唤醒次数和总墙钟时间，说明轮询间隔与响应延迟、CPU 占用之间的取舍。

(4) _[4.3**]_ `thrd_sleep` 在睡眠被信号打断时返回 -1，并通过第二个参数报告剩余时间。用 POSIX 的 `setitimer` 在 100 ms 后发一个 `SIGALRM`，主线程调用 `thrd_sleep` 睡 1 秒：

```c
#define _POSIX_C_SOURCE 200809L
#include <signal.h>
#include <stdio.h>
#include <sys/time.h>
#include <threads.h>
#include <time.h>

static volatile sig_atomic_t hits;

static void on_alarm(int sig) {
    (void)sig;
    ++hits;
}

int main(void) {
    struct sigaction sa = { 0 };
    struct itimerval it = { 0 };
    struct timespec dur = { .tv_sec = 1, .tv_nsec = 0 };
    struct timespec rem = { 0 };
    struct timespec start, end;

    sa.sa_handler = on_alarm;
    sigaction(SIGALRM, &sa, NULL);

    it.it_value.tv_usec = 100000;
    setitimer(ITIMER_REAL, &it, NULL);

    clock_gettime(CLOCK_MONOTONIC, &start);
    int rc = thrd_sleep(&dur, &rem);
    clock_gettime(CLOCK_MONOTONIC, &end);

    long ms = (end.tv_sec - start.tv_sec) * 1000 +
              (end.tv_nsec - start.tv_nsec) / 1000000;
    printf("rc = %d, hits = %d, elapsed = %ld ms, rem = %ld.%09ld\n", rc,
           (int)hits, ms, (long)rem.tv_sec, rem.tv_nsec);
    return 0;
}
```

验收：退出码 0，`rc = -1`，`hits = 1`，`elapsed` 约 100 ms，`rem` 约 0.9 秒。说明想在信号后继续睡完剩下的时间应该怎么写。

</Exercise>

### 4.3 综合与挑战

用递归分治把 1 到 100000 求和：每个线程负责一个区间，区间长度不小于 1000 时把区间对半切开，再创建两个线程分别求和。

```c
typedef struct {

```

(1) _[3.3]_ 实现 `range_sum`，在线程函数内部用 `thrd_create` 创建子线程，并用 `thrd_join` 汇总结果。验收：`sum = 5000050000`。用 `atomic_int` 统计创建过的线程总数（创建后先 `atomic_fetch_add` 再创建），记录这个数。区间阈值取 1000 时是多少？取 10000 时是多少？由此说明线程数量与递归深度的关系。

(2) _[4.4]_ 主线程不等待，直接 `return 0;` 结束进程时，尚未完成的工作线程会怎样？写一个程序验证：4 个工作线程各睡 300 ms 后打印一行，`main` 创建完线程就返回。再把 `return 0;` 换成 `thrd_exit(0);`，结果有何不同？`thrd_exit` 与 `exit` 对线程的影响分别是什么？
