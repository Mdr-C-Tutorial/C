# 21. 本地化与扩展文本

本地化 (localization) 指程序按地区的习惯处理数字格式、货币符号、字符串排序和字符分类等。C 标准库通过区域设置 (locale) 支持本地化：头文件 `<locale.h>` 提供查询和修改区域设置的接口，`<ctype.h>`、`<string.h>`、`<wchar.h>` 等头文件中的部分函数，其行为受当前区域设置影响。

## 1. 核心接口 `setlocale`

`setlocale` 用于查询或修改当前的区域设置。设置失败时返回空指针，因此每次修改都应检查返回值。

```c
#include <locale.h>
#include <stdio.h>

int main(void) {
    const char *result = setlocale(LC_ALL, "");
    if (result == NULL) {
        puts("setlocale failed");
        return 1;
    }

    puts(result);
    return 0;
}
```

成功时，程序打印实现用于标识当前区域设置的字符串；失败时打印固定的错误信息。例如：

::: code-group

```text [成功示例]
en_US.UTF-8
```

```text [失败]
setlocale failed
```

:::

成功时打印的名称由操作系统和 C 库决定，不能假定它在各平台上一致。传入空字符串 `""` 表示按运行环境（通常是操作系统的环境变量）选择区域设置。

## 2. 数字与货币格式

`localeconv` 返回指向 `struct lconv` 对象的指针，该对象描述当前区域设置下的数字和货币格式，例如 `decimal_point`（小数点字符）和 `currency_symbol`（货币符号）。这些信息用于输出给人看的文本；程序内部的计算逻辑应与区域设置无关，只在输入输出时按地区习惯处理。

## 3. 排序与比较

字符串排序若需要遵循地区规则，应使用 `strcoll` 和 `strxfrm`，而不是用 `strcmp` 直接按字节比较。按字节比较只适合协议字段和机器可读数据，不适合人类语言文本。

## 4. 区域设置是全局状态

`setlocale` 修改的是整个程序的区域设置，而不是某个函数或模块私有的状态。程序的一部分修改区域设置后，其他部分的格式化输出、字符分类和排序结果都会随之改变。

## 5. 与多字节字符和宽字符的关系

区域设置还决定多字节字符的编码方式，从而影响 `mbtowc`、`wcrtomb` 等多字节与宽字符之间的转换函数，以及 `<wctype.h>` 中宽字符分类函数的结果。处理 UTF-8 等多字节文本前，通常需要先调用 `setlocale(LC_ALL, "")` 或选择一个具体的区域设置。

## 6. 多线程程序中的区域设置

在多线程程序运行期间调用 `setlocale`，可能与其他线程中受区域设置影响的函数调用产生数据竞争。应在创建其他线程之前完成区域设置，此后不再修改。
