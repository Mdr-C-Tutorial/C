# 5.5 跳转语句

跳转语句会改变通常的控制流。`break` 和 `continue` 作用于循环或 `switch`，`return` 结束当前函数，`goto` 跳到同一函数中的标号。

<Exercise id="10520" :d="2" :w="2">

先不编译，写出下面程序的输出，再编译运行核对。

```c
#include <stdio.h>

int main(void) {
    int count = 0;
    int i;
    for (i = 0; i < 10; ++i) {
        if (i > 7) {
            break;
        }
        if (i % 4 == 0) {
            continue;
        }
        ++count;
        printf("%d ", i);
    }
    printf("\n%d %d\n", count, i);
    return 0;
}
```

1. 写出全部输出。`count` 和 `i` 最后各是多少？
2. 把 `break` 换成 `continue`，打印的那行数字有变化吗？第二行的 `i` 变成多少？说明 `break` 与 `continue` 分别让循环在哪里结束。
3. 调换两处判断的顺序，先判断 `i % 4 == 0` 再判断 `i > 7`，第二行的 `i` 变成多少？从 `i = 8` 那一轮说明原因。
4. `i` 为什么声明在 `for` 外面？改成 `for (int i = 0; ...)` 后，循环之后还能打印它吗？编译结果是什么？

下面的程序想找出乘积为 6 的第一对整数，找到就停止搜索。它现在只退出了内层循环。

```c
#include <stdio.h>

int main(void) {
    for (int i = 0; i < 5; ++i) {
        for (int j = 0; j < 5; ++j) {
            if (i * j == 6) {
                printf("found %d %d\n", i, j);
                break;
            }
        }
        printf("row %d done\n", i);
    }
    return 0;
}
```

1. 写出完整输出，说明为什么会出现两组 `found`。
2. 用标志对象的办法改造：外层循环条件加上 `&& !found`，内层找到后置位标志。改造后只出现一组 `found 2 3`，`row` 最多打印到第 2 行。说明最后这一行 `row 2 done` 为什么仍然出现。
3. 用把搜索抽成函数、找到后直接 `return` 的办法改造。函数写 `static int find_pair(int *pi, int *pj)`，找到返回 1，找不到返回 0。
4. 在内层 `break` 之后用 `goto` 跳到外层循环之后的标签，使 `row 2 done` 不再打印。比较标志版与 `goto` 版：两者打印的 `row` 行数相差多少？循环条件分别需要怎么写？
5. 把内层找到后的 `break` 换成 `i = 5; j = 5;`（直接改循环变量让循环结束）。本题上界为 5，程序确实停下来了。再把两个上界都改成 100，在找到后打印一对下标、计数到 5 次就返回，观察下标在 5 与 6 之间来回跳的现象。说明为什么第一次找到的 `1 6` 与之后反复出现的 `6 1` 不是同一对，以及这种写法为什么在评审中不被接受。

<Exercise id="10522" :d="5" :w="4">

`goto` 在工程里最常见的用途是统一错误清理。下面的函数有缺陷：有的分支提前返回，跳过了释放动作。

```c
#include <stdio.h>

static int cleanups;

static void release(void) {
    ++cleanups;
}

static int run(int stage) {
    if (stage < 0) {
        return -1;
    }
    if (stage == 1) {
        return -1;
    }
    if (stage == 2) {
        release();
        return -1;
    }
    release();
    return 0;
}

int main(void) {
    for (int s = -1; s <= 3; ++s) {
        int rc = run(s);
        printf("stage %d rc=%d cleanups=%d\n", s, rc, cleanups);
    }
    return 0;
}
```

1. 写出输出。`stage` 为 -1 和 1 的那两次调用，各自执行了 `release()` 没有？打印出来的 `cleanups` 为什么在 `stage 1` 那一行仍是 1？缺陷在哪几行？
2. 改成单出口：函数末尾只留一个 `done:` 标签，标签之后统一调用 `release()`，前面所有失败分支都写 `goto done;`，返回值统一由 `rc` 对象带出。改写后五次调用的 `cleanups` 依次是多少？`rc` 是否仍与原来一致？
3. 为什么返回值必须在跳转之前写好，或者用一个 `rc` 对象贯穿？如果在每个失败分支里直接 `return -1;`，会跳过什么？
4. 把 `release` 换成真实的 `free` 与 `fclose` 两个调用，写出两资源版本的函数骨架。说明清理顺序为什么与申请顺序相反，以及某个指针为 `NULL` 时 `free` 为什么仍然安全（`fclose` 则不同）。
5. 有人主张把清理写进一个函数、在每个失败分支各调用一次，而不用 `goto`。以本题的三个失败分支为例，列出这种写法的具体代价，并说明正文为什么说 `goto` 在这里“最常见、也最合理”。

</Exercise>

<Exercise id="10523" :d="6" :w="5" multi>

本页的三个跳转语句分别解决不同层次的问题。下面三问把它们放进实际程序，每问单独验收。

(1) _[4.3]_ 写一个统计工具：从标准输入读整数。读到 `0` 结束，输出 `个数 总和` 并返回 0；负数跳过；读到非整数或 EOF 时输出 `bad input after N values`，返回 1，`N` 是此前已计入的个数。

样例输入：

```in
3
-4
5
0
7
```

样例输出：

```out
2 8
```

要求：循环写成 `for (;;)`，`0` 用 `break`，负数用 `continue`，读失败用 `goto` 跳到函数末尾的错误处理，不要在分支里重复 `printf` 和 `return 1`。验收另两组：输入 `3` 后跟 `abc` 得 `bad input after 1 values`，退出状态 1；空输入得 `bad input after 0 values`，退出状态 1。最后去掉 `goto`，只用标志对象表达读失败，重写一遍，记录需要新增哪些对象、条件怎么改，并说明原版在“读到 0 之后不再读取”这一点上为什么更直接。

(2) _[4.3]_ 把 (1) 失败后的策略改成“跳过该行继续读”，用 `getchar` 丢弃当前行剩余的字符直到换行，然后 `continue`。说明为什么只写 `continue` 会陷入死循环：`scanf` 读到错误字符后有没有把它取走？

(3) _[6.4]_ 下面的状态机程序想依次走完三个阶段，实际行为与作者的预期不一致：

```c
#include <stdio.h>

int main(void) {
    int state = 0;
    int steps = 0;

    for (;;) {
        switch (state) {
            case 0:
                printf("state 0 -> 1\n");
                state = 1;
                break;
            case 1:
                printf("state 1 -> 2\n");
                state = 2;
                continue;
            case 2:
                printf("state 2 -> done\n");
                goto done;
            default:
                printf("unknown\n");
                goto done;
        }
        printf("after switch, state=%d\n", state);
        if (++steps > 10) {
            goto done;
        }
    }

done:
    printf("finished after %d steps\n", steps);
    return 0;
}
```

写出输出，逐条说明程序里的 `break`、`continue`、`goto` 各自把控制送到哪里，并解释 `steps` 为什么只有 1。把 `case 1` 的 `continue` 改成 `break`，`steps` 变成多少？再把 `case 0` 的 `break` 也改成 `continue`：先预测不加任何保护时程序会怎样，再在 `for` 循环体开头加一个自增的轮次计数与上限，确认它为什么会一直跑下去。最后从“`continue` 跳过的是本轮剩余语句”这一条解释原因。

</Exercise>
