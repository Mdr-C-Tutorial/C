# 5.5.2 goto

`goto` 会把控制流跳转到同一函数内的某个标号 (Label)。它功能强，但应谨慎使用。现代 C 工程里，`goto` 最常见、也最合理的用途是统一错误清理路径与跳出深层嵌套循环。

## 1. 基本语法

```c
goto label;
/* ... */
label:
    statement;
```

标号具有**函数作用域 (Function Scope)**，并且处于独立的标号命名空间（不会与同名的普通对象或类型名冲突），但跳转目标必须在同一个函数之内。若需要跨函数跳转，不能使用 `goto`（非局部跳转见第 22 章的 `<setjmp.h>`）。

## 2. 标号放置与 C23 改进

在 C17 及更早的标准中，标号必须前缀于一条**语句 (Statement)**，而不能直接前缀于一条声明，也不能直接放在复合语句末尾的右花括号 `}` 之前。如果需要在这些位置放置标号，传统写法是在标号后补一条空语句 `;`：

```c
void process(int x) {
    if (x < 0) {
        goto done;
    }
    /* ... */
done:; /* C17 及之前：右花括号前需加空语句 ';' */
}
```

C23 放宽了这一语法限制：标号现在可以直接出现在声明之前，也可以直接放在复合语句末尾的 `}` 之前，无需再写多余的分号。

## 3. 跳转与块作用域对象的约束

使用 `goto` 时必须注意目标位置与块作用域对象声明之间的关系：

1. **跳过带初始化器的普通自动对象**：如果 `goto` 向前跳过了一条带初始化器的自动存储期对象声明（如 `int x = 10;`）直接进入该对象的作用域内部，该对象虽然存在，但其初始化并未执行，此时它的值是不确定的，直接读取会导致未定义行为。
2. **禁止跳入可变修改类型的作用域**：标准严格禁止 `goto` 从可变修改类型（例如第 7 章介绍的变长数组）的作用域外部跳转到其作用域内部，这类代码无法通过编译（详见 14.5 节）。

::: tip 方向原则

在工程代码中，`goto` 应当遵循**只向后（向下）跳转、不向前（向上）回跳**的原则。向上的回跳等价于手写无结构的循环，应始终改用 `while`、`for` 或 `do while` 表达。

:::

## 4. 两个合理的工程场景

### 4.1 一次跳出多层嵌套循环

由于 `break` 只能退出最内层循环，当在二维或三维搜索中一旦命中目标就要立刻结束全部外层循环时，向循环外紧邻的标号执行一次向下 `goto` 比维护多层布尔标志更直接：

```c
#include <stdio.h>

int main(void) {
    int target = 12;

    for (int i = 1; i <= 5; ++i) {
        for (int j = 1; j <= 5; ++j) {
            if (i * j == target) {
                printf("found: %d * %d = %d\n", i, j, target);
                goto search_done;
            }
        }
    }

search_done:
    puts("search finished");
    return 0;
}
```

输出：

::: terminal

found: 3 * 4 = 12
search finished

:::

### 4.2 函数末尾的集中清理路径

当一个函数需要按顺序获取多项资源（如打开多个文件或分配多块存储）且中途任意一步都可能失败时，使用 `goto cleanup;` 跳转到函数末尾按逆序统一释放，可以避免在每个失败分支重复书写清理代码。这一模式的完整规范将在 [14.5 goto 与统一清理](/教程/正文/语法和标准库/14_文本转换_错误与程序生命周期/14_5_goto清理模式) 中专门展开。

int main(void) {
