# 7.1 数组

## 1. 数组声明和初始化

### 1.1 数组声明

数组声明的一般形式是：`元素类型 数组名[元素个数]`。数组对象在内存中连续存放，元素下标从 `0` 开始。`元素个数` 必须是能在编译期确定的常量表达式（变长数组除外），并且不能为负数或零。

```c
int a[4];              // 4 个 int 对象
double table[8];       // 8 个 double 对象
char name[32];         // 32 个 char 对象
```

如果在声明点能看到初始化器，也可以省略长度，让编译器按初始化器自动推导：

```c
int a[] = {1, 2, 3};   // 长度为 3
char s[] = "mdr";      // 长度为 4，包含 '\0'
```

在项目代码中，声明长度时建议使用具名常量或 `enum` 常量，而不是裸字面量，这样在需求变更时更容易维护。注意 `const int` 对象不算常量表达式：用它作长度，在函数外无法通过编译，在函数内得到的是变长数组。

### 1.2 数组初始化

1. 字符串字面量初始化字符数组：可以把字符串字面量放在花括号里，但更多情况下省略。

   如果数组的大小未知，那么字符串字面量里面的每个字符（包括空终止字符）用来初始化数组的各个元素；如果数组的大小已知，允许数组大小比字符串字面量的大小少 1，此时数组里无空终止字符。

   ```c
   char arr1[] = "mdr";
   char arr2[] = { "mdr" };
   // arr1 和 arr2 为 { 'm', 'd', 'r', '\0' }

   char arr3[3] = "mdr";
   // arr3 为 { 'm', 'd', 'r' }
   ```

2. 花括号环绕的初始化器列表初始化数组

   每个初始化器前面可以带一个形如 `[ 下标 ] =` 的**指派符**，指定这个初始化器初始化该数组的第 _下标_ 个元素。如果一个初始化器无指派符，如果它是第一个初始化器则初始化下标为零的元素，否则初始化前一个初始化器初始化的元素的后一个元素。

   如果数组的大小未知，那么初始化器的最大下标会确定数组大小（也就是足够装得下数组里面的元素），同时在初始化过后，数组从不完整类型变成完整类型。

   ```c
   int arr1[3] = { 1, 2, 3 };
   int arr2[]  = { [2] = 5 };          // { 0, 0, 5 }
   int arr3[]  = { [2] = 5, 6, 7 };    // { 0, 0, 5, 6, 7 }
   int arr4[]  = { 1, 2, 3, [2] = 5 }; // { 1, 2, 5 }
   ```

   用嵌套初始化器初始化数组的数组：

   ```c
   int arr1[3][2] = { {1, 2}, {3, 4}, {5, 6} };
   int arr2[3][2] = { {1}, {3, 4}, {[1] = 6} }; // { { 1, 0 }, { 3, 4 }, { 0, 6 } }
   ```

   如果嵌套的初始化器外围没有花括号，就只从列表中依次取出刚好够初始化这个子数组的初始化器，剩下的留给后面的元素。

   ```c
   int arr1[3][2] = { 1, {2}, {3, 4} }; // { { 1, 2 }, { 3, 4 }, { 0, 0 } }
   int arr2[3][2] = { 1, 2, 3, 4 };     // { { 1, 2 }, { 3, 4 }, { 0, 0 } }
   ```

   指派符可以嵌套：

   ```c
   int arr1[3][2] = { [2][1] = 3 }; // { { 0, 0 }, { 0, 0 }, { 0, 3 } }
   ```

## 3. 下标运算符

`a[b]` 定义为 `*(a + b)`。数组在表达式中会转换为指向首元素的指针（见第 8 章），所以 `arr[2]` 与 `p[2]` 访问的是同一个元素。

```c
int arr[4] = {10, 20, 30, 40};
int *p = arr;

int n1 = arr[2];
int n2 = p[2];
```

下标运算符不检查范围。访问不存在的元素（下标小于 `0`，或者不小于元素个数）是未定义行为，访问前应确保下标在有效范围内。

## 4. 用 `sizeof` 计算数组长度

由于数组的元素在内存中紧密连续排列，`sizeof` 作用于数组对象时，返回整个数组占用的总字节数，即 `元素个数 * sizeof(单个元素)`。因此在数组标识符本身可见的作用域内，可以用总字节数除以首元素字节数，在编译期安全地求出数组的元素个数：

```c
#include <stdio.h>

int main(void) {
    int scores[] = {85, 92, 78, 90, 88};
    size_t count = sizeof scores / sizeof scores[0];

    printf("total bytes = %zu, count = %zu\n", sizeof scores, count);
    return 0;
}
```

输出（`int` 为 4 字节的实现）：

::: terminal

total bytes = 20, count = 5

:::

::: warning 仅对真正的数组对象有效

`sizeof arr / sizeof arr[0]` 只能在 `arr` 的类型确实是数组时使用。一旦数组作为实参传给函数，函数形参会调整为指针（见第 8 章第 10 节），此时在函数内部对形参求 `sizeof` 得到的是指针本身的大小，而不是原数组的大小。

:::

## 5. 多维数组与内存布局

C 语言中的多维数组本质上是**数组的数组 (Array of Arrays)**。例如 `int mat[3][4];` 声明了一个包含 3 个元素的数组，其中每个元素的类型又是“包含 4 个 `int` 的数组”。

多维数组在内存中按**行主序 (Row-major Order)** 连续存放，即第一行的 4 个元素依次排布，紧接着是第二行的 4 个元素，最后是第三行的 4 个元素（右边的下标变化最快）：

```c
#include <stdio.h>

int main(void) {
    int mat[2][3] = {
        {1, 2, 3},
        {4, 5, 6}
    };

    for (size_t r = 0; r < 2; ++r) {
        for (size_t c = 0; c < 3; ++c) {
            printf("%d ", mat[r][c]);
        }
        printf("\n");
    }
    return 0;
}
```

输出：

::: terminal

1 2 3 
4 5 6 

:::

在双重循环遍历二维数组时，外层循环按行递增、内层循环按列递增的顺序与内存连续排布顺序完全一致，能够充分利用处理器缓存局部性，获得最佳的访问性能。

## 6. 变长数组 (Variable Length Array, VLA)

C99 引入了**变长数组 (VLA)**：具有块作用域且无链接的自动存储期数组，其声明长度可以使用运行期求值的正整数表达式，而不必是编译期常量表达式。

```c
void print_zeros(int n) {
    /* n 在运行期确定（必须满足 n > 0），vla 是变长数组 */
    int vla[n];
    for (int i = 0; i < n; ++i) {
        vla[i] = 0;
    }
}
```

使用变长数组时必须遵守以下规则与工程边界：

1. **长度必须严格大于 0**：如果在运行期求出的长度不大于 0，行为未定义。
2. **`sizeof` 在运行期求值**：对变长数组求 `sizeof(vla)` 时，其结果不再是编译期常量，而是在运行期根据当时的长度计算字节数。
3. **初始化限制**：在 C17 及之前，变长数组不能带有初始化器；C23 起允许使用空初始化器 `int vla[n] = {};` 将变长数组全部零初始化，但仍不允许提供非空初始化列表。
4. **标准可选性与栈溢出风险**：C11 起，变长数组成为可选特性（不支持的实现会定义宏 `__STDC_NO_VLA__`；C23 将指向变长数组的指针等“可变修改类型”恢复为必选，但自动存储期的变长数组对象本身仍为可选）。由于变长数组通常在调用栈上分配空间，若长度不受控（例如直接由外部输入决定 `n`），极易导致栈溢出漏洞。在工程代码中，当数据规模较大或由外部输入决定时，应使用第 11 章介绍的动态存储分配（`malloc` / `calloc`），而非变长数组。
