# 22. 非局部控制与信号

在常规的 C 程序中，控制流只沿着语句顺序、分支、循环以及函数的调用与返回逐层推进。本章讨论两组打破这种常规顺序路径的标准接口：

1. [信号 (`<signal.h>`)](/教程/正文/语法和标准库/22_非局部控制与信号/22_1_signal)：响应外部中断事件或严重运行时异常的控制转移机制。
2. [非局部跳转 (`<setjmp.h>`)](/教程/正文/语法和标准库/22_非局部控制与信号/22_2_非局部跳转)：跨越多个函数调用栈帧直接回退到预设恢复点的机制。

## 为什么它们不应替代常规控制流

在缺乏语言级异常机制的 C 语言中，初学者有时会尝试用信号处理函数或 `setjmp` / `longjmp` 来处理日常错误。这种做法会带来严重的可维护性与正确性风险，原因在于 C 语言没有自动析构机制：

| 机制 | 触发方式 | 栈帧变化 | 主要约束与代价 |
| --- | --- | --- | --- |
| 函数返回值 / 错误码 | 同步、显式判断 | 逐层正常返回 | 每层调用者可确定地释放锁、内存与文件流 |
| `signal` / `raise` | 异步中断或同步硬件异常 | 在当前执行点打断并借用栈帧执行处理函数 | 异步信号内严禁调用非异步信号安全函数（如 `printf`、`malloc`）；仅可安全读写 `volatile sig_atomic_t` 等受限对象 |
| `setjmp` / `longjmp` | 同步、显式调用 `longjmp` | 直接丢弃中间所有活动栈帧，回退到 `setjmp` 所在栈帧 | 中间层分配的动态内存、打开的 `FILE *` 句柄及持有的互斥锁会被全部跳过而泄漏；`setjmp` 所在函数中被修改过的非 `volatile` 自动存储期对象在跳转后取值未指定 |

因此，工程中的基本准则是：**一切可预期的业务错误、I/O 失败和格式错误都应通过函数返回值逐层传递并结合函数内 `goto cleanup` 清理资源**；信号处理仅用于设置异步通知标志或应急终止，而 `setjmp` / `longjmp` 仅限于深层递归解析器或协程运行时等受控边界内部使用。
