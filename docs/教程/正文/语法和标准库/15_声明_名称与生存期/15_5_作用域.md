# 15.5 作用域

作用域 (Scope) 描述“一个标识符在源代码中可见的区域”。它是静态语义规则，与对象是否已经创建是两个概念。理解作用域可以直接避免命名冲突、阴影覆盖和接口泄露。

## 1. 四种常见作用域

::: concept scope-kinds title="四种作用域及其区间"

文件作用域从声明点持续到翻译单元结尾；块作用域从声明点持续到当前复合语句结束；函数原型作用域只在函数声明的形参列表内有效；标号作用域覆盖整个函数体。它们共同决定同名标识符何时表示同一个实体，何时表示不同实体。

:::

::: generate scope-overview kind=explanation concepts=scope-kinds

面向刚开始学习 C 的读者，逐一讲解四种作用域的区间和典型出现位置；强调作用域是静态语义规则——名字是否可见在翻译期就确定了，与对象何时创建是两回事。

:::

## 2. 块作用域与阴影覆盖

```c
#include <stdio.h>

int main(void) {
    int x = 1;

    {
        int x = 2;
        printf("inner x = %d\n", x);
    }

    printf("outer x = %d\n", x);
    return 0;
}
```

输出：

::: terminal

inner x = 2
outer x = 1

:::

::: generate block-scope-shadowing kind=explanation concepts=scope-kinds

借助上面的示例代码，面向刚开始学习 C 的读者分步解释：内层块重新声明了同名标识符，外层名字在该块中被遮蔽，因此两次输出分别为 2 和 1。说明这种写法合法但可读性下降，除非刻意表达“局部覆盖”，否则建议避免。

:::

## 3. 函数原型作用域

函数声明中的形参名只在该原型内部有效，它们主要用于可读性和文档化，不会在原型外形成可见名字。

```c
int add(int left, int right);  /* left/right 仅在这个声明里有效 */

int add(int a, int b) {
    return a + b;
}
```

定义阶段可以使用不同的形参名，类型匹配才是关键约束。

## 4. 标号作用域补充

`label:` 的可见范围覆盖整个函数体，因此 `goto` 可以跨块跳转到该标号，但目标仍必须位于同一函数内。它不受普通块作用域限制。

```c
int f(int x) {
    if (x < 0) {
        goto fail;
    }
    return 0;

fail:
    return -1;
}
```

这类写法常用于统一失败出口，但仍应控制在清晰、可验证的范围内。

## 5. 声明点的时间边界

::: concept scope-declaration-point title="块作用域从声明点开始"

块作用域标识符并不是“进入块就可见”，而是从声明点之后才可见。

:::

```c
int x = 1;
{
    /* 此处仍是外层 x 可见 */
    int x = 2; /* 从这里开始，内层 x 可见 */
}
```

::: generate declaration-point kind=explanation concepts=scope-declaration-point,scope-kinds

借助上面的示例代码，面向刚开始学习 C 的读者解释“声明点”这个时间边界：为什么内层块开头处可见的仍是外层 `x`，以及这个细节在同名遮蔽和长函数重构中为什么关键——把声明移动到更窄的位置，能自然收缩可见范围，减少误用旧名字的机会。

:::

<Exercise id="11529" :d="4" :w="3">

下面的程序有三处与作用域有关的缺陷，输出也是错的。规格如下：`sum_above` 返回所有大于 `threshold` 的元素之和，并把同样的量累加到全局 `total`（每个元素只加一次）；`clamp_sum` 返回 `1 + 2 + ... + n`，若超过 `2 * n` 就取 `2 * n`；`scale` 在 `factor > 0` 时返回 `factor * value`，否则返回 `value`。

```c
#include <stdio.h>

int total = 0;

static int sum_above(const int *a, int n, int threshold) {
    int sum = 0;

    for (int i = 0; i < n; i++) {
        if (a[i] > threshold) {
            {
                int sum = sum + a[i];
                total += sum;
            }
        }
    }
    return sum;
}

static int clamp_sum(int n) {
    int sum = 0;
    goto cap;

    {
        int ceiling = n * 2;
    cap:
        for (int i = 1; i <= n; i++) {
            sum += i;
        }
        if (sum > ceiling) {
            sum = ceiling;
        }
    }
    return sum;
}

static int scale(int factor, int value) {
    if (factor > 0) {
        int value = factor * 2;
        return value;
    }
    return value;
}

int main(void) {
    int a[] = {1, -2, 3, 4, -5};
    int sum = sum_above(a, 5, 0);

    printf("sum = %d, total = %d\n", sum, total);
    printf("clamped = %d\n", clamp_sum(4));
    printf("scaled = %d\n", scale(2, 5));
    return 0;
}
```

(1) 先按原样编译运行，记录输出；再用 `-O2` 编译运行一次，比较两次结果。两次输出里哪些行可以稳定复现，哪些行每次运行都可能变？按规格，正确的 `total` 应该是多少？

(2) 用 `-Wall -Wextra -Wshadow -Wjump-misses-init` 编译，抄下与这三处缺陷对应的警告，说明每条警告指向哪条作用域规则。

(3) 修好三处缺陷。验收：`gcc -std=c17 -Wall -Wextra -Wshadow -Wjump-misses-init` 在 `-O0` 与 `-O2` 下都无警告，输出都是 `sum = 8, total = 8`、`clamped = 8`、`scaled = 10`。

(4) 解释 `sum_above` 里 `int sum = sum + a[i];` 中右边的 `sum` 为什么不是外层那个 `sum`，并说明 `clamp_sum` 里 `goto` 跳过了什么。

### 6.3 综合与挑战

<Exercise id="11530" :d="6" :w="4">

下面的模块在 `-std=c17 -Wall -Wextra` 下能编译运行，但输出与规格不符，在 `-O2` 下结果还会变。规格如下：

1. `summarize(1, a, n)` 打印 `a` 中正数的个数，并把这个数加到全局 `total`。
2. `record(bad)` 打印本次调用新增的错误数（`bad` 非零记 1，否则记 0），同时让全局 `errors` 累计。
3. `classify(1)` 返回 10，`classify(2)` 返回 11，`classify(3)` 返回 0。
4. `clamp_sum(4)` 返回 8：$1+2+3+4=10$ 超过 $2 \times 4$，取上限。

```c
#include <stdio.h>

int total = 0;
int errors = 0;

static int count_positive(const int *a, int n) {
    int count = 0;

    for (int i = 0; i < n; i++) {
        if (a[i] > 0) {
            count++;
        }
    }
    return count;
}

static int classify(int mode) {
    switch (mode) {
    case 1:
        int adjusted = 10;
        return adjusted;
    case 2:
        return adjusted + 1;
    default:
        return 0;
    }
}

static void record(int bad) {
    int errors = 0;

    if (bad) {
        {
            extern int errors;
            errors++;
        }
    }

    printf("call errors = %d\n", errors);
}

void summarize(int mode, const int *a, int n) {
    switch (mode) {
    case 1:
        int count = count_positive(a, n);
        {
            int count = count;
            total += count;
        }
        printf("positive = %d\n", count);
        break;
    default:
        printf("mode %d ignored\n", mode);
        break;
    }
}

static int clamp_sum(int n) {
    int sum = 0;
    goto cap;

    {
        int ceiling = n * 2;
    cap:
        for (int i = 1; i <= n; i++) {
            sum += i;
        }
        if (sum > ceiling) {
            sum = ceiling;
        }
    }
    return sum;
}

int main(void) {
    int samples[] = {3, -1, 4, 0, 5, -9, 2};

    summarize(1, samples, 7);
    summarize(1, samples, 7);
    record(1);
    record(0);
    printf("classify = %d %d %d\n", classify(1), classify(2), classify(3));
    printf("clamped = %d\n", clamp_sum(4));
    printf("total = %d, errors = %d\n", total, errors);
    return 0;
}
```

(1) 在 `-O0` 和 `-O2` 下分别编译运行，抄下两次输出，指出哪些行不同。

(2) 用 `-std=c17 -Wall -Wextra -Wshadow -Wjump-misses-init -Wnested-externs -pedantic-errors` 编译，把诊断按「错误」和「警告」分开抄下。逐条说明它涉及哪个名字、由哪条作用域规则引起；其中与 `adjusted`、`ceiling` 有关的两条，也要说明它们分别与 `case` 标号的作用范围和 `goto` 跳过声明有关。

(3) 改写程序，使规格得到满足，并且上述严格选项在 `-std=c17` 与 `-std=c2x` 下都无诊断。验收输出：

```text
positive = 4
positive = 4
call errors = 1
call errors = 0
classify = 10 11 0
clamped = 8
total = 8, errors = 1
```

(4) 用 `-std=c2x` 重编原程序，比较 (2) 里的错误列表，说明少了哪一类错误、C23 为此放宽了什么规则。

(5) `record` 里块内的 `extern int errors;` 看起来是在「重新声明」，实际指向哪一个对象？如果要让函数内的局部名字与全局对象并存，应该怎么写？

</Exercise>
