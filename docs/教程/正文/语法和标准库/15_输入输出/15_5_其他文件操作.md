# 其他文件操作

本节收集一些在实际工程中很常用、但不适合放进“打开/读写/定位”主线叙事的 `stdio.h` 能力：状态与错误处理、缓冲控制、重定向、临时文件等。

## 1. EOF 与错误状态：`feof` / `ferror` / `clearerr`

对一个流进行读操作后，如果发现“没有读到想要的数据”，你需要区分两类情况：

1. 到达文件末尾（EOF）；
2. 发生 I/O 错误。

标准库提供了两个“状态查询”接口：

```c
#include <stdio.h>

int feof(FILE* stream);
int ferror(FILE* stream);
```
以及一个“清除状态”接口：

```c
#include <stdio.h>

void clearerr(FILE* stream);
```
注意：`feof` / `ferror` 不会“预测”下一次读操作是否会失败，它们仅反映过去的 I/O 操作设置的状态。判断是否读到数据，应该先看读函数的返回值，再在需要时用 `feof` / `ferror` 解释失败原因。

## 2. 打印错误信息：`perror`

```c
#include <stdio.h>

void perror(const char* s);
```

这里只列出函数原型，没有设置 `errno` 或调用 `perror`，因此不会产生运行期输出。

当某个库函数失败后，`perror` 会把 `s` 与一条实现提供的错误信息输出到标准错误流（通常是 `stderr`）。它常用于调试与简单工具程序。

::: tip

更精细的错误处理通常还会配合 `<errno.h>` 中的 `errno`（这是标准库的一部分）。但本章不把“错误码体系”作为主线展开，你只需知道：遇到 I/O 失败时，先检查返回值，再决定是否打印信息/退出/重试。

:::

## 3. 缓冲与刷新：`fflush` / `setvbuf` / `setbuf`

### 3.1 `fflush`

```c
#include <stdio.h>

int fflush(FILE* stream);
```
对输出流调用 `fflush(stream)`，会尝试把用户态缓冲中的数据写出；成功返回 0，失败返回 EOF。

标准还允许传入空指针：`fflush(NULL)` 会刷新所有输出流。

::: warning 注意

对输入流调用 `fflush` 的行为在标准中没有定义。可移植代码不要这样写。

:::

### 3.2 `setvbuf` / `setbuf`

你可以通过 `setvbuf` 控制一个流的缓冲方式：

```c
#include <stdio.h>

int setvbuf(FILE* stream, char* buf, int mode, size_t size);
void setbuf(FILE* stream, char* buf);
```
其中 `mode` 常用取值为：

1. `_IONBF`：无缓冲；
2. `_IOLBF`：行缓冲；
3. `_IOFBF`：全缓冲。

缓冲策略与性能/交互体验关系很大，但它们也很“实现相关”。对教程而言，你只需要掌握两条规则：

1. 默认缓冲策略通常已经足够；
2. 当你在交互式程序中希望提示信息立刻出现时，可以考虑 `fflush(stdout)`。

## 4. 重定向流：`freopen`

`freopen` 可以把一个已有的流“重新绑定”到一个新文件上（常见用途：把 `stdin` / `stdout` 重定向到文件）。

```c
#include <stdio.h>

FILE* freopen(const char* filename, const char* mode, FILE* stream);
```
成功返回 `stream`，失败返回空指针。

::: warning 注意

`freopen` 的具体效果包含实现细节（例如失败时原流是否关闭等），写代码时应以“返回值检查”为核心：只要返回空指针，就把它当作重定向失败来处理。

:::

## 5. 临时文件：`tmpfile` / `tmpnam`

```c
#include <stdio.h>

FILE* tmpfile(void);
char* tmpnam(char* s);
```
`tmpfile` 会创建一个临时二进制文件并以“更新模式”打开它；当该流关闭，或程序正常结束时，这个临时文件会被自动删除（具体细节有实现相关部分，但这是它的设计目标）。

`tmpnam` 返回一个可能可用于临时文件的名字。但它有明显缺陷：名称生成与实际创建不是原子操作，在并发/多进程环境中可能产生竞态；因此更推荐使用 `tmpfile`。

<Exercise id="11414" :d="5" :w="4">

实现把多个文件依次写入一个输出流的函数：

```c
#include <stddef.h>
#include <stdio.h>

typedef enum {
    MERGE_OK,
    MERGE_INVALID,
    MERGE_OPEN_ERROR,
    MERGE_READ_ERROR,
    MERGE_WRITE_ERROR,
    MERGE_CLOSE_ERROR
} MergeResult;

MergeResult merge_files(
    FILE *output,
    const char *const source_paths[],
    size_t source_count
);
```

要求：

1. 按 `source_paths` 中的顺序以二进制方式打开并复制每个文件，不得一次把整个文件读入内存。
2. 开始写入前先检查全部路径指针；路径无效时不得修改输出流。
3. 每个输入流只由本函数拥有，并且无论成功还是失败都必须关闭。
4. 输出流由调用方拥有，本函数不得关闭；成功返回前应调用 `fflush`。
5. 检查 `fopen`、`fread`、`fwrite`、`fclose` 和 `fflush` 的结果，并返回最先发生的错误类别。
6. 失败时输出流可能已经包含前缀数据；函数只保证释放自己取得的资源。
7. 调用方必须保证输入路径不指向与 `output` 关联的文件。

</Exercise>

<Exercise id="11415" :d="4" :w="3">

一幅灰度图由取值 0～9 的像素组成。实现下面的函数，把降噪后的图像写成字符画：

```c
#include <stddef.h>
#include <stdio.h>

typedef enum {
    DIGIT_IMAGE_OK,
    DIGIT_IMAGE_INVALID,
    DIGIT_IMAGE_WRITE_ERROR
} DigitImageResult;

DigitImageResult write_denoised_digit_image(
    FILE *output,
    const unsigned char *pixels,
    size_t width,
    size_t height
);
```

固定使用以下十个字符表示从暗到亮的十级灰度：

```text
 .:-=+*#%@
```

对每个像素，只考察其上、下、左、右四个方向中实际存在的相邻像素。如果它与每个相邻像素的差的绝对值都大于 1，就使用所有相邻像素的算术平均值替代它；平均值采用整数四舍五入。没有相邻像素时保持原值。

要求：

1. 降噪判断必须全部基于原图，不能让先处理的像素影响后面的像素。
2. 每行字符画后写入一个换行符，成功前调用 `fflush(output)`，但不得关闭输出流。
3. `output == NULL`、`pixels == NULL`、宽或高为 0、尺寸乘法溢出，或者任一像素大于 9 时返回 `DIGIT_IMAGE_INVALID`。
4. 参数无效时不得向输出流写入数据。
5. 任意写入或刷新失败时返回 `DIGIT_IMAGE_WRITE_ERROR`；此时输出流可能已经包含字符画的前缀。
6. 除循环计数外，额外空间复杂度应为 $O(1)$。

</Exercise>
