# 9. 字符与字符串

本章从字符、基本字符集和字符串字面量出发，再学习 `<ctype.h>` 与 `<string.h>`。单个字符、以空字符结尾的字符串和指定长度的字节序列是三种不同的数据，标准库分别为它们提供了不同的函数。

## 1. 本章内容

1. [字符串字面量](/教程/正文/语法和标准库/9_字符与字符串/9_1_字符串字面量)
2. [ASCII 与基本字符集](/教程/正文/语法和标准库/9_字符与字符串/9_2_ASCII与基本字符集)
3. [`<ctype.h>`](/教程/正文/语法和标准库/9_字符与字符串/9_3_ctype)：判断字符类别并转换大小写。
4. [`<string.h>`](/教程/正文/语法和标准库/9_字符与字符串/9_4_string)：处理空终止字符串和指定长度的字节序列。

## 2. 两条基本规则

传给字符分类函数的值必须是 `EOF`，或能表示为 `unsigned char` 的值。使用字符串函数时，必须保证源字符串以空字符结尾，并且目标数组有足够的空间；处理可能含有空字符的任意字节序列时，应使用带显式长度的内存函数（如 `memcpy`、`memcmp`）。

阅读下面的程序，写出输出，并说明每一行结果从哪里来。

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    const char raw[] = "ab\0cd";
    char word[4] = "abc";
    char shifted[] = "abcdef";

    printf("%d %d\n", (int)sizeof raw, (int)strlen(raw));
    printf("%s\n", raw);
    printf("%d %d\n", (int)strlen(word), (int)sizeof word);

    memmove(shifted + 2, shifted, 4);
    printf("%s\n", shifted);

    printf("%d\n", (int)((const char *)memchr(raw, 'c', sizeof raw) - raw));
    printf("%d\n", strcmp(raw, "ab"));
    return 0;
}
```

问题：

1. `sizeof raw` 与 `strlen(raw)` 为什么相差 4？
2. `printf("%s", raw)` 只输出 `ab`，`raw` 里 `\0` 之后的 `cd` 去哪了？
3. `strlen(word)` 与 `sizeof word` 分别是多少？相差的那个字节是什么，由谁写入？把 `word` 的声明改成 `char word[] = "abc";` 后两者又各是多少，为什么仍然差 1？
4. `memmove` 那一行输出 `ababcd`。如果换成 `memcpy`，结果有保证吗？这里为什么必须用 `memmove`？

本机输出（逐行）：`6 2`、`ab`、`3 4`、`ababcd`、`3`、`0`。

只用 `<ctype.h>`，实现就地修改的函数：

```c
#include <stddef.h>

void title_case(char *s);
```

要求：

1. 每个单词的首字母大写，同一单词内其余字母小写；单词由 `isspace` 识别的空白分隔；
2. 只处理基本字符集中的字母，其他字符（数字、标点、`>= 0x80` 的字节）原样保留，也不把它们当作分隔单词的空白；
3. 判断字母一律用 `isalpha`、`islower`、`isupper`，不得写成 `c >= 'a' && c <= 'z'` 这类形式。写一小段程序验证 `'9' - '0'` 等于 9，并说明这一条为什么可以依赖，而「`'a'` 到 `'z'` 连续」不能依赖；
4. 调用 `isspace`、`toupper`、`tolower` 前先把 `char` 值转换成 `unsigned char`，说明不转换在什么情况下会出错；
5. 不改动字符串长度。

验收（本机输出，每行给出输入与结果）：


```c
size_t mdr_strlcpy(char *dest, const char *src, size_t size);
```

<Exercise id="10913" :d="5" :w="3" multi>

下面的程序有四处缺陷。先按原样编译运行，再逐条定位。编译器的诊断并不足以把它们都拦下来。

```c
#include <ctype.h>
#include <stdio.h>
#include <string.h>

static void shout(char *s) {
    for (size_t i = 0; i < strlen(s); i++) {
        s[i] = (char)toupper(s[i]);
    }
}

static void copy_name(char *dest, const char *src) {
    strncpy(dest, src, 8);
}

static int count_fields(char *line, const char *delim) {
    int count = 0;

    for (char *tok = strtok(line, delim); tok != NULL; tok = strtok(NULL, delim)) {
        count++;
    }
    return count;
}

int main(void) {
    char name[8];
    char csv[] = "a,b,c";
    char accented = (char)0xE9;
    char *text = "one,two,three";

    copy_name(name, "a-very-long-name");
    printf("name: [%s]\n", name);

    for (char *tok = strtok(csv, ","); tok != NULL; tok = strtok(NULL, ",")) {
        printf("tok: %s\n", tok);
    }
    printf("field count on second pass: %d\n", count_fields(csv, ","));

    printf("isalpha: %d\n", isalpha(accented));
    printf("isalpha(unsigned char): %d\n", isalpha((unsigned char)accented));

    shout(text);
    printf("text: %s\n", text);
    return 0;
}
```

程序最后一行 `shout(text)` 会崩溃。在终端里直接运行时，崩溃之前打印的内容仍然可见；把输出接进管道时标准输出是全缓冲的，这些内容可能来不及写出，这时可以先用 `setvbuf(stdout, NULL, _IONBF, 0)` 关掉缓冲，或者用调试器在崩溃处查看。

(1) _[2.1]_ 先只看编译器给了什么。用 `-std=c17 -Wall -Wextra` 编译，记下全部诊断。这四处缺陷里有几处被报告了？只靠 `-Wall -Wextra` 能不能发现全部四处？

(2) _[3.2]_ 逐条定位其余三处缺陷。四处分别属于：`strncpy` 的截断与空字符、向只读的字面量写入、`strtok` 修改被分割的字符串、`ctype` 函数收到负的 `char` 值。指出哪一处让程序崩溃、哪三处只让结果不符合预期。让程序在崩溃前把输出刷出来的办法有两种：`setvbuf(stdout, NULL, _IONBF, 0)`，或直接重定向到文件后看文件内容。运行时会看到 `field count on second pass: 1`，解释这个结果为什么说明 `strtok` 已经改动了 `csv`。

(3) _[3.2]_ 逐一修正：`copy_name` 增加容量参数并用 `memcpy` 加空字符；`shout` 改为遍历到空字符为止；拆分时先把 `csv` 复制到一份临时数组再交给 `strtok`，使 `csv` 保持原样；`isalpha` 前先转 `unsigned char`。修正后编译零警告，输出依次为 `name: [a-very-]`、三行 `tok:`、`field count on second pass: 3`、两行 `isalpha: 0`、`text: ONE,TWO,THREE`。再改用 9.4 节提到的可重入版本 `strtok_r` 拆同一行，说明它多出的那个参数在做什么。

(4) _[5.3*]_ 不用 `strtok`，实现一个不修改原串的字段遍历：

```c
#include <stddef.h>

/* 按 delims 中任意字符分割 line，把各字段的起点和长度写入 out，
   最多写 max_fields 个，返回实际字段数；line 不被修改。 */
size_t split_fields(const char *line, const char *delims,
                    const char **starts, size_t *lengths, size_t max_fields);
```

用 `strcspn` 找下一个分隔符的位置。相邻分隔符之间产生空字段（长度为 0），末尾分隔符之后也产生一个空字段，空行产生一个长度为 0 的字段。验收：

```text
split("a,,b,", ",")  -> 4 个字段：[a] [] [b] []
split("", ",")       -> 1 个字段：[]
split("x;y,z", ";,") -> 3 个字段：[x] [y] [z]
```

再写 `size_t count_byte(const char *data, size_t n, char value)`，用 `memchr` 统计任意字节序列中某字节出现的次数，用 `const char raw[] = "a\0b\0c";` 与 `sizeof raw` 验证 `count_byte(raw, 6, '\0')` 为 3。说明为什么这两个接口必须带长度参数，而不能只靠空字符判断结尾。

</Exercise>
