# 3.7 类型转换运算符

本节讨论两类“类型转换”：

1. **显式转换**：强制类型转换 (Cast)，由你写在源代码里；
2. **隐式转换**：由语言规则自动发生（例如算术提升、赋值转换）。

在深入显式转换之前，需要先理解编译器在表达式背后自动执行的隐式转换规则。

## 1. 隐式类型转换 (Implicit Conversions)

当运算符的操作数类型不同，或表达式的类型与目标位置（如赋值左侧、函数形参、`return` 目标类型）不一致时，C 语言会按确定规则自动转换类型。

### 1.1 整数转换等级与整数提升

C 标准为每种整数类型规定了**整数转换等级 (Integer Conversion Rank)**，按等级从高到低依次为：

$$\texttt{long long} > \texttt{long} > \texttt{int} > \texttt{short} > \texttt{signed char} > \texttt{\_Bool}$$

对应的无符号整数类型与有符号整数类型具有相同的等级（例如 `unsigned int` 与 `int` 同级）。

在绝大多数算术、位运算与关系表达式中，凡是转换等级低于 `int` 的整数类型（如 `_Bool`、`char`、`signed char`、`unsigned char`、`short`、`unsigned short`），都会先经历**整数提升 (Integer Promotions)**：

1. 如果 `int` 能够表示原类型的全部可能取值，则值被转换为 `int`；
2. 否则，值被转换为 `unsigned int`。

在常见的 32 位或 64 位平台上，`char` 和 `short`（无论有无符号）的取值范围都完全落在 `int` 之内，因此在参与 `+`、`-`、`<<` 等运算前都会先提升为 `int`：

```c
#include <stdio.h>

int main(void) {
    unsigned char a = 200;
    unsigned char b = 100;
    int sum = a + b; /* a 和 b 先提升为 int，相加结果为 300，不会在 8 位内回绕 */

    printf("%d %zu\n", sum, sizeof(a + b));
    return 0;
}
```

输出（`int` 为 4 字节的实现）：

::: terminal

300 4

:::

### 1.2 寻常算术转换 (Usual Arithmetic Conversions)

对于二元算术运算符（如 `+`、`-`、`*`、`/`、`%`）和关系运算符（如 `<`、`>`、`==`），如果两个操作数类型不同，编译器会按**寻常算术转换**规则将它们统一到同一个公共类型：

1. **浮点优先**：若任一操作数是浮点类型，则整数操作数转换为该浮点类型；两个不同精度的浮点类型按 `long double` > `double` > `float` 向高精度对齐。
2. **先做整数提升**：若两个操作数都是整数类型，双方先各自完成整数提升。提升后若类型仍不同，则按以下三条规则转换：
   - **同号看等级**：双方同为有符号或同为无符号时，低等级类型转换为高等级类型。
   - **无符号等级不低于有符号**：若无符号操作数的等级**大于或等于**有符号操作数的等级，则有符号操作数转换为该无符号操作数的类型。
   - **有符号等级更高**：若有符号操作数的类型能够完整容纳无符号操作数的所有值，则无符号操作数转换为该有符号类型；否则双方都转换为与该有符号操作数对应的无符号类型。

::: warning 有符号与无符号混用的经典陷阱

由于 `int` 与 `unsigned int` 等级相同，根据上述规则，当 `int` 与 `unsigned int` 直接比较或运算时，`int` 会被隐式转换为 `unsigned int`！如果此时 `int` 对象的值为负数，转换后会变成一个巨大的正数：

:::

```c
#include <stdio.h>

int main(void) {
    int a = -1;
    unsigned int b = 1u;

    if (a < b) {
        puts("a < b");
    } else {
        puts("a >= b (converted to unsigned!)");
    }
    return 0;
}
```

输出：

::: terminal

a >= b (converted to unsigned!)

:::

在求值 `a < b` 时，`-1` 被转换为 `unsigned int` 的最大值 `UINT_MAX`，导致 `a < b` 的结果为假。开启编译器选项 `-Wsign-compare`（包含在 `-Wextra` 中）可以在编译期捕获这一风险。

### 1.3 赋值与初始化中的转换

在赋值表达式 `left = right`、带初始化器的声明、函数实参传递以及 `return` 语句中，右侧的值会被隐式转换为左侧目标对象的类型。这种转换可能导致高位截断（如 `long long` 转 `short`）或小数部分丢失（如 `double` 转 `int`）。建议在工程中开启 `-Wconversion`，让编译器对其中的窄化转换给出诊断。

## 2. C 的 cast 语法

C 的强制类型转换语法是：

```c
(type-name) expression
```

其中 `type-name` 是类型名，`expression` 是被转换的表达式。强制类型转换是一个一元运算符，它产生一个具有指定类型的新值，**不会修改原操作数对象本身**。

当需要主动促进浮点除法（避免整数除法截断）或消除有符号/无符号混用警告时，显式转换能让意图一目了然：

```c
int total = 7;
int count = 2;
double average = (double)total / count; /* total 先转为 double，再触发寻常算术转换，结果为 3.5 */
```

此外，将表达式显式转换为 `void`（如 `(void)x;`）是一种标准惯用法，用于向编译器和代码阅读者表明“此处有意丢弃该表达式的值或有意暂不使用该形参”，从而抑制未使用警告。

## 3. 常见转换类别与标准风险

### 3.1 整型之间转换

整型转换可能发生截断或符号变化：

```c
unsigned char u8 = (unsigned char)1000; /* 结果与实现的 unsigned char 宽度有关 */
```

具体规则区分目标类型的符号性：

1. **转换为无符号整数类型**：结果定义为对 $2^N$ 取模（$N$ 为目标无符号类型的位宽），始终良定义。例如在 8 位 `unsigned char` 上，`(unsigned char)-1` 的值严格等于 `255`。
2. **转换为有符号整数类型**：若原值在目标有符号类型可表示范围内，值保持不变；若超出范围，在 C23 之前结果由**实现定义**（或产生实现定义信号），C23 起由于统一规定有符号整数采用二进制补码表示，结果按位宽模 $2^N$ 截断为对应的补码值。

### 3.2 指针转换与对齐

本章不讨论指针相关的转换。相关规则将在后续章节中系统介绍。

### 3.3 浮点与整型互转

浮点转整型时，如果值超出目标整型可表示范围，行为未定义；此外，小数部分会被舍弃（向零取整）。

例如 `(int)3.9` 的结果为 `3`，`(int)-3.9` 的结果为 `-3`。若需要将浮点数按四舍五入等方式转为整数，应使用 `<math.h>` 中的 `round`、`lround` 等函数，并在转换前确认数值落在目标整型可表示的范围之内。
