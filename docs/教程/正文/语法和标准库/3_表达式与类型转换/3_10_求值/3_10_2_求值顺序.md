# 3.10.2 求值顺序

求值顺序讨论的是：一个表达式里多个子表达式谁先算、谁后算，以及哪些先后关系由标准保证。很多“偶发错误”并不是算术本身有问题，而是把本应拆开的读写挤在同一表达式里，结果触发了未定义行为。

## 1. 三种常见关系

C11 起，标准使用**先序于 (Sequenced before)** 关系描述单线程内的求值顺序。任意两个计算步骤 `A` 与 `B` 之间必居其一：

1. **顺序已确定 (Sequenced before)**：`A` 先序于 `B`（或 `B` 先序于 `A`）。`A` 的值计算和全部副作用在 `B` 开始之前已经完成。
2. **顺序未定 (Indeterminately sequenced)**：`A` 与 `B` 不会交错执行，必有一方先于另一方完成，但标准未规定谁先谁后（例如两次不同函数调用的执行先后）。
3. **无序 (Unsequenced)**：`A` 与 `B` 之间没有任何先后保证，执行过程甚至可能重叠交错（例如普通二元运算符 `+`、`-`、`*`、`=` 左右两侧子表达式的求值）。

::: warning 优先级与结合性不决定求值顺序

运算符的优先级和结合性只决定表达式如何加括号分组（即谁是谁的操作数），**绝不决定子表达式谁先求值**。例如在 `f() + g() * h()` 中，虽然 `*` 的优先级高于 `+`（等价于 `f() + (g() * h())`），但编译器完全可以先调用 `f()`，也可以先调用 `h()`，三者的调用顺序是未指定的。

:::

## 2. 两个典型例子

```c
int i = 0;
int x = ++i + 1;  /* 有效：对 i 只有一次修改 */
```

```c
int i = 0;
int x = i++ + i;  /* 未定义行为：修改和读取对同一对象无先后保证 */
```

第一段中只有一次对 `i` 的修改，没有其他访问与之冲突，`x` 的值为 2。第二段中，左操作数 `i++` 对 `i` 的修改与右操作数 `i` 的读取之间没有先后保证，行为未定义（见 3.10.1 节）。修复的方法是拆成多条语句。

## 3. 函数调用里的顺序陷阱

函数实参的求值顺序通常不应被假定。例如 `f(i++, i++)` 会形成对同一对象的未排序双重修改，属于未定义行为。把更新动作放到调用前单独完成，再把结果作为实参传入，会更清楚。

## 4. 具有求值顺序保证的四个运算符

在全部 C 运算符中，只有以下四个运算符在单条表达式内部对操作数的求值提供从左到右的先序保证：

| 运算符 | 顺序与短路规则 |
| --- | --- |
| 逻辑与 `E1 && E2` | 先完整求值 `E1`（含其全部副作用）；若 `E1` 为 0 则 `E2` 不求值，否则再求值 `E2`。 |
| 逻辑或 `E1 \|\| E2` | 先完整求值 `E1`（含其全部副作用）；若 `E1` 非 0 则 `E2` 不求值，否则再求值 `E2`。 |
| 条件运算符 `E1 ? E2 : E3` | 先完整求值 `E1`（含其全部副作用）；随后仅求值 `E2` 与 `E3` 中被选中的那一个分支。 |
| 逗号运算符 `E1 , E2` | 先完整求值 `E1`（含其全部副作用）并丢弃其结果值，随后再求值 `E2`（注意：函数实参列表中的逗号是分隔符，不是逗号运算符）。 |

`&&` 和 `||` 都按从左到右求值，并带有短路语义：左侧已足以决定结果时，右侧不会被求值。这一点既能减少不必要计算，也常被用来保护右侧表达式的前置条件。

```c
if (ptr != NULL && *ptr == 'A') {
    /* 只有 ptr 非空时才会解引用 */
}
```

这里先判断 `ptr != NULL`，再决定是否访问 `*ptr`，顺序是有标准保证的。

## 5. 未指定顺序不等于未定义行为

有些表达式虽然子表达式先后未指定，但只要彼此不发生冲突读写，仍然是合法代码。例如独立对象的纯计算通常不会触发 UB。真正需要警惕的是“同一对象在同一完整表达式里出现无序冲突访问”。

例如下面的程序中，两个函数只做输出、不共享可修改状态：

```c
#include <stdio.h>

static int left_val(void) {
    puts("left");
    return 10;
}

static int right_val(void) {
    puts("right");
    return 20;
}

int main(void) {
    int sum = left_val() + right_val();
    printf("sum = %d\n", sum);
    return 0;
}
```

这段代码没有未定义行为，`sum` 的值必定是 `30`；但先打印 `left` 还是先打印 `right` 属于未指定行为，不同编译器或不同优化级别可能给出不同顺序。若业务要求严格的先后调用次序，应将两次调用分别存放在独立的局部对象中。

## 6. 判定顺序问题的实用步骤

排查复杂表达式时，可以按三步检查：先找是否有同一对象的多次读写，再看这些访问之间是否有标准保证的先后关系，最后判断是否跨越完整表达式边界。只要第二步回答不出来，最稳妥做法通常就是拆成多条语句，让先后关系由语句顺序显式表达。
