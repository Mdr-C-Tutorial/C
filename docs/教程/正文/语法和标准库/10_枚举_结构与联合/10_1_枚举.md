# 10.1 枚举

## 1. 定义

1. 枚举由一组已命名的整数常量值组成，每个不同的枚举构成不同的枚举类型
2. 每个枚举都有一个**底层类型**

## 2. 声明

枚举类型的声明为：`enum (属性说明符序列) (标识符) (: 类型) { 枚举项列表 }`

1. 枚举项列表中的每个 `枚举项` 之间由逗号分隔
2. 每个 `枚举项` 为 `枚举常量 (= 常量表达式)` 的形式
3. 如果省略 `: 类型`，则为无固定底层类型的枚举：这个枚举的底层类型由实现定义，这个类型一定能表示每一个枚举项的值；
   否则为固定底层类型的枚举，底层类型即为 `类型`

当某个枚举项省略 `= 常量表达式` 时，它的值等于前一项加一；首项若也省略，则默认从 `0` 开始。

```c
enum color {
    COLOR_RED,       // 0
    COLOR_GREEN,     // 1
    COLOR_BLUE = 8,  // 8
    COLOR_ALPHA      // 9
};
```

## 3. 作用域与名称

枚举常量名进入其所在作用域，不带 `enum` 前缀，因此要避免与其他标识符重名。枚举类型名本身需要通过 `enum 类型名` 使用；如果希望省去 `enum` 关键字，可以配合 `typedef`。

```c
typedef enum color color_t;

color_t c = COLOR_GREEN;
```

## 4. 转换与比较

枚举对象在表达式中按整数的转换规则参与运算。比较运算和 `switch` 的 `case` 标签都可以直接使用枚举常量，这比直接写整数字面量更容易阅读。

```c
enum state {
    STATE_INIT,
    STATE_READY,
    STATE_STOP
};

int run(enum state s) {
    switch (s) {
        case STATE_INIT:
            return 0;
        case STATE_READY:
            return 1;
        case STATE_STOP:
            return 2;
    }
    return -1;
}
```

`switch` 默认分支仍然建议保留，因为枚举对象在运行期仍可能接收到未预期值。

## 5. 关于固定底层类型

固定底层类型的写法（`enum E : unsigned char`）由 C23 引入；如果目标编译器尚未支持 C23，可以继续使用普通枚举，并在函数接口处检查取值范围。

## 6. 重复枚举值是合法的

同一个枚举中的不同枚举常量可以具有相同的值，标准并不禁止。这可以用来为旧名称提供兼容的别名，但要注意可读性：多个名字对应同一个值时，`switch` 中只会出现其中一个，应在该分支注释说明，避免读者误以为遗漏了分支。

```c
enum token_kind {
    TOK_EOF = 0,
    TOK_END = 0,   /* 与 TOK_EOF 同值，作为兼容别名 */
    TOK_ID  = 1
};
```

## 7. 枚举与位标志

普通枚举适合表示互斥的状态，例如解析器所处的阶段、连接状态或错误类别。可以同时成立的多个选项更适合用位标志表示：每个选项占一个二进制位，用无符号整数保存它们的组合，并为每一位单独定义常量。如果把选项的各种组合逐一列为枚举常量，常量的个数会随选项数成倍增长。

```c
enum msg_kind : unsigned char {
    MSG_PING = 0,
    MSG_DATA = 1,
    MSG_CLOSE = 2

unsigned char msg_kind_encode(enum msg_kind kind);
bool msg_kind_decode(unsigned char raw, enum msg_kind *out);

    printf("sizeof = %d\n", (int)sizeof(enum msg_kind));
    unsigned char raws[] = {0, 2, 3, 255};
    for (size_t i = 0; i < sizeof raws / sizeof raws[0]; i++) {
        enum msg_kind kind = MSG_PING;
```

实现一个任务状态机。状态和事件的枚举已经给出，请补全转移表、`task_step` 和两个名字函数（`#include` 省略了，按需补上）。

```c
enum task_state {
    TASK_INVALID = 0,
    TASK_PENDING,
    TASK_RUNNING,
    TASK_PAUSED,
    TASK_DONE,
    TASK_FAILED,
    TASK_STATE_COUNT
};

enum task_event {
    EV_START,
    EV_PAUSE,
    EV_RESUME,
    EV_FINISH,
    EV_FAIL,
    EV_RESET,
    EV_COUNT
};

enum task_state task_step(enum task_state state, enum task_event event);
const char *task_state_name(enum task_state state);
const char *task_event_name(enum task_event event);

int main(void) {
    enum task_state s = TASK_PENDING;
    enum task_event script[] = {EV_START, EV_PAUSE, EV_RESUME, EV_FINISH,
                                EV_RESET, EV_START, EV_FAIL, EV_RESET};
    printf("%s", task_state_name(s));
    for (size_t i = 0; i < sizeof script / sizeof script[0]; i++) {
        s = task_step(s, script[i]);
        printf(" -%s-> %s", task_event_name(script[i]), task_state_name(s));

    printf("pending+finish = %s\n",
           task_state_name(task_step(TASK_PENDING, EV_FINISH)));
```

- 其余状态与事件的组合都转到 `TASK_INVALID`。

3. 运行结果应为：

11014 里，枚举项和名字表是分开写的：加一个级别，要在枚举和表里各改一次，漏改一处两边就对不上。C 的预处理器可以把同一份清单展开成两份代码，这种写法称为 X 宏（X-macro）。

下面的清单把级别名和对应的字符串放在一起，请用这份清单展开出枚举类型和名字表，并验证两者同步：

```c
#define LOG_LEVELS(X)      \
    X(LOG_TRACE, "trace")  \
    X(LOG_DEBUG, "debug")  \
    X(LOG_INFO, "info")    \
    X(LOG_WARN, "warn")    \
    X(LOG_ERROR, "error")  \
    X(LOG_FATAL, "fatal")

/* 在这里用 LOG_LEVELS 展开出枚举 log_level 和名字表 level_names */

int main(void) {
    printf("%d %d\n", LOG_LEVEL_COUNT,
           (int)(sizeof level_names / sizeof level_names[0]));
    for (int i = 0; i < LOG_LEVEL_COUNT; i++) {
        printf("%d %s\n", i, level_names[i]);
    }
    return 0;
}
```

要求：

1. 用辅助宏 `AS_ENUM(id, name)` 展开成枚举项，令 `LOG_TRACE` 从 0 开始依次递增，并在清单之后补一个 `LOG_LEVEL_COUNT` 作为元素个数。用 `#undef` 撤掉辅助宏，再定义 `AS_NAME(id, name)` 展开成一张以枚举值为下标的字符串表 `level_names`。
2. 运行结果应为：

```text
6 6
0 trace
1 debug
2 info
3 warn
4 error
5 fatal
```

3. 在清单末尾加一行 `X(LOG_NOTICE, "notice")`，不改其他任何代码，重新编译运行。两个数字和输出怎样变化？说明为什么这种做法能保证枚举与名字表同步，而 11014 的手工表做不到。
4. 现在之所以能直接用 `LOG_LEVEL_COUNT` 当数组长度、用 `[id] = name` 指派，是因为这份清单的值恰好从 0 开始连续递增。如果把清单改成能给每一项指定值的形式，并让某些值不连续（例如 `LOG_DEBUG` 取 10），数组里没有指派到的位置存的是什么？`LOG_LEVEL_COUNT` 还能当元素个数用吗？此时遍历这张表要注意什么？
5. X 宏用一层间接的可读性换来两个名字的同步。说明这种写法适合什么规模的清单，什么情况下反而该保持 11014 的手写表。
