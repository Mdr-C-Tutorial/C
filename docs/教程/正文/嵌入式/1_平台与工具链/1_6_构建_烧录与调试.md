# 1.6 构建、烧录与调试

关于开发板的 Boot 设置如下：

| BOOT0 | BOOT1 | 存储器      | 说明                         |
| ----- | ----- | ----------- | ---------------------------- |
| 0     | x     | Flash       | 闪存存储器，是我们的程序所在 |
| 1     | 0     | 系统存储器  | 即是 Bootloader 固件所在地   |
| 1     | 1     | SRAM 存储器 | 在 SRAM 中调试代码           |

## 1. 串口下载

> 在一般的 STM32 最小系统板上都带有串口下载电路，这里使用 STM32F103C8T6 板子。
> 与仿真器相比，**ISP（In-System Programming）** 更加简单，但只能烧录程序，不能在线调试且下载速度慢

### 1.1 USB 转串口驱动

笔者使用的是 **CH340** 驱动芯片，其他芯片殊途同归（当然有时间你可以自己搓一个）。
要使用串口，需要先安装 USB 转串口驱动：CH340 版本，可以在网上搜索下载，这里就不赘述了。

CH340 的上位机接口是一根 USB 线，连接到电脑的 USB 口上，而它的两个串口引脚，`RXD -> PA9`，`TXD -> PA10`，连接到开发板即可。

<Exercise id="61127" :d="2" :w="2">

串口下载走的是 ST 固化在系统存储器里的自举程序，它的帧格式在 AN3155 里规定。本题按下面这份摘要实现拼帧，不需要真串口：

- 串口参数：115200 波特率、8 位数据、偶校验、1 位停止位。
- 每个命令帧两个字节：命令字节，紧接它的按位取反。自举程序发现两者不互补就回 NACK。
- 带参数的命令先发命令帧，再发参数帧；参数帧最后一个字节是这一帧前面所有字节的按位异或。
- 应答一个字节：`0x79` 为 ACK，`0x1F` 为 NACK。
- 常用命令：`0x00` Get（无参数），`0x31` Write Memory（4 字节地址），`0x43` Erase（1 字节页掩码，`0xFF` 为全片），`0x11` Read Memory（4 字节地址）。

写一个主机程序 `isp_frame.c`，按命令行参数打印一整条 Write Memory 命令的全部帧：

```text
$ ./isp_frame 0x08000000 0x10
cmd   31 CE
addr  08 00 00 00 08
len   0F
data  00 01 02 03 04 05 06 07 08 09 0A 0B 0C 0D 0E 0F
csum  0F
```

要求：

1. 地址与字节数都从命令行解析，用 `strtoul` 加 `base 0`，`0x` 前缀与十进制都能用。
2. `len` 行打印 N−1，N 为字节数；`data` 行是从 0 开始的递增序列，长度等于 N。
3. `csum` 行是数据帧的校验字节：N−1 与全部数据字节异或。
4. 字节数为 0、超过 256，或不是 4 的倍数时打印一行错误，以 1 退出。

验收：上面那条命令的输出与给出的完全一致；再试 `./isp_frame 0x0800FC00 8`，`addr` 行应为 `08 00 FC 00 F4`，`csum` 行应为 `07`。用 `gcc -std=c17 -Wall -Wextra isp_frame.c -o isp_frame` 编译。

</Exercise>

<Exercise id="61129" :d="4" :w="3">

串口 ISP 与 SWD 都能把固件写进 Flash，但两者能做的事差别很大。本题先把对照表写出来，再动手做一个能给出可信结论的实验。

(1) 列一张对照表，比较串口 ISP 与 SWD 探针：接线根数、是否需要改 BOOT 电平、能否在线调试、能否读回 Flash、烧录速度量级、能否在程序运行时介入。

(2) 串口 ISP 的速度可以算出来。按 115200 波特率、8 位数据、偶校验、1 位停止位，一个字节在线路上占几位？另有起始位 1 位，写出每秒能传多少字节。把 `debug_demo.bin`（520 字节）与 1.8 节 `minimal.bin` 的大小换算成理论最短耗时，再乘以协议开销系数（每帧有应答、命令与校验，取 1.3～1.6 倍），给出两档估计值。与 SWD 的 `openocd -c "program ..."` 实测耗时对照。

(3) 现场设备装在外壳里，BOOT0 与 NRST 都引不出来，只有一根串口线。按 [6.4 Bootloader 与固件升级](/教程/正文/嵌入式/6_质量_安全与交付/6_4_Bootloader与固件升级) 的思路，说明为什么要在应用里写一个 Bootloader，而不是指望用户拨 BOOT0。这个 Bootloader 至少要做哪四件事？

(4) 另一种做法是应用收到升级命令后直接跳回系统存储器里的自举程序。查 AN2606，列出跳转前必须做的三件事（关掉已使能的中断、把用到的引脚恢复成复位状态、把栈指针交还给自举程序），写出跳转函数的骨架。

(5) 这条「跳回自举程序」的路径少了一道保护：它不校验新固件是否完整。给出两条你会补上的检查，并说明它们分别挡住什么情况。

验收：第 (2) 问给出算式与两个耗时数，其中 `debug_demo.bin` 在 115200 下的理论最短时间约为 0.05 s；跳转函数里能看到关中断、恢复引脚、设置 MSP 与跳转到系统存储器地址；第 (5) 问的两条检查要一条与长度或校验和有关，一条与「写失败后能否回退」有关。

</Exercise>
